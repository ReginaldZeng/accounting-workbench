# 工作簿契约与来源

## 正式来源

- 导出入口：`01_Current_Deliverables/app/backend/routers/logistics_review.py` 中 `review_export`，路由为 `/api/logistics-review/export`。
- 四步就绪检查：同文件中的 `review_readiness`，路由为 `/api/logistics-review/readiness`。
- 恒茂标准表：`01_Current_Deliverables/app/backend/routers/logistics_standard_export.py` 中 `build_standard_workbook`。
- 前端入口：`01_Current_Deliverables/app/frontend/src/views/LogisticsReview.jsx` 的「导出复核表」。
- A–J 新版标准账单：同一路由文件中的 `review_standard_bill`，路由为 `/api/logistics-review/standard-bill`；数据接入页入口为「导出当前 A–J」。

这些文件是事实来源。应用格式升级后，应同步更新技能和校验器，不要依赖本参考文件继续接受已经下线的旧口径。

## A–J 新版标准账单

只有 `标准逐笔` 一页，第一行严格为主体、金蝶系统单据编号、费用类型、数量计算标准、账单数量、数量单位、费用总额、费用拆分1、费用拆分2、备注十列。G=H+I，允许 0.01 元浮点容差；无单号费用保留为“无金蝶单号”，不能漏出总额。承运商和账期写入文件属性及文件名，不增加标题行或身份列。

该文件是当前有效账单及人工费用修正的标准化输出，不包含计提、发票或复核登记结论，业务状态只能标为“标准账单（不代表已复核）”。

## A–N 新版标准账单

首页为 `标准逐笔`，表头严格为：主体、金蝶系统单据编号、费用类型、数量计算标准、账单数量、数量单位、费用总额、运费、送货/入仓费、提货费、卸货费、上楼费、其他、备注。G=H+I+J+K+L+M，允许 0.01 元浮点容差，空费用单元格按 0 计算。配送页按同名列取数；`4.山姆` 依次为干线、送货费、提货费、交仓卸货费、上楼费（空）、暂存费、备注；`5.外仓` 依次为运费、送货/入仓费（空）、提货费（空）、合计（装卸）、上楼费（空）、其他（空）、备注。

正式导出入口同为 `/api/logistics-review/standard-bill`，使用 `format=an`；默认 `format=aj` 保持原 A–J 行为。接口读取带费用明细列的原始附件并保留原工作表，不将汇总“附加费”猜拆为五类。A–N 只代表标准账单有效，业务状态只能标为“标准账单（不代表已复核）”。

## 动态费用列上传解析

A–G 固定为主体、金蝶系统单据编号、费用类型、数量计算标准、账单数量、数量单位、费用总额；H 起至备注前为任意数量费用列，备注必须是业务块末列。费用列可增删、换序，名称去空白后不能为空或重复，也不能与固定业务字段重名。每行费用总额等于全部费用列合计，空费用按 0。旧 A–J 仍保存为运费和附加费；动态格式逐项保留原费用名称。首页为 `标准逐笔` 时只读取首页，其余页仅作原始追溯，避免原页旧标准块造成重复导入。

## 恒茂四段式标准表

必须按顺序具有：

1. `01复核说明书`：复核对象、核量核价设置、账单与计提、异常、附件和提交结论。
2. `02单据运费`：做账维度、费用行追踪、核对方案、物料、数量、金额、单位费用及备注。
3. `03计提对账单`：主体、科目、部门、产品线、产品项目、凭证、计提、账单和差异解释。
4. `原账单-…`：系统能取得原始 Excel 时附上；原账单右侧可带系统复核链接。

`02单据运费` 的账单金额、标准金额、数量差异和金额差异可能含公式。多物料行的单据级字段可合并，金额只在费用首行出现一次，校验时不能简单对整列求和。

`03计提对账单` 的合计行用于勾稽：`计提金额(含税) - 账单金额 = 计提差异(计提-账单)`，允许 0.01 元浮点容差。

## 其他承运商现有表

必须具有 `复核表` 和 `复核明细`。`复核表` 的合计行用于勾稽：`计提金额(含税) - 账单金额 = 差异`，允许 0.01 元浮点容差。

`计提更正单` 只在登记了更正时出现，不能作为必备页。原始账单可能以 `原账单-…` 页附上；旧数据或特殊来源没有附件时保留警告，不伪造附件。

## 校验器边界

校验器执行 ZIP 完整性、openpyxl 回读、页签、承运商/账期、关键表头、合计勾稽、公式及缓存错误扫描，并提取业务状态。

校验器不执行以下事项：

- 不重算 Excel 公式，不把空缓存当成 0。
- 不替代四步 readiness，不判断发票、请款或审批是否真实完成。
- 不验证每个价格是否符合合同，不替代人工检查差异解释。
- 不做 WPS/Excel 视觉验收。

最终交付如需“已复核/可提交审批”，同时满足系统业务状态和文件 `--require-final` 检查；仅文件写有“已复核”但系统未登记时，以系统状态为准并明确提示。
