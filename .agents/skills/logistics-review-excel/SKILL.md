# 物流账单复核表 Excel

## 目标

按核算工作台当前复核结果交付可回读、可追溯的 `.xlsx`。导出是只读动作；登记已复核、撤销登记、修改归类、确认差异、写备注和更正计提都不是导出动作，必须另有用户明确指示才能执行。

## 必要输入

- 承运商：使用系统内的准确名称，例如 `恒茂`、`迅鸽`。
- 账期：统一为 `YYYY-MM`。
- 输出位置：用户指定时遵从；未指定时用 `output/logistics-review-excel/<账期>/<承运商>_<账期>_物流账单复核表.xlsx`。

从当前对话和已选页面推断已有信息，只追问仍缺失的承运商或账期。不得猜测账期，不得把一家承运商的设置、价格或结论套给另一家。

## 标准流程

1. **确认系统内复核状态**
   - 在物流账单复核台选择承运商和账期，按当前顺序检查：数据接入 → 逐单核价核量 → 逐笔计提复核 → 发票审核与登记。
   - 能调用现有会话接口时读取 `GET /api/logistics-review/readiness?carrier=<承运商>&period=<账期>`；保留 `steps`、`blockers`、`can_sign` 结论。
   - 有待处理项仍可导出工作稿，但必须明确称为“复核草稿”，不得称为已复核或付款审批版。不得为了让检查通过而自动确认异常或登记已复核。

2. **从系统正式入口导出**
   - 首选页面「导出复核表」，或复用当前已登录会话访问 `GET /api/logistics-review/export?carrier=<承运商>&period=<账期>`。
   - 不绕过接口直接拼数据库结果，不用另一套脚本重新计算核价、核量、计提或发票结论。
   - 接口需要当前用户权限；没有登录会话时，打开核算工作台让用户登录后继续，不索取或记录密码、Cookie、令牌。
   - 下载失败时先报告真实错误并检查服务、权限、承运商和账期；不得用空白模板冒充复核结果。
   - 不覆盖用户原件或已有复核表；目标已存在时先另起带时间戳的文件名。

3. **回读验收实际交付文件**
   - 在本项目根目录运行：

     ```bash
     python .agents/skills/logistics-review-excel/scripts/audit_review_workbook.py "<文件路径>" --carrier "<承运商>" --period "<账期>" --json
     ```

   - 仅在用户要求最终闭环版且系统状态也已闭环时增加 `--require-final`。
   - 命令退出码 `0` 才表示文件结构验收通过；警告必须如实带入交付说明。业务草稿与文件损坏是两回事，不要把草稿误报为 Excel 校验失败。
   - `openpyxl` 不计算公式。公式数量、无 `#REF!` 和合计勾稽通过，不等于公式已由 Excel/WPS 重算；需要公式显示值或视觉验收时，用可用的 Excel/WPS/LibreOffice 实际打开重算后再检查。没有这些工具时明确说明未做视觉或重算验收。

4. **交付**
   - 给出可点击的 Excel 文件路径。
   - 简述文件格式、计提/账单/差异合计、业务状态，以及仍存在的警告或未闭环事项。
   - 若未取到真实复核数据、未回读文件或未做视觉验收，不得宣称对应事项已完成。

## 工作簿口径

当前系统输出四类格式，验收时不得强行互相改写：

- **A–J 新版标准账单**：仅 `标准逐笔` 一页，严格 A–J 十列；G=H+I，承运商和账期写在文件属性中。通过 `/api/logistics-review/standard-bill` 导出。它只代表标准账单有效，不代表复核闭环，不能使用 `--require-final` 冒充已复核。
- **A–N 新版标准账单**：首页为 `标准逐笔`，严格 A–N 十四列；G=H+I+J+K+L+M，空费用按 0 计算，随后保留原始工作表。通过 `/api/logistics-review/standard-bill?format=an` 导出。它只代表标准账单有效，不代表复核闭环，不能使用 `--require-final` 冒充已复核。
- **恒茂四段式标准表**：`01复核说明书`、`02单据运费`、`03计提对账单`，随后为 `原账单-…` 页。说明书中的“八、提交结论”区分草稿与可提交审批。
- **其他承运商现有表**：`复核表`、`复核明细`；按实际结果可含 `计提更正单` 和 `原账单-…` 页。第二行显示待复核或已复核。

字段、公式和业务含义以当前应用为准。详细来源和验收边界见 [references/workbook-contract.md](references/workbook-contract.md)。

## 财务复核红线

- 总额对平不代表主体、费用类型、产品线、部门和凭证归口一致。
- 账单没有金蝶单号的仓储、冷藏等费用不能因不进逐单核对而漏出账单总额。
- 无合同价或无单价时只能写系统已有的“无法核价/仅核算术”等结论，不能补造价格依据。
- 公式必须与系统标准金额和结论一致；发现 `#REF!`、合计不勾稽、页签缺失或承运商/账期不符时停止交付并回到正式导出链路排查。
- 原始账单只读保留，不修改供应商原始费用名、金额和原始页内容。
- 不向外部网站、邮件或第三方服务上传账单；文件包含真实财务数据。
