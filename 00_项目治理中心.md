项目目录结构 PROJECT FOLDER STRUCTURE
==================================================

**AI_INSTRUCTION**
Project Structure:
- `01_Current_Deliverables/` — Latest approved deliverables only.
  - `app/` — The running application (all tools share ONE app).
  - `docs/<YYYYMMDD_工具名>/` — Each tool's CURRENT signed baseline documents only.
- `02_Revision_History/` — All development work must occur here.
- `03_Source_Materials/` — Requirements, references, source materials, organized as:
  - `00_平台通用/` — Platform-wide materials (portal, deploy, design, governance archives). Always sorts first.
  - `<YYYYMMDD_工具名>/` — One folder per tool line: ALL its draft versions, samples and materials.
- `00_Change_Log.md` — Master project change ledger. **History only, frozen at V2.169.**
- `00_Change_Log/` — Ledger fragments from V2.170 onward: ONE file per change, named
  `V<version>_<tool-line>_<summary>.md`. Sharded so that parallel branches never collide on the
  ledger (the old "insert at top of one big table" rule guaranteed a merge conflict per branch).
  See `00_Change_Log/README.md`. Added 2026-08-05.
- `04_部署包/` — Local staging area for built deployment packages (backend zips). NOT a governed
  deliverable tier: git-ignored in full, so it does not exist in a fresh clone. Packages are
  build artifacts (source is in git, re-buildable any time); deployment history lives in
  `00_Change_Log.md`. Added 2026-08-01.

Tool-line folder rule (V2.51, 2026-07-09): create a tool's folder on the day its requirement
confirmation doc v1.0 is drafted; prefix = that date (`YYYYMMDD_`). Folder listing therefore
reads as the tool development timeline. Current lines: 20260703_银行对账（含理财对账支流）·
20260705_物流计提 · 20260708_物流对账 · 20260709_成本台账.

项目版本治理 PROJECT VERSION GOVERNANCE
==================================================

**AI_INSTRUCTION**
Before every new task:
1. Read `00_Change_Log.md` (history) AND scan `00_Change_Log/` (recent, V2.170+)
2. Determine latest version
3. Propose new version
4. Use the era development folder — ONE folder per Major era, format `YYYYMMDD_VX.X_Description`
   (created at the start of a Major; all Minor versions of that era iterate inside it.
   Documentation-only tasks need NO revision folder. Amended per V2.51, 2026-07-09;
   see `02_Revision_History/20260703_V1.2_接真数据/README_本夹说明.md`)
5. Ensure the era folder mirrors the current deliverables before changing code
6. Perform development
7. Generate deliverables
8. Synchronize approved files
9. Add ONE new fragment file under `00_Change_Log/` (V2.170+). Never edit `00_Change_Log.md`.

No step may be skipped.

**OWNER_COMMENT_CN**
这是项目最核心流程。所有开发必须遵守。修订夹制度自 V2.51 起按实际做法转正：
一个 Major 时代一个开发夹（当前为 20260703_V1.2_接真数据），纯文档任务无修订夹。
