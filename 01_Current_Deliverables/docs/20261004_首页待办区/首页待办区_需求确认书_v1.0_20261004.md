## 一、为什么要做

工具线越来越多，**"我做完了，轮到你审"这个交接点，现在每条线各做各的**：

| 环节 | 现在怎么交接 | 审在哪里 |
|---|---|---|
| 汇率录入 | 写金蝶只提交不审核，发钉钉和邮件 | 金蝶 |
| 物流计提录金蝶 | 存草稿、回传凭证号 | 金蝶（提交、审核都在金蝶） |
| 物流付款做账（红冲 / 更正 / 核销） | 凭证补完分录后提交 | 金蝶 |
| 计提更正 | 登记「应改为什么」，打印更正单交专人 | 金蝶 |
| BOM 报价 | 初审 → 终审，有自己的待办页 | 工作台 |
| 发票管家 | 提交审核 → 审核页 | 工作台 |

**问题一：消息发出去就没了。** 钉钉和邮件是「告诉过你了」，不是「你还欠着」。没有一个地方能回答两个最常被问的问题——审的人问「我名下还有几件没审」，做的人问「我交上去的那笔审了没」。

**问题二：系统不知道该挂在谁名下。** 现在的「指定人」是通知收件人（手机号或钉钉号），不是工作台账号。

**问题三：后台自己在跑的活越来越多**（汇率定时录入、钉钉单自动接入……），机器做完之后落到谁手上，只有收到那条钉钉的人自己知道。

## 二、定位：是什么，不是什么

| 是 | 不是 |
|---|---|
| 一张「**谁手上还压着什么**」的清单 | **审批流** —— 不在工作台里替金蝶做审核 |
| 各环节交接点的**统一落点** | **任务管理** —— 不能随手新建一条待办 |
| 做的人查「审了没」的地方 | **催办系统** —— 一期不新增任何催人的消息 |

**五条铁律：**

1. **只挂不审。** 该在金蝶里审的，工作台只告诉你「该去审了」，不替人点。「审核留给人」这条不动。
2. **销账看事实，不看点击。** 金蝶里审了才算办结，以金蝶单据状态为准；不让人在工作台再点一次「我审过了」。
3. **没指定人不许悄悄丢。** 某环节没配处理人，待办挂到主管理员名下并写明「这个环节还没指定处理人」，不是不生成。
4. **首页不现查金蝶。** 首页只读本地一张待办表，打开首页不触发任何金蝶取数。
5. **待办只能由环节产生。** 不能手工新建、不能手工删除；只有「办结 / 源头撤回 / 主管理员作废（留痕）」三种去向。

### D8 展开：为什么待办记环节不记人

如果生成待办时把「张三」写死在那一行上，张三休假或调岗时，他名下没办完的要一条条手工转。记环节之后，设置里把「汇率审核人」从张三改成李四，**没办完的那几条下一秒就在李四名下**，不用迁移、不会漏。

留痕不受影响：谁发起的、最后是谁办结的，这两样照实记在待办上。

## 四、第一批接入的四个环节

| 环节 | 什么时候挂上 | 挂给谁 | 怎么算办结 | 点了去哪 |
|---|---|---|---|---|
| ① 汇率待审 | 汇率写入金蝶并提交成功（手工点的、定时自动跑的都算） | 汇率审核人 | 这一批汇率在金蝶里全部变成「已审核」 | 汇率录入 › 录入状态看板 |
| ② 物流计提凭证待审 | 「一键录入金蝶」成功 | 物流计提凭证审核人 | 这一批凭证在金蝶里全部「已审核」 | 物流计提 › 已录入凭证 |
| ③ 付款做账凭证待审 | 付款凭证补完红冲 / 更正 / 核销分录并提交成功 | 付款凭证审核人 | 这张凭证在金蝶里「已审核」 | 付款做账 › 这张请款单 |
| ④ 计提更正待办 | 复核台登记了一笔「应改为」 | 计提更正处理人 | 见 Q2 | 付款做账 › 这家承运商 |

**颗粒度（一条待办是多大的一件事）：**

- ① 一个月 × 一个组织 = **一条**，不是 8 条。行上写「8 条 · 已审 3」。
- ② 一个落账月份录进金蝶的凭证 = **一条**，行上写「12 张 · 已审 5」。（初稿写「一次录入的一批」；实现时改成按月——同一个月分几次录的并在一条里，审核人只看到一件事，不是一堆碎的。）
- ③ 一张凭证 = 一条。
- ④ 同一家承运商同一个账期的更正 = 一条。

**源头撤了怎么办：** 汇率在工具里撤销、计提凭证撤销录入、更正被撤掉——对应的待办自动标「已撤回」，从处理人名下消失，记录留着。

**三处要如实显示、不能含糊的情形：**

- ② 录进金蝶的是**草稿**，要有人先在金蝶提交，审核人才审得了。待办行上直接写「其中 4 张还是草稿、没提交」，不让审核人进金蝶扑空。草稿由谁提交见 Q1。
- ③ 如果凭证**提交失败**（已保存但没提交上），这条挂给做账人，写「请到金蝶手动提交」，不挂给审核人。
- 金蝶里把凭证**删了**：待办标「金蝶里已找不到这张凭证」，挂回发起人，不自动销。

## 五、页面长什么样

样机见 `prototype/home_todo.html`。要点：

**位置。** 问候区正下方、页面卡片上方。**默认收着**（D13）：点问候区右侧的数字才展开，再点同一个数字或点「收起」收回去。展开后，在 1920×1080 开 150% 缩放（实际可用约 1280×720）的笔记本上，待办清单完整落在首屏。

**问候区右侧改放待办提示（D12）。** 两个数并排：「待我处理 N 件」（有超期的在下面写「几件超过 3 个工作日」）、「我发起的 N 件在等别人」。一进首页不用往下看就知道有没有事；点哪个数，下面就展开清单并停在对应页签。

原先这个位置的「已开通页面」进度条、当前期间、是否封存整块去掉。开通了几个页面，下面「我有权限的 N / 显示全部 N」两个按钮上本来就有数；期间和封存状态进到具体页面后，在页面自己的期间选择器上看（封存的月份显示为灰）。

**三个页签。**

| 页签 | 给谁看 | 内容 |
|---|---|---|
| 待我处理 | 审核人、处理人 | 按环节设置，现在挂在我名下的 |
| 我发起的 | 做的人 | 我交出去的，现在在谁手上、等了多久、审了没 |
| 最近办结 | 都能看 | 近 7 天办结的，谁在什么时候办的 |

**一行写什么（表格，不做卡片）。** 要做什么（待审核 / 待处理）· 事项 · 谁交过来的 · 等了多久 · 在哪办（金蝶 / 本工作台）· 当前状态。

**在金蝶办的那几类，行尾两个动作：**

- 「看明细」——跳到工作台里对应的页面，看到这批是哪几条、凭证号多少。
- 「我已办，立即核对」——马上去金蝶读这一条的状态，审了就当场销，不用等下一轮。**这是为 D3 的滞后准备的出口。**

**没有待办时。** 问候区右侧的提示写一句「现在没有等你处理的事」，没有可展开的。

**超期。** 挂了超过 3 个工作日的，「等了多久」标成琥珀色。只变色，不发消息（见 Q4）。

**侧栏。** 首页图标右上角带数字（待我处理的条数）；为 0 不显示。

**机器交过来的和人交过来的，区分开。** 「谁交过来的」一列里，定时任务自动跑的写「系统 · 汇率定时录入」，人点的写姓名。

## 六、处理人设置

- **在哪配：** 系统设置里加一页「待办处理人」。每个环节一行，选一个或多个工作台账号。
- **谁能改：** 主管理员。每次改动留痕（谁、什么时候、从谁改成谁）。
- **没配的环节：** 这一行标红提示「还没指定处理人，待办会先挂到主管理员名下」。
- **处理人看不到那个页面怎么办：** 待办只是提醒去金蝶审，审核人不需要开通工作台里的对应页面。「看明细」点了没权限时，按现有的「申请开通」走，不另外开口子。

第一批四个环节的初始名单见 Q3，上线前填。

## 七、销账与核对

**怎么核：** 后台每 20 分钟把**所有没办结**的待办拿去金蝶核一遍单据状态（和现有的钉钉单扫描、发票凭证同步同一个节奏）。核到「已审核」就销，并尽量把金蝶里的审核人记下来。

**所以会有滞后：** 在金蝶点完审核，最长要等 20 分钟首页才销。等不及就点那一行的「我已办，立即核对」。

**金蝶连不上时：** 不销，行上写「上次核对没连上金蝶（10:20）」。**绝不因为读不到就当成已审。**

**已知限制（一期不做）：** 待办办结之后，如果有人在金蝶里又把它反审核了，待办不会自动挂回来。各工具页面自己的状态看板仍会照实显示「待审核」。

## 八、和数字员工办公室的关系

**待办区和数字员工办公室是一条链的两头：** 办公室那头看的是「机器替我们干掉了哪些活」，待办这头看的是「机器（或同事）干完之后，轮到谁接手」。数字员工每产出一件东西，落点就是某个人名下的一条待办。

**办公室本身另立项，不在本确认书范围。** 这里只把清单记下来。按《AI 合同预审工具 需求确认书 v1.0》D2 定的口径——**一个工位 = 一件自带触发器、无人值守的重复劳动**——后台已经在自己跑的有：

| 工位 | 它自己在干什么 | 干完交给谁 |
|---|---|---|
| 汇率录入员 | 每天定点抓人行中间价 → 建汇率 → 过四道闸门 → 写金蝶并提交 | 汇率审核人（本确认书 ①） |
| 发票接收员 | 每 20 分钟扫钉钉审批 → 建票夹 → 拉附件识别 → 票齐自动进审核 | 发票审核人 |
| 催票员 | 后补单到期自动钉钉催票 | 申请人 |
| 发票凭证同步员 | 每 20 分钟回查金蝶凭证号 | 无（纯同步） |
| BOM 立项员 | 钉钉单走到成本核算节点自动立项；同步财务经理节点的同意 / 退回 | 成本会计初审 |
| 物流请款单接收员 | 每 20 分钟扫钉钉公对公付款申请 | 物流复核人 |
| 取件机（报表送达 / BOM 落公盘 / 银行流水接入） | 内网机器定时取件送达 | 对账人、收件人 |
| 合同预审员（财务 / 法务） | 原定的头两个工位，仍卡在法务签字 | — |

**不进办公室的：** 银行对账认领、物流复核、BOM 复核、临时工考勤、付款做账、报表导出——人点了才跑、要人判断，是工具不是员工。

合同预审确认书写的是「工位凑够三个以上再做完整办公室」。**现在已有七个在跑，这个条件已经满足，不必等合同预审。**

## 九、待确认问题

### 卡开发的：**无**

### 不卡开发的（上线前定）：

- **Q1：物流计提录进金蝶的草稿，由谁在金蝶提交？** 现在工具只存草稿。建议：录入人自己提交，待办行上对审核人写明「还有几张没提交」。
- **Q2：计提更正怎么算办结？** 现在有两条路：一是打印《计提更正单》交专人去金蝶改；二是付款做账时系统把红冲更正合进付款凭证。建议：合进付款凭证并写入金蝶的，自动销；走打印那条路的，由处理人点「已在金蝶改好」并填凭证号——**这是第一批里唯一需要人手点的**，因为系统没法知道专人改的是哪张凭证。
- **Q3：四个环节各配谁？** 汇率审核人、物流计提凭证审核人、付款凭证审核人、计提更正处理人。
- **Q4：超期怎么算、要不要催？** 建议 3 个工作日标色；一期不新增催办消息，先看大家会不会自己来看。用不起来再加「每天早上一条钉钉汇总」。
- **Q5：录入人和审核人是同一个人时，要不要标「自审」？** 前提是能从金蝶读到审核人，这一点**还没实测**，读不到就做不了。

## 十、对现有工作的影响

| 影响面 | 结论 |
|---|---|
| 首页「不取业务数据」的规矩 | **加一条例外**：首页读一个轻量的「我的待办」接口，只读本地待办表，不碰金蝶。此前唯一的例外是「我的申请记录」 |
| 数据库 | 新增一张待办表（建表不改表，沿用现有做法）。不动任何既有表 |
| 四个环节的现有代码 | 各在交接成功的那一行后面加一句「记一笔待办」。记失败只留痕、**不拦原有动作**——不能因为待办没记上就让汇率写不进金蝶 |
| 钉钉 / 邮件通知 | 不动 |
| 权限 | 不新增准入点。每人只看得到自己名下的和自己发起的。处理人设置只有主管理员能改 |
| 汇率线原定口径 | 通知模块 `notifier.py` 头注「保留邮件与消息两种，不做待办」指通知渠道不走钉钉待办，**不变**；已在那条注释下补一句说明，免得以后再读岔 |
| 上线 | 改了后端，**须重启**。本机测试库不起核对线程（免得开发机去查真金蝶，沿用现有做法） |
