## 1. 目标与价值

核算组每月做大量「银行–金蝶」逐笔勾稽，量大、易漏、易错。本工具把重复易错的算账自动化，**让人只处理判断和例外**。三目标：

1. **归一**：各家银行 / 支付 / 理财的乱格式单据 → 标准《银行流水明细表》。
2. **找差**：银行流水 × 金蝶序时账逐笔勾稽，自动找出 **漏账 / 做错（金额差，比对到 4 位小数）/ 晚记**。
3. **可信**：每笔结论可落到凭证号可抽查，结果附三道勾稽的《可信度报告》自证。

**v1.4 后新增的第四个价值点——省人力**：出纳把流水按月存进共享盘即可，**打包 / 加密 / 填密码 / 上传整段劳动从出纳身上拿掉**（§9.2 共享盘上行取件机）。

## 3. 用户与场景

- **使用方**：核算组会计（制单 / 复核）。
- **交付方**：出纳（每月把流水存进共享盘，或按规范打包上传——§8）。
- **运维方**：系统管理员（部署取件机、配置停机告警——§10）。
- **典型动作**：选会计期间 → 银行流水自动接入（或手工上传）→ 一键接金蝶取数 → 看资金看板全貌 → 逐笔稽核查某账户「多少漏账 / 做错 / 晚记」→ 导差异清单人工核。
- **高频诉求**：优先核**疑似漏账**（银行出账了、金蝶没做账）。

## 6. 对账逻辑 · 状态模型（核心）

### 6.1 基础七类（每笔银行流水恰好归入一类）

| 状态 | 定义（银行存款 1002 视角） | 优先级 | 处理 |
|---|---|---|---|
| **疑似漏账** | 银行有、金蝶**整个取数窗口**查无（且账户已对上台账） | ★ 最高 | 优先核 · 补账建议 |
| **做错·金额** | 配对上但金额不等（**比对到 4 位小数**；差额显示到 4 位） | 高 | 生成补账建议 |
| **晚记·本月** | 配对上，金蝶日晚于银行日 ≥1 天，**未跨会计月** | 中 | 确认 |
| **跨期晚记** | 配对上，金蝶跨了会计月才入账 | 中高 | 关注：扭曲期末 |
| **金蝶单边·待查** | 金蝶有、银行无 → **疑银行流水未导全** | 中 | 查银行数据齐否 |
| **账号对不上台账** | 账号无法在台账唯一命中（掩码 / 短号 / 查无 / 一号多主体） | 单列 | 交人工 · 补台账 |
| **已匹配** | 金额（4 位）相等、同向、金蝶日 = 银行日、置信度达标 | — | 已核 |

> ⛔ **原「做错·精度」已废止**（v1.3）：金蝶因设置有时产生 4 位小数属正常，不能当"小数点错"；真正的金额差统一由「做错·金额」按 4 位小数比对捕获并显示差额（例：银行 .75 vs 金蝶 .7478 → 差 0.0022，归做错·金额）。

### 6.2 增量三类（v1.4 归拢，均"只标候选、交人工，不自动核销"）

| 新状态 / 能力 | 定义 | 铁律 |
|---|---|---|
| **组合待确认** | 银行 1 笔 = 金蝶 2~3 张**合计分毫不差**（同户同向 5 天窗，如理财赎回拆"本金 + 收益"）→ 不喊漏账 / 做错；随行列**整组等式**（含各凭证号） | 只标候选，不自动核销 |
| **疑记错户·账在他户** | 同额同向日差 ≤3 天、异户，且银行对方户名命中他户凭证摘要（强证据）→ 指认"账已记在 ×户 记-XX"，两腿互指并一行 | 无户名证据不猜 |
| **内部往来·两腿列示 + 双漏侦测** | 内部划转明写每腿做账状态；两户一收一支同额、金蝶两边查无 → 双标「内部往来·未做账」（实证抓出 450 万未做账划转） | 防金额巧合三道闸（对方户名限集团主体等） |

**置信度**：每笔匹配附 高 / 中 / 低——高＝金额 + 方向 + 对方 / 摘要一致；中＝金额 + 方向 + 日期近但对方 / 摘要缺；低＝仅金额方向、候选多或日期远。**低置信度强制复核。**

## 9. 数据接入（自动 / 手工双通道）

### 9.1 手工上传通道
上传即解析并**按所选期间定格入库**；此后逐笔稽核 / 余额调节 / 资金看板各页**直接读快照**，不重复解析。见 §8 交付规范。

### 9.2 共享盘上行取件机（v1.4 后新增，V2.486–493）

**背景**：出纳本就把流水按月存在共享盘（`\\10.10.8.251\...\资金流水\2026年\{月}\`）。服务器在腾讯云公网、够不着内网共享盘（与报表取件同一约束）。

**方案——反向取件机**（方向与报表取件相反：报表把云端文件拉回共享盘，本脚本把共享盘文件推上云端）：

| # | 机制 | 规则 |
|---|---|---|
| 1 | 部署位置 | 一台**常开的内网电脑**（能看见共享盘），装取件机脚本 + `bank_pull.ini`（填与服务器一致的 pull_token）+ 每小时计划任务 |
| 2 | 连接方向 | **内网主动出网推**，办公室零入口；与服务器共用 `pull_token`（core `_PULL_PATHS` 放行 `/api/bank-pull/*`） |
| 3 | 扫描节奏 | **每小时**扫共享盘月目录；月目录名宽松认期间（`6月流水` / `2026年08月` 都行） |
| 4 | 稳定期判据 | 目录内容连续 `settle_minutes` 分钟大小 / 数量不变才认"传完"才推；**未稳不推**（防推到写一半的目录）；页面点「立即扫描」则忽略窗口直推 |
| 5 | 增量 | 按大小 + mtime 去重，只推新增 / 变化的文件 |
| 6 | 落库 | 手工上传与自动推**共用同一条 `_ingest_bank_dir()` 管线**——财资归并 / 逐笔查重 / 重复待确认弹窗 / 月份不符警告一条不落地继承，杜绝绕过闸门的旁路 |

**三条铁律（代码 + 真机实测双证）**：

1. **不覆盖人工上传**——若本期已有非"取件机自动"来源的数据，只暂存不落定（实测：手工上传 + 已确认后再推，人工的确认人 / 时间 / 来源分毫未动）；
2. **保留人工确认闸**——自动推解析后照打「重复待确认」，**不自动确认**，等核算组当月打开页面弹窗点确认、留痕落其名下；
3. **传完才推**——稳定期实测：内容在变 → 重新计时不推；稳定未满窗口 → "约 X 秒后可推"不推；**只推绝不删共享盘**。

**真机实测**：19:37 一轮推 174 文件 → 服务器 8 月并入 442 笔；`来源 = 取件机自动` + `重复待确认 = true` 入库；无令牌 / 错令牌均被拒（401）。

### 9.3 停机钉钉告警（v1.4 后新增，V2.494–496）

取件机停了、页面亮红灯还不够——**服务器主动推钉钉给指定人**，不必盯页面。

| # | 机制 | 规则 |
|---|---|---|
| 1 | 判定 | **服务器侧自检**：取件机最近回报超过**约 2 小时**（每小时任务，取 130 分钟——漏约 2 轮才算停，避免每小时正常间隔误报）= 停了。页面红灯与钉钉告警**共用此阈值** |
| 2 | 触发源 | 取件机停了不会自己上报，故靠别处高频入口触发自检：报表取件机每分钟的 pending（独立心跳）、页面「数据接入」加载、bank-pull/pending 自身 |
| 3 | 不刷屏 | 去重标记——**只在"从在跑变停"那一刻发一次**「⚠️【银行流水取件机】停机预警」；恢复后清标记并发一条「✅【银行流水取件机】已恢复」；一次停机**最多两条** |
| 4 | 收件人 | **在前端配**（「数据接入」页 🔔 停机钉钉告警，填钉钉手机号；收起态显示打码号码 `136****3676` 便于核对配了谁）；未配收件人则不发；走**风控 AI 机器人**单聊通道（机器人为主、工作通知回退，复用 notifier） |
| 5 | 前提 | 服务器 `conf.ini [dingtalk]` 已配钉钉应用（汇率 / 物流线在用）；未配时前端红字提示 |

**真机实测**（2026-09-06）：停机→发 ⚠️、还停着→去重不发、恢复→发 ✅，三条链路全通。

### 9.4 财资平台多份导出归并口径（R20，2026-09-01 定）

同一批次里出现多份财资平台导出时（8 月及共享盘常态）：

1. **每份都解析**，谁也不略过；
2. **按【账户】整户择优并入**：同一账户出现在多份里，取**笔数最多**的那份（并列比收支合计，再并列归到整体更全的文件名下）；**整户整取，绝不跨文件按行拼**——按行去重会误杀同日同额的真实重复交易（实证：同日两笔 1,865,786.33 来回划转），全量并入则会把重叠账户记两遍；
3. **让位的每一份过逐笔查重**：其每一笔（含余额在内全字段）必须能在被采用的那份里找到；找不到计「疑漏笔数」，页面红字 ⚠「请人工核对是否漏账」；
4. **页面三态**：▶并入（绿）／ 重复（已解析、逐笔证明是子集，不重复并入）／ ⚠核对（有笔只在此文件里，疑漏账）。未并入的真流水整行红字加粗不折叠；回单 / 证明 / 理财 / 第三方等无关文件折叠进「跳过 N 个文件」；
5. **人工确认闸**：出现让位 / 重复 / 疑漏时上传后**弹窗**逐条列示，须人工点「我已逐条核对，确认重复判定」才算完——**确认人 + 时间留痕入审计**；未确认前状态行持续琥珀提醒、每次进页面重新弹窗。查重是机器初核，**判定责任在人不在系统**。

**8 月实证**：财资并入 200 笔 / 1 户 → 429 笔 / 11 户；文件 1 逐笔查重疑漏 0 笔（机器证明子集）。回归 12/12。

### 9.5 上传定格入库

- 上传 / 推送即解析并**按所选期间定格入库**；此后各页直接读快照；
- **重传即覆盖**本期快照（留痕：谁 / 何时）；解析口径升级后需**重传一次才生效**；
- 流水实际月份 ≠ 所选期间 → 红字警告"可能选错月份"；
- **已封存期间禁止上传**。

## 11. 稽核可信性框架与非功能需求

### 11.1 《可信度报告》三道勾稽（每次稽核自动产出）
1. **笔数勾稽**：每笔恰归一类、不重复消费，Σ 与来源汇总一致；
2. **余额勾稽**：期初 + Σ收 − Σ支 = 期末；
3. **数据齐（总额）**：Σ收 / Σ支对自带汇总（同比对到 4 位小数）；金蝶单边 >0 时提示"银行流水可能未导全"。

→ **三道全过才算本次结果可信**；否则标「待复核」并指明未过的那道。

### 11.2 非功能需求

| 类别 | 要求 |
|---|---|
| **性能 / 缓存** | 视图**进入秒开**：普通 GET 读缓存、仅「一键接入金蝶」（/sync）才实时取数；前端切视图保留状态 / 后台刷新；金蝶登录态复用、余额落地增量刷新 |
| 屏幕适配 | 1920×1080 主，支持 125% / 150% 缩放及 1366×768，关键信息不掉首屏 |
| UI 风格 | 冷灰 Linear / Notion 风；表格优先；语义色只用于状态 |
| 安全 | 金蝶只读；`conf.ini` 授权复用；压缩包密码不落盘 / 不进日志；pull_token 令牌鉴权；不外传数据 |
| 可维护 | 模块化、可读命名、错误处理、无硬编码 / 无静默失败；每文件带 [Change Log] 头 |
