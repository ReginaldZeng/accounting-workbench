## 1. 目标与价值

装订好的凭证册越堆越多，现在要找某一本，只能凭记忆走到档案室一个柜子一个柜子翻。搬办公室、装箱、送外仓、到期销毁时，位置全变了，谁也说不清哪一本现在在哪。

本工具做三件事，一句话概括：**给每本凭证册一个终身不变的编号，给每个存放点一个地址，再把「谁现在在哪」这件事记成一本可以批量改、改了有痕迹的电子账。**

1. **快速找到**：输入「主体 + 年月 + 凭证号」，直接告诉你这一号在哪一本、这一本此刻在哪个柜子哪一层哪个箱。不用翻。
2. **快速锁定**：每本书脊上贴一张标签，印着大字册号与凭证号区间。走到那一层，人眼扫一眼书脊就知道是不是这本。
3. **批量转移**：搬办公室、装箱、送外仓、销毁——**整层、整箱、整柜一次性搬**，系统里改一次，全部跟着走，且留下「谁、什么时候、把哪些册子、从哪搬到哪、为什么搬」的完整痕迹。

## 2. 核心设计主张（本工具的地基）

### 2.1 标签只印身份，不印位置 ✅

| | 内容 | 会不会变 | 印在标签上？ |
|---|---|---|---|
| **身份** | 册号、主体、期间、凭证号区间 | **永不变**（装订完就定死了） | ✅ 印，且印成大字 |
| **位置** | 档案室B → 3号柜 → 第2层 → 2026年03箱 | **经常变**（搬迁/装箱/外仓/销毁） | ❌ **不印** |

位置一旦印在标签上，每转移一次就得重贴一次标签。几百上千本册子，一次搬迁就是几百张标签重印重贴——工具反而变成负担，最后没人用，台账立刻失真。

把位置留在系统里，转移就只是改一条数据库记录。**"这本在哪"永远去系统查，"这本是谁"永远看标签。** 标签贴一次、管到销毁。这正是"批量转移"能够成立的前提。

### 2.2 位置是一棵树，册子挂在树叶上 ✅

位置节点不限定层数：

```
档案室B                        （节点类型：库房）
 └── 3号柜                     （节点类型：柜）
      └── 第2层                （节点类型：层）
           └── 2026年03箱      （节点类型：箱）
                ├── SZL2026-03-01   ← 凭证册
                └── SZL2026-03-02
外部仓库（联合档案托管）          （节点类型：外仓）
外借 › 天健事务所 · 王审计        （节点类型：外借）
2026年销毁批次（销毁字第7号）      （节点类型：销毁批次 · 终态）
财务办公室 › 3号工位柜           （节点类型：临时点）
```

**"装箱"不是一个动作，而是把箱变成一个位置节点。** 箱本身可以被整个搬走：`3号柜/第2层/2026年03箱` 整体挪到 `外部仓库` 底下，箱里所有册子的位置自动跟着变，一次操作。同理，整个"3号柜"搬到新办公室，也是一次操作。

### 2.3 册号是给人看的 ✅（Q1：凭证类型不占段）

```
SZL2026-03-02
└┬┘└─┬┘ └┬┘└┬┘
 │   │   │  └── 册序：该主体该月的第 2 册
 │   │   └───── 月份：03 月
 │   └───────── 年度：2026 年
 └───────────── 主体简码：星期零（SZL）
```

由系统在登记时**自动生成**（同主体同年月自动取下一个册序），不靠人编，保证不重号。目前只归档记账凭证一种，册号不加类型段；表内保留 `凭证类型` 字段备日后扩展。

**首段的主体简码取自平台级「主体档案」**（基础数据 › 主体档案），不在本工具里另建一份。**该主体一旦有过凭证册，简码即锁死不可改**——册号已经印在标签上贴到书脊了，改简码只有两种结局：旧标签与系统对不上，或者几百张标签重印重贴。详见《主体档案_设计与影响分析_v1.1》。

### 2.4 「已装箱」由位置派生，不作为存储字段 ✅

若「已装箱」是手工维护的状态字段，它会和位置字段打架：有人把册子从箱里取出放回柜子，改了位置忘了改状态，系统一边显示「已装箱」，一边显示位置「3号柜第2层」——两个都是系统说的，无从取信。

**做法**：只存四种状态，第五种算出来。

| | 取值 | 来源 |
|---|---|---|
| **存储状态**（数据库字段） | 在库 / 借出中 / 待销毁 / 已销毁 | 人工维护，四选一 |
| **显示状态**（界面与筛选器） | 在库 / **已装箱** / 借出中 / 待销毁 / 已销毁 | 若「存储状态=在库」且「当前位置节点类型=箱」→ 显示为**已装箱** |

界面上看到的、筛得到的仍是五种；但事实来源只有一个（位置），**永远不可能自相矛盾**。册子放进箱节点即自动变「已装箱」，取出即自动变回「在库」，无人需要记得改状态。

## 3. 数据模型（三张新表，不动任何既有表）

### 表一：凭证册 `archive_volumes`

| 字段 | 说明 | 备注 |
|---|---|---|
| 册号 | `SZL2026-03-02` | **主键**，系统生成，印在标签上 |
| 主体 | 星期零 / 深圳星期零 / 上海分…… | 沿用工作台既有主体口径 |
| 年度、月份 | 2026、03 | 会计期间 |
| 凭证类型 | 默认「记账凭证」 | 暂不进册号，留字段备扩展 |
| 册序 | 第 2 册 | |
| **凭证号起 / 凭证号止** | 51 / 100 | **按号查册全靠它** |
| 册内凭证张数 | 50 | = 止 − 起 + 1，系统自动算 |
| **存储状态** | 在库 / 借出中 / 待销毁 / 已销毁 | §2.4；「已装箱」不存 |
| **当前位置** | 指向位置树的某个节点 | 唯一的"活"字段，转移时改的就是它 |
| 借出人 / 应还日期 / 借出前位置 | | §6.3；归还时按「借出前位置」自动回位 |
| 保存到期年份 | 2057 | §6.4，可配置年数 |
| 备注 | | |

**关键校验**：同一主体、同一期间下，各册的凭证号区间必须**互不重叠、且首尾相接不跳号**。系统在登记时即时拦截，并提供《号段体检表》列出「没有任何一本覆盖到的凭证号」——通常意味着**漏装订或册子丢了**。

### 表二：位置树 `archive_locations`

| 字段 | 说明 |
|---|---|
| 位置ID | 系统内部主键 |
| 上级位置ID | 指向父节点，根节点为空（自定义深度即靠它实现） |
| 名称 | 「3号柜」「第2层」「2026年03箱」 |
| **节点类型** | 库房 / 柜 / 层 / **箱** / 外仓 / 临时点 / 外借 / 销毁批次 |
| 完整路径 | `档案室B › 3号柜 › 第2层 › 2026年03箱`（缓存字段，查询显示用） |
| 是否终态 | 「销毁批次」为终态：册子进去后不可再转出 |

> 「箱」这个节点类型是 §2.4「已装箱」显示状态的唯一判据。

### 表三：转移单 `archive_transfers` + 转移明细 `archive_transfer_items`

| 转移单字段 | 说明 |
|---|---|
| 转移单号、操作人、操作时间 | 留痕三要素 |
| 转移原因 | 办公室搬迁 / 装箱 / 送外仓 / 调回 / 销毁 / 借出 / 归还 |
| 源位置 → 目标位置 | |
| 涉及册数 | |
| 审批单号 | **销毁时必填**（§6.2） |
| 借出人 / 应还日期 | **借出时必填**（§6.3） |

明细逐本记录「册号 + 转移前位置 + 转移后位置」，**历史永久保留，不可删改**。操作留痕沿用工作台既有 `audit_log` 机制，不另起炉灶。

### 4.1 两条录入通道，各管各的 ✅

| 通道 | 用途 | 频率 |
|---|---|---|
| **Excel 批量导入** | 把柜子里现存的历史册子一次性搬进系统（期初） | **只用一次**，录完基本不再碰 |
| **登记新册（单本录入）** | 每月凭证装订完，当场录一本 → 打一张标签 → 贴上 → 放进柜子 | **天天用** |

**登记新册屏的设计要点**：装订完的那一刻，系统已经知道上一本止于第几号。所以——

- **起号自动接上一本**（上一本止于 62 → 本册起 63），**张数自动算**（= 止 − 起 + 1），**册序自动排**，**凭证类型 / 保存到期自动填**；
- **全表人只需填一个数字：这一本装到第几号为止。** 因为"上一本止到几号"人去翻册子会翻错，系统却一定知道；把人要填的东西压到一个数，出错面就只剩那一个数；
- **存之前系统当场做三条体检**：号段不重叠（不会一个凭证号查出两本）→ 号段不跳号（首尾相接）→ 拿金蝶核一遍（该期间共 N 张，本册收至第 N 号则本月号段完整闭合）；
- 存完直接「保存并打印标签」或「保存并继续录下一本」；连录多本时位置只选一次。

> **录入必须发生在装订的那一刻**，隔几天补录，台账就开始失真（见 R2）。

## 5. 标签设计 ✅

标签贴在**书脊**。书脊实测宽度 **3–5cm**，故：

- **默认标签尺寸 30 × 50 mm**（宽 × 高，竖排，贴在最窄的 3cm 书脊上也不溢出）
- **尺寸不写死**：设置页可自定义宽/高/页边距/每行列数，输入后实时预览排版。日后换标签纸或换打印机，改个数就行，不必改代码。

```
┌──────────────┐  30mm 宽
│ SZL2026-03-02│  ← 册号，最大字号
│              │
│ 星期零        │  ← 主体
│ 2026年03月    │  ← 期间
│              │
│ 第 51-100 号  │  ← 凭证号区间，找号时看这行
│ 第2册/共2册   │
└──────────────┘  50mm 高
```

**标签上没有位置。** 理由见 §2.1。

**A 期**：网页勾选册子 → 按设定尺寸生成 A4 不干胶排版页 → 浏览器直接打印或导出 PDF。零硬件成本。
**B 期**：对接标签打印机。因尺寸已参数化，只需新增「输出到打印机」通道，排版逻辑零返工。

## 6. 多人共用下的流程设计

### 6.1 转移冲突拦截

甲勾选「3号柜第2层」的 42 本准备送外仓，乙同时把其中 5 本挪去了办公室。若不管，甲提交后会静默覆盖乙的操作，系统显示这 5 本在外仓，实际在办公室——**台账开始骗人。**

**方案**：转移提交时校验「这些册子当前的位置，是否仍等于你勾选时看到的位置」。若有出入，**拒绝提交并列出冲突的那几本**（"这 5 本已被李出纳于 14:30 移至财务办公室，请确认后重试"），并提供「刷新这几本的位置」「仅转移其余 37 本」「查看对方的转移单」三个出口。宁可让人多点一次，不可让账悄悄错。

### 6.2 销毁：两人四眼、不可逆 ✅

| 步骤 | 谁 | 做什么 | 册子状态 |
|---|---|---|---|
| ① 申请 | **总账会计** | 建销毁批次节点 → 勾选册子 → 填**销毁审批单号** → 提交 | 在库 → **待销毁** |
| ② 执行 | **财务经理** | 复核清单 → 二次确认 → 执行 | 待销毁 → **已销毁** |

- 「待销毁」阶段可由总账会计**撤回**，册子退回原位置。
- 「已销毁」为终态：只读、不可再转移。
- **记录永久保留、永不删除**——销毁的是纸，不是账。
- 权限位：`archive_edit`（总账会计）、`archive_destroy`（财务经理）。财务经理无 `archive_edit` 时不能登记转移，只能执行销毁——职责分离。

### 6.3 借出 / 归还 ✅

审计、税务、事务所常把整本册子借走。若不登记，找不到册子时分不清是**被借走**还是**丢了**——而那正是最需要工具的时刻。

- **借出**：勾选册子 → 填借出人、事由、应还日期 → 状态转「借出中」，位置转到「外借 › 借出人」节点，并记下借出前位置。
- **归还**：一键归还 → 状态回「在库」，位置**自动回到借出前的位置**（系统记着，不必人工重选）。
- **逾期未还**：列表标红，首页给出"当前借出 N 本，其中逾期 M 本"。

### 6.4 到期提醒 ✅

登记时自动计算「保存到期年份」并在册子列表与首页提醒：到期后该册**可进入鉴定销毁流程**（到期只是可以销毁，不是必须销毁，仍需走 §6.2 双人审批）。

> **保存期年数做成按凭证类型可配置项、不硬编码**。默认值待业务方按现行《会计档案管理办法》财务口径核实后填入（见「待补 B」）。

## 7. 与金蝶打通

### 7.1 用途一：校验号段有没有漏装订（A 期做）✅

金蝶知道某主体某月实际有多少张凭证（如 1–100 号）。系统拿它与已登记册子的号段一比，即可指出「2026年01月的 96–100 号，没有任何一本册子覆盖到」——通常意味着**漏装订，或册子丢了**。顺带在登记新册时自动带出起止号校验。**代价很轻**：只需每个期间的起止号，不落明细。

### 7.2 用途二：按凭证摘要反查凭证号（B 期首选）🔲

会计找凭证时，脑子里往往不是"3月第85号"，而是"那笔付给极鲜达的运费"。把金蝶凭证摘要同步进来，即可输入"极鲜达"查到凭证号，再由凭证号定位册子与柜子。链路可通（`kingdee_client.fetch_gl_voucher_subjects` 现成）。**代价不轻**：须维护凭证明细本地副本并跟红冲、反过账。

**切分**：A 期做用途一；用途二列 B 期第一优先，待实际用起来确认"按摘要找"确属高频再做。
