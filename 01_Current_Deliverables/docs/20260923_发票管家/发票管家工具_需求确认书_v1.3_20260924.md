## 一、为什么要做

**四件事现在都靠人：**

1. **登记**：发票信息要一张张录进台账——慢，录错了也没人知道。
2. **查重**：同一张票报两次，只能靠经手人的记性拦。
3. **后补票**：预付款、先付款后补票的，靠 Excel《发票&收据后补申请单》跟——票到没到、还差多少、该催谁，都得人去翻。
4. **抵扣**：月底在电子税务局一张张勾选。

**为什么是"扫码＋放高拍仪"，不是"拍照上传"。** 扫码枪"嘀"一声就调出审批单；发票往高拍仪下一放，自动拍、自动读出票面二维码，号码、日期、金额和查重结果当场就有。**能读码的不认图，能读原件的不认图**——速度和准确度都在这一步定了。

**为什么现在能做。** 钉钉审批打印件上的二维码，普通扫码枪就能读，系统凭它就能调出整张审批单（2026-09-23 已实测，见 F1）。这是整个方案的钥匙：发票挂到哪张单上、查重、对金额、追欠票，全靠它。

## 二、定位：是什么，不是什么

| 是 | 不是 |
|---|---|
| **收票管家**：每张票挂到一张钉钉审批单上，登记、查重、审核、入台账 | **报销系统**：不替代钉钉审批，审批流照走 |
| **事前拦截**：扫的时候钱还没付，重复票当场拦下 | **验真工具**：不去国税查验平台逐张验（有验证码，不绕）；用税局清单对账代替（见九） |
| 预付、先付后票的**发票后补池**：业务同事网页填报、指定接收人、到期自动催 | **替人办税**：提交勾选、统计确认仍由人在电子税务局操作 |
| 抵扣勾选的**准备工具**：出「清单导入勾选」文件 | **做账工具**：一期不生成凭证 |

**四条铁律：**

1. **原件优先，识别兜底。** 能从电子原件、二维码读的，绝不"认图"。认图（OCR）得来的字段一律标"待核"，人核过才算数。
2. **缺什么就明说。** 二维码读不出、电子原件没拿到、明细没补全——直接显示缺什么，不假装登记完整。
3. **一张票的金额只能用一次。** 默认一票一单；确需拆给几张单（如一张票冲几笔预付），必须手工选"拆分"并留痕，合计不能超过票面。超了就是重复，拦。
4. **系统只做到"出文件"。** 凡是要登录电子税务局点的，都留给人。

## 四、在工作台里的位置

**「发票管家」是核算工作台的一个一级板块，和应付、成本、应收同级。** 下面四个二级菜单，都是点了直接进页面：

| 一级 | 二级 | key | 主要谁用 | 干什么 |
|---|---|---|---|---|
| 发票管家 `inv` | 收票工作台 | `invdesk` | 实习生 | 扫审批单建票夹，逐张放发票，实时出图片和字段，提交送审核（见五） |
| | 发票后补池 | `invlater` | 财务接收人 | 业务同事填的后补单都在这里；收到发票点一下（见七） |
| | 发票审核 | `invaudit` | 会计 | 复核提交上来的票夹和后补收到的票，通过才进台账（见八） |
| | 发票台账 | `invledger` | 会计、财务经理 | 审核通过的票都在这里；查询、导出、抵扣勾选、期初导入（见九） |

- 板块排在应收后面（设置页可调，见 Q15）。一期上线前各菜单状态为"开发中"，只有指定人可进。
- **业务同事的后补填报网页不在菜单里**：它是一个单独的网址，钉钉登录认人，业务同事不需要工作台账号（见七）。
- 一张票的一生：**收票工作台**（或**发票后补池**）登记 → **发票审核**通过 → 进**发票台账** → 抵扣勾选。

## 五、收票工作台：实时票夹

**工位配置**：电脑＋扫码枪（必须能扫二维码，只扫条形码的不行）＋高拍仪（选"免驱"的，网页直接调用，不装厂家软件）。

**一张单的操作：**

1. **扫审批单二维码（嘀）** → 屏幕自动开一个这张单的**票夹**：单号、类型、申请人、收款方或事由、金额；附件里的电子票，系统已自动读出、列进票夹，标"等纸质件"。
   - 付款单**没附发票**时，同时显示后补情况：已登记 → "发票后补，预计 9 月 30 日到票，接收人：李四"；**没登记 → 黄牌"无票、未登记后补"**（见 D15）。
2. **把发票放到高拍仪下** → 画面一静止就自动拍（也可按空格拍），系统从照片里读出二维码，**票夹里马上多一张**：
   - **第一拨，当场出来**：图片、号码、日期、金额，以及查重结果——
     - ✅ **已登记**
     - 🔴 **重复**："这张票已于 9 月 3 日挂在李四的费用报销单上"——红屏＋提示音，不能继续挂
     - 附件里已读到的票，再放它的纸质件＝"纸质件已到"，打勾，**不算重复**
   - **第二拨，几秒后补上**：销方、税号、税额、税率、项目类别——从电子原件读，或识别出来标"待核"（见六）。
3. **没有二维码的票**（出租车票、定额票等老式票）→ 同样放上去拍，系统改走识别，字段标"待核"，实习生当场对照图片核一下。
4. **放下一张**，直到这张单的票放完。票夹底部实时显示：**票合计 vs 单据金额**，一致还是差多少（只提示，不拦）。
5. **点"提交"** → 票夹送到**发票审核**。有重复票没移除、或还有票在识别中，提交不了。
6. **扫下一张审批单**，开下一个票夹。上一个没提交就扫了下一张，先提醒一下。

**其它进票方式（同样实时进票夹）：**

- **没有高拍仪**：用手机钉钉扫一下电脑屏幕上的配对码，手机就变成这个票夹的相机，拍一张电脑上就多一张。
- **电子文件**：把 PDF／OFD／XML／图片直接拖进票夹。
- **只有扫码枪**：也可以拿扫码枪扫发票二维码，先登记号码、日期、金额，图片和明细后补。

**票夹的状态**：收票中 → 待审核 → 已通过（进台账）／已退回（回到收票工作台，带退回原因）。

## 六、票面明细和电子原件从哪来

二维码里只有**号码、日期、金额**。销方名称、税号、税额、税率、项目明细，按下表顺序补全——**先到的先用，后到的用来核对**：

| 来源 | 谁动手 | 准确度 |
|---|---|---|
| ① 审批附件里的电子票（PDF／OFD／XML） | 系统，扫单时自动拉 | 原件直读，不会认错 |
| ② 电子税务局「全量发票查询」批量下载的文件包 | 财务每周拖一次进系统，按号码自动对上 | 原件直读，不会认错 |
| ③ 高拍仪／手机照片识别 | 实习生当场核，审核时再看 | 标"待核"，核过才算 |

- ①② 拿到的电子原件**由系统存档**，满足 F6；将来可直接交给凭证归档线。
- 没有电子原件的纸质票（老式票）：照片存档，纸质原件照旧装订。

## 七、发票后补池

**现在**：业务同事另填一张 Excel《发票&收据后补申请单》（14 个格子），"实际收回"那几行靠人手记。

**改成**：业务同事打开一个网址填后补单，填了的就进**发票后补池**；财务在池子里看、收、催。

### ① 填报（业务同事，电脑上）

打开网址（发到各部门群，钉钉工作台里也可以放一个入口）→ **用钉钉认人**：在钉钉里打开的直接进；在浏览器里打开的，点"钉钉登录"确认一下（见 F9）。业务同事不用开工作台账号。

**新建后补单：**

1. **关联付款单**：列出"我近期发起的付款单"，**没附发票的排前面**，可按收款方、金额搜；点一下选中，自动带出：
   - 公对公的**供应商信息**：收款方（工商名）、开户行、银行账号（见 F10）；
   - 付款金额、付款事由、ERP 单号、申请部门、审批编号。
   不是自己发起的单，输入审批编号也能关联。
2. **填 4 项**：发票种类（专票／普票／收据）、预计到票日期、预计到票金额（默认＝付款金额）、税率（选填）。
3. **上传资料**（选填）：合同、订单、说明等，拖进来就行。
4. **指定财务接收人**：从财务名单里选，默认上次选的人。
5. 提交 → 进后补池；接收人的钉钉马上收到消息："张三提交了发票后补：某包装设备租赁公司 ¥1,000.00，预计 9 月 30 日到票"。

**我的后补单**：业务同事能看到自己每一笔走到哪一步了；供应商发来电子票，也可以直接在这里上传。

### ② 付款审核（实习生）

实习生在收票工作台扫这张付款单时，屏幕上直接显示"已登记后补，接收人李四"。没附发票、又没登记后补的，亮黄牌（见 D15）。

### ③ 收票（财务接收人，在池子里点一下）

池子默认显示"我接收的"，按状态分：待收、部分到票、已收齐、超期。

- **纸质票交到手上**：找到这一笔，点一下"收到"，**顺手放高拍仪或扫码枪扫一下发票** → 系统自动查重、冲减，这张票送**发票审核**。接收人本身有审核权限的，可以"收到并审核通过"一步做完。
- **电子票**：业务同事在"我的后补单"里上传 → 接收人收到提醒，点一下"确认"。
- **自动比对销方**：发票上的销方名称和付款单上的收款方（工商名）对不上——比如钱付给 A、票是 B 开的——**标红**（见 D16）。
- 金额不够的算"部分到票"，余额继续挂着；一张票冲几笔预付、一笔预付分几次到票都能记。
- 收齐后，钉钉通知业务同事"已签收"。

**为什么"点一下"时还要扫一下**：不扫，这张票就不在台账里，查重就有漏洞——同一张票回头又拿去报销，系统拦不住。实在来不及扫，可以先只点"收到"，池子里标黄"已收到、号码未登记"，直到有人补扫（见 D14）。

### ④ 催票（系统）

到预计日期前几天提醒业务同事，超期后每周提醒一次，都抄送接收人（用现成的机器人单聊）。月底一键导出欠票清单，**按供应商汇总**，用来对预付账款的挂账。

| 实际收回日期、实际收回金额 | 接收人**点"收到"时系统自动记**（2 个） |

另外新增两项：**财务接收人**（谁负责收这张票）、**资料附件**。

**收据**：收据没有发票号码，不进查重；点"收到"时录金额，按金额冲减，池子里标"收据"。

**后补池里一笔的字段：** 付款单号、收款方（工商名）、开户行、银行账号、付款金额、付款事由、填报人、**财务接收人**、填报时间、应补票种、预计到票日、已到票金额、未到票金额、状态（待收／部分到票／已收齐／超期／已收到号码未登记）、销方比对（一致／不一致）、资料附件、最近一次提醒。

## 八、发票审核

> **这一节是我按"会计复核"理解写的，请在 Q13 确认。**

**是什么**：收票工作台提交的票夹、后补池收到的票，先进**审核队列**，由会计复核；**通过了才进发票台账**，退回的回到收票工作台，带退回原因。

**系统先标好，人来确认：**

| 看什么 | 系统怎么标 |
|---|---|
| 识别来的字段 | 标"待核"的逐个对照图片 |
| 金额 | 票合计 vs 单据金额，差多少 |
| 销方 | 发票销方 vs 付款单收款方（公对公） |
| 抬头、税号 | 是不是本公司 |
| 可否抵扣 | 按票种＋项目类别（如"\*餐饮服务\*"）给建议，**会计定** |
| 特殊情况 | 拆分、收据、只点了收到没扫号码的 |

**两档处理：**

- **没有任何异常的票夹：可以批量通过**，一次勾一批。
- **有异常的：逐张过**，处理完才能通过。

**谁不能审谁**：提交人不能审核自己提交的票夹。只有主管理员可以自审，留痕标"自审"——沿用 BOM 报价审核的单人模式口径（见 D20）。

## 九、发票台账

**审核通过的票都在这里，一票一行：**

| 分组 | 字段 |
|---|---|
| 挂在哪张单 | 审批单号、单据类型、申请人／部门、收款方或事由、单据金额 |
| 票面 | 票种、发票号码、开票日期、销方名称、销方税号、金额、税额、价税合计、税率、项目类别 |
| 状态 | 来源（附件／税局包／二维码／识别）、电子原件有无、纸质件到否、抵扣状态（可抵扣未勾选／已勾选／不可抵扣） |
| 留痕 | 登记人、审核人、各环节时间、改动记录 |

点开一行：图片或电子原件、挂靠的审批单、审核记录。

**页面里的几个页签：**

1. **台账查询**：按日期、销方、票种、抵扣状态、审批单筛选；导出 Excel。
2. **抵扣勾选**：
   1. 会计在电子税务局「抵扣类勾选」按期导出**未勾选清单**，拖进来；
   2. 系统逐张比对台账，给出"是否勾选"：已审核＋可抵扣 → 是；**会计最终确认**；
   3. 导出文件，原样传回电子税务局「清单导入勾选」→ 人工提交勾选、统计确认；
   4. 顺带出两张对账表：**税局有、台账没有**（票开了还没交上来——系统顺手和后补池里没收齐的单比一比，提示"可能是这笔后补的票"）；**台账有、税局没有**（抬头或税号不对、不是开给本公司的、已作废或红冲——要查）。
   这比去查验平台逐张验真更可靠：**税局清单上有的，就是真票，而且就是开给我们的。**
3. **期初导入**：上线前的历史票导进来，查重才有底（范围见 Q6）。
