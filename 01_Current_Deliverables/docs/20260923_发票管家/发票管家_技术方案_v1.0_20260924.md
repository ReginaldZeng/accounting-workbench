## 4. 处理流水线

**识别码分类**（`invoice_parse.classify_code`）：`https://aflow.dingtalk.com/...` 或含 `procInstId=` → 审批链接；20–21 位纯数字且前 8 位是合法日期 → 审批编号；以 `01,` 开头 → 发票二维码；其它 URL → 未知链接；其它 → 未知。

**扫审批单**：链接 → GET 短链接（免登录）取 `procInstId`、`corpid` → `topapi/processinstance/get` → 规范化 → 按 inst_id upsert 票夹 → 设为该用户当前票夹 → `attach_status=pending` 交后台线程拉附件和「图片」栏。审批编号 → 按编号前 12 位（到分钟）±2 分钟窗口，在已配置模板里 `listids` 找实例。钉钉未配置 → 400「未配置钉钉（conf.ini [dingtalk]）」。

**进票**（扫码枪码 / 上传 / 相机 / 手机 / 附件）：
1. 文件：落盘 → 生成预览、缩略（run_in_threadpool）→ 按类型解析：PDF 有文字层＝同步全解析（文字位置＋二维码）；PDF 无文字层/图片＝同步读二维码，`proc_status=pending` 交后台识别；OFD/XML＝同步解析＋"虚拟图片"；ZIP＝解包逐个处理（GBK 文件名、限深 2 层、单包 ≤ 200MB、单文件 ≤ 25MB）；照片里只有审批链接 → 当作扫审批单。
2. 发票二维码（扫码枪/手机）：无图片，只登记号码/日期/金额（fieldSrc=qr），明细等附件或税局文件包补全。
3. **查重**（模块级 `threading.Lock` 包住"查 + 插"）：同票夹同 dup_key → 合并为"纸质件已到"（补挂图片，不新建）；其它票夹的有效票（review≠void）或期初表命中 → 新建行但 `flags.dup` 置位，提交被拦；双方都是 split 且分配合计 ≤ 票面 → 允许。
4. 校验：发票抬头 vs 票夹公司主体、vs 本公司清单；公对公销方 vs 收款方（`normalize_name` 后比较）；二维码金额/号码 vs 解析值；金额+税额=价税合计。
5. 可否抵扣建议 `deduct_suggest`：专票且非不可抵扣类别（餐饮服务、居民日常服务、娱乐服务、贷款服务）→ yes；普票里旅客运输（类别含"运输服务*客运"或 type_label=旅客运输服务、铁路/航空电子客票）、通行费 → yes（注明原因）；税额为 0/免税/不征税 → no；抬头不符 → no；其余 → no。

**后台线程**（routers/invoice.py 模块导入即起 1 个 daemon，`threading.Event` 唤醒 + 3 秒轮询兜底；启动时把 running 重置为 pending）：①`inv_folder.attach_status=pending` → 下载附件与图片栏 → 逐个进票；②`inv_item.proc_status=pending` → OCR（rapidocr 单例＋锁，图片先缩到长边 ≤ 1800）→ 字段合并（二维码/原件来的字段不覆盖；OCR 来的字段进 pending 待核）→ done/failed（最多重试 2 次）。本地 SQLite 也跑（便于自测）；**只有催票线程**在 SQLite 下不跑。

**催票线程**（仅非 SQLite）：每 10 分钟醒一次，到设置的整点后当天首轮：未收齐的后补单，`预计日 - 今天 ≤ beforeDays` 且当天未提醒 → 提醒；已超期且距上次提醒 ≥ everyDays 天 → 提醒。发给申请人 uid ＋ 接收人 uid（`notifier.send_dingtalk_to`），结果写 inv_log。

## 8. 上线步骤与风险

1. 业务方验收通过 → 合并 origin/main（冲突处：NAV_MODULES、CODED_VIEWS、Sidebar 图标、static 重建）→ 定号 → release.json → 变更记录片段定号 → 单提交 → FF 推送。
2. 服务器 cron ≤5 分钟拉取并重启后端 → create_all 在 MariaDB 建 inv_* 表 → 核对 `SHOW TABLES LIKE 'inv_%'`、/api/health 版本号。
3. 系统设置：四个菜单保持"开发中"，只有 dev_users/主管理员可见 → 业务方实测 → 改"人工并行" → 管理员按人开准入点与敏感动作点。
4. 风险：①硬盘 9.3G——原图超 2MB 压缩、定期关注 `du -sh inv_uploads`；②重启中断——识别任务状态落库、启动续跑；③钉钉未配置/发起人离职——友好报错、可手工拖文件；④相机需 HTTPS——配对码与相机页固定走 https 域名；⑤并行分支撞号——合并时定号；⑥票总管/税局导出格式未见实物——列名自动识别＋拿样本后校准。
5. 回滚：`git revert` 后推送；inv_* 表与 inv_uploads/ 残留无害。
