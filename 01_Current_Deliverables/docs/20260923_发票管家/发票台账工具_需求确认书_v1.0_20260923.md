## 一、为什么要做

**四件事现在都靠人：**

1. **登记**：发票信息要一张张录进台账——慢，录错了也没人知道。
2. **查重**：同一张票报两次，只能靠经手人的记性拦。
3. **后补票**：预付款、先付款后补票的，靠 Excel《发票&收据后补申请单》跟——票到没到、还差多少、该催谁，都得人去翻。
4. **抵扣**：月底在电子税务局一张张勾选。

**为什么是"扫码"，不是"拍照上传"。** 一张单几张票，拍照上传要等识别、要逐字核对；扫码枪"嘀"一声就拿到发票号码、日期、金额，当场知道重没重复。**能扫码的不拍照，能读原件的不认图**——速度和准确度都在这一步定了。

**为什么现在能做。** 钉钉审批打印件上的二维码，普通扫码枪就能读，系统凭它就能调出整张审批单（2026-09-23 已实测，见 F1）。这是整个方案的钥匙：发票挂到哪张单上、查重、对金额、追欠票，全靠它。

## 二、定位：是什么，不是什么

| 是 | 不是 |
|---|---|
| **收票台账**：每张票挂到一张钉钉审批单上，登记、查重、跟欠票 | **报销系统**：不替代钉钉审批，审批流照走 |
| **事前拦截**：扫的时候钱还没付，重复票当场拦下 | **验真工具**：不去国税查验平台逐张验（有验证码，不绕）；用税局清单对账代替（见七） |
| 抵扣勾选的**准备工具**：出「清单导入勾选」文件 | **替人办税**：提交勾选、统计确认仍由人在电子税务局操作 |
| 预付／先付后票的**欠票台账**，到期自动催 | **做账工具**：一期不生成凭证 |

**四条铁律：**

1. **原件优先，识别兜底。** 能从电子原件、二维码读的，绝不"认图"。认图（OCR）得来的字段一律标"待核"，人核过才算数。
2. **缺什么就明说。** 二维码扫不出、电子原件没拿到、明细没补全——台账上直接显示缺什么，不假装登记完整。
3. **一张票的金额只能用一次。** 默认一票一单；确需拆给几张单（如一张票冲几笔预付），必须手工选"拆分"并留痕，合计不能超过票面。超了就是重复，拦。
4. **系统只做到"出文件"。** 凡是要登录电子税务局点的，都留给人。

## 四、实习生怎么操作（收票工位）

**工位配置**：电脑＋扫码枪（必须能扫二维码，只扫条形码的不行）＋高拍仪（选"免驱"的，网页直接调用，不装厂家软件）。

**一张单的操作：**

1. **扫审批单二维码** → 屏幕调出这张单：单号、类型、申请人、收款方或事由、金额；附件里的电子票，系统已自动读出、列好。
2. **逐张扫发票二维码**（"嘀"一声一张）→ 每张当场出结果：
   - ✅ **已登记**
   - 🔴 **重复**："这张票已于 9 月 3 日挂在张三的报销单上"——红屏＋提示音，不能继续挂
   - ⚠ **金额对不上**：票面合计 ≠ 单据金额，标出差额（只提示，不拦）
   - 附件里已读到的票，再扫它的纸质件＝"纸质件已到"，打勾，**不算重复**
3. **没有二维码的票**（出租车票、定额票等老式票）→ 放到高拍仪下拍一张，系统识别，实习生核对几个字段。
4. **扫下一张单**，上一张自动收口。

也可以直接把文件拖进页面上传（PDF／OFD／XML／图片），效果同上。

**票面明细和电子原件，实习生不用管**（见五）。

## 五、票面明细和电子原件从哪来

二维码里只有**号码、日期、金额**。销方名称、税号、税额、税率、项目明细，按下表顺序补全——**先到的先用，后到的用来核对**：

| 来源 | 谁动手 | 准确度 |
|---|---|---|
| ① 审批附件里的电子票（PDF／OFD／XML） | 系统，扫单时自动拉 | 原件直读，不会认错 |
| ② 电子税务局「全量发票查询」批量下载的文件包 | 财务每周拖一次进系统，按号码自动对上 | 原件直读，不会认错 |
| ③ 高拍仪照片识别 | 实习生核对 | 标"待核"，核过才算 |

- ①② 拿到的电子原件**由系统存档**，满足 F6；将来可直接交给凭证归档线。
- 没有电子原件的纸质票（老式票）：照片存档，纸质原件照旧装订。

## 六、预付款／先付后票：用付款单＋补交单替代 Excel 后补单

**现在**：业务同事另填一张 Excel《发票&收据后补申请单》（14 个格子），"实际收回"那几行靠人手记。

**改成：**

1. **付款时**：付款申请单加一个单选「发票情况」：随单提供／发票后补／收据后补／无需发票。选"后补"时再填：预计到票日期、预计到票金额（默认＝付款金额）、发票种类、税率（选填）。审批通过后，系统自动记一笔欠票。
2. **票到了**：业务同事在钉钉发起「发票补交」审批（手机上就能发）：选关联的原付款单（钉钉自带控件，付款单上已经在用）＋附上发票。电子票附上即可，系统自动查重、冲减欠票；纸质票连同打印的补交单交给财务，**实习生扫补交单、再扫发票，和平时一模一样**。一笔预付分几次到票、一张票冲几笔预付，都能记。
3. **没到票**：到预计日期前几天，钉钉提醒经办人；超期后每周提醒一次，抄送财务（用现成的机器人单聊）。
4. **月底**：一键导出欠票清单，用来对预付账款的挂账。

**Excel 后补单 14 个格子的去向：**

| Excel 格子 | 去向 |
|---|---|
| 申请部门、申请人、申请日期、钉钉审批号、收款单位、付款内容、付款金额、采购订单号（ERP） | **付款单上本来就有**，系统直接读，不用再填（8 个） |
| 发票种类、税率、预计收回日期、预计收回金额 | 付款单新增，选"后补"时才出现（4 个） |
| 实际收回日期、实际收回金额 | **系统自动记**，补交单扫码冲减时写入（2 个） |

业务同事少填一张表，"实际收回"不再靠人手记；原来那行"适用范围"变成「发票情况」选项的说明文字。

**收据**：收据没有发票号码，不进查重；补交收据时按金额冲减欠票，台账上标"收据"。

## 七、抵扣导出

1. 会计在电子税务局「抵扣类勾选」按期导出**未勾选清单**，拖进系统。
2. 系统逐张比对台账，给出"是否勾选"的建议：已登记＋已核对＋票种可抵扣 → 是；按票面项目类别（如"\*餐饮服务\*"）提示不可抵扣的。**会计最终确认。**
3. 导出文件，原样传回电子税务局「清单导入勾选」→ 人工提交勾选、统计确认。
4. 顺带出两张对账表：
   - **税局有、台账没有**：票开了还没交上来——很可能就是欠票；
   - **台账有、税局没有**：抬头或税号不对、不是开给本公司的、已作废或红冲——要查。

这比去查验平台逐张验真更可靠：**税局清单上有的，就是真票，而且就是开给我们的。**

## 八、台账长什么样

**发票台账（一票一行）：**

| 分组 | 字段 |
|---|---|
| 挂在哪张单 | 审批单号、单据类型、申请人／部门、收款方或事由、单据金额 |
| 票面 | 票种、发票号码、开票日期、销方名称、销方税号、金额、税额、价税合计、税率、项目类别 |
| 状态 | 来源（附件／税局包／二维码／识别）、核对状态、电子原件有无、纸质件到否、抵扣状态 |
| 留痕 | 登记人、登记时间、改动记录 |

**欠票台账（一笔后补付款一行）：** 付款单号、收款方、付款金额、审批通过日、经办人、应补票种、预计到票日、已到票金额、未到票金额、状态（未到／部分到／已到齐／超期）、最近一次提醒。

### 卡"欠票台账"（④）的：**2 个**

- **Q1（钉钉审批管理员）：付款申请单能不能加「发票情况」字段？** 单选：随单提供／发票后补／收据后补／无需发票；选"后补"时出现：预计到票日期、预计到票金额、发票种类、税率（选填）。有几个付款模板（公对公、对私……）就都要加。可选：审批流按"发票情况＝后补"加一个条件分支（比如多走一道财务经理）。
  **不改的退路**：保留 Excel 后补单，由实习生在系统里手工建欠票——能用，但少了"自动"这一半。
- **Q2（钉钉审批管理员）：能不能新建「发票补交」审批模板？** 字段：关联原付款单（必填）、本次到票金额、发票种类、附件、备注；流程建议一步：发起人 → 财务。

### 不卡开发、上线前要定的：

- **Q3：查重从哪天算？** 从上线日开始，还是先把今年已报销、已抵扣的票导进来当期初？已抵扣的可以从电子税务局"已勾选"清单导；已报销但没抵扣的，要从报销记录里导。**不导期初，上线前的票就拦不住。**
- **Q4：要接哪些审批模板？** 报销单、付款申请（公对公）、付款申请（对私）、备用金……列个清单，并指明每个模板以哪个字段作为"单据金额"。
- **Q5：金额对不上时的容差？** 分位误差、部分开票、一单多票都会让金额对不上。建议只提示、不拦截，请确认。
- **Q6：催票规则**：预计到票日前几天提醒？超期后多久提醒一次？抄送谁？
- **Q7：权限**：菜单放在哪个板块（建议"应付"）？谁能看台账？谁能解绑改挂（建议只给财务经理）？谁能导出抵扣文件？
- **Q8：扫完要不要在钉钉审批评论里写回一句核对结果？** 例如"发票已核：3 张，合计 ¥1,000.00，无重复"——财务初审人在钉钉里就能直接看到。需确认钉钉应用有写评论的权限。
- **Q9：硬件**：扫码枪、高拍仪现在有吗？要几个工位？
- **Q10：工具名**：暂定「发票台账」，可改。

### 需要的样本（开发和验收都要用）：

1. 电子税务局「抵扣类勾选」导出的未勾选清单 1 份（可打码）
2. 「全量发票查询」批量下载的文件包 1 个（含 PDF、OFD、XML）
3. 各类纸票的照片或实物 10 来张：专票、普票、火车票、机票、出租车票、定额票、过路费
4. 近期审批单打印件 5 张：附电子票的、只交纸质的、发票后补的都要有——用来验证扫码和字段对照

## 十二、对现有工作的影响

| 影响面 | 结论 |
|---|---|
| 钉钉应用 | 复用现有应用（审批读取、附件下载、机器人单聊都在用），**不用新建**。只有 Q8 写回评论需要确认权限 |
| 钉钉审批模板 | Q1 付款单加字段、Q2 新建补交单，需要钉钉审批管理员操作；**不改动现有审批流**（Q1 的条件分支是可选项） |
| 凭证归档线 | 本工具存下的电子原件是归档的上游；接口预留，一期不动归档线 |
| 导航与权限 | 新增一个菜单和对应准入点，走既有机制 |
| 服务器 | 电子原件存储：数电票 PDF 每张约百 KB，每月千张约 100MB；照片识别只有少量，内存影响可忽略 |
| 电子税务局 | 办税流程不变，勾选方式由"逐张勾"改为"清单导入" |
