Description: 总账凭证批量审核、选择部分凭证反审的上线与运维说明。

入口：核算工作台 → 总账板块 → 凭证审核；支持 `#/voucherreview` 深链。

功能与口径
- 主体多选、会计期间、状态、制单人多选、摘要包含筛选。改条件立即清空勾选；查询后生效。
- 一张凭证一行。日期、凭证号、真实明细行数、制单人、状态固定显示；多主体查询强制显示主体。
- 列设置按浏览器和登录人保存。默认显示主体、审核人、借贷总额；科目、币别、汇率和原币可选。
- 原币按币别和借贷方向分别汇总，避免混币合计或把借贷金额相加。选中附加列时异步扫描全凭证分录并缓存；不拿第一行代替整张。
- 列表每页 20/50/100 张；明细每页 50 行。摘要命中任一行返回整张凭证，行数和金额保持整张口径，明细高亮关键词。
- 批量审核 A 状态先 Submit，再 Audit；B 状态直接 Audit。每次最多 100 张，每张单独锁定、校验、执行和留痕。
- 反审可任选当前页中的部分凭证。只接受工作台成功审核且指纹仍匹配的当前审核周期；外部审核、外部重新审核、凭证修改后均不接受旧所有权。
- 指纹包括审核时间、审核人 ID、修改时间、记账状态、主体、期间、编号和总额；金蝶实时校验仍是最终准入依据。
- 任何操作都不自动反记账、反结账或改变金蝶审批规则。金蝶接口账号的权限与制单审核限制照常生效，工作台操作人另行留痕。

权限
- 菜单准入 `enter:voucherreview`；动作 `voucher_audit` / `voucher_unaudit` 独立登记，均为敏感动作。
- 后端逐路由校验登录、菜单开关和权限；非金蝶模式拒绝写入。沿用现有管理员/子管理员规则，不批量扩张普通账号权限。

数据与故障处理
- 新增四张独立表：vr_jobs（幂等任务与逐张结果）、vr_ownership（本次审核所有权与互斥锁）、vr_counts（行数缓存）、vr_summaries（全分录汇总缓存）。只 create_all，不改既有表。
- vr_jobs 保存请求、操作人、时间、阶段和逐张前后快照；audit_log 同步写业务日志。请求 UUID 唯一；相同 UUID 不重放。
- 超时、异常回包、成功后回读失败均标为 uncertain 并保留凭证锁；绝不根据看到状态 C 就补认审核所有权。
- 金蝶明确失败的请求显示失败并释放锁；提交已成功、后续审核明确失败时会保留提交后快照，刷新后可重新选择。
- 后端启动把未完成任务标为待核实，不自动重试。部署复用 busy.hold 等待写操作结束。当前生产为单进程；扩多 worker 前应增加主实例恢复协调。
- 待核实凭证由管理员对照 vr_jobs 请求/阶段、金蝶操作日志和实时凭证处理；确认无人继续执行后，以凭证 ID 和原 lock 令牌为条件清空锁，同时清空 fingerprint，记录核实人、依据和原因。不得直接补造反审所有权；C 状态但来源不明的凭证到金蝶人工处理。
- 只读汇总计算重启中断后显示失败，重新进入/刷新会重新计算。行数/汇总缓存按凭证修订指纹隔离。

验证
- 15 项离线测试：创建提交审核、审核中直接审核、选择部分反审、外部审核和重审拒绝、过期快照、重复请求、并发锁、超时冻结、明确拒绝解锁、已记账/作废拒绝、重启不重放、删行间隙精确计数、多币原币借贷分列、权限与菜单关闭。
- 金蝶只读联调：表头分页、完整金额、真实行数（包括超过三十万行凭证）、明细分页、摘要命中后整张返回。
- 浏览器检查工作台导航、筛选、列表与明细；前端 production build。已有 FundDashboard 重复对象键和大 chunk 提示属于原有代码，本次不改变。
- 没有以真实凭证执行审核/反审来做测试。写接口状态转换使用桩测试；真实操作结果由金蝶返回并逐张展示。
