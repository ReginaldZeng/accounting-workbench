# 数字员工办公室 · 需求确认书 v1.0

- 日期：2026-10-04
- 状态：**业务方 2026-10-04 口头定了方向并指示先做；一期已按本书实现（见第八节），待签署、待上线**
- 范围：门户层「数字员工办公室」——工位值班表、干活记录、给闲置电脑常开的大屏链接
- 不含：工时（业务方定：暂时不用）；带小人的办公室场景；合同预审工位本身（另见《AI 合同预审工具 需求确认书 v1.0》）

---

## 一、为什么要做

后台自己在跑的活已经有七八件（汇率定时录入、钉钉单自动接入、自动催票、BOM 自动立项……），但**它们各记各的，有的只留「最近一次」，有的只在内存里、后端一重启就没了**。结果是两件事没人知道：

- **机器停了没人知道。** 只有取件机有停机告警。汇率定时、发票接入、请款单扫描这些要是悄悄停了，页面上看不出来，只能等有人发现「这个月怎么没录」。
- **机器到底干了多少，说不出来。** 没有一处能回答「这个月它替我们干掉了多少件」。

《AI 合同预审》确认书（2026-07-17）写的是「工位凑够三个以上再做完整办公室」。现在已有八个在跑，条件早就满足。

## 二、定位：是什么，不是什么

| 是 | 不是 |
|---|---|
| 一张**工位值班表**：谁在岗、谁停了、干了多少、交给了谁 | 纯装饰——屏上每个元素都要有信息量，小人只在真有一次交接时走一趟 |
| 机器这一头的**成绩单**（人那一头是首页待办区） | 按人分的「数字分身」——不用真人姓名、头像，不和任何同事一一对应 |
| 能放在办公室里常开的一块屏 | 业务明细的入口——这里看不到供应商、客户、金额 |

**沿用合同预审确认书的两条：** 一个工位＝一件自带触发器、无人值守的重复劳动（按活分，不按人分）；主角是数字，不是动画。

**四条铁律：**

1. **只显示件数、状态和单号。** 值班表和大屏上不出现供应商名、客户名、金额、合同名——放在办公室里，路过的人都看得见。单号（钉钉审批编号）可以显示（D12）：它本身不带这些信息，没有钉钉权限的人拿着也打不开。
2. **「没上岗」和「停了」分开说。** 开关没开、没配置、还没部署，是「没上岗」并写明原因；本来在跑、现在没动静了，才是「停了」。
3. **空转不记账。** 这一轮没活可干不算干活；真干了、或出了错才记一笔。
4. **记不上不拦活。** 值班表记录失败，绝不影响工位本身的活（汇率照写、单照接）。

### D4 展开：为什么闲置电脑不登一个账号挂着

两个原因：

- **登录只管 7 天。** 到期那块屏就退回登录页，得有人去重新登。
- **一台没人看着、一直登着账号的电脑，谁走过去都能用那个账号。** 哪怕是个没权限的账号，也是个口子。

大屏链接里带一串口令，只能读这一张脱敏的值班表，进不了工作台、点不了任何东西。链接丢了，别人最多看到「本月干完 412 件」。主管理员随时可以「换一个」，旧链接立刻失效。

## 五、页面

**值班表**（登录后从门户进）：上面四个数——在岗工位、本月干完、交出去还没人接、上一轮出了错的工位；下面一张表，一个工位一行：它在干什么、多久干一次、上次干活、本月件数、状态、干完交给谁。点一行看这个工位最近的干活记录。

**四种状态：**

| 状态 | 什么意思 |
|---|---|
| 正常 | 按时报到，上一轮没出错 |
| 有出错 | 按时报到，但上一轮出了错（下一轮干成了自动恢复） |
| 停了 | 超过它该有的间隔三倍还没报到（每天跑一次的容忍 50 小时，每 20 分钟的容忍 70 分钟） |
| 没上岗 | 开关没开、没配置、还没部署——行上写明是哪一种 |

**大屏**（闲置电脑用，D9）：在业务方 2026-07-19 的等距办公室原型（`05 数字员工办公室/prototype/dashboard.html`）上重新设计，配色、等距画法、桌面小卡都沿用，改了这几处：

| 原来 | 现在 | 为什么 |
|---|---|---|
| 只有合同预审一个组，数字是假的 | 照真实值班表摆工位，按组分区：发票组 / 总账组 / 应付组 / 成本组 / 法务组 | 现在真有十几个工位在跑 |
| 9 张桌子里 7 张「待认领」空桌 | 有几个真工位摆几张桌子 | 空桌子没有信息量 |
| 三种状态：在岗 / 待命 / 空 | 四种：亮屏＝正常、黄屏＝上一轮出错、红灯闪＝停了、暗屏空椅＝没上岗 | 三米外要分得清「停了」和「本来就没开」 |
| 取件机没有位置 | 单独一间「取件间」，画成机柜 + 指示灯 | 它们是机器不是人 |
| 收件箱（等预审员来领） | 交接台：工位交出去、还没人接的活摞在这儿，有就亮灯 | 这是机器和人的交接点，数字读首页待办表 |
| 茶水台、洽谈区 | 拿掉 | 原项目说明里自己定的：屏上每个元素都要有信息量 |
| 交接动画循环播放 | 两次刷新之间某工位真多了一笔活、且要交给人，才走一趟 | 原项目说明里写的「真实上线必须是事件触发」 |
| 左栏：今日预审 / 本月累计 / 为法务省下多少小时 | 在岗工位 / 今天干完 / 本月干完 / 等人接手；下面各组在岗 | 不做工时（D3） |
| 右栏：实时任务流 / 待人工处理 | 刚干完的活 / 要人看一眼（停了、出错、超期没人接） | 接真数据 |
| 人物是两个方块（身体 + 头） | 圆头小人：每个工位发型、发色不同，衣服颜色跟组走；正常的在打字、偶尔点头，出错的挠头冒「!」，停了的趴在桌上睡，各有各的节奏；走去交接的那位看得见脸 | 业务方看后说方块人「太死板」。仍然不对应任何真人 |
| 小卡贴在桌子右前角往左展开 | 从人的右手边往右展开，统一画在最上层 | 原位置正好把坐着的人盖住 |

**大屏第二版：插画版（D10，现在用的这一版）。** 画面是业务方出的图，代码只负责把真实值班表「摆」上去：

| 画面上看到的 | 实际意思 |
|---|---|
| 人坐在工位上敲键盘，显示器亮绿灯 | 这个工位正常；十分钟内刚干过活的不会离开座位 |
| 人坐着挠头，头顶冒「!」，显示器亮黄灯 | 上一轮出了错 |
| 人趴在桌上睡，头顶飘 Zzz，显示器红灯闪 | 停了（该报到没报到） |
| 椅子空着，显示器暗着，名牌是灰的 | 没上岗（开关没开 / 没配置 / 等签字） |
| 画面中间弹出一张「新任务」派工单，单子一张张飞到工位上 | 定时任务这一轮真扫到了新活（D11）。单子上写谁接了什么（只有件数）；接到的人说「收到，开工」，敲一阵键盘，干完说一句交给谁 |
| 有人起身走到右下角交接台放一张单子 | 这个工位刚干完一笔、要交给人接手 |
| 显示器上闪一圈绿光、人敲几下键盘，不弹窗 | 定时任务巡了一圈，没有新活 |
| 交接台上摞着单子，旁边写「等人接手 N 件」 | 首页待办区里还没人处理的件数 |
| 左上角玻璃间里三台电脑，各有一盏灯 | 三台取件机 |
| 有人去茶水间喝水、去沙发坐一会儿 | **没有业务含义**，只是让画面不死板。同一时间最多两个人离座，回来接着干 |

工位怎么坐：第一排成本组和法务组（BOM 立项员、BOM 终审同步员、合同预审员），第二排总账组和应付组（汇率录入员、待办核对员、物流请款单接收员），第三排发票组（发票接收员、催票员、发票凭证同步员）；每排最右边一张桌子空着，留给以后新增的工位。

**派工单是回放，不是实况。** 大屏每分钟取一次数，看到某个工位多了一笔干成的活，才弹出来演一遍「派工 → 开工 → 干完 → 交接」，比真实发生最多晚一分钟；演的时候那笔活其实已经干完了。一次最多列四个工位，多的写「还有 N 个工位也有新活」。

**右栏和底部（D12）。** 右栏从上到下：时间、要人看一眼、刚干完的活、值班表。

- **刚干完的活**：每笔一张卡。句子统一写成「已……」：已接入 3 张钉钉单 / 已送审 2 个票夹（票齐了）/ 已接入 4 张请款单 / 已自动立项 1 单 / 已同步终审 / 已核对 5 条，销账 2 条 / 已对上 N 张发票的金蝶凭证 / 已写入 8 条。有单号的在下面列钉钉单号，卡片上最多列两个，多的写「共 N 张」。
- **哪些活带单号**：发票接收员（新接的单、票齐送审的单）、物流请款单接收员、BOM 立项员、BOM 终审同步员——这四个是按钉钉单干活的。汇率、催票、凭证同步、待办核对没有钉钉单号，卡片上只有件数。每笔最多记 6 个单号。
- **值班表**：默认收起成一行「9 在岗（1 出错）· 1 停了 · 2 没上岗」，点标题或按键盘 R 展开，这台电脑的浏览器会记住。展开后「刚干完的活」只剩最上面一两张。
- **实时动态滚动条**：在左下，最近十笔活连同单号首尾相接地滚。
- **定时任务排队（D13）**：在「刚干完的活」和「值班表」之间。**只排按钟点跑的**——现在只有两个：汇率录入员（每天 14:00）、催票员（每天一轮，钟点在发票管家设置里）。一行一个：`明天 14:00 汇率录入员 · 15 小时后`；三分钟内的标黄，到点的显示「轮到了」。没上岗、停了的不排队。
  - **巡检的不算定时任务**（业务方 2026-10-04 指出）：发票接收员、发票凭证同步员、物流请款单接收员、待办核对员、BOM 立项员、BOM 终审同步员这六个，是每隔二三十分钟去钉钉、金蝶看一眼有没有新活，有才干、没有就空转——不是「几点干什么」。它们不一个个排，只在排队表最下面收成一行：「另有 N 个工位在巡检……最近一次 X 分钟后」。
  - 时间是各任务报到时自己报的「下一轮什么时候」，不是推算的。
  - **一个员工可以排好几条**（D14）：BP 的驾驶舱值守员有早、下午两条，业绩快报员有日报、周报、月报、季报四条，排队表按「任务」一条一行。最多列最近四条，后面还有的写「后面还排着 N 条」。

**BP 的两个员工怎么接进来的（D14）。** 他们的活在 BP 工作台里干，核算这边看不见，所以由核算后台每分钟去 BP 读一次它「系统设置 › 定时任务」页用的那份清单（任务、下次几点、上次跑的结果、调度在不在转），替他们报到、记账：

| BP 那边 | 办公室里看到的 |
|---|---|
| 调度在转 | 在岗；每条任务的「下次几点」排进排队表 |
| 某条任务新跑了一次 | 记一笔，弹派工单：「业绩快报 · 周报已推 3/3 个群」「驾驶舱值守 · 下午已开跑」 |
| 有群没推出去 | 记成「有没干成的」；哪个群、什么原因只进出错原文（主管理员登录后才看得到），不上大屏 |
| 定时调度没开 / 这类任务全停用 | 没上岗，写明是哪一种 |
| BP 连不上 | 没人替他们报到，十分钟后显示「停了」 |

只读，不触发、不改 BP 的任务时间，**没有改 BP 的任何代码**。值守「开跑」之后查出了几条待办，办公室不知道（那个结果在 BP 的值守页），大屏上只显示它开跑了。

发票接收员这个工位实际干的是「接钉钉单 → 建票夹 → 识别附件 → 票齐送审」，所以卡片上写的是「已接入 N 张钉钉单」「已送审 N 个票夹」，没有写成「发票预审」——审是发票审核人审的。

九个人物各对一个工位，是画出来的形象，**不对应任何真人**。公司 LOGO 用的是原文件，没裁、没重画。屏上不放顶部横幅；右边一栏是时间、要人看一眼、值班表、刚干完的活，下面一排是四个数和各组在岗情况。

不登录、只认大屏口令、每分钟自己刷新。地址是 `/office-screen.html#k=<大屏口令>`；不带口令打开显示内置的样例数据（右上角标「样例数据」），可以当演示用。
