**【平台通用】首次登录强制改密（业务方提议，评估结论：必要——账号与重置密码都是主管理员设置的，
管理员知晓成员密码；平台又管着写金蝶/对外发送/模型密钥，初始密码长期沿用等于密码形同虚设）**

## 改法

1. **db.py**：users 表加 `must_change_pwd` 列（Table 声明 + `_ensure_user_columns` 老库 ALTER 补列，
   存量账号默认 0=不强制）；`create_user` / `reset_pwd` 置 1；新增 `change_own_pwd(name, old, new)`——
   验旧密→写新密→清标记，规则：新密 ≥8 位、不得与原密码或姓名相同；密码值不落任何日志。
2. **app.py `_auth_gate`**（真闸）：登录用户带 must_change_pwd=1 时，除 `/api/change-pwd` 外的全部
   `/api/*` 一律 403（`code:"must_change_pwd"`）——**含 `/api/bp-authz`，改密前 BP 也进不去**；
   直连 API 绕不过。新增 `POST /api/change-pwd`（本人改密，audit 只记「谁改了密码」不记值）。
3. **core.py `_user_public`**：外发 must_change_pwd 布尔（login/me 都带）。
4. **前端**：新增 `views/ForcePwd.jsx`（门户风格深色卡片：原密码/新密码/确认新密码，客户端预校验+
   服务端报错回显，可「换个账号登录」）；`App.jsx` 在登录判定后、进门户前门控渲染，改完 getMe 刷新放行；
   账号管理「重置密码」提示语追加「对方下次登录需自行改密」。

## 生效范围

- **今后新建的账号**与**被重置密码的账号**：下次登录强制改密。
- **存量账号**：不强制（默认 0）。想让某个老账号也走一遍：给他重置一次密码即可。
