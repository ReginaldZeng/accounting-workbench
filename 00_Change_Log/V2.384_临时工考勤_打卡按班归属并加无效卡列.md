# V2.384 · 临时工考勤 · 打卡按「属于哪一班」归属，逐日加「无效卡」列

**日期**：2026-08-29　**分支**：main

Reginald 看着黄寒寒 6/9 那行说：**「这种不应该是中间卡吗」**，
接着提：**「逐日这里，在上班和下班中间加多一列，无效卡吧——除了上下班以外的打卡」**。

两句都点在要害上。

## ① 打卡原来是按日历天硬切的

```
改前
  8日  上班 19:51   下班 次日08:32   次数 1     ← 只算了自己格子里那 1 张
  9日  上班 00:15   下班 20:03      次数 4     ← 背了上一班的 3 张，跨度还对不上
```

夜班跨零点，凌晨的宵夜卡、早上的下班卡都属于**起点日那一班**，可它们记在次日的格子里。
原来只按「天」记归属（`consumed`），次日若还有当晚的新上班卡就整天划不走，
于是 4 张卡全算到次日头上。

改成**按「张」记**（`used_pts`）：每一班用掉哪几张卡记清楚，次日只剩没被用掉的。

```
改后
  8日  上班 19:51   无效卡 次日00:15 次日00:42   下班 次日08:32   次数 4   跨度 12.68
  9日  上班 20:03   无效卡 —                    下班 —           次数 1   跨度 —
```

9 日那张 20:03 是**一次没有下班卡的刷卡**，现在如实显示成「仅1次打卡」，
不再顶着「4 次卡、跨度 0」的名头。

## ② 逐日加「无效卡」列（在上班和下班中间）

摆的是**上下班之外的那些卡**（午休、宵夜）。它们不参与在厂时长计算，
但摆出来这一行才读得通——否则「上班 19:51 → 下班 次日08:32、次数 4」，
中间那两张去哪了，看的人只能猜。

表头带悬停说明；跨度算不出来时显示「—」而不是 0（V2.383）。

## 效果

红灯一条没动：⚠撑不起 4 ／ ⚠待查 0 ／ ✓撑得住 1,594。
「◇未计工时」从 17 变 34、「△仅1次卡」相应变化——那是归属修正后的**正确**分布：
原来挂在次日的那批卡回到了起点日，次日剩下的孤立刷卡才如实归入「仅1次卡」。

内核测试 114 条全过。
