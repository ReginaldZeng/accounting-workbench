# V2.613 报表导出：序时账翻页提速（42 万行 2 小时→2 分钟）+ Excel 改只写模式（峰值内存 2.8G→0.7G）

起因（2026-09-23 真机）：导 2026 年 8 期，107 孝感市星期九一个主体卡了 1 个多小时不出结果。上服务器看：导出线程活着，约每分钟收到金蝶一页数据——不是死了，是慢。107 号 8 月序时账 **423,180 行**。

## 1. 序时账翻页：偏移翻页 → 按分录内码接着取（`kingdee_client.fetch_journal_full`）

- 原来：`StartRow` 偏移翻页 + 服务端按「凭证号, 分录行号」排序，每页 2000 行。金蝶每翻一页都要从头数过前面所有行，越往后越慢。实测 107：第 1 页 2.7s、2 万行处 6.1s、6 万行处 14.4s、12 万行处 20.0s、20 万行处 32.4s，40 万行处约 60s（服务器实况每页约 50–60s）。整本估 1.5–2 小时。
- 现在：`FEntity_FEntryId > 上一页末行` + 按内码排（主键），每页 5000 行，**每页恒定 1–2 秒**；107 整本 423,180 行 **126 秒**取完、行数一致。内码唯一且单调，翻页不丢行、不重行。
- 序时簿口径不变：本地按【凭证号(数值) → 分录行号(数值) → 内码】排回原顺序。
- 对照验证（同一次登录、同一数据）：101 旧 45,217 行 120.1s / 新 45,217 行 18.9s，**逐行完全一致**（0 行不同）；105（174 行）、108（4 行）同样 0 差异。小主体新写法多几秒固定开销，可忽略。

## 2. 写 Excel：普通模式 → 只写模式（`report_export.py`）

- 原来普通模式把几百万个单元格对象全攒在内存里：107 实测峰值 **2.8G**，服务器总共 3.6G（导出时可用约 1.7G），一个主体就能把后端挤进交换区甚至被系统杀掉。
- 现在 `Workbook(write_only=True)` 逐行流式落盘：107 峰值 **685MB**，文件完全相同（30.5MB，序时账 423,180 行）。
- 版式不变：字体/数字格式/边框/对齐/合并区/列宽/冻结/自动筛选/网格线全部照旧。逐格对照：101（650,182 格）、103（1,582 格）新旧文件 **0 差异**。

## 结果

107 从「取数 1.5–2 小时 + 写文件时内存爆」变成**本机端到端约 4 分钟、峰值 0.7G**。

发布：沿用 main 自动部署；改了后端 `.py`，**会自动重启后端**——正在跑的导出会被中断，重启后重导即可（已导好的文件不受影响）。回退＝反向提交本提交。
