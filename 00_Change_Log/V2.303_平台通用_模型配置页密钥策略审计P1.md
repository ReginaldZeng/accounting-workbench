**【平台通用】模型配置页：更换密钥 / 人员策略 / 调用审计 三项 P1 点亮**

## 起因

Owner 部署 V2.302 后：「已经2.89了，但是这里还是改不了密钥」「还有人员策略和调用审计的P1」。
V2.302 时这三项刻意灰显（当时的边界：key/策略走 .env 手工、审计跳各台）。本次全部做实——
且**不依赖网关**：三项都是"核算代理 → 各工作台自己的管理端点"，直连模式即可用。

## 改动

| 文件 | 内容 |
|---|---|
| `routers/llm_hub.py` | ①`POST /api/llm-hub/key`：更换密钥代理——key 直达工作台 `POST /api/llm/key`（写它自己的 .env + 热载，立即生效），**核算不存不记 key 值**，audit 只记"谁给哪台换了哪家的钥"；成功后失效状态缓存。②`POST /api/llm-hub/policy`：人员策略代理（默认每人日限次/token + 豁免名单）。③`GET /api/llm-hub/audit`：聚合各已接入工作台 `/api/llm/ask-audit` 按时间倒序（问数/AI 分析/通用对话全覆盖——BP V2.229 起三类都落审计账），答案截 300 字，不可达的台如实列出。全部管理员（can_admin_accounts）可见 |
| `ModelConfig.jsx` | ①区「更换密钥/写入密钥」激活：KeyWriter 一次性写入框（password 输入、只写不回显、保存后刷新打码 keyHint；工作台不可达则禁用）。②-b 改 PolicyEditor：日限两框 + 豁免名单文本框（展示名，存储侧 percent-encode）+ **全站硬闸只读**（防烧穿的最后一道，仅服务器 .env 可改——BP 端点就没开放它）+ 保存立即生效。④ 改 AuditPanel：近 7/30 天 + 只看报错 + 悬停看答案摘要 + 不可达工作台警示。副标题口径更新：密钥/策略/审计已集中管理，「内部凭证」才需网关在线 |
| `api.js` | setWorkbenchKey / setWorkbenchPolicy / getLlmHubAudit |

BP 侧配套（记 BP 台账 **V2.230**，包 2.230/徽标 V2.90）：`POST /api/llm/key`、`POST /api/llm/policy`
（appSettings 闸；写 .env 原子替换 + os.environ 同步 + llm_quota.reload_limits() 热载）。

## 验证（本机 8000↔8010 全链路）

- 更换密钥：写 kimi 假 key → BP **不重启**即 configured + 打码 keyHint、.env 落行；UI 全流（点更换→输入→保存→卡片刷新 sk-u***8777）。
- 人员策略：UI 存 60次/30万/豁免曾禹锡 → usage limits 立即反映、豁免名 percent-encode 存/解码显示正确；测毕恢复原值。
- 调用审计：聚合出 BP 的 analysis/问数/失败记录（含吊销凭证后的 502 那笔 ok=0），带工作台标签，只看报错过滤可用。
- 途中修一个自伤 bug：KeyWriter 用了 `setWorkbenchKey` 却忘了加进 import——构建不报错、运行时 ReferenceError 卡「写入中…」。教训：**新增跨文件引用后，浏览器过一遍真实点击流再算完**（构建过≠能跑）。

## 边界与遗留

1. key 传输路径 浏览器→核算→BP 与登录口令同信道；服务器现为明文 HTTP——**建议尽快上 HTTPS**（backlog）。
2. 策略编辑当前只对 BP（唯一已接入台）生效；其他台接入后同一面板管理。
3. 网关侧密钥（GW_*）仍 .env 手工——网关尚未在服务器启用，启用后如需 UI 管理另起版本。
