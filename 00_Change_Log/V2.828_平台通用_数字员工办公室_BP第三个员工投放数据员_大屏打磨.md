# V2.828 平台通用：数字员工办公室——BP 第三个员工「投放数据员」+ 大屏打磨（停了要醒目、自己换新版、右栏腾地方）

日期：2026-10-05

**起因**：V2.797 上线后上服务器核对，发现线上的 BP 工作台（V2.581）比本机那份代码新很多，定时任务清单里多了四条投放相关的任务，办公室不认识、被忽略了：千川数据每日拉取、投放ROI快报每日重建、投放ROI快报定时推送、千川实时预警。问用户要不要设第三个员工，用户说「加」。

**改法**：

- `backend/worker_store.py`
  - 工位注册表加 `bp_ads` 投放数据员（经营分析组，按钟点跑）。工位总数 14 → 15。
  - `set_queue()` 的任务可以带 `patrol=True`（巡检型：隔一阵看一眼，不是几点干什么）。存的时候在任务名前加 `~` 记住，值班表的 `queue` 里这条 `sched=False`。**没有改已上线的表结构。**
  - 一个工位管好几条任务时按「每条任务各自最近一次」判有没有出错：干活记录的 `trigger` 里用 `#` 带任务名（如 `定时#adroi-daily`），值班表取最近 40 笔按任务分组，有一条最近一次没干成就算「有出错」。原来只看最后一笔，后一条任务干成了会把前一条的错盖掉。工位干活记录接口返回的 `trigger` 去掉 `#` 后面的部分。
- `backend/office_bp_bridge.py`
  - 任务类型 → 工位的对应加四个：`qianchuan` / `adroi` / `adroipush` / `qcwatch` → `bp_ads`。改成按工位归组处理。
  - 四种任务各自的一句话（照线上 BP `app/scheduler.py` 写运行记录的格式解析）：「千川数据已拉取 3/3 个账户」「投放ROI快报已重建，要处理 4 条，有 2 条告警」「投放ROI快报已推 2/2 个对象」/「到点了，这次跳过没推」。
  - **投放ROI快报重建的备注里有投放金额和 ROI，一个字都不转存**：一句话里只取「要处理 N 条」「告警 N 条」两个数；出错原文写的是「详情在 BP 的定时任务运行记录里」。
  - 千川实时预警是巡检型：排队表里不算定时任务；正常的一轮不记账，出错才记一笔。
  - 没见过的任务第一次只记进度、不补记（这次刚接进来的四条，当天早上已经跑过的不会被补记成刚干完）；从没跑过的任务先登记「认识了」，它第一次真跑的那笔记得上。不认识的任务类型忽略。
  - 认得 BP 的「每 N 分钟」排期（`when.type=interval`），说成「08:05–23:35 每 30 分钟」。
- `frontend/public/office-screen.html`：投放数据员坐最右一列第三排，用 12 号人物（图已在 V2.797 里）。十二张桌子坐满，备用座位清空。排队表下面那行「另有 N 个工位在巡检」改成「另有 N 项巡检」（投放数据员自己有一项巡检，按工位数说不准了）。
- **大屏打磨**（用户问「这个页面还有什么可以优化的」，我提了几条，用户说「做」）
  - **停了要醒目**：有工位停了 → 画面一圈红边（缓慢闪）+ 顶上一条红色横幅「谁 停了 · 多久没动静」，不止一个时写共几个。上一轮出错的不这么闹（投放ROI快报有告警这类每天都可能有），仍只在右栏。
  - **页面自己换新版**：`routers/office.py` 的大屏接口多带一个 `page`＝大屏页面和图片文件最后改动的时间戳；大屏每次取数比一下，变了就自己重新加载。看文件时间而不是版本号——只改页面不改后端的上线不重启后端，版本号是启动时算的，会漏。用页面「全屏」按钮进的全屏会被重载打断，所以那种情况先不重载、左上角提示「页面有新版本 · 退出全屏后自动更新」；用 F11 或浏览器 kiosk 方式全屏的不受影响。
  - **右栏给「刚干完的活」腾地方**：「要人看一眼」没事时缩成一行「都正常」（高度 109 → 43）。右栏那一列原来会被长文字撑宽、贴到屏幕右边，改成定宽。
  - **名牌放大**：桌上的名牌字号 12.5 → 14.5。排队表里任务名不再被截断，多久一轮只留「每天 / 工作日 / 每周一 / 每月 1 日」，不重复钟点。
  - **汇总数字改成干活次数**：值班表 `kpi` 多给 `todayRuns` / `monthRuns`（一笔干活记录算一次）。下面两张卡改叫「今天干活 N 次」「本月干活 N 次」，各组在岗那块也按次数。原来是把张、条、次、个群加在一起叫「件」。值班表里每个工位自己的数仍用自己的单位。
  - **取数从每分钟改成每 30 秒**：派工单最多晚半分钟。
  - **头顶写着在处理什么**（用户：「他们的头顶要不要加一个正在处理哪一个审批单之类的」）：派工回放的那几秒，气泡从「收到，开工」换成「处理 3 张钉钉单 · 尾号 0417」；没有单号的工位写「正在：去金蝶看审了没」「正在：业绩快报 · 周报」这类；干完再说交给谁。单号只放尾号四位（整串十八到二十一位，完整的在右栏卡片上）；不放审批单标题（常带供应商和金额）。**这是回放不是实况**：任务干完才报、大屏半分钟后才知道，没有去改各任务让它们实时上报——一张单几秒就处理完，半分钟取一次数也抓不到。
  - 说话的气泡从正头顶挪到头的右上方（两排桌子之间的空地上）：放正头顶会盖住后一排桌上的名牌。
