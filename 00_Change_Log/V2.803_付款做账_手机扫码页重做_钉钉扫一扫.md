# V2.803 付款做账：手机扫码页重做 + 钉钉里实时扫

日期：2026-10-05

用户真机打开 V2.802 的手机页后：「这个页面，是不是可以在优化下」「扫描，而不是拍照」。

- **实时扫**：站点是 http（域名没备案），手机浏览器不允许网页直接开摄像头；但在钉钉里打开可以调钉钉自带的「扫一扫」。
  - `routers/logistics_voucher.py`：`GET /api/logistics-voucher/dd-config`，给本站页面做钉钉 JSAPI 签名（沿用发票管家的 `jsapi_config` 和企业编号）。
  - 手机页在钉钉里：底部大按钮「扫一扫」→ 钉钉扫码界面 → 扫到直接出结果；可开「连续扫」（查到一张 1.6 秒后自动再开扫码）；旁边留「拍照」备用。鉴权没过也会试着调一次，调不起来给出原因并退回拍照。
  - 不在钉钉里（微信、Safari 等）：只能拍照识别，页面上写明「把网址发到钉钉里点开就能直接扫」。
- **页面重做**（`VoucherScanPage` 不再套电脑弹窗的版式）：
  - 结果是一张大卡：主体色块（深圳星期零蓝 / 深圳星期九青 / 孝感星期九橙，分堆时一眼认）、记-号 56 号字、凭证月份；下面供应商 / 金额 / 审批编号 / 付款单；重复扫、附更正单有标记。
  - 本次已扫改成卡片列表（左边主体色条），上面按主体计数；点某一张可回看。
  - 主按钮固定在底部（拇指够得着，留了全面屏安全区）；「读出来」放右上角；手输审批编号收进「扫不了？」里。
  - 空状态画了付款单示意图，标出二维码位置。
- 电脑弹窗和手机页共用一个状态钩子 `useScan`。

验证：三种状态（钉钉里查到 / 非钉钉空状态 / 还没做账）用线上真实查询结果本地渲染看过版式。
