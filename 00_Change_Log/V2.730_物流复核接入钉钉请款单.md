# V2.730 物流复核总表接入钉钉请款单（第 1 步：进度 + 账单就绪 + 发票进发票管家）

## 用户要的
- 自动拿钉钉审批数据：请款单一到，发票进发票管家、账单进物流账单核对。
- 总表复核状态显示钉钉节点情况（已提交 / 待谁审批 / 已付款），不同主体进度可以不一样。
- 识别到钉钉单，工作台显示「账单已就绪」。
- 账单、发票都要能替换：出错了不会重走流程，以工作台为准。

## 做法
- **扫全模板**：每 20 分钟扫一次钉钉「付款申请（公对公）」。不是扫某人的待办，否则看不到还没流到你、已经审完、已经付款的单子。
  - 首次扫近 60 天，之后只扫近 3 天新提交的，加上还在审批中的。
  - 收款方全称对上金蝶「物流运输服务…」供应商才留；之前出现过的收款账号也认。其余不入库。
- **落格**：一张请款单落到「承运商 × 主体 × 月份」一格。
  - 承运商：金蝶供应商编码。
  - 主体：审批单「公司主体」。
  - 月份：先看请款金额是否正好等于某月该主体、该供应商的计提；再看事由或附件名里写的月份；都认不出就进「没认出月份」，手工认领。
- **进度标**：显示在每个主体格「付款(复核)」下面，点开看节点记录、附件、票夹、账单状态。
  - 待我审批：橙色。
  - 待某某审批：蓝色。
  - 已通过·待付款：浅绿。
  - 已付款：绿色。判断方法是金蝶出现付款单，按 供应商编码 + 付款组织 + 金额 一对一配上。
  - 已撤回 / 已拒绝：划线。
- **总表**
  - 复核状态加「钉钉 x/y 已付款」「账单来自钉钉请款」。
  - 筛选加「待我审批 / 已提交请款 / 已付款」。
  - 表头加「待我审批」「没认出月份」两组快捷标签和「扫钉钉」按钮。
  - 状态「账单已传」改叫「账单已就绪」。
  - 新增「账单已到·待配置」（承运商没配取数说明）和「有请款·无计提」。
- **附件分角色**
  - 表单 xlsx：账单，进复核台。
  - 表单里带「账单 / 盖章 / 对账 / 盘点」的 pdf：账单盖章件。
  - 其余：发票，归发票管家。
  - 审批人在评论里传的：审核留档。
  - xlsx 原件存进 logistics_payreq_file，留作版本、可以重新解析。
- **自动拉进来**：只对起算日（首次扫描那天）之后提交的单子。
  - 建发票管家票夹，发票管家自己拉附件、识别发票。
  - 这家这月复核台还没账单才导入；已有账单不覆盖，弹窗里提供「用这份替换」（二次确认）。
  - 同一份账单被两个主体的请款单带来（易风达：孝感 87,168 + 深圳 800 共一份），按 sha256 认出来，不重复导入。
  - 上线前的老单只显示进度，可以在弹窗里手工点「拉进来」。

## 改动
- 新增 `kernels/logistics_payreq.py`：纯函数，负责表单解析、附件分角色、认月份、进度标、配付款单。单测 `kernels/test_logistics_payreq.py` 8 项。
- 新增 `routers/logistics_payreq.py`：扫描、拉进来、认领月份、附件下载、总表合并、20 分钟定时。
- `kernels/logistics_review_store.py`：新表 logistics_payreq / logistics_payreq_file，create_all 自动建。
- `routers/logistics_review.py`：总表的金蝶 2241 读取和计提汇总抽成 `_ov_kd_rows` / `_ov_accr`，供认月份共用；账单解析抽成 `import_bill`，上传页和钉钉自动导入共用；总表返回 `payreq`。
- 前端 `LogisticsReview.jsx` / `api.js`：进度标 DtChip、请款单弹窗 PayReqDlg、钉钉栏、筛选。
