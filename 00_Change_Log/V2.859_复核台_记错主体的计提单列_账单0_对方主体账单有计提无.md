# V2.859 复核台第①步：记错主体的计提单列（账单 0），对方主体显示「账单有、计提无」

日期：2026-10-07

V2.856 只是在「平」的那一行上加了个标。用户看了说：「这里应该是918账单数0」「深圳星期九，计提数0，账单时918」。

查实：物流部的丰源 8 月账单里，XSCKD219878（918.93）本来就在「8月深圳星期九」那张表上；是系统 2026-09-28 那次导入把它的主体标成了深圳星期零（那次不是按现在的取数说明解析的）。金蝶里这张销售出库单的销售组织也是深圳星期九，发票、请款单也是深圳星期九。所以用户说的才是对的显示。

改动（`routers/logistics_review.py`、`LogisticsReview.jsx`）：
- 付款做账判定「记错主体」的计提，不再拿去配本主体的账单，单列一行：账单 0（标「不在本主体账单」）、差异＝计提数、标「记错主体 → ××· 付款做账时红冲」。
- 对方主体账单上金额相同的那一行（账单有、计提无）标「计提记在 ×× 记-N · 付款做账时补提」。
- 这两行由主体更正解决，不标红、不算「有差异未解释」，也不出「拆过来」的按钮。表下说明同步改写；导出复核表的备注里也写上。
- 数据：把丰源 2026-08 账单行 XSCKD219878 的主体改为深圳星期九（按人工改归类的方式存，原因写明，留操作日志；第②步可以「恢复账单原值」）。

验证：线上只读叠加——易风达、迅鸽、顺丰冷运、跨越、天鹰五家新旧逐行一致；丰源改主体后：深圳星期九 计提 0 / 账单 918.93，深圳星期零 记-390 计提 918.93 / 账单 0，剩下未解释的就是 记-389 与电商那两行 ±1,450。

另记一个隐患（没改）：丰源现在的取数说明读不了这份三张表的账单（试解析出来是一堆空行），下个月钉钉自动导入丰源账单会出问题，要先把取数说明补全。
