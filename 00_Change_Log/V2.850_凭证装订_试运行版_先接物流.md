# V2.850 凭证装订：试运行版上线（其它模块下新菜单，先接物流）

日期：2026-10-06

样机 v0.1 给用户看后，用户定：「没审核的显示」「可以，先做物流试运行」，并问「你怎么知道哪些没标，所以计提更正单什么时候打印，谁打印」。

对这两个问题的做法：
- **哪些没标**：系统不知道人有没有真把凭证号写上去，只知道这张纸质单**扫没扫过**。所以页签叫「还没扫到的」，用来找「单子还没到手 / 漏扫」，页面上写明它不是装订完成的凭据。
- **更正单谁打、什么时候打**：谁装订谁打。扫到那张单时结果卡上直接「打印这张的更正单」；用手机扫的，回到电脑在「计提更正单」页签把「扫过、还没打的」一次打出来。更正单上印凭证号，所以要等付款凭证做好才打得出来。系统记下谁、什么时候打过。

改动：
- 菜单：侧栏「其它模块」下新增「凭证装订」（`vbind`，默认「测试验证」可进入）；准入点 `enter:vbind` 自动生成，存量账号不给。有这个菜单准入的就能用扫码、清单、打更正单（接口同时认原来的 `logistics_upload`、`voucher_scan`）。
- 新页 `VoucherBind.jsx` 三个页签：
  - 扫码标注：扫码枪 / 审批编号 / 传照片 → 大号结果卡（主体按颜色、凭证号、凭证月份、已审核 / 还没审核·凭证号可能会变、要不要附更正单、之前谁扫过）；右边是这一轮已扫的清单。
  - 还没扫到的：按凭证月份列已有凭证号的纸质单，扫过的记谁、什么时候；没有纸质付款单的凭证（主体更正的原主体红冲、暂估转待认证）标「不用扫」。
  - 计提更正单：要附更正单的单子，纸质单扫没扫到、更正单打没打过，单张打或一次打完。
- 留痕：新表 `logistics_bind_scan`（一张审批单一行：第一次 / 最近一次谁扫的、扫了几次、更正单谁打的）。电脑、手机（`#/vscan`，标题改成「凭证装订」）扫的都记。
- 要不要附更正单：做账记录里记了就用记的；9 月最早做的三张没记，现算（记-261、记-264 各 1 笔）。
- 付款做账页：去掉「扫码查凭证」按钮和弹窗，换成跳到「凭证装订」的链接。

验证：线上只读叠加（新表未建，按都没扫过算、不落库）——9 月装订清单 3 张（记-260 / 261 / 264，都还没审核，261、264 要附更正单），8 月是金蝶已有的支付凭证；扫易风达孝感那张返回 记-264、要附更正单。三个页签的版式用同样的数据本地渲染看过。**没有在线上页面里真扫过，更正单没有从这一页真打过。**

上线：后端有改动，需重启（新表自动建）。给实习生开账号：勾「其它模块 › 凭证装订」的菜单准入即可。
