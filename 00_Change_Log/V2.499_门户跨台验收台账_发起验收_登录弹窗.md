# V2.499 · 门户跨台验收台账（发起验收 → 系统语气登录弹窗 → 收口）

**日期**：2026-09-06　**分支**：claude/accounting-workbench-logs-homepage

Reginald：验收台账不该在核算工作台，应该在门户；直接上跨台（核算+BP+法务）。要能「发起某某验收」——我推给某个账号、要他验收，他登录就弹窗，不理下次再弹，一直不验我能关闭/打回开发中/隐藏。弹窗用系统语气、并让他注明有没有要完善的点。「打回」改叫「暂不验收」。

## 口径（业务方定稿）
- **落门户**：验收台账从核算工作台内页 → 门户一个页签（全员可见）；核算侧旧菜单 `acceptance` 退掉（V2.492 那版）。
- **跨台**：清单直接用 `portal_tools`（核算/BP/法务全在），不再绑核算 nav 模块。
- **派活验收**：管理员对某工具「发起验收」＝指派待验收任务给某账号 + 附「要看的点」。
- **登录弹窗（系统语气）**：被指派人登录门户即弹「系统·验收提示：X 已就绪，邀您验收」+ 要看的点 +
  结论（**通过 / 暂不验收**）+ **需要完善的点**。点「稍后再说」只关不改状态 → 下次登录再弹（缠到验完）。不摆发起人。
- **收口（管理员）**：每行 打回开发中 / 关闭 / 隐藏。
- **满意度**：一线打星（复用，工具身份＝门户工具 id）。**近7天调用**：核算卡走 ops 埋点，BP/法务暂显「—」（待接 BP 令牌）。

## 改法
### 后端
- **db.py**：新增 `verify_task`（一工具一条当前验收任务：指派人/说明/状态 pending·pass·reject·closed·hidden/完善点/发起人/验收人）；
  配套 `verify_assign / verify_all / verify_act / verify_set_status / verify_pending_for`。满意度 `tool_rating` 复用（key=str(门户工具id)）。
- **app.py**：`/api/portal/acceptance`（拼跨台行：门户工具×进度×验收任务×满意度×近7天调用+nudge+发起用账号列）、
  `/popup`（我名下待验收，登录弹窗用）、`/assign`（管理员发起）、`/act`（被指派人或管理员：通过/暂不验收+完善点）、
  `/escalate`（管理员：close/hide/reopen＝打回开发中并把门户工具状态设回 beta）、`/rate`（全员打星）。
  发起/验收/打分全写 `db.audit` →「日志中心›操作留痕」可查。近7天调用按门户工具 `mods`→ops 板块归。
  **退掉核算侧 acceptance 模块**（旧 `/api/acceptance*` 保留但不可达）。

### 前端
- **新增 `views/PortalAcceptance.jsx`**（门户「验收台账」页签，深色）：按 lane 分组的跨台表，管理员「发起验收」弹窗指人+写要看的点、
  「收口▾」菜单；一线只打星；`暂不验收` 用琥珀色（软于原「打回」红）。
- **新增 `views/VerifyPopup.jsx`**（登录验收弹窗，系统语气）：通过 / 暂不验收 + 需要完善的点 + 稍后再说。渲染在 Portal 内、不分页签。
- **Portal.jsx**：nav 加「验收台账」页签 + 常驻 `<VerifyPopup/>`。
- **退掉核算侧**：删 `views/Acceptance.jsx`，App/Home/Sidebar 移除其菜单/横幅/红点接线。

## 校验
- 后端 py_compile+导入过；`verify_task` 建表、整链路实测过（发起→对方 popup 拿到任务+要看的点→提交 通过+完善点→弹窗清空→台账反映→留痕）。
- 前端 build 过；本地浏览器端到端点验通过：门户跨台台账（管理员/一线两态）、发起弹窗、系统语气登录弹窗（通过/暂不验收+完善点）、提交后关闭并反映。
- 钉钉/邮件外推留后续（需先配 `conf.ini [dingtalk]/[smtp]`）。
