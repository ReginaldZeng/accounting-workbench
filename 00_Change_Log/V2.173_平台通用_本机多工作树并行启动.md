**【平台通用】本机启动器按工作树自动分端口，新增「一键启动全部」；顺带修好 dev 代理端口**。
**起因**：V2.170~V2.172 把并行开发的代码冲突解决了，但一试跑就发现本机跑不起来——
**每个工作树的 `启动.bat` 都写死 8000，而且开机第一件事就是 `taskkill` 掉占用 8000 的进程**：
开第二个工作树会把第一个静默杀掉，4 条并行分支根本没法同时验证（"改完看不了"比冲突更挡路）。
另发现 `vite.config.js` 的 dev 代理写死 `localhost:8099`，而启动脚本一直起在 8000——**dev 模式下
`/api` 代理其实一直是断的**；就算改对，多工作树并行时写死端口还会串台（A 的页面调到 B 的后端，
界面看着还挺正常，这类"跑得通但是错的"最难查）。
**改法**：①端口规则——主库仍 **8000**（不动，书签/习惯不受影响），`.claude\worktrees\<名字>` 下的
工作树按名字算出 **8001~8098** 的固定端口（同一工作树每次都是同一个，可以存书签）；
②两个 `启动.bat`（项目根 + `app/`）改为只 `taskkill` **自己那个端口**，绝不碰别的工作树；
③新增 `一键启动全部.bat` + `start_all.ps1`：枚举主库与全部工作树，各开一个窗口起在各自端口，
打印「名称/端口/地址/在跑」一览表，已在跑的自动跳过；带 `-ListOnly` 只看表不启动；
内置端口撞车自检（两条线算出同一端口会明确告警，提示改工作树名字错开）；
④`vite.config.js` 代理改为跟随环境变量 `FW_PORT`（默认 8000），dev 服务器端口＝后端端口+1000；
新增 `app/dev_frontend.bat` 自动算好 FW_PORT 再起 vite。
**验证**：①`start_all.ps1 -ListOnly` 实测列出 4 条 checkout ＝ main 8000 / f-1cff09 8017 /
july-bank-statement… 8021 / logistics-accrual… 8093，**四个端口互不相同**；
②`启动.bat` 端口推导实跑得 `TAG=f-1cff09 PORT=8017`，与手算一致；
③起后端 8017 + `FW_PORT=8017 npm run dev`，实测 dev 页在 9017、`http://localhost:9017/api/health`
**200 且返回的是 8017 那个后端的真实 JSON**，代理确实指向本工作树、没有串台。
**不影响服务器**：线上由宝塔 Python 管理器托管 `uvicorn app:app --host 0.0.0.0 --port 8000` + Nginx 反代，
**根本不经过 `启动.bat`**；且端口规则只在路径位于 `.claude\worktrees\` 下时才触发，服务器上仍为 8000。
访问方式不变（单 IP 单地址）。
**遗留**：①端口由工作树名字的字符和取模得出，理论上可能撞车——已做启动前自检并给出改名建议，未做自动避让；
②`一键启动全部.bat` 只枚举 `.claude\worktrees\` 下的工作树（本项目的既定放法），放在别处的 worktree 不会被列出。
