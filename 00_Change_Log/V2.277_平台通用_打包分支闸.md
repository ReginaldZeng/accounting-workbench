**【平台通用】部署包只能从 main 打**。

**起因（当天实翻车）**：服务器长期跑在**未合并的** `dashboard-section-rename` 分支上（左下角徽标显示分支名，
V2.176 的自报机制其实一直在提示，但没人把它当信号）。业务方随后把存货台账分支打的包传了上去——
两个包**各自都是"完整的工作台"、只是各缺对方**，一覆盖就把报表板块的菜单与路由整块抹掉，报表导出当场不可用。

**根因不是谁操作失误，是架构**：一个 FastAPI 后端 + **一个整包编译的前端 bundle**，
没法按业务线拆分发布。所以任何分支包都是"缺了别人的完整工作台"，谁后传谁覆盖。
规矩只能有一条——**只从 main 打包**。而规矩靠人记防不住（今天就是靠人记，失守了），故固化成脚本。

**改法**：
1. `pack_deploy.main()` 在算完 branch 后加闸：`branch != "main"` 且未加 `--allow-branch` → 打印原因并 `return 1`
   （`__main__` 里是 `sys.exit(main())`，退出码 1 能被 .bat/CI 感知）。
2. 提示直接给两条出路：发服务器→先合 main 再在主库跑；只是自测→`--allow-branch`。
3. 分支包不禁止但**打标**：包名插 `_分支<分支名>`，配合版本戳里的 branch 字段与前端徽标，
   万一还是传了，服务器左下角也认得出来。

**验证**（三种情形实跑）：
| 情形 | 结果 |
|---|---|
| 分支上直接打包 | 拒绝，退出码 **1**，提示两条出路 |
| 分支上 `--allow-branch` | 放行 + 警告，包名 `…V2.259_分支cost-ledger-blockers-0c4_20260812.zip` |
| main 上打包 | 正常，`V2.276 · main · 1cacc8c`，59 个文件 |

**遗留**：闸只管分支，不管 `dirty`。工作区脏时仍可打包，只在版本戳里记 `dirty:true`、
前端徽标显示「（有未提交改动）」——是否也要拦，等有实际教训再定，先不过度设计。
