## 现场

**主管理员**（侧栏显示「曾禹锡 · 管理员」）打开②通知设置，页面写着：

> 你没有「报表导出·改落地路径与通知」权限（敏感点，默认不给）——上面几项只能看不能改。

**但这话不可能是真的**：`db.user_can()` 对 `role=admin` 是**第一行就无条件返回 True**，
主管理员不存在"没有某个权限点"这种状态。

## 原因：一句被吞掉的错误，冒充成了权限问题

```jsx
useEffect(() => { getRptExportConfig().then(applyCfg).catch(() => {}) }, [])   // ← 旧
```

`getRptExportConfig()` 一旦失败（403／500／服务没起来／网络断），`.catch(()=>{})` 一吞了之，
`cfg` 停在 `null`。而②页的判定是：

```jsx
{!cfg?.can_edit && <div className="banner">你没有…权限</div>}
```

`cfg` 为 null → `cfg?.can_edit` 是 undefined → `!undefined` 恒真 → **这条权限提示无条件显示**。

**旁证**（现场截图）：落地路径、收件人、钉钉手机号三个框全是占位符，发件邮箱写「未配置」，
邮件开关是 `useState(true)` 的默认勾选态——**全都是 cfg 没加载上的样子**，不是服务器上的真实值。

**危害不在于少一条报错，而在于报错报到了错的地方。** 照着这条提示去开
`rpt_export_cfg` 权限，无论开多少次都不会好，因为压根不是权限问题。

## 改法

分清「读不出来」和「没权限改」，各说各的：

| 情况 | 页面显示 |
|---|---|
| 请求失败 | **设置读不出来，上面显示的都不是服务器上的真实值。** 实际错误：`/api/rptexport/config 403`<br>并附对照：403＝缺「一键导出」权限（**不是**"改设置"那个）／500＝服务器出错看后端日志／连不上＝服务没起来 |
| 读到了、但 `can_edit=false` | 你（**账号名**）没有「报表导出·改落地路径与通知」权限…（原文案，另把**当前账号名**摆出来，免得搞错登录的是谁） |

403 那条特意点明"缺的是**一键导出**那个权限"——因为这个接口的门是 `rpt_export`，
而提示语里出现的是 `rpt_export_cfg`，两个不同的点很容易被当成一个。
