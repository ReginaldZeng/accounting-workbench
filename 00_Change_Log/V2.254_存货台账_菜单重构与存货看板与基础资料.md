**【存货台账】菜单重构 + 存货看板 + 基础资料扩容**。

**起因**：业务方复盘成本台账卡点时，翻出 V2.53 出过的《成本台账_趋势看板_样机_v1.html》——**样机里有「存货看板」，工具里从来没有**。查证：确认书 v1.1 通篇搜「趋势」「看板」零命中，v1.0 只在 C 期规划提过一句「月度环比趋势」。即样机拿去过会时它在里面，交付物里没有，文档也没说它去哪了——是**掉了**，不是记录在案的待办。业务方随即定下新结构：

| | 改前 | 改后 |
|---|---|---|
| 二级 | 成本台账（可进入，八步工作流页） | **存货台账**（纯分组） |
| 三级 | 仓库类型 | **台账导出**／**存货看板**／**基础资料** |

**改法**：

1. **菜单**（`app.py:NAV_MODULES`）：`costledger` label→存货台账、`group_only=True`；新 `clexport`（台账导出，挂原 `CostLedger.jsx`，页面代码一行未动）、`cldash`（存货看板，新页）；`clwh` label→基础资料。**key 一个没改**（D6/D7：数据/权限/审计历史全绑 key）。
   **这条修订《导航与权限架构重构确认书 v1.0》的 D8**（"「月结核对」这一层取消、页面内容上提"）——当年的理由是"只有一个子项，多一层没意义"；现在有三个并列三级，分组这层重新成立。前提变了，不是把 D8 改回去。
   ⚠**别与成本台账确认书自己的 D8 混淆**（那条是"导出补按仓库表"）。成本台账确认书的 **D14（准入闸设在二级）本次原样保住**，见下条。
2. **准入闸保住 V2.142**（这是本次最容易踩坏的地方）：`_enter_cap` 原逻辑「纯分组不设闸 → 子项各长各的闸」，直接套用会把业务方定的「一组一个闸」当场推翻。改为**把 `cap` 判断提到 `group_only` 之前**，并让子项按父项算出来的闸继承（父项没闸才自立门户）；分组显式声明 `cap="enter:costledger"`。
   实测：三个三级 cap 全＝`enter:costledger`；`_nav_cap_meta` 只注册一条（不重复、不出现"进入 台账导出"这种错标签）；四个动作点 gate 全部解析出来，没有落进"不受菜单门控"那堆（正是报表线 V2.240 踩过的坑）。
   **回归**：银行对账/物流对账/财务会计三个 group_only 组的子项**仍各设各的闸**，一个没变。
3. **基础资料页**（原「仓库类型」页）：新增①**存货类别 → 总账科目对照**，原②仓库类型切片器、③仓库对照顺延。
   **拆的是 V2.132 那颗雷**：`category_to_subject`/`extra_subjects` 此前**只有 json 一个来源、无数据库兜底**，而部署包历来整体排除 `sample_data/` → 那文件从没上过服务器，一点取数就 500。现改为 `app_settings.cost_ledger_cat_subject` 为唯一真相源、json 降级为首次使用的种子（与 V2.119 仓库类型同规格）。页面显式标出"当前生效的是数据库还是种子"，避免重演"两处都能改、不知道谁生效"。
   保存只拦两条硬的：**同一类别挂到两个科目**（那部分存货会被算两遍、勾稽必然不平，且错得隐蔽）、**空对照**。**不校验"类别必须在金蝶存在"**——金蝶随时新增类别，卡这里会让人改不了；真没对照上的，异常稽核的「对照缺失」会点出来。
4. **存货看板**（新页 `CostLedgerDash.jsx` + `GET /api/cost-ledger/dashboard`）：五个指标卡 + 四图（结存趋势／科目构成／库存商品收发流量／周转天数）。图表沿用资金看板的做法——**手写内联 SVG + `--cat-*` 分类色，不引第三方图表库**（全站至今零 UI 依赖）。
   取数：科目余额**逐期取**（金蝶无多期入口），收发存**一次取多期**（新增 `kc.fetch_inventory_period_totals`，走 `FIsDisplayPeriod`）→ 5 期＝6 次调用而非 10 次。「库存商品」含哪几个类别读基础资料的对照表，不写死。
   **两个口径同页并存，页面上写死说明**：结存/构成＝科目余额口径（含在途/委托加工/材料采购），收发流量/周转＝收发存表口径。107 的 2026-5 是 10,994,036.02 vs 10,958,051.26，差额就是在途与委托加工。各自标注、不做加减，逐笔核对指向「台账导出」的三道勾稽。
   呆滞/账龄金蝶报表接口取不到，如实回占位（`aging.available=false`），不装作有。

**发现但未采纳样机的一处**：样机「周转天数趋势」标的是 36.3／37.7／27.3／52.6 天，与同一张样机卡片上的「库存商品周转 6.7 天」**自相矛盾**，用它自己标注的公式（平均库存÷发出×30）也复算不出。按卡片口径（仅库存商品）实现，实跑 6.5／9.8／7.7／6.5／6.6 天。样机那条折线判断为画稿示意值——同「挂账尾差样机写 2、实际 7」。
