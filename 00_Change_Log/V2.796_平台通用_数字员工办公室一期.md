# V2.796 平台通用：数字员工办公室一期（门户层值班表 + 干活记录 + 大屏链接）

日期：2026-10-04

**起因**：后台自己在跑的活已有七八件，但各记各的（有的只留最近一次，有的只在内存里、重启即丢）：机器停了没人知道，干了多少也说不出来。用户 2026-10-04 定：放门户层、要放在闲置电脑上常开、暂时不用工时，先做。

**改法**：

- 新增 `backend/worker_store.py`：工位注册表（9 个）+ 新表 `worker_run`（干活记录）、`worker_beat`（报到），自带 MetaData、导入时 create_all（只建不改既有表）。`beat()` 每圈报到（没启用传原因 → 「没上岗」）；`record()` 真干了活或出了错才记，同一个错连着出只留一条；全部吞异常。`roster()` 判四种状态：正常 / 有出错 / 停了（超过间隔三倍没报到）/ 没上岗。
- 新增 `backend/routers/office.py`：`/api/office/roster`（登录）、`/api/office/runs`（登录，出错原文只给有系统设置权限的）、`/api/office/screen`（**不登录，认请求头里的大屏口令**）、`/api/office/screen-token`（主管理员生成 / 换 / 停用，留痕）。
- `app.py`：include 路由；登录门加大屏口令例外（只放 `/api/office/screen`，口令没生成＝关着）；取件机三台并进值班表（读现有取件机监控，不另记）。
- 七个后台任务各加几行报到与记一笔：`fxrate.py`（汇率定时）、`invoice_intake.py`（发票接入）、`invoice_books.py`（催票）、`invoice_vouchers.py`（凭证同步）、`bom_quote.py`（自动立项、OA 终审同步）、`logistics_payreq.py`（请款单扫描）、`todo.py`（待办核对）。summary 只写件数，不写供应商 / 产品 / 金额。
- 前端：新增 `views/WorkerOffice.jsx`（值班表 + 工位记录弹框 + 大屏链接弹框；大屏模式字号跟屏幕高度走、不能点、每分钟刷新）；`App.jsx` 加门户层 zone `office` 与免登录路由 `#/office-screen?k=…`；`Portal.jsx` 首页加状态灯入口；`api.js` 加接口。
- **大屏重新设计**（用户看了自己 7 月做的等距办公室原型后要求）：新增 `frontend/public/office-screen.html`——沿用那份原型的配色、等距画法、桌面小卡和小人骨架，改成照真实值班表摆工位（按组分区、四种状态、取件间机柜、交接台、事件触发的交接），去掉假数字、空桌子、茶水台和洽谈区。`#k=<口令>` 读 `/api/office/screen`，不带口令用内置样例数据。为它给值班表接口加了 `zone`（坐哪一组）、`kind`（工位 / 机器）、`feed`（刚干完的活，脱敏）、`kpi.todayN / total`。大屏链接弹框给的地址改成这一页；React 里的表格版大屏路由留作备用。人物按用户意见（「太死板」）重画：方块人换成圆头小人，按工位 key 定发型发色、衣服颜色跟组走，正常打字点头 / 出错挠头冒叹号 / 停了趴着睡，动效时长与起拍各不相同；小卡从桌角挪到人的右手边并单独一层，不再盖住人；地面组名只留组名。
- 文档：`01_Current_Deliverables/docs/20261004_数字员工办公室/` 确认书 v1.0（含第八节实现与验证记录）。
- 画风探索（用户嫌矢量小人不够精致）：`prototype/style2_cubicle_sample.html`（等距写实格子间样张，纯代码画的上限）；`大屏出图清单_v1.0_20261004.md`（交给生图工具的清单：底图 + 每人坐姿 / 走动图集的格子规格、提示词、自查表、交付文件名；图到后由代码接线，现有矢量版留作备用）。参考过 GitHub 上的 mdopcoffice、pixel-agents 等同类项目，只借思路，不用其素材（前者未授权）。
- **大屏换成业务方出的插画**（用户 2026-10-04 用生图工具出了「半写实插画风 + 品牌布局 v4」一套图，原图放在 `05 数字员工办公室/03_Source_Materials/大屏素材/`，没改动）：
  - 新增 `backend/tools/office_art_pack.py`（开发机上跑一次）：原图格子不是整数（坐姿每格 443.5、走动每格 295.67）、人物在格子里的位置有偏差，脚本按整图等分裁格 → 清掉从隔壁格子伸进来的碎片（鞋底、头顶）→ 底边贴齐、头部居中 → 统一成 256×256 的 WebP 图集；空椅子裁成和坐姿图一样的取景；底图另抠一层显示器（人坐在桌后，显示器要盖在人前面）；LOGO 原文件原样拷贝。产物进 `frontend/public/office-art/`（22 个文件约 4 MB，构建时拷进 `backend/static/`）。
  - `frontend/public/office-screen.html` 重写成贴图版：底图 1672×941 上按 12 张桌子的坐标摆人、状态灯、名牌；正常敲键盘 / 出错挠头冒「!」/ 停了趴着睡飘 Zzz / 没上岗空椅暗屏；刚干完一笔要交给人的，起身走去右下角交接台；交接台上的单子数＝首页待办没人处理的件数；取件机是左上玻璃间里的三台电脑。空闲的人会去茶水间、沙发坐一会儿（没有业务含义，同时最多两人离座，十分钟内刚干过活的不离座）。不放顶部横幅，右栏 + 底部一排数字。
  - 原来代码画的等距办公室改名 `office-screen-vector.html` 留作备用，插画加载失败自动退回。
  - `worker_store.roster()` 给每个工位加 `lastAgoMin`（上次干活距今几分钟），大屏据此判断「正在忙」。
- **派工单弹窗 + 派工动画**（用户 2026-10-04：「触发定时任务的时候能不能有个弹窗，然后进行任务分配之类的动画」「或者有新任务的时候」）：
  - `worker_store.roster()` 每个工位多给两个原始时间戳 `lastTs`（最近一笔干活记录）、`beatTs`（最近一次报到）。
  - `office-screen.html`：两次刷新之间 `lastTs` 变了且那笔干成了 → 画面中间弹「新任务」派工单（头像、工位名、组、接了什么），单子逐张飞到工位，那位说「收到，开工」敲 6 秒键盘，再说「干完了 · 交给××」，要交给人的走去交接台（原来的 `handoff()` 并进这条链）。只有 `beatTs` 变了（巡了一圈没新活）或出错 → 不弹，显示器闪一圈绿光、敲几下键盘。一次最多列 4 个工位；上一张没演完，下一张排队。
  - 样例模式：开场自动演一次；按 D 再演一次（随机 1–3 个工位），按 P 看「巡了一圈」，按 B 有人去休息。
  - 取舍：没做成「定时任务一触发就弹」。每个任务二十分钟转一圈，大多数时候没活，都弹等于几分钟弹一次「没事」；而且大屏一分钟才取一次数，弹的时候活已经干完了，所以它是回放不是实况。
- **「刚干完的活」放大 + 带单号，值班表可折叠，底部滚动条加回**（用户 2026-10-04：「刚干完的活得明显一点，比如发票接收员，已完成 x 张…，钉钉单号 XXX。值班表可以折叠」「之前我们做的滚动条呢」）：
  - `worker_store`：`worker_run` 加一列 `refs`（单号，`|` 隔开，最多 6 个；表已建过的库启动时自动补列）；`record(..., refs=[…])`；值班表的 `feed` 和工位干活记录都带出 `refs`，`feed` 另带 `n`、`refLabel`。原则由「只显示件数和状态」放宽成「件数、状态和单号」，仍不许带供应商 / 客户 / 金额。
  - 四个按钉钉单干活的任务把审批编号带出来：`invoice_intake.py`（新接的单 `newIds`；`auto_submit_ready(refs)` 把票齐送审的单号放进传入的列表，返回值不变）、`logistics_payreq.py`（`newIds`，不存进设置）、`bom_quote.py`（立项、终审同步的 `appno`）。干活记录的句子统一改成「已……」（已接入 / 已送审 / 已自动立项 / 已同步终审 / 已核对 / 已对上 / 已写入）。
  - `office-screen.html`：右栏顺序改成 时间 → 要人看一眼 → 刚干完的活 → 值班表。「刚干完的活」一笔一张卡（头像、工位、结果、一句话、钉钉单号最多两个 + 共 N 张），最新一笔加重、新来的闪一下，放不下的整张拿掉；值班表默认收起成一行汇总，点标题或按 R 展开，记在浏览器 localStorage；派工单每行也带单号；左下加回「实时动态」滚动条（矢量版有、换插画版时漏了），最近十笔首尾相接地滚，内容没变不重排。为放滚动条，下面一排数字的高度从 210 压到 148。
  - `WorkerOffice.jsx`：登录后的工位干活记录里也显示单号。

**为什么大屏不登录账号**：登录 cookie 只管 7 天，到期就退回登录页；且一台没人看着、一直登着账号的电脑是个口子。大屏口令只能读一张脱敏的值班表。

- 本机 8120（sqlite 测试库 + 编的工位记录）浏览器走过：门户状态灯 → 值班表 → 点工位看记录 → 主管理员生成大屏链接 → 大屏模式。接口实测：不带口令 401、带错 401、带对 200 且只能读值班表（读干活记录 401）；未登录读 `/api/office/roster` 401。1920×1080 下十二个工位一屏放完。

- 各任务返回结果的字段是照代码读的，没拿真的一轮结果对过。
- 「本月件数」从上线那天开始记，上线前的不倒推。
- 不做工时；停了只在值班表变红，不发钉钉（取件机已有自己的告警）；大屏链接一期只有一个。

- 仓库多了约 4 MB 图片（`frontend/public/office-art/` 与构建产物 `backend/static/office-art/` 各一份）。
- 改了后端，上线随自动部署重启；重启后各任务陆续报到（最慢的二十分钟内）。
