# V2.576 电商对账取件机（上行 · HTTP 推送，纳入取件机监控）

取件机改为与报表/银行同款 HTTP 主动推送（放弃裸镜像 EC_INBOX_ROOT）。

## 服务端（routers/ec_workbench.py + core.py）
- 新增 `/api/ec/workbench/pickup/{pending,push,report,request-scan}`：
  - `push` 只收「原始相对路径 X-Ec-Relpath + 文件字节」，服务器按 V2.575 同一套解析（期间按年月文件夹、店铺按别名），认得出才按列自动识别入库；内容指纹去重，重复推=无操作。
  - `pending`/`report` 供轮询与心跳；资金流水/金蝶不走此通道。
- `core._PULL_PATHS` 放行 pending/push/report（同一 pull_token）；request-scan 走登录。

## 监控（app.py `_pull_registry()`）
- 加「电商资料取件机」一台（id=ecrecon）：门户取件机监控页自动显示状态+上轮成绩，停机钉钉告警、结果通知收件人全走现有注册表驱动的设置端点。

## 取件机脚本（tools/pickup_ecommerce.ps1 + pull_reports.ini.example + 取件机安装说明.md）
- 增 `ecommerce_recon_dir`：随报表任务每分钟扫公盘 `4.1 电商对账` 原生树，按相对路径推给核算工作台；30 秒新写入不碰、签名去重、回执心跳。

取件机零店铺配置、文件夹不用改名；上线前须在基础资料给每店填公盘文件夹名（别名），否则该店文件判「认不出店铺」不入库（安全不误收）。
