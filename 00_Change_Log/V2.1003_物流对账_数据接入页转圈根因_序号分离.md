Description: 【物流对账】第①步「数据接入」永远转圈的真正根因：前端 loadIk 与逐单 load()
             共用同一个请求序号 _reqSeq——进一家时 loadIk 先取号、load 后取号，ik 响应回来
             序号已过期被丢弃，setIk 永远不执行。给 loadIk 单独的序号 _ikSeq。

## 背景

第①步数据接入一直停在「读账单原件、按取数说明检查中…」。先把后端读原件的慢治了
（V2.1002：懒取 blob + 补索引 + 总表 SWR），服务器 req_log 证明接口 51~106ms、200 全返，
但用户页面仍转圈——回头查前端，发现响应根本没被采用。

## 查实

`LogisticsReview.jsx`：防串单序号 `_reqSeq`（V2.992 引入，防切承运商后慢响应盖新页面）被
`loadIk()`（第①步）和 `load()`（逐单主表）**共用**。React effect 按声明顺序执行：
loadIk 先取号(seq=1)，load 后取号(seq=2)；ik 响应回来时 `seq !== _reqSeq.current` → 丢弃。
所以第①步从 V2.989 上线起就**永远转圈**——之前后端慢（2~3.5s）只是表象，响应到了也被扔。
服务器日志侧证：接口一次次 200 返回，前端就是不渲染。

## 改法

`frontend/src/views/LogisticsReview.jsx`：`loadIk` 改用独立的 `_ikSeq` ref，
`_reqSeq` 仍只管逐单主表（防串单语义不变）。一行级改动。

## 验证

- `npm run build` 通过（vite，5s）；
- 服务器 req_log：修复后 intake 接口 51~106ms / 200（V2.1002 已验），本改为纯前端序号分离，
  逻辑一目了然：loadIk 的响应不再被 load 的取号顶掉。

## 改动文件

- `frontend/src/views/LogisticsReview.jsx`：`_ikSeq` 独立序号。
- `backend/static/`：前端构建产物。
