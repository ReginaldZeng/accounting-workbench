# V2.633 物流账单复核台（核价×核量→归一态）· pilot 迅鸽

[Change Log] Date: 2026-09-26 | Author: Claude Opus 4.8 | Version: V2.633

**一句话**：物流账单复核这条线的第一版落进本体——复核 = **核价（收费标准，单价 vs 签署合同价格卡）× 核量（数量 vs 金蝶出库）→ 归一态**，金额是导出。样机搬进工作台的代码结构，核价核量内核用真数据端到端重现样机结果。占「付款对账」入口，其余物流入口不动，0 数据上 git。

## 复核为什么是这两轴（业务方定）

- **收费标准**：账单单价对不对，比合同。价一律来自合同，不拿账单金额倒算（否则核价是循环、永远零差）。
- **数量**：账单数量对不对，比金蝶。核量口径按承运商计费方式定——**快递比件数、干线整车比重量/吨、仓储比板天**，不一律比 kg（迅鸽商品金蝶多按袋/个计量，比 kg 必错）。
- 金额差异 = 账单 − 合同单价 × 核对数量，是前两者导出的。一条账单行只有单价=合同 且 数量=金蝶 才算复核通过。

## 后端（7 处）

- 新建 `kernels/logistics_review_store.py`：3 张表（自带 MetaData，db.py to_metadata 挂进来，create_all 只建不改）。
  - `logistics_bill_lines` 中间表：双粒度 grain='detail'(对账逐单,带单号) / 'accrual'(计提,按费用项)。
  - `logistics_price_card` 价格卡：承运商×费用项×计价单位×单价(或阶梯 tier_json)×生效期×合同位置×确认状态。
  - `logistics_intake_spec` 取数说明：一家一条 spec_json，通用解析器按它认列（按列名不按序号——同一家导出月间列会漂移，写死必错）。含迅鸽取数说明种子。
- 新建 `kernels/logistics_price.py`：从合同价目表导价格卡（迅鸽云仓格式：快递按省×重量档 tier、基础/增值服务费、包装材料）；查价 std_freight（首重+续重+<3kg 分档）/ unit_price。
- 新建 `kernels/logistics_review.py`：核价核量引擎。price_check（快递用基价比档，加收另算不当多收）/ qty_check / verdict / summarize / verdict_counts。
- 新建 `kernels/logistics_intake.py`：通用解析器。按取数说明认表头/认列/认汇总/拆单号；detail 逐单 + accrual 月结（段头往下找合计取数）。
- 新建 `routers/logistics_review.py`：7 端点——取数说明读 / 导入合同价格卡 / 价格卡读 / 上传账单解析落中间表 / 接金蝶回填出库数量（只读 SAL_OUTSTOCK，剔包装）/ 复核结果（费用项汇总+逐单+归一态计数+分页）。
- `db.py`：挂 3 表 + 迅鸽取数说明种子（表空才插；价格卡走「导入合同价目表」不硬编码）。
- `app.py`：注册 logistics_review 路由。
