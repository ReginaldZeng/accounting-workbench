# V2.910 付款做账：自动做账做完发钉钉提醒——涉及两个主体的红冲单独标出来

- 日期：2026-10-11
- 作者：Claude Opus 5.5
- 模块：应付板块 › 物流对账 › 付款做账 › 自动做账

## 起因

用户：「那个自动做账的功能是不是要加一个提醒，就是得提醒对应同事，那些他做了」。

系统自动做的付款凭证只提交、不审核。原来做完只写在三个地方：付款做账页的「上一轮」、首页待办、数字员工办公室——都要人自己打开才看得到，
没有任何主动推送。同事不打开页面就不知道，凭证就没人去金蝶审。

先出了样机（`01_Current_Deliverables/docs/20261011_自动做账提醒/prototype/auto_notify.html`），又按上一轮演练的真数据手工试发了一条给用户本人。
用户看后定：

- 「发给曾禹锡」；
- 「开发，但是注意，计提更正单是在复核时候打印，所以这里只需要提醒，尤其是多主体红冲」。

## 做了什么

### 1. 「真做」的一轮做完，发一条钉钉

写清四样，要紧的放前面：

1. **没做成的**：哪张、原因。
2. **涉及两个主体的红冲**：这张凭证里另外整笔红冲了哪张计提、这笔应是哪个主体的、那个主体在它自己的付款凭证里补提。
3. **有红冲更正的**：改了什么（尾差多少、哪张计提、复核台登记的计提更正）。
4. **只核销的**：主体｜供应商｜金额　凭证号。

最后一段「接下来」：到金蝶审核；有红冲更正的装订时记得附计提更正单（**复核时打印的那张，这里不再让人去打印**）；
涉及两个主体的两边凭证对着审。

消息是纯文字（钉钉单聊不认颜色和加粗），靠小标题和空行分段。超过 1,800 字时只核销的合成一行「N 张，合计多少」，要人留意的逐张留着。

### 2. 系统不自动做的多主体红冲，也提醒一次

「计提记错主体」这类系统不自动做（要人单张做）。它和上面第 2 种往往是一对：一个主体那张系统做了、里面带着红冲，另一个主体那张要人来补提。
所以这类也列进消息的「要人来做」里，写明计提记在了哪个主体的账上、哪张凭证、多少钱。

实例（2026-10-11 演练数据）：丰源 深圳星期零 4,117.46 那张里另红冲 记-390 918.93（应是深圳星期九的），系统会做；
丰源 深圳星期九 918.93 那张要人来做。

### 3. 什么时候发、什么时候不发

| 情形 | 发不发 |
| --- | --- |
| 这一轮真做成了至少 1 张 | 发，一轮一条 |
| 这一轮有没做成的 | 发；同一张、同一个原因只说一次（它每 20 分钟会重试，不能每次都发） |
| 出现了新的「要人来做」的多主体红冲 | 发；每张只说一次 |
| 没有新东西的轮次、和上一轮一样没重算的轮次 | 不发 |
| 「演练」档 | 不发 |
| 人在页面上自己点「保存到金蝶」做的 | 不发（首页待办照常挂给审核人） |
| 金额不符等其它「不做」的 | 不发（一直挂在页面上） |

### 4. 页面：「自动做账」栏多一行「做完提醒」

- 开关「发钉钉」，默认开。
- 发给谁：默认跟首页待办「付款凭证审核人」走；点「改收件人」可以单独勾人，一个都不勾＝跟审核人走。
- 没认过钉钉身份的账号标「发不到」，不悄悄发不到。
- 「发一条试试」：按上一轮的结果、照正式提醒的样子排一条，标明【试发】，只发给点按钮的人自己；不碰金蝶。
- 下面一行写上一条什么时候发给了谁、做成几张、没做成几张、其中红冲更正几张、几张涉及两个主体；点「看发了什么」看原文。
  没发出去的写明原因。
