# V2.512（原编 V2.509，撞号改号）· 历史标准成本直接导入：模板 → 「导入待确认」批次 → 成本会计批量确认即已审核（无物料明细）

**日期**：2026-09-07　**业务方定**：「历史数据，我直接上传标准成本吧，就不一个个上传采购核算表了」→ 「可以」（审核方式与模板按建议默认：先落批次、勾选批量确认；空模板）。

## 口径

- 一行一个产品的**五分项（含税 元/kg）**：CP码·物料编码·产品名称·客户·规格·渠道·核算日期·原料·包材·加工费·装卸费·管理费·全成本·来源单号。必填：CP码、产品名称、六个数。
- **红线收到这一层**：五分项之和＝全成本（差 ≥0.01 不入）；CP 必填；文件内同名同 CP 重复不入；渠道/日期认不出不入。有问题的行留在批次里显示原因，不拦好行。
- 确认即「已审核」：`status=已审核`、`finalized_by=确认人`、`ack.by=标准成本导入`（reviewer 记确认人）、四步视为已确认、类别取建议值、占定稿指针、对外给 BP（feed 行 `imported:true`）。**不经财务BP终审**。
- 同 CP / 同物料编码在台账已有审核版 → 确认时**必须答** A 原版失效 / B 并行 / C 历史版不对外（系统按核算日期先后给建议：本行更早→C，否则→A）。答 C 打 `historical=1`、不占指针。
- **没有物料明细**：`source_type=std_import`，台账/详情标「导入·无明细」，详情页横幅说明；三个核算侧导出口 + BP 脱敏导出一律 400「没有采购核算表可导出」；导出菜单隐藏；上游链路可把它当上游（按名/CP 配，全成本对得上即可）；换码承接照常参与。

## 做了什么

- 后端：`GET /api/bom/std-import/template`（模板 xlsx，含示例行 + 说明页）、`POST …/upload`（解析校验 → 批次 JSON 落 `bom_uploads/_stdimport/`，不走 _staging TTL）、`GET …/batches` / `…/batch`、`POST …/confirm`（需 `bom:audit`；未答 A/B/C 整批不动回 needAnswer；确认过的行移出批次、空则删）、`POST …/discard`。`_std_confirm_row` 造记录：`mat/pack` 反推不含税小计、费用直写 `fee_*`、summary 只放五分项键，`compose` 复现全成本（实测 diff 0）。`_entry_view.imported`、feed `imported`、`_std_no_export` 守卫。
- 前端：待办页「⇪ 导入标准成本（历史）」按钮 + 「导入待确认 N 批」块（可入/有问题/要答 A/B/C 计数，处理 ›）；`StdImportModal`：下载模板 → 上传 → 逐行表（勾选、校验结果、候选 + A/B/C 下拉与建议）→ 「确认入台账（已审核）」（无审核权限者只能保存批次等成本会计）/ 重新上传 / 作废本批。台账与详情标「导入·无明细」，详情横幅，导出菜单隐藏。
