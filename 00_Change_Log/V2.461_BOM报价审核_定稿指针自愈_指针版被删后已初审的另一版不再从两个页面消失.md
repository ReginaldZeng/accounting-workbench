# V2.461 · 定稿指针自愈：指针版被删/替换后，同产品另一条已初审版不再"两个页面都看不见"

**日期**：2026-09-06　**业务方报**：标准成本台账搜 SZY004024「没有啊」（台账 0 行），但半成品的上游链路里它还在。

## 根因

三版卤味复合调味酱同一个 `product_key`。删掉指针所在那版（522031 的）后，剩下 240399 那版状态仍是「初审」、却**没有定稿指针**：
- 标准成本台账只列**有指针**的行 → 不显示；
- 待办与复核只列最新版**未初审**的产品 → 也不显示；
- 上游链路按名字找同名记录 → 还能找到它。
于是成了一条"幽灵"记录：数据在、页面上哪都看不到。

## 修法

- `db.bom_repoint(src, product_key)`：该产品有 active 且 初审/已审核 的版本却无指针 → 指向核算日期最新的一版；全是未审核则不动（那是正常待办态）。
- 两处触发：①**删除**时对涉及的产品自愈；②**打开台账**（`/api/bom/ledger`，两种模式）时对"已初审/已审核却无指针"的产品自愈——老数据一打开就修好。自愈留痕「定稿指针自愈」。

## 验证

scratch 库：删指针版 → 指针自愈到剩下的已初审版、标准台账能看到；人为清空指针 → 打开台账自动修回并留痕；全是未审核的产品不自愈。

## 服务器上

上线后打开一次标准成本台账，SZY004024 就会回来（状态初审）。
