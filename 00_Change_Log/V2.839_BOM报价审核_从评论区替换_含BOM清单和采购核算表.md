# V2.839 · BOM报价审核：处理页每组加「从评论区替换」（含 BOM 清单和采购核算表）

**日期**：2026-10-06　**业务方**（看着 350508 处理页仍是两组）：「怎么还是这样，是不是可以加多一个从评论区替换（含 BOM 和核算表）」

## 背景

V2.838 起评论区附件能取到了，但立项时评论区那份更新版采购核算表因 **CP 后缀变了**（研发改一次 BOM 换一个后缀：-2 → -3）被当成另一个产品**自成一组**，表单里的旧版原样留着——页面上还是两组，等于没替换。两组「用量自洽·多1」查实是核算表里多列了一行「水」（BOM 清单没列），BOM 清单自动配对本身是对的。

不做自动替换：同名不同 CP 后缀也可能是并行产品（空白袋 CP07118902 / 印刷袋 CP07118902-2），谁顶谁要人定。

## 改

- **处理页每组操作条**加「💬 从评论区替换」→ 弹窗：
  - ① 评论区的采购核算表：文件名、逐产品 CP / 名称 / 全成本 / 料行数 / 勾稽平不平、评论人、上传时间；标「本组当前就是这份」或「已在本单另一组入账·替换后并入本组」；可选「不换采购核算表」。
  - ② 评论区的研发 BOM 清单：CP / 行数 / 评论人 / 时间；默认带出与所选核算表同 CP 的那份；可选「不指定」。
  - 没取到的评论区附件灰字列出（重传旧件标可忽略）；底部一句话说明确认后会发生什么；「重新从钉钉取」。
- **后端**
  - `GET /api/bom/comment-files`（列清单，取数缓存 10 分钟）、`POST /api/bom/replace-from-comment`（`sheetFileId` / `bomFileId` 至少一个）。
  - `_do_replace_sheet` 新增：`pair_loose`（新旧产品键不同也按「同名 + 同 CP 主码」配成替换，再不行新旧各剩一个则配上；**只在人点替换时用**）、`adopt`（这份文件的同一条记录已在本单别的组入账 → 并入本组，不再插重复的）、`source_type`（评论区＝来源方「评论区上传」）、`force_bom`（指定的 BOM 清单名/码配不上时单对单直接挂）。返回多 `same`（本组当前已是这份）。
  - 只换 BOM：按清单重挂本组产品，③用量自洽确认清掉重认；已审核通过的不让换（先撤销审核）。
  - 既有规则不变：勾稽不平不入、上游链路闸、已财务BP终审的旧版非主管理员不能直接顶（V2.585）、补录组新版承接补录标记、下游依赖打回。
  - kernel 加 `user_name(userid)`（评论人姓名，进程缓存）。
- 替换结果面板：被拦的产品显示原因（原只写「勾稽不平」）。
- 确认书 v1.4 §4 补一句（md + docx）。

## 测
- 后端沙盒 + 真钉钉 350508：立项后两组 → 清单 1 张核算表（李美霞 7-23）/ 2 份 BOM（吴冰）/ 1 个没取到（重传旧件）→ 在旧组上替换：有效记录只剩 CP4897807-3（并入原组、不重复），旧 CP4897807-2 标「被替换（评论区替换）」，BOM 11 行；重复点识别「已是这份」不重复入账；只换 BOM 11→10 行且③确认清掉④保留；已审核换 BOM 被拦；评论区那条未入账时新入一条（来源方评论区上传）；旧版已终审时成本会计被拦、主管理员放行。ALL PASS。
- 浏览器实点（本地沙盒）：两组各有按钮 → 弹窗预选最新核算表 + 同 CP 的 BOM → 确认 → 页面变为「本单共 1 组·1 个产品·1 条替换留痕」；再开弹窗显示「本组当前就是这份」、确认键置灰。构建通过，换行干净。
