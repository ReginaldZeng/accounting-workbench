# V2.989 物流对账：账单复核台改四步（① 数据接入 ② 逐笔计提复核 ③ 逐单核价核量 ④ 发票审核）

日期：2026-10-17

用户 10-17 定：复核台分四步，确认与登记放在第④步最底下；第④步只看结果，审核仍在发票管家。样机（跨越 9 月真数据）：https://claude.ai/artifact/PCWe2YK8QuG5Af4SdyoYpu ，用户看过说「开始正式开发」。

## 页面
- 步骤条：数据接入 / 逐笔计提复核 / 逐单核价核量 / 发票审核。进一家默认从第①步开始；登记制的（路凯、禾享、货拉拉）照旧直接到第④步。页面上写「第①②③步」的提示跟着改了编号。
- **第①步 数据接入（新）**：
  - 4 个数：账单原件几份、读出来多少、读全没有、请款单合计和读出来的差。
  - 账单从哪来：存的原件（文件名、谁、什么时候、怎么来的），「用原件重新解析」（取数说明改过之后用；人工改的主体/费用类型、备注按单号保留）；「上传 / 替换 / 删除账单」打开原来的账单弹窗；钉钉请款单附件按角色计数（几张请款单附的是同一个账单只存一份）；解析记录（操作日志里最近几次）。
  - 每页读了什么：每页单数、读出来的、账单合计、差、结论；点「看列」看算钱的列（绿）、账单合计列（蓝框）、本月没这列的、像是钱但没算进去的列、其它有数字的列。
  - 本月各家接入情况（点开才算）：请款单、原件、读出来的、和请款单差、钱怎么取、结论；几列加起来算钱、又没配合计兜底的标黄字提醒。
- **第④步 发票审核**：顶上按请款单一块：账单（本主体）＝请款单＝发票三个数、发票清单（号码、类型、销方、购方、价税合计、税率、纸质票、发票管家审核）、四项核对（三数一致、销方是承运商、购方是本主体、发票管家审核），「在发票管家打开」。下面照旧是原第③步的请款单清单、发票与暂估。
- **确认与登记** 挪到第④步最底下，加按主体一览（① 读全没有、② 计提 vs 账单、③ 逐单、④ 发票、「本主体通过」），登记按钮不变。

## 后端
- `kernels/logistics_intake.sheet_report`：按取数说明把一份账单每页「算钱的列加起来 vs 账单自己的合计列」列出来。合计列＝取数说明的 total_col；没配、又是几列相加的，按表头认一个像合计的列（应付/合计/总运费…）只拿来比；只读一个金额列的算本身就是合计。加哪些行＝读进来的第一行到最后一行，再接上并进同一张单的续行，空行、合计行（含不合 row_re 的行）不算。结论 ok / unsplit / gap / maybe / nocheck / skip / accrual。
- 新 `routers/logistics_intake_check.py`：`GET /api/logistics-review/intake`、`GET /api/logistics-review/intake-overview`、`POST /api/logistics-review/reparse`（已登记复核的月份不许；留操作日志「物流复核-用原件重新解析」）。报告按 原件sha×取数说明 缓存。
- `import_bill` 的操作日志多写一句明细合计。
- `/api/logistics-review/invoices` 每张请款单多带 收款方、公司主体全称、提交时间（第④步核销方、购方用）。
