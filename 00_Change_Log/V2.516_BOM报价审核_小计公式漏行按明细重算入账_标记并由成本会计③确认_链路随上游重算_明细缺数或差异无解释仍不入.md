# V2.516（原编 V2.515，撞号改号）· 小计公式漏行 → 按明细重算入账（乙案）：标记 + 成本会计③确认认可 + 链路随上游重算；明细缺数 / 差异无解释仍不入

**日期**：2026-09-08　**业务方定**：「小计行是不是只做提示，因为我们也是要输出财务版本和脱敏版本的」→ 三选一答「按乙来」。

## 口径（取代"六项勾稽任一不平就不入账"）

- **能解释的差按明细重算入账**：源表「小计」公式求和范围没框到底部新增的料（申报小计恰＝前 N 味之和），或差异全由上游重算传导而来——按明细重算小计 → 变动 → 6 成本合计 → 7 增值税(×13%) → 8 含税(×1.13) → 10 全成本(+9 管理费固定加成)。规则与星期九原版模板公式一致。
- **不静默**：记录打 `recalc` 标记（源表值 / 重算值 / 差异 / 幅度 / 疑似漏加的料 / 链路传导明细），入账即写变更留痕「小计按明细重算」；处理页勾稽列显「全平·已重算」+ 源表→重算；详情页横幅、右栏「采购原表写的 ¥…（已重算）」、台账标「小计重算」；两版 zip 说明.txt 带一行。**复核③「确认用量自洽」即认可重算**（③本来就是定稿前置，不另加闸）。
- **链路随上游重算**：同一工作簿内复配料重算后，半成品料行里引用它的「含税价」换成重算后的全成本（成本不含税＝用量×含税价÷(1+税率)），半成品再重算，成品同理——上游链路不会再报「价格对不上」。
- **仍不入**：明细缺「成本不含税」值（算不出）；或小计差对不上任何几味料之和 **且** 重算幅度 > 5%（`RECALC_MAX_PCT`，疑似表填错）。这类记 `recalcBlocked` 原因，处理页/替换回报都讲清"不能按明细重算：…"。
- **后果**：台账数、财务版/脱敏版、对外给 BP 的数与 OA 里采购原表不一致；一致的是志鹏传回 OA 的财务版。
