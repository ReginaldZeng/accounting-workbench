# V2.385 · 临时工考勤 · 中性档不该带金额（以及一次失败的深修）

**日期**：2026-08-29　**分支**：main

Reginald 指着黄相元 6/7 说「这好像也是一场」——7 日的 00:22、08:36 是 **6 日夜班**的宵夜卡和下班卡，
不该在植物肉那行又当成一天，还算出「重算 18 小时、金额 ¥342」。

## 根因

黄相元是**拆行的人**（植物肉白班 + 小料夜班）。打卡归属是**按行**算的：
小料那行正确地把 7 日两张卡归给 6 日夜班，植物肉那行不知道，又拿去切了一个 19.4 小时的「班」。

## 深修试过了，失败，已回退

我改成「按人合并归属，切班前先摘掉别的行用掉的卡」。结果**更糟**：

```
4日  原本 07:25→17:41 重算 9.0
     改后 11:35→17:41 重算 5.0   ← 早上 07:25 被夜班那行抢走了
⚠ 撑不起上报：4 → 164
```

原因：夜班那一行是拿**这个人整月的打卡**去切的，3 日 17:30 被当成夜班上班卡，
于是把 4 日早上的 07:25 当成它的下班卡吃掉了——那是个凭空造出来的「夜班」。
==要真修，得让每一行只认「这一行报了工时的那些天」，那是更大的改动，不该在这种连续小修里做。==
已完整回退，`撑不起` 回到 4。

## 实际改的：中性档不再显示金额

「金额」＝ 差异 × 单价，**只在上报了工时的日子才有意义**（多记 1 小时就多付这么多）。
上报为 0 的中性档（有打卡未计工时 / 仅1次卡），差异＝整段在厂时长，
乘出来的数不是任何意义上的风险敞口——黄相元 6/7 那天公司**一分钱没付**，却显示 ¥342。

现在这类行金额一律记 0。全表原有 8 行带假金额（最大 ¥342），现在 0 行。

## 残留，如实记下

拆行的 116 个人里，仍有 **16 行**（占全表 1.0%）是「这天的卡已被自己另一行的班用掉、
却还单独摆了一行」。它们现在**都在中性档、不标红、金额 0**，不影响任何结论，
但看的人仍可能觉得重复。要根治得做上面那个「每行只认自己报工的日子」的改动。
