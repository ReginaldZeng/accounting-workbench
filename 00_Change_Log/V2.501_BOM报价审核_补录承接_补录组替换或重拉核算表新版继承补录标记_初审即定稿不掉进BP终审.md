# V2.501 · 补录承接：补录组替换 / 重拉核算表，新版继承「补录」标记——初审即定稿，不因换了表就掉进财务BP终审

**日期**：2026-09-06　**业务方问**：「如果我替换 BOM 或者核算表了，他就一定要 BP 终审。但是我在补录的时候，也会出现更新评论区核算表上去啊」。

## 问题

替换核算表（手动上传 / 重连钉钉重拉）是**新建记录、旧版标被替换**，新记录不带 `historical=2`，于是补录组换了表就变成普通单：初审后停在「初审」等财务BP终审。补录场景里评论区补传新版核算表很常见，这条路必须也是"补录"。

## 改

- `_do_replace_sheet(..., historical=None)`：不显式传时，**组里只要有补录记录（historical=2），新版一律继承**；显式传 true/false 覆盖。新记录打 `historical=2` + 审计「补录承接」。回包多 `backfill`。
- `/api/bom/replace-sheet`（表单字段 `historical`）、`/api/bom/refetch-replace`（JSON `historical`）透传。
- 前端替换成功提示追加「补录组：新版承接「补录」标记，初审通过即定稿」。
- 下游打回未复核（上游已更新）是同一条记录改状态，标记本来就在；复核改费用 / 采纳商品版走 `_invalidate_review` 也只降状态不动标记——这两条早已是对的，本版只补"新建记录"这条。

## 实测（沙盒库，真钉钉 186641 补录组）

手动上传 川香 商务版替换：新版全部 `未复核 + historical=2 + 无终审戳`，旧版标被替换；新版两步复核 + 定性 → 「已审核」、backfillSealed、ack.by=历史补录，BP 终审待办不含。对照 089246 普通组替换 backfill=false；普通组显式传 historical=1 → true。

## 顺带看到的（未改）

重连钉钉重拉只取**第一个**商务版附件；186641 这种一单两张商务版（台式 / 川香）的，重拉会把另一张的产品当"组内新增"塞进来。手动上传替换不受影响。要不要按组的原文件名匹配再拉，另议。
