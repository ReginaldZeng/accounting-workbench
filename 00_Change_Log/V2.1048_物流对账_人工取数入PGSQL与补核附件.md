**【物流对账】人工取数入 PGSQL 与补核附件**。**起因**：金蝶 WebAPI 有每日限额，页面打开、缓存过期、翻页和定时预热会重复取数，限流后无法复核。**改法**：复用 `period_inputs`，不建新库、不建新表；总表 2241 按月份保存，逐单按 `logistics_review:<承运商>` 与 `docs:<单据类型>` 分片保存，逐笔分录按承运商和月份保存，归类结果按账单、分录和规则指纹保存。默认只读快照，只有人工点击才刷新；部分刷新不影响其他分片，实际未涉及的单据类型不形成待办。无有效快照标“待取数”，不按零数量、零计提或核对一致处理，最终登记校验同步阻断。删除每 20 分钟总表金蝶预热，供应商范围默认读已存名单。

新增金蝶补核模板与 `.xlsx` 上传，原附件以 `logistics_bill_raw.role=kingdee_fallback` 独立留档，不与供应商原始账单混用；补核物料全程不登录金蝶，未知单号单列，锁月禁止上传和刷新。上传改为 FormData，保留中文文件名。前端提供销售出库单、其它出库单、分布式调出单的范围选择、全部刷新、来源与时间、模板下载、附件上传，以及逐笔人工刷新按钮。

**发票对照补齐**：人工刷新计提分录时同步生成 `invoice_previews` 快照；默认读取快照与本地发票管家的实时审核状态，不再自动调用 `_preview_data` 或金蝶。票面内容变化时明确待人工刷新，不使用旧对照；审核状态变化可直接使用本地当前值。

**验证**：后端 63 项 unittest 通过，覆盖跨承运商隔离、分片指纹、无关类型、真实 XLSX 字节与原附件入库、未知单号、锁月、零金蝶调用、快照就绪阻断、发票快照和联合测试隔离；前端 `npm run build` 通过；`qa_logistics_redesign.cjs`、`qa_logistics_review_flow.cjs`、`qa_logistics_doc_panel.cjs` 三组真实 Chrome 回归全部通过，含中文文件实际上传、部分/全部刷新范围和逐笔 `fresh=1`。Python 语法编译和差异空白检查通过。
