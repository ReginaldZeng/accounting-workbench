# V2.465 · 撞名不再自动定人：把钉钉部门列出来，交成本会计判

**日期**：2026-09-06　**分支**：main

Reginald（8 月复核后定案）：撞名的人**不要工具自己认**，把每个候选的**钉钉部门**摆到表里，让成本会计按部门判谁是临时工。

## 背景

V2.458 让工具在「临时工撞名天天打卡的正式工」时按打卡日 F1 自动定人。实测虽然定对了丁菊华，
但业务方不接受「工具替人在两个人里挑」——猜错就是把甲的工时记到乙头上。而**钉钉部门**其实是决定性线索：
临时工部门写「…-临时普工-XX人力」，正式工写「销售/研发/品牌…中心」，成本会计一眼就分得出。

## 改法（三处，同一件事）

1. **取数侧 `resolve_dups` 不再猜**：定人只认一种情形——合并手机号后**只剩一个人**（同一人的多个钉钉账号）。
   只要是 **≥2 个不同的人**，一律退回（still）交成本会计。原先按 F1 的两条规则（甩开一倍、V2.458 的近乎完美领先）**作废**。
   每个候选补上 **钉钉部门**、手机尾号、打卡天数，并把各自打卡（days）一并带出。
2. **打卡表里各写一行**：`pull_month` 把每个待指认候选**各写成打卡表的一行**（同名、各带自己的钉钉部门+尾号+打卡）。
   核对侧 `match_punch` 一看「同名多行」→ 判「同名待指认」，而不是把整个人丢掉害他被判「没打卡」。
3. **核对侧新判定档 `ambig`**：`◇ 同名待指认（成本会计按钉钉部门判断）`。逐日撞名的人本就匹配不到唯一打卡行，
   老逻辑会打成「⚠ 记了工时但无打卡」冤枉员工——现在改判中性的 `ambig`，不算待查、不算异常。
   `match_punch` 返回的候选带上部门+尾号；④逐日导出对 ambig 行写**静态判定**（像白夜混合那样，绕开公式的 `AND(I=0,K>0)→无打卡` 那层）。

配套：`build_punch_xlsx` 的「重名定人」底稿页加「钉钉部门」列并改文案；①概览四档表加「◇ 同名待指认」一行；
前端 `DupReview` 改成「工具没定人，请按钉钉部门定」并列出部门；②总览待指认提示、逐日 BAND 同步。

## 校验

- 端到端（丁菊华同名两行：临时工「临时普工-锦绣人力」/ 正式工「销售中心」）：
  导出④逐日两天判定＝`◇ 同名待指认…`，`同名待指认日次=2`、`待查日次=0`（不再被冤成无打卡）。
- `resolve_dups`：两个不同的人 → 全退 still，候选带部门（临时普工-锦绣人力 / 销售中心）+尾号（9276/2969）+各自打卡；
  同一人多账号 → 仍自动合并直接认。
- 单测改/增：撞名交成本会计（带部门）✓、同一人多账号仍合并✓、势均力敌交人工✓、核对侧撞名判 ambig 不判无打卡✓。
  全量内核 120/120 全过；前端 build 通过。

丁菊华「报了工时没打卡」的正解：她是撞名，工具不该猜、也不该把她当没打卡——本期判「同名待指认」，成本会计照钉钉部门（临时普工-锦绣人力）一眼定人。
