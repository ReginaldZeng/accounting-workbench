# V2.930 复核台导出：每箱计费千克单独一列，金蝶核对量的公式引用这一格

- 日期：2026-10-13
- 作者：Claude Opus 5.5
- 模块：应付板块 › 物流对账 › 账单复核台 › 导出复核明细

## 起因

用户看恒茂导出的复核明细，金蝶核对量的公式是 `=ROUND(L3/N3*10.5,2)`：「这个10.5得放出来吧？」

10.5 是页面上给这个物料填的「每箱计费千克」（V2.913）。导出时我把它直接写进了公式，表上看不到这个数是哪来的，也没法筛、没法一眼看出哪个物料填的是多少。

## 改动

- `backend/routers/logistics_review.py`（导出）
  - 「ERP·金蝶数据」那一组里，「折箱数」后面加一列「每箱计费千克」，逐个物料填页面上维护的那个数。
  - 金蝶核对量的公式改成引用这一格：`=ROUND(金蝶数量/每箱数量*每箱计费千克,2)`，例如 `=ROUND(L3/N3*P3,2)`。
  - 只有按计费吨重核的承运商才出这一列；别的承运商的表不变。

## 验证

- 服务器上用新代码只读导出恒茂 2026-08：有这一列；192 行物料填了数，这 192 行的公式都引用这一格，没有再写死系数的；
  抽三行复算（4980÷10×10.5＝5229、34430÷10×10.5＝36151.5、7920÷10×10.5＝8316）和原来的数一样。
- 导出极鲜达 2026-08（不按吨重核）：没有多出这一列。
- **没验的**：没在 Excel / WPS 里打开看过版式。

## 同样的情况还有两处，这次没动

- 按体积计费的（极鲜达）：公式里写死了箱子的长宽高和每方千克数。
- 按托计费的：合计公式里写死了每托箱数、每托千克数。
