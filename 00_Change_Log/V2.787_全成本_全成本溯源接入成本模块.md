# V2.787 全成本溯源：接入成本模块（界面重做 + 并入 Codex 后端），状态「待验收」

日期：2026-10-04　作者：Claude / c

接 Codex 交接（`给Claude_全成本工作台前端交接.md`）。界面重做，接口、出表规则、取数口径都沿用 Codex V-draft；随后按用户指令接入成本模块，定名「全成本溯源」。

## 原界面的问题（设计评审）

- 层级平：状态、按钮、说明文字、合计、配置全是一个个同样分量的框从上往下堆，看不出本期卡在哪一步。
- 主按钮「确认已结账并生成全成本表」埋在一段文字里，灰着时不说为什么点不了。
- 待办是一串文字，不能直接跳到处理的地方；18 张试产工单的确认藏在折叠的「本期口径与依据」最底下。
- 全成本表每行三行高（内嵌按钮），一屏看不了几个产品；没有合计行、不能排序、不能看每公斤；为了找产品另加了一个下拉框。
- 产品追溯是弹窗，说明文字把表格挤到屏幕外；底稿对比 10 列挤在一起，看不出哪颗料差得多；切到采购价再回来，底稿选择丢了。

## 新界面

- **流程条**：状态 + 「本期依据 → 取数试算 → 确认已结账 → 正式全成本表」四步，当前步高亮，下一步该点的按钮是主按钮；待办逐条列出、带「去处理」。确认结账前弹一次口令确认。
- **合计衔接**：金蝶完工成本 ＋ 在产调整 ＝ 全成本合计（后端已校验的等式），旁边是来源差异、无产出调整、共享比例。
- **全成本表**：产品列和「合计 / 单位成本」两头固定，中间按 材料 / 人工 / 制造费用 / 调整 分组横向滚动；每行一条构成色条；可切「金额 / 每公斤」、按列排序、按车间筛；底部固定合计行。点整行进产品明细。
- **本期依据**独立页签：口径、共享分摊依据、试产工单（可筛「待确认」、可批量计入/不计入）、依据说明平铺；底部固定保存条。
- **在产调整**、**金蝶原始数据**各一个页签（原始数据不再是弹窗）。
- **产品明细**整页打开：顶部成本构成（四段条 + 11 项每公斤/金额/占比），可上一个/下一个连看；底稿对比按 用量 / 单价 / 成本 / 差异拆解 分组，带差额条，点物料就地展开三种价格和采购记录；返回主表或切页签，底稿选择都还在。

## 守住的规矩

空值显示「—」不显示 0；多份底稿不自动取最新；底稿来源与版本差异提示常显；采购价与出库计价分开标；试算/正式、数据时点常显；前端不另算口径（只有「每公斤 ＝ 金额 ÷ 完工量」和「筛选合计 / 可比项小计 ＝ 逐行相加」）。

## 文件（`01_Current_Deliverables/app/frontend/src/views/`，均为新增）

`ActualCost.jsx` 主页 · `ActualCostInputs.jsx` 本期依据 · `ActualCostSources.jsx` 金蝶原始数据 · `ActualCostTrace.jsx` 产品明细 · `ActualCostStandard.jsx` 底稿对比 · `actualCostShared.jsx` 共用 · `actualCost.css` 样式。
对外仍是 `<ActualCost org year period user />`，与 Codex 的 CostLedger 入口对得上。接口调用自带在 `actualCostShared.jsx`，不依赖 `api.js` 的改动。

## 接入成本模块，定名「全成本溯源」（2026-10-04，用户定）

- **菜单**：`app.py` NAV_MODULES 加 `fullcost`「全成本溯源」，成本模块下独立二级（排在存货台账之后、BOM 报价审核之前），状态「待验收」。自动生成准入点 `enter:fullcost`，存量账号一律不给；没挂进「存货台账」组，是因为全成本含每个产品的单位成本，不该跟着 `enter:costledger` 一起放开。
- **页面**：新增 `views/FullCost.jsx`（页头 + 主体 + 期间），`App.jsx` 加路由、`Sidebar.jsx` 加图标。期间默认上个月，上个月没东西就往前找最近一个有配置或结果的月份（最多三个月）。支持深链 `#/fullcost`。
- **后端**（Codex 审阅补丁，基线 V2.756；并入前逐个比过指纹，三个被改文件的基线与现行 V2.786 完全一致）：
  - 新增 `routers/actual_cost.py`、`kernels/actual_cost.py`、`actual_cost_service.py`、`actual_cost_export.py`、`actual_cost_trace.py`、`actual_cost_standard.py`、`actual_cost_107_2026_08.json`（107 账簿 8 月的规则种子，只有规则没有金额）。
  - `kingdee_client.py`：新增只读取数 `fetch_accounting_period` / `fetch_actual_cost_sources` / `fetch_cost_calc_raw`。
  - `requirements.txt`：加 `XlsxWriter`（导出带公式的 Excel）。
- **与 Codex 补丁的两处不同**：
  1. 路由在 `app.py` 单独注册，没有嵌进 `routers/cost_ledger.py`（嵌套挂载在本机 FastAPI 0.138 下会让 `kernels/test_api_surface.py` 两项路由自检报错）。`cost_ledger.py`、`CostLedger.jsx`、`api.js` 因此一行没动。
  2. `routers/actual_cost.py` 的 `authorized()` 多判一道准入点 `enter:fullcost`（侧栏状态只挡菜单不挡接口）。

### ⚠ 对存货台账有影响的一处

`kingdee_client.fetch_cost_calc` 的翻页由 `start += 10000` 改成 `start = len(raw) + 1`（Codex 实测 107/2026-08：按 10000 翻会把上一页最后一行重取一遍）。存货台账「制造费用勾稽」也走这个函数——成本计算单超过 1 万行的期间，结果会少掉原先重复的那一行。既有单测通过，真金蝶下的效果我没有实跑。

## 上线与遗留

- 2026-10-04 用户批准上线。服务器已先装 `XlsxWriter 3.2.9`（系统 Python 3.11）；`actual_cost_export.py` 另把该库改成软依赖——没装时后端照常启动，只在导出时给出明白提示，不会把整个后端启动带崩。

- 交接里列的数据侧未完成项（同步线上底稿、单位换算、替代料、费用分类对应）不在这次范围。
- 本地预览脚本 `.claude/actual-cost-preview/` 与 launch.json 里的三个预览配置只在本工作树用，未入库。
