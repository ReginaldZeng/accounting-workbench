# V2.597 科目余额解析（物流）：下钻按核算维度结构化精确匹配（根治，弃摘要拼凑）

用户要根治版：供应商在序时账的核算维度里、是结构化的（金蝶界面「核算维度」列＝物流运输服务027/武汉易风达…；2241.02 还含费用归属、6601 含部门/费用项目/产品），不能靠摘要模糊拼。

- 取数层：`valid_dim_fields()` 逐个探本账套序时账有效的核算维度槽（FASSTACTID + FF100001/3/4/5/6/7/8，各自 _query_raw 试、无效即跳、结果全局缓存）；`fetch_gl_voucher_subjects` 加 extra_fields，把有效槽一并带出（别名 dim0/dim1…）。
- 匹配层：`build_voucher_lines` 收集该行所有结构化维度值（旧 FF100002 + 新探槽），按 `_dim_match(dim, codes)` 精确匹配——余额表维度编码 dim 的每一段都要在该行维度值里（单值精确、复合维度如 2241.02 供应商/费用归属 按子集判、只有全中才算）。退化顺序：结构化维度→FF100002→供应商核心名在摘要（兜底）。
- 意义：供应商在哪个槽由程序自己探（不用人工指认），逐笔按结构化维度精确到笔 → 差额归零、不再靠摘要。

验证：合成金蝶风格行——单维(2221.01.07 供应商在 dim 槽、FF100002 空)精确配 2 笔 1455.77/12.39、别的供应商027不进；复合(2241.02 供应商+费用归属)只中供应商009那笔、099不进；样例仍走维度编码 67.99/55.25 不变；py_compile/EOL 均过。⚠ 真机须看：探到的槽里是否就是「物流运输服务016」这类编码、逐笔合计是否与余额表本期发生严丝对上（对上＝根治成功；仍有差＝该科目维度在更靠后的槽或余额表编码口径不同，看差额条/诊断框再调 GL_DIM_CANDS）。
