# V2.289 · 存货台账 · 原始底表补金蝶元数据头 + 页签按来源配色

**日期**：2026-08-13　**作者**：Claude / c　**线**：存货台账（cost-ledger-blockers）

## 起因

业务方：「然后其他几个原始表也没有元数据噢，最好是 sheet 页做下颜色区分」。

V2.288 让手工上传的《成本计算单》做到了逐格原样——**连带把问题暴露出来**：那张带着金蝶的
元数据头（核算体系/核算组织/会计政策 + 期间 + 币别），而接口取回的另外四张「原始·」页光秃秃
直接是表头。同一批"原始底表"，两套样子。

## 金蝶原件长什么样（照抄，不自造）

从业务方 3 月数据包里逐张比对，金蝶导出件的元数据头是**两行**，且**各报表措辞并不统一**：

| 报表 | 第 1 行 | 第 2 行 |
|---|---|---|
| 收发存汇总（跨维度） | 核算体系:… ／ 核算组织:… ／ 会计政策:… | `会计期间:2026年第3期-2026年第3期` ／ `本位币:人民币` |
| 收发存汇总（按日期） | 同上 | `日期:【2026-03-01】-【2026-03-31】` ／ `本位币:人民币` |
| 成本计算单 | 同上 | `会计期间:2026年3期-2026年3期` ／ **`币别:`**`人民币` |
| 库存账龄 | `库存组织:107(…)` ／ `货主类型:…` ／ `货主:…` | `物料范围:全部` ／ `仓库范围:全部` ／ `批号范围:全部` |

注意「第3期」vs「3期」、「本位币」vs「币别」——**照抄不统一**，不顺手统一成一套。
统一了就不是金蝶原件的样子，而这几页存在的理由就是"和金蝶导出来的一样"。

## 做法

四张接口取回的原始页（跨维度／按日期／制造费用明细／货损与处置明细）加元数据头：

- 第 1–2 行按上表逐字写；核算组织取**主体档案全称**，空则退简称（沿用 V2.253 的兜底口径——
  多主体下宁可写简称，也不能把 101 的报表署成孝感）；
- 第 3 行是**工具自己加的**取数留痕（金蝶原件没有这行）：来源报表、取数时间、取数人，
  以 `〔工具留痕〕` 开头显式标明**这行不是金蝶原文**；
- **手工上传那张一个字不加**——它已有自己的元数据行，且它的契约就是逐格原样。

⚠**连带坑**：货损页的合计公式原本写死 `=SUM(P2:P…)`。表头下移三行后，写死的 2 会把元数据行
圈进合计区。改成跟着元数据头算（`hr+1`）。全文件搜了一遍 `=SUM(`，另一处在「费用项目构成」
（结论页，不加元数据头，不受影响）。

页签按**来源**分三色：

| 色 | 含义 | 页 |
|---|---|---|
| 蓝 `4B53C4` | 工具算出来的结论与透视，可据此下判断 | 核对结论/账实勾稽/汇总透视/异常清单/损益归集/收发存明细/成本勾稽/类别漂移 |
| 灰 `8A94A6` | 金蝶接口只读取回的原始底表，留痕用、勿改 | 原始·收发存跨维度／按日期／制造费用明细／货损与处置明细 |
| 橙 `D9822B` | **人工上传**的原表——来源是人不是接口，看数时该多一分警觉 | 原始·成本计算单 |

两条自律：
- **只上色不改页序**——页序是 D17/D18 定的"结论在前、底表在后"，配色不能顺手动它；
- **在最后按页名统一上色**，不在各建各的时候上：「汇总透视」是把 5 张合并后新建的，
  建页时上色会漏掉合并出来的那张。

配色说明写在「核对结论」页尾——**不解释的颜色等于没有颜色**。

## 实测（107/2026-3）

- 四张接口页元数据头逐行核对无误；「原始·成本计算单」仍是 2 行元数据（业务方原件自带）；
- 货损页合计公式由 `=SUM(P2:P…)` 正确变为 **`P11 =SUM(P5:P10)`**，起止行跟着表头走；
- 页签配色：蓝 7 页 / 灰 4 页 / 橙 1 页，页序未变；
- **回归**：上传那页与业务方原表**仍是 12,139 行、逐格 0 格不一致（291,336 格全中）**；
- 全量 **114 测试通过**。
