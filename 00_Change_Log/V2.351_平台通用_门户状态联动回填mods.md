# V2.351 · 平台通用 · 门户状态自动联动：回填 mods，让它真的生效

**日期**：2026-08-23　**分支**：main

## 起因
使用者：**「我在里面设置的是在建，外面怎么变成了人工并行」**。

## 诊断
V2.331 做的「门户状态自动联动」**一次都没生效过**——不是映射错了，是**入口条件从未满足**。

联动靠每张卡上挂的 `mods`（这张卡对应工作台里哪几个导航模块）。实测：**14 张卡的 `mods` 全为空**，
于是 `app._portal_autolink` 每张都判「无法推导」→ 回落**手工档**，显示的一直是建门户时定的那一档，
跟管理员在「系统设置 › 导航模块上线管理」里改什么毫无关系。

空的原因是一次没做完的迁移：
- `_ensure_portal_columns()` 给老库**补了 mods 这一列，但只补列、不补值**；
- `seed_portal_tools()` **只在表为空时**灌种，而卡片在 V2.331 之前就已经存在。

V2.331 的变更日志其实留了话——「改完这份清单要提醒管理员去点一次同步」——但那次提醒没落到人，
而且那颗按钮（`reset_portal_tools_defaults`）会把状态/概述/标签/图标/排序**整体覆盖回出厂**，
用它只为补一个字段，副作用太大。

## 改法
`db.py` **纯追加** `backfill_portal_mods()`，模块导入时自动跑一次：
- 只填**当前为空**的卡，管理员手工挂过映射的一律不碰；
- 按名称匹配出厂清单，**只写 mods 这一个字段**，不碰状态/概述/标签/图标/排序；
- 幂等，异常吞掉不影响启动。

⚠ 平台线在 `db.py` 有未提交改动（V2.331 那批本身就没提交），本次是**纯新增 40 行、
删除行数不变（28→28）**，未改他们任何一行。

## 实证
回填后核算 9 张卡全部 `statusSrc=auto`；BP 5 张仍 manual（BP 无模块状态体系，本就该手工）。
六档 → 四档逐档实测（改「导航模块上线管理」→ 看门户）：
```
敬请期待→敬请期待 ✓   开发中→开发中 ✓   测试验证→开发中 ✓
人工并行→人工并行 ✓   待验收→人工并行 ✓   引擎正常→已上线 ✓
复核工具=引擎正常 + 看板=开发中 → 开发中 ✓（木桶取最低）
```
测试改动跑完即还原，库里状态未变。

## 使用者要知道的两件事
1. **「在建」只对应「开发中」这一档。** 侧栏的缩写映射是：开发中→**在建**、测试验证→测试、
   人工并行→并行；而**待验收**在侧栏就显示「待验收」，映射到门户是**人工并行**。
   本机库里临时工考勤两个模块存的是「待验收」，所以门户显示「人工并行」是对的。
2. 联动修好后，有两张卡的显示会变（这是真实状态的反映，不是错）：
   - **存货成本台账** 人工并行 → 开发中（存货看板=开发中，木桶取最低）
   - **汇率录入** 已上线 → 人工并行（汇率录入模块=待验收）
   若认为汇率录入确实该是「已上线」，要改的是**工作台里那个模块的状态**，不是门户。
