## 批量确认：一句理由管一批

这类东西**本来就是成批出现的**——2026-06 十四笔里十三笔是蒸练补贴，
金额只有 ¥30 和 ¥270 两档，多半是同一张审批单管全部。
逐条点十四次、逐条抄同一句理由，人只会越抄越敷衍，那这个理由就白填了。

现在：勾一批 → 填一句理由 → 一次确认。理由**写进每一条记录**，
外加一个「批量: N」字段，事后翻得出是哪一次批的、批了哪些。

- 理由照样必填（跟单条认定同一条规矩）
- 一次最多 500 条
- 已确认的行退到灰底，级别标记撤掉——它不再是待办，但**条目仍在，没被删**
- 勾已确认的行 → 按钮变成「撤销确认」，不用填理由
- 勾了混合的 → 两个按钮都在，各管各的那几笔
- 撤销**只动本期认定**。长期认定是跨期的，不该被某一期的批量操作顺手抹掉，
  要撤去第④步那份长期清单里单条撤（提示语里写明了）

后端复用已有的认定台账（`奖罚` 类型早就在 `_ACK_TYPES` 里，键是 `姓名|项目`），
只是这一页原来没给入口。新增 `POST /api/tempatt/ack/batch`，
`动作` 取「认定」/「撤销」。确认和撤销都写审计日志。

## 筛选：跟逐人 / 逐日一样

部门 / 归属 / 姓名（沿用同一个筛选组件）＋ 本页自己的三样：

- **级别**：全部 / ⚠异常 / △存疑 / 提示，带条数，空档不占地方
- **项目**：蒸练补贴 / 奖金 / 罚款…（只有一种项目时不摆这个下拉）
- **只看未确认**：确认过一批之后，剩下的一眼就看得见（没确认过任何一条时不摆）

顺手把筛选组件补了两个口子（`extraActive` / `onClear`）——
不然本页这三样一开，计数行还写「共 14 笔」，「清空筛选」也清不掉它们。
