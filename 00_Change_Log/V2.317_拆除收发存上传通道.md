# V2.317 · 拆除第①步的 🅱 上传报表通道

**日期**：2026-08-18　**作者**：Claude / c　**线**：main（存货台账）

业务方：「这个其实删掉是不是也可以」→「删，因为那个通道只上传一个表格没啥用啊」。

我先提了反对意见（Owner 早先立过「金蝶数据要能人眼核对，怕领导觉得黑箱有 BUG」，
🅱 就是为这个留的退路），并给了「保留但默认折叠」的替代方案。**业务方复述后仍要删，照办。**

理由成立：🅱 只吃《存货收发存汇总表（跨维度）》**一张表**，
而 🅰 一键取数本来就把这张连同另外五项一起取回来——留着等于多一条要维护、要测、
要在文档里解释的路，换来的自证能力其实很有限（想核对可以直接对着导出的「原始·收发存跨维度」页看，
那页本来就是金蝶原样）。

## 拆了什么

| | |
|---|---|
| 后端 | `POST /api/cost-ledger/analyze` 路由与 `cost_ledger_analyze` 处理函数（38 行） |
| 前端 | 第①步的 🅱 卡片、`file` state、`run()` 处理函数、`api.js` 里的 `analyzeCostLedger` |
| 版式 | 第①步由两栏改单栏；🅰/🅱 记号一并去掉（只剩一条路，编号没意义了） |

**没拆**（拆了会连累别的）：

- ⚠`parse_cross_report` / `parse_bydate_report` —— **🅰 通道也走它们**，删了金蝶取数一起废；
- ⚠已落库的 `source="upload"` 历史期间 —— payload 结构与 🅰 完全一致，只是 `meta.src` 标记不同，**照常可读可导**；
- 第⑧步的**成本计算单**上传口 —— 那是另一条通道，为底稿多出的 6 列分摊依据留的（需求确认书 Q7 仍未答）。

## 顺手修掉一句挂在屏上很久的错话

🅰 通道的说明里写着：

> 本通道不含货损/盘盈亏页，故不做损益归集——要出损益归集请用 🅱 上传带这两页的报表。

**V2.256 起就不成立了**（损益归集改从管理费用/营业外支出的科目余额下钻取凭证分录，
两条通道都能做），代码里甚至有一条注释写着"别再这么写"，但页面上那句一直没改。
现改为写明损益归集就在本通道内、不需要那两页。

同批清掉的还有：第①步导航副标题「上传收发存汇总表 · 取科目余额」→「一键从金蝶只读取回本期六项」；
第⑦步空态「本次上传的工作簿未包含货损/盘盈亏页」→「本期未取到损益归集数据，请先在第①步取数」。
