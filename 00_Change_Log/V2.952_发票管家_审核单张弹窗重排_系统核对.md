# V2.952 发票管家：审核单张弹窗重排，加「系统核对」

**起因**：用户 2026-10-14 看着线上弹窗说「这个页面是不是可以重新设计下，比如购买方税号已查验，销方税号与库里一致，而且版面上 emm」。
原来的问题：发票图下面空着一大截；右边一长条——纸质票、核销暂估、金蝶凭证三个大框压在票面字段上面，字段一格一个输入框排到底；
电子原件的票每个字段只标「原件」，看不出系统到底替人核了什么。

**样机定了三轮**（`01_Current_Deliverables/docs/20261014_发票审核单张弹窗重排/prototype/audit_item_dialog.html`）：
第 1 版三块全放右边，用户指出「左边不是下面有空白吗」；第 2 版把票面挪到图下面，用户纠正「应该是系统核对放在左边，右边是票面和要办的事」；
第 3 版照这个摆。用户说「上线我看看」——我第一次只上了另一处文字修改（V2.951），用户看了问「是不是没改到」，这才把真页面改了。

**改成这样**：

- **左边**：发票图（高度略收），图下面接**「系统核对」**——系统替你核过什么、结论是什么，一行一句；有问题的排最前、标色。现在出这几行：
  - 购买方：名称、税号对本公司抬头清单（一致／税号不在清单／抬头不是本公司／和这张单的公司主体不一致）；
  - 销售方：税号对销方档案（一致·第几次来票／新销方第一次来票／同一税号档案里叫别的名字／税号校验位不对／销方核查有记录）；
  - 收款方：开票的是不是付款单的收款方；
  - 金额：金额＋税额是否等于价税合计，带算式和税率；
  - 查重：有没有在别的单上出现过，票总管清单里有没有；
  - 来源：电子原件／二维码／拍照识别，还有几个字段要人核；
  - 税局查验：和税局清单对过没有、结果如何。
- **右边**：上面**「票面」**——字段排成两栏（名称、号码、税号这些长的占整行），不是待核的字段平时不画输入框的边、像字一样，点进去才出框；
  下面**「这张票要办的事」**——纸质票、核销暂估（后补票才有）、金蝶凭证收在一张卡里。
- 这些核对系统原来大多就在做（只在字段「待核」时才露出来），这次是把结论常显；「销方第几次来票」是新数的。只读，不改任何数据。

**接口**：`GET /api/inv/folder/{id}` 的每张票多带 `checks: [{key, label, tone, text, sub}]`（`routers/invoice.item_checks`）。不改库表。
字段面板每行加了 `data-k`（只为排版，别的页不受影响）。

**验证**：后端 `tests.test_invoice_books_api` 45 条全过（新增 test_38：正常的七行、新销方／第 2 次来票、七种有问题的情况、收据不出、接口带出）；
前端回归 38/41（3 条原来就红的自助登记）。本机预览里实际点开看过：左边图＋系统核对、右边票面＋要办的事，两边高度差不多（772 / 816 像素）。
没验：线上真数据；窄屏下的排法只按原来的规则退成单栏，没专门看。

**文件**：`backend/routers/invoice.py`、`frontend/src/views/InvAudit.jsx`、`inv-audit.css`、`invShared.jsx`、`tests/test_invoice_books_api.py`。
