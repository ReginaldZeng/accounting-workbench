# V2.469 · 发起人离职单的备用下载通道：授权在职审批人 → 钉盘代下载（需应用开通 Storage.DownloadInfo.Read）

**日期**：2026-09-06　**业务方问**：「没有别的办法吗」（V2.468 结论"只能手工下载"）。

## 再探

| 路 | 结果 |
|---|---|
| 审批附件下载接口（新/老） | 发起人没了一律 `userNotExist` / `60121`，即使先授权审批人也一样——它只认发起人 |
| `processinstance/cspace/preview`（把附件授权给某审批人） | **errcode 0**，能授权 |
| 钉盘 `/v1.0/storage/spaces/{spaceId}/dentries/{fileId}/downloadInfos/query?unionId=审批人` | **403「应用尚未开通所需的权限：Storage.DownloadInfo.Read」**——不是用户问题、不是路径问题，是应用权限没开 |
| 同接口 v2.0 / `files/` 变体 | 404 接口不存在（路径错） |

所以有别的办法：**给应用开通 `Storage.DownloadInfo.Read`**，再以在职审批人的身份从钉盘拿带签名的下载地址。权限开通前拿不到，开通后本机未验（没权限），但错误码指向明确。

## 做了什么

- `dingtalk_bom.storage_download()`：从 `operation_records` 找仍在职的审批/抄送人（`v2/user/get` 有 unionid），逐个 ①`cspace/preview` 授权 ②钉盘 `dentries/downloadInfos/query` 取 `resourceUrls` + `headers`；403 指名权限时直接回「需开通 Storage.DownloadInfo.Read」。
- `fetch_approval`：常规下载回「用户不存在」时自动走备用通道；成功则 `via=storage(代下载·某人)`，下载带签名头；失败把原因带回 `storageHint`。
- 立项提示分两种：权限未开 → 「①开通权限后重新立项即自动代下载 ②或 OA 后台下载后手工上传」；其它 → 原因 + 手工上传。
