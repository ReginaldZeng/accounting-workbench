**【平台通用】取件机运行监控——门户级一屏看全三台取件机，每台两条通知（运行 + 结果）**。
**起因**：取件机到了 3 台（报表 / 银行 / BOM），散在各工具页各看各的，且只有银行做了停机告警。需求方要：①一个页看全三台运行；②首页一个总呼吸灯；③BOM 核算表落公盘后主动钉钉通知相关人。评审中扩成对称模型：每台都要「运行通知（停机告警，给运维）+ 结果通知（成果送达，给干活的人）」两条。
**改法**：
① **监控注册表 + 状态**（app.py `_pull_registry` / `_pull_status`）：三台统一描述（所属工作台 / 方向 / 频率 / 存活阈值 / always_on），今天全挂核算组、以后别台加一条即可；「在不在跑」差值服务端算（前端拿本机钟会跳变）。
② **停机告警通用化**（`_one_pull_alert` / `_pull_alert_check_all`）：银行原 `_bankpull_alert_check`（需求方定稿）**原样不动**，报表机 / BOM 机补上；只对常开机发、没配收件人不发、转停 / 恢复各一次去重。
③ **结果通知**（`_send_result_ding` + 三个触发点）：BOM 落公盘（报表机 `bom_dest` 镜像 → 报 `bomCopied` → CP 码 + 产品去重发钉钉）、报表落共享盘（`copied` → 报表送达）、银行流水接入（`bank_pull_commit` 并入 > 0 →「可去对账」）。运行 / 结果两拨收件人分开配。
④ **BOM 小取件机心跳**：`bom_pull.ps1` 每轮回报 `/api/bom/outbox/report` → 存 `bom_pull_sync`；BOM 按**常开**对待（停了红 + 告警，非「休息」）。
⑤ **接口**：`/api/portal/machines`（监控页，admin）、`/api/portal/machines/summary`（首页灯，登录即可）、`/api/portal/machines/alert-recipients`、`/api/portal/machines/result-recipients`、`/api/bom/deliver-status`（BOM 工具只读面板）。
⑥ **前端**：门户管理加「取件机监控」分区（三卡 · 三态呼吸灯 · 上轮成绩 · 每卡两行收件人）；首页 hero 加总呼吸灯（挨 AI 卡，全绿 / 有红，admin 点进监控页）；BOM 报价审核工具顶部只读送达面板（通道灯 + 发给谁打码 + 触发规则 + 改请联系管理员）。
**验证**：Python 语法、前端 vite build 均过；改动 EOL 无 CRLF/LF 污染（`--stat` == `--ignore-space-at-eol`）；送达文案渲染单测（CP 码 + 产品去重、超 6 项截断）；起一次性测试后端（测试库 + 测试 conf，0 数据入 git）真机点过：登录 → 门户监控页（三态）、首页总灯、BOM 只读面板、对称双收件人配置——全渲染正确、`always_on` 生效。
**遗留**：①真机钉钉**实发**未触发（测试环境未配钉钉；走生产同款 `notifier.send_dingtalk`，需部署后配收件人 + 服务器钉钉 + 真事件端到端点亮）。②「结果里有错误 → 定向推给制单人」（银行制单人映射、BOM 建单人）按需求方定，留下一版。③「落公盘」实由**报表取件机 `bom_dest`** 负责（非 BOM 小取件机）——若部署把成本会计那台直接指公盘，送达触发点需相应挪。
