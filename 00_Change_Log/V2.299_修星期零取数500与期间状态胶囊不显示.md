# V2.299 · 修「星期零取数 500」与「期间状态胶囊一个都不显示」

**日期**：2026-08-17　**作者**：Claude / c　**线**：main（存货台账）

业务方两句话，两个都是真故障，而且**都属于"错误被吞掉、看着像功能没做"**。

---

## ① 深圳星期零（101）一键取数 500

```
TypeError: 'NoneType' object is not iterable
  kingdee_client.py  fetch_cost_calc  →  raw += batch
```

**根因：金蝶报表无数据时返回 `Rows: null`，不是 `[]`。**
于是 `r.get("Rows", [])` 的默认值**不生效**（键在、值是 None），拿到 None，下一句 `raw += batch` 当场炸。

星期零是贸易主体、**没有生产**，成本计算单自然为空——
可这一炸，把已经取回来的跨维度、按日期、科目余额三张表**一起拖下水**，整条取数 500。

而 V2.286 定的"代码错误不再降级成提示"（那条是对的，它抓出过被误删的函数）
在这里把一个**正常的空数据**升级成了致命错误。

修：四处分页取数统一改 `r.get("Rows") or []`，并在 `fetch_gl_balance` 上方留一条
`_ROWS_NULL` 说明（**主体没有某类业务是常态，不是错误**）。

🧪 修后 101/2026-7：取数成功，跨维度 4 行、按日期 4 行、科目余额有，
**三道勾稽全过**，制造费用块为空——空得其所。

## ② 期间选择器十二个月一个胶囊都不显示

不是没做。是 `/api/period-statuses?source=cl:<主体>` **一调用就 NameError**：

```python
# app.py
"statuses": {str(m): _cl_period_data_status(y, m, org) ...}   # ← 这函数在 routers/cost_ledger.py
```

拆 `routers/` 那次引用断了没人发现。前端 `PeriodPicker` 的 `.catch(() => setSt({}))`
把 500 吞成"没有状态"，于是右上角光秃秃——**看着像这功能压根没做**。

修两处：
- `app.py` 在该分支内**函数内导入**（放顶部会在启动时拖进整个成本台账模块，耦合与启动开销都不划算）；
- `PeriodPicker` 的 catch 补 `console.warn`：UI 仍降级不挡人用，但**要留声**。
  这个 catch 藏了上百个版本，代价就是没人知道它坏了。

🧪 修后：`cl:107` → 2/3/5/7 月「数据已上传」，8 月「数据未上传」；
`cl:101` → 7 月「数据已上传」，其余「数据未上传」。彩色胶囊回来了。

---

**两件事的共同点**：**错误被降级成"什么都没有"**——空数据被当成致命错误、致命错误被当成空数据，
正好互为镜像。前者已由 `_ROWS_NULL` 口径收口，后者补了告警。

全量 **120 测试通过**。
