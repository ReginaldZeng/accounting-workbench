# 00_Change_Log/ — 变更台账分片区 / Ledger Fragments

> 本目录受 `00_项目治理中心.md` 治理，是 `00_Change_Log.md` 的**续写区**，不是替代品。

## 为什么有这个目录

`00_Change_Log.md` 的版本索引表规定「最新版本置顶」。单线开发时这没问题；**多条需求并行开发**时，
每条分支都往同一张表的同一行位置插入新行 → 每次合并必然冲突，且冲突发生在一个 208KB 的大表里，
手工解冲突极易错行、漏行、串行。

分片化把「往同一处插入」变成「各自新增一个文件」——git 层面天然零冲突。

## 规则（三条）

1. **V2.169 及以前**的历史条目留在 `00_Change_Log.md`，**只读、不再改动**（治理原则：历史只可新增或标记作废，禁止删除篡改）。
2. **V2.170 起**每条变更 = 本目录下**一个** `.md` 文件，文件名即 `V<版本号>_<工具线>_<简述>.md`。
   - 例：`V2.170_平台通用_并行开发基建改造.md`
   - 工具线取值：`平台通用` `银行对账` `物流计提` `物流对账` `成本台账` `凭证归档` `AI合同预审` `汇率录入`
3. **一次开发任务 = 一个文件**。禁止一个文件塞多条版本，也禁止一条版本拆成多个文件。

## 版本号怎么定（并行开发下的防撞号）

并行时多条分支同时"定下一个版本号"必然撞号（历史上 V2.167 就撞过一次，事后归口成 V2.169）。
现在的规则：

- **开发期用分支名占位，不抢版本号**。片段文件先叫 `V-draft_<工具线>_<简述>.md`。
- **合并进 main 的那一刻才定号**：看 `00_Change_Log/` 里已有的最大号 +1，重命名文件、填 `version` 字段。
- 因为合并是串行的（一次只合一条），这一步天然不会撞。
- 撞号了也不致命：改文件名 + 改 `version` 字段即可，不像改大表那样要动别人的行。

## 条目格式

文件必须以治理要求的 `[Change Log]` 头开始，随后是一段 YAML 元信息，再是正文。

```markdown
[Change Log]
Date: 2026-08-05
Author: Claude / c
Version: V2.170
Description: 一句话摘要。

---
version: V2.170
date: 2026-08-05
line: 平台通用
author: Claude / c
status: Synced
revision: 01
---

**【工具线】一句话标题**。**起因**：…… **改法**：…… **验证**：…… **遗留**：……
```

字段说明：

| 字段 | 取值 | 说明 |
|------|------|------|
| `version` | `V2.170` | 合并进 main 时才最终确定 |
| `date` | `YYYY-MM-DD` | 完成日 |
| `line` | 工具线名 | 对应原表 Description 里的【工具线】标签 |
| `author` | `Claude / c` 等 | 同原表 Author 列 |
| `status` | `Proposed`/`In Progress`/`In Review`/`Approved`/`Synced`/`Reverted`/`Superseded` | 同原表 Status 列 |
| `revision` | `01` 或修订夹名 | 同原表 Revision Folder 列 |

正文写法沿用既有习惯：**起因 / 改法 / 验证 / 遗留** 四段式，事实优先，写清楚"为什么这么改"。

## 怎么看全量台账

```bash
python 00_Change_Log/_合并视图.py
```

会在项目根生成 `00_Change_Log_合并视图.md`（历史正文 + 全部片段拼成的完整台账，最新置顶）。
该文件是**生成物、已 gitignore、不入库**——因为它每次都能重新生成，入库就等于把冲突源又请回来了。

只想看最新几条、不想跑脚本：直接按文件名倒序看本目录即可，文件名自带版本号和工具线。

## 开发九步里的位置

治理九步法的第 1 步「读 `00_Change_Log.md`」和第 9 步「更新 `00_Change_Log.md`」，
自 V2.170 起改为：

- 第 1 步：读 `00_Change_Log.md`（历史）**＋** 扫 `00_Change_Log/`（近期）。急用可跑一次合并视图。
- 第 9 步：在 `00_Change_Log/` **新增**一个片段文件，**不再**改 `00_Change_Log.md`。
