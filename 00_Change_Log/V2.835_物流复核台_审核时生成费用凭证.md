# V2.835 物流复核台：不计提、直接做账的那几家，审核时生成费用凭证

日期：2026-10-06

禾享这类承运商不计提：审批通过后直接做一张费用凭证（借 费用 + 进项税 / 贷 应付），付款时再做付款凭证。V2.831 只是「认」人已经做好的那张。用户定：「这种还是没法自动，因为维度需要人检查下」「连带审核一起吧，审核完检查之后生成凭证」——所以放在复核台审核这一步，系统带出上一次的维度，人核对后才生成，不进自动做账。

- `routers/logistics_voucher.py`
  - `_last_direct(book, sup_code)`：找这家在这个账簿上一次「直接做账」的费用凭证，取它的科目、部门、费用项目、产品分类、产品项目、税率、摘要写法当默认值（只读金蝶）。
  - `_fee_draft(inst)` + `GET /api/logistics-voucher/fee-draft`：请款单、票夹里的发票（有票按发票税额挂待认证 2221.01.06、摘要以发票号开头；没票按税率挂暂估 2221.01.07）、默认维度、金蝶里这家还没被用过的费用凭证（防重复做）。
  - `_fee_post` + `POST /api/logistics-voucher/fee-post`：必须勾「我已核对」；金蝶里已有没用过的费用凭证时要另勾「仍然新建」；科目、部门、费用项目、摘要必填，摘要不能带「计提」；税率按百分数填。建凭证并提交、**不审核**；记到 `logi_voucher_fee`，并自动把这张凭证选定给这张请款单（付款做账时直接核销它）；写操作日志。
- `LogisticsReview.jsx`：登记制、还没认到费用凭证的那一行多一个「审核 · 费用凭证」按钮 → 弹窗：选请款单 → 维度（可改，带下拉）→ 凭证预览 → 勾确认 → 生成。金蝶里已经有人做过的，提示并给「就认这张（不新建）」。
- `api.js`：`voucherFeeDraft`、`voucherFeePost`。

验证：线上只读叠加跑禾享 8 月那张，带出的维度和模拟生成的分录与曾禹锡做的 记-196 一致（借 6601 1,308.91、借 2221.01.07 13.09、贷 2241.02 1,322.00）；四种拦截都生效。**没有真往金蝶写过**，第一次用请在金蝶核对。
