# V2.949 发票管家：金额核对，等确认的后补票不算两遍

**起因**：用户 2026-10-13 夜里发来线上发票审核的截图问「看看这个啥情况」：一张 1,322 的付款单，金额核对写着
「付款 1,322 −（专票 1,322 ＋ 普票 0 ＋ 发票后补单 1,322）＝ 差额 −1,322」，红字「票比付款多，重点关注」。

**查实**（线上只读）：这张单申请人 10-12 登记了后补单（1,322），10-13 17:31 自己把发票传到了后补单上（V2.923 的功能）。
这张票现在等财务确认/审核，按规矩「审核通过才算已到」，所以后补单的「已到」还是 0、「还没到」还是 1,322；
可这张票本身已经躺在「已收发票」里、算进了专票 1,322。同一笔钱两头各算一次，单子其实是平的，却报了一笔假差额。
V2.948 的「钉钉流程里后到的发票」记到后补单后也是同一种状态，会报同样的假差额。

**改法**：

- 金额核对（`folder_gap`）：已经交来、还在等确认的后补票（申请人自己传的、钉钉流程里后到的），票照旧算在专票/普票里，
  后补单那头把这部分从「还没到」里减掉（最多减到 0；交多了的照实报「票比付款多」）。这部分金额另外带出来（`laterWait`）。
- 页面：金额核对下面多一句说明「发票后补单里有 x 的票已经交来、在下面等你审核，已经算在发票里了，后补单这边不再算还没到」；
  下面发票后补单那一行，「还没到」显示减掉之后的数，旁边写「已交来 x 待审核」，状态从「待收」改显示「票已交来·待审核」。
- 后补单本身的「已到」口径没变：还是审核通过（或接收人点确认收到）才算已到。后补池那边的数字、催票都不受影响。

**连带好处**：票齐自动进审核、审完自动结单都用的这个差额。原来这种单会因为假差额既不自动送审、最后一张审完也不自动结单，现在正常了。

**顺带回答用户的问题**（业务在后补单上传了发票，是自动到审核、还是要去后补单确认）：自动到审核，不用再去后补单确认。
在发票审核里审核通过＝确认收到，后补单当场变收齐（V2.948 起审核完马上重算）。后补池里的「确认收到」按钮留着，是给「收纸质票的人不是审核人」时用的。

**验证**：后端 `tests.test_invoice_books_api` 43 条全过（新增 test_36：没交票、交一部分、交齐、交多了、逐张审核通过后、接收人自己扫的票，六种情况差额都对）；
`tests.test_invoice_api` 只有原来就红的 test_09；前端回归 37/40（3 条原来就红）。本机预览里那张演示单：差额从报错变成 0.00，说明和「已交来 600.00 待审核」都显示出来。
没验：线上那张 1,322 的真单（上线后看一眼）。
