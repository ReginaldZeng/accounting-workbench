# V2.728 BP「以他人视角查看」：内部身份接口

日期：2026-10-01

## 起因
BP 侧 Owner："现在按照强制改密了，但是我想切到他们账号看下他们能看到什么"。强制改密（V2.330）后管理员不再知道别人的密码，没法登录别人账号看 BP。BP 没有自己的登录，身份全靠 `/api/bp-authz` 透传的 X-BP-*，所以 BP 侧做「以他人视角查看」（BP V2.551），需要核算告诉它"某个账号会被透传成什么身份"。

## 改动（只加接口，不改任何既有行为）
- `GET /api/internal/bp-users`：可被模拟查看的账号列表（启用中、且有 BP 准入），只回 姓名 / 岗位中文名 / 分组 / 是否全权，不回权限明细。
- `GET /api/internal/bp-identity?name=`：某账号会被 `/api/bp-authz` 透传的身份 `{name, post, grp, perms[]}`——**与 bp-authz 同一个 `db.bp_perm_codes`**，口径零分叉（主管理员 / BP 子管理员 = `*` + 敏感码，普通账号 = 板块码 + 数据域码）。停用或不存在 → 404；无 BP 准入 → `perms=[]`。
- 鉴权：仅 BP 后端同机回环 + `X-Internal-Token`（与 `/api/bomcost/*` 同一把 `BOMCOST_INTERNAL_TOKEN`）。登录门 `_auth_gate` 对 `/api/internal/bp-*` 按同一判据放行，路由里再验一遍。不对浏览器开放，不回密码 / 会话，不写任何数据。
- 谁能发起模拟、只读、审计都在 BP 侧做（真实身份须 `*`；模拟期间一律只读；每次开始 / 结束记审计）。

## 自测
临时 SQLite + TestClient：无令牌 / 错令牌 401；非回环来源 401；停用账号 404；无准入账号 perms=[]；列表只含启用且有 BP 准入的账号；有准入账号 perms 与 bp_perm_codes 一致。`py_compile` 通过。

## 部署
纯后端，随 main 自动部署（deploy_acc.sh）后重启生效。服务器 `.env` 已有 `BOMCOST_INTERNAL_TOKEN`（成本台账通道在用），无需新配置。
