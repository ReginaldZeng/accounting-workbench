**【BOM报价审核】从 BP 工作台线交接后首版落地（挂 核算工作台 · 成本模块 · 成本会计）**。
交接自 `_交接_成本台账_20260902/`（含样机、可运行脚本、3 单真实审批样例）。菜单复用既存占位 `bomprice`
（成本模块二级，状态 敬请期待→待验收，准入点自动生成 `enter:bomprice`，默认不给合 D5「存量全部不给」）。

**为什么与既存「存货台账」完全隔离**：核算侧已有 `cost_ledger`（存货月结核对）。本工具虽在交接文档里被称
「成本台账模块」，实为 BOM 成本核算表复核，二者数据/口径无关。故全线命名空间 `bom_quote`，三张新表
（`bom_quote_entry` 版本粒度一版一行 / `bom_quote_audit` 复核留痕 / `bom_quote_final` 定稿指针独立表），
零触碰既存 schema 与接口——加表走 `create_all`（既有工具惯例，非红线）。

**增量·研发自洽校验（同任务内追加）**：使用者提出「挂成本会计这，就要比研发BOM和采购是否一致」。核实后——
BOM清单 与 成本核算表 **同为研发出品**（BOM清单抬头即研发部），采购的价与BOM**暂不对成本会计开放**，故「研发vs采购」
现建不了（数据可得性卡口，如实告知）。**先落地能做且成本会计该管的**：同一审批里 `成本核算表(添加量)` vs
`研发BOM清单(用量)` 逐料自洽校验，标 用量不符/核算表缺料/核算表多料（缺多料=BOM结构不一致）。
比对引擎与将来接采购**同一套**，采购开放后换一个源即升级。实现：kernel 加 `parse_bom_list`(解析BOM清单，抽产品名/客户/CP码)
+ `compare_bom`(按物料名对齐、编码兜底) + `match_bom_list`(**同审批批次内**配对，归组键→CP码→名/半成品四级)；
db 加 `bom_list` 列(+_ensure迁移)；入账/取数把同批BOM清单按产品挂到记录；详情页加「研发自洽校验」面板(自洽全平/差异表·只看差异·全部)+补挂口 `/attach-bomlist`；
seed **按审批分组**配对(跨版本同产品不串台)。实测：样例 8 版全部自洽全平(德式18/复调17-18/木薯6-8料)，负例(改用量/删料)正确报 用量不符/缺料/多料；真机走查面板绿态与逐料表 OK。
⚠ 存量已入账记录(本增量前入的)无 bom_list → 面板提示「未附BOM清单」，可用补挂口上传或清库重新种子。

**增量·价格校验（同任务内追加，复核第二步）**：使用者定「复核先用量后价格、分开做」；且「有编码的料可调金蝶近期已审核采购/应付作对比、弹窗列编码/供应商/型号/规格/数量/含税单价」。
这把「采购价不开放」彻底解开——**实际采购价在金蝶应付单里，核算工作台本就连金蝶，不用求采购**。业务方定：编码同一套（研发BOM物料编码=金蝶FNumber）、应付单为主。
实现：kingdee_client 加 `fetch_material_prices(code,months)`（通用 ExecuteBillQuery+字段自愈）；**本账套字段元数据实测**（金蝶从本机可达）：应付单 含税单价=`FPRICE_P`、数量=`FQTY_P`、税率=`FTaxRate`（标准 FTaxPrice/FPrice 本账套物料行返回空，已换）；过滤零价核销行。
router 加 `/api/bom/kd-purchase`（金蝶实采，连不上回 offline 友好提示）+ `/api/bom/material-usage`（BOM反查：本台账其他产品同编码填价，看研发跨产品定价一致性，纯本地）。
前端（**按使用者定，价格校验不单开一节、放进原料/包材明细**）：明细行加「核价」列→弹窗两页签 ①应付单列表（金蝶实采·vs研发飘红）②BOM反查（同编码在别的产品填了多少·vs本单）。
**真机实测（金蝶 live）**：大豆拉丝蛋白(101010045) 研发填 23.00，金蝶应付实采 20.74~21.80 → 全部标▼低 1.2~2.3（研发高报），BOM反查另一版也填 23.00(一致)。
**连带修复**：排版差异版去重原「留第一版」会留到**精简版（无物料编码）**、致价格校验形同虚设——改为 `richness()` **留最全版**（seed 两遍取最全 + book 遇更全版覆盖旧版明细）；实测样例 78 物料带编码全在。db 加 `bom_list` 列另配 `_ensure_bom_columns()` 迁移。
⚠ 采购订单物料行含税单价字段本账套未探明（标准 FTaxPrice 返空），暂只用应付单（合业务方「应付单为主」）；日后探明再并入。

**增量·复核细化 6 项（同任务内，使用者逐条提）**：①「上一版」判定＝同产品(归组键)全部版本按核算日期排序(同日按入账先后)取紧邻前一版，顺带把排序 id 由字符串比改数值比；②用量自洽校验与明细做成**两步曲·可点页签**（顶部「①用量自洽校验 → ②明细核价」，点①只看研发自洽面板、点②只看成本核算明细，默认②；右栏全成本/引用两页签始终可见；①有差异时页签带琥珀点）；③明细加**成本含税列**(=成本不含税×1.13)，**占比改按成本含税/全成本含税算**；④**税率可改**（编辑态明细税率内联输入，前端现算成本、后端权威重算 成本/小计/全成本 并逐项留痕「税率·<物料>」）；⑤核价弹窗**分页每页10行、不换行**；⑥应付单查**近一年**+**模糊搜索框**（跨供应商/单号/规格/产品/物料过滤）。
真机全验：两步曲布局✓、成本含税列(大豆拉丝蛋白2.1298→2.4067)+占比8.1%✓、改税率13%→9%→成本2.1298→2.2080/全成本随之重算/变更记录「税率·大豆拉丝蛋白 13.0%→9.0%」✓、弹窗分页(第2/3页·共30条)+搜索(AP00030618 过滤)✓。后端单测：改税率 costExcl=qty×price/(1+新税率) 权威重算通过。

**增量·来源标注 + 一单两版核算表处理 + 基础设置第三页（业务方定 2026-09-03，实单 202608101601000105116 联调）**：
使用者提「要注明数据从哪来」并揭示真实流程——钉钉「BOM表报价」一单的核算表槽有三个：`商务输出`（采购·全量底稿，含供应商/型号/规格/实价/发票税率）、`商务复核`、`商品版本`（成本会计脱敏公开版，**只有采购版有问题时才出**）。分两条线：①新未审OA只有商务版；②已审OA另有商品版（可能调过价/税）。
**关键实证（拉真单 diff）**：商品版 ≠ 缺料，而是**商务版删掉「型号/规格/供应商(品牌)」三列**——物料行、编码、名称、添加量、采购价、税率、成本**全保留**，本单价/税与商务版完全一致（纯脱敏，未调价）。故定案：
