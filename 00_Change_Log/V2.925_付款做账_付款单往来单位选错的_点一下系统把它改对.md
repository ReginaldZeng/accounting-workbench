# V2.925 付款做账：付款单往来单位选错的，点一下系统把它改对

- 日期：2026-10-12
- 作者：Claude Opus 5.5
- 模块：应付板块 › 物流对账 › 付款做账（总表上方的红色提示）

## 起因

路凯 深圳星期零 1,002.09 那张一直挂着「付款单编码不对」：同一家公司在金蝶有两条供应商档案（「物流运输服务074」「其他押金022」），出纳建付款单时选成了押金那条。
计提挂在 074 上，照那样审核，付款凭证会冲到 022，074 的计提核销不掉。原来的提示只有一句「请出纳把往来单位改成…再做账」。

用户：「这个路凯的，我们可以直接调整付款单编码吗」。

## 先手工试通

1. 查现状（只读）：付款单 FKD00008407 当天中午被人审核过、出的凭证已删；两条档案在三个组织都有，公司名一样。
2. 用户在金蝶把付款单反审核。
3. 我用金蝶的保存接口只改往来单位、收款单位两格。第一次被金蝶拒绝（用户还开着那张单，「修改冲突」）；用户关掉页签后改成。
   改完核对：金额、对方账号、户名、付款用途、结算方式、备注都没被连带改。
4. 之后没人动手：17:36 系统扫描配上付款单 →「编码不对」提示消失 → 自动做账提交、审核 → 金蝶出凭证 记-399（制单人系统操作员）→ 系统补核销分录、提交。
   凭证四行：借 2241.02 供应商往来 1,002.09（物流运输服务074）/ 贷 1002 银行存款 1,002.09；借 2221.01.06 待认证进项税额 115.28 / 贷 2221.01.07 暂估进项税 115.28。

## 做成按钮

总表上方那条红色提示下面多一个按钮「把往来单位改成『物流运输服务074』」。点了先弹确认，写明哪张付款单、从哪个编码改成哪个、只改哪两格。

**只在这几条都满足时才改，任何一条不满足就不动并说明原因**：

| 前提 | 不满足时 |
| --- | --- |
| 付款单是 创建 / 重新审核 / 暂存 | 已审核的提示先在金蝶反审核（出了凭证的先删凭证）；审核中的提示先撤销提交 |
| 付款组织、金额和请款单一致 | 不动 |
| 往来单位、收款单位现在都填的是那个错的编码 | 不动，请人到金蝶看 |
| 错的编码和对的编码在这个组织是同一个公司名 | 不动，请人到金蝶看 |
| 这笔付款在金蝶还没有凭证 | 不动，提示先处理那张凭证 |

- 只改往来单位、收款单位两格，别的不碰；**不提交、不审核**。
- 金蝶说「冲突」（有人开着这张单）时，提示把那个页签关掉再点。
- 保存后读回来确认真的改了才算成。
- 改完马上把这张付款单配给请款单、消掉提示（和 20 分钟一轮的扫描是同一个配法），不用等。之后照常做账。
- 不做成自动改：这是在改出纳建的单据，要人点。留操作日志（谁、哪张单、从哪个编码改成哪个）。
- 写金蝶的那一段挂了占线牌子（系统更新会等它做完）。

## 验证

- 真实的一次：路凯那张是手工脚本改的，用的就是这同一段保存内容，改成、后续全链路走通（见上）。
- 服务器上只读演练新接口的五个分支（金蝶的保存换成假的、写库只记内存）：没有提示 → 不做；付款单已审核 → 让先反审核；
  前提都满足 → 发出去的保存内容和手工那次一样、提示消掉、留痕；两条档案不是同一个公司名 → 不做；金蝶说冲突 → 提示关页签。
- **没验的**：按钮本身没在浏览器里点过（我登不了页面）；现在线上没有第二张「编码不对」的单，新接口的真实成功路径要等下一张出现。
