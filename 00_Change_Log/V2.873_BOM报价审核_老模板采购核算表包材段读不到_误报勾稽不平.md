# V2.873 · BOM报价审核：2025 年老模板的采购核算表包材段读不到，误报「勾稽不平」

**日期**：2026-10-08　**业务方**：历史补录 `202509221346000166946` 鸡蛋豆腐 CP1384107，处理页报「包材小计=Σ明细：采购核算表写的小计 — ≠ 逐料相加 0.0000」「变动=原料+包材：15.5464 ≠ 12.0157（少算 3.5307）」，不入账。问「这个是为啥」。

## 查实

源表本身是平的：原料小计 12.0157 + 包材小计 3.5307 = 变动合计 15.5464，全成本 23.4175，逐行都对得上。是**解析器没读到包材那一段**：

- 新模板包材段的表头行是「类别｜**包材编码**｜**物料名称**｜型号｜规格…」，解析器靠「包材编码」这一格认包材段。
- 这张 2025-09 的老模板，包材段表头行写的是「类别｜（空）｜**项目**｜添加量｜**包材含税含运采购价**…」——没有「包材编码」，也没有「物料名称」。
- 于是包材 8 行整段被跳过，包材小计读成空、逐料相加为 0，少掉的 3.5307 正好就是包材小计。

提示里那句「多半不是漏行而是表填错，退回改表」对这张表是错的——表没填错，是工具没读对。

## 改（`kernels/bom_quote.py` `parse_sheet`）

- 认包材段表头：除「包材编码」外，带「包材…采购价」的那一行也算（只在「2、制造费用」之前找，不会认到别处）。
- 包材段表头缺「物料名称 / 编码 / 单位 / 品牌 / 型号 / 规格」这几列时，沿用原料段表头的列位（同一张表，列是对齐的）。只补认料要用的这几列，其它列不补——新模板的解析结果一个字不变。

## 测

- 回归：本机留档的 39 份采购核算表，新旧解析器结果逐字段比对，**39 份完全一致**。
- 按 166946 那张表的版式和数值造表：改前 原料 8 行 / 包材 0 行、两项勾稽不平；改后 原料 8 行 / 包材 8 行、六项勾稽全平、全成本 23.4175。
- 上线后用线上留档的原文件再验一次（只读）。

## 用法

已经记成「待修」的这张单不会自己重算：上线后在处理页点「上传替换采购核算表」，选**同一份文件**再传一次即可入账。
