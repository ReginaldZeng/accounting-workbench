# V2.916 发票管家：后补单详情重排版

**起因**：用户贴了线上截图说"这个详情有点丑"。原来是 22 个字段一锅端摆成四列小格子：每格一样重、看不出重点；
「事由」一长段被挤在 230 像素宽的一格里，竖着拖出老长；银行账号、审批编号在格子里被折断。

**改法**（只动 `InvLater.jsx` 详情弹窗的上半部分和 `inv-later.css`，下面的「收到的票 / 资料 / 经办记录」没动，接口没动）：

- **金额一排**：付款金额、预计到票金额、已到、（有才显示）已收未登记、还差、预计到票日。还差没收齐时标琥珀；到票日超期标红写"超期 N 天"、3 天内到期标琥珀。
- **到票进度条**：已到（绿）＋已收未登记（琥珀）占预计到票金额的比例。
- **两张分组卡**：「收款方与发票」（收款方、开户行、银行账号、发票种类、税率、财务接收人、上次催票）、「付款单」（申请人、部门、公司主体、审批模板、审批编号、ERP 单号、登记）。账号和审批编号不折行。
- **事由通栏**：在「一、」「1、」这类编号前断行（只加换行，不动内容；小数点不算编号）；超过 6 行或很长的先收起，点「展开全部」。
- **备注**：没填就不占地方。
- 列表里的到票日提示和详情共用同一个判断（`dueInfo`），口径没变。

**验证**：`tests/qa_inv_frontend.cjs` 新加一条（金额排的顺序和颜色、进度百分比、账号不折行、事由断行后内容一字不少、收起/展开），32/35 通过；
不过的 3 条是「自助登记…」旧用例，改动前就不过，与本次无关。照用户截图的数据造了假单，改前改后各截了图对比（1920 宽和 1366 笔记本屏、待收和部分到票超期两种情形）。

**遗留**：新建后补单时的预览、「收到发票」弹窗还是原来的小格子样式，这次没动。

**发布**：只改前端（并 main 时重新构建 static），不重启后端。回退＝反向提交。
