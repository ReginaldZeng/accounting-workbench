# V2.993 付款做账自动轮：金额更正的确认放到复核台（主体通过时顺手确认），多收待扣回不再误拦

日期：2026-10-19

用户看付款做账页 4 张「可以做账」却一直没被自动做掉（顺鸽 8 月孝感 3,151.50 / 深圳 29,746.39、极鲜达 8 月孝感 99,860 / 深圳 75,093.68），问「这几个为啥没触发自动做账」，查实后又说「这个不应该在这一页确认，应该在审核账单时就确认了」。

## 查实（生产库 logi_voucher_auto_last / logistics_review_subj / logi_carry_adj）

- 顺鸽两张：计提比发票多 24.00 / 45.99，**应为金额是系统按发票金额自己猜的**，没有任何人确认过 → 护栏拦下是对的；
- 极鲜达孝感 99,860：复核台 10-14 已登记「FBDR075425 多收 400 待扣回」（曾禹锡），更正方案就是按登记算出来的——**人明明在复核时确认过**，但 `_auto_ok` 只认付款做账页的「选择核销哪些计提」（picked），多收扣回把计提顶成「金额更正(amt)」类型后一律按没人确认拦下。**护栏误伤**；
- 极鲜达深圳 75,093.68：发票 ≠ 计提差 230.08，登记的 48.84 扣回解释不了，本来就该人看，不在本次范围。

复核台总表的「⚠ 需更正」「已通过，但计提与复核应付差 ××，需红冲更正（谁）」只是**现算提示**，`logistics_review_subj` 的 note 全是空的——复核时差异摆在眼前、人点了通过，但「按多少钱更正」这个结论没有任何地方落库。

## 改法

### 1. 复核台：主体通过时顺手确认「差异怎么办」

- `logistics_review_subj` 加 `diff_verdict` 列：空 / `fix`（计提多了，按复核后金额红冲更正）/ `keep`（账单没错，差异另外处理）。老库启动时自动补列。
- 总表差异格里的「⚠ 需更正」徽标**变成可点**：点开弹窗选结论；选完显示「✓ 已确认更正 / 差异另说」，tooltip 写明谁确认的、做账会照做。已登记复核的月份也能补登记（不改复核结论，只告诉做账差异怎么处理）。
- 第②步（计提 vs 账单）组头的「⚠ 计提差」同样可点；标「本主体通过」时这个主体还有差异的，标完自动弹出确认。
- 新接口 `POST /api/logistics-review/subject-diff-verdict`；`subject-mark` 顺带接受 `diff_verdict`。

### 2. 付款做账自动轮：复核台确认过的金额更正当作「人已确认」

`_auto_ok` 的「金额更正留给人确认」护栏，确认渠道从 1 条扩成 3 条，任一即可：

1. 付款做账页点过「选择核销哪些计提」（原有）；
2. **复核台主体通过时确认过「计提多了，按复核后金额红冲更正」**（`diff_verdict=fix`）——本次新增；
3. **计提的更正本身就是复核台登记的多收待扣回/本月扣回顶出来的**（per 里 `mode0` 是 hx/tail 被 carry 顶成 amt 的）——修误伤；系统猜的 amt 叠了扣回的（mode0=amt）不算，仍要 ① 或 ②。

`_auto_fp` 指纹纳入复核结论（diff_verdict 非空的行）：复核台确认/改了结论，定时下一轮立刻重算，不等 6 小时强制重读。

预览提示写明出处：「按红冲处理……（复核台已确认计提有误、按复核后金额更正：谁 什么时候）」。
