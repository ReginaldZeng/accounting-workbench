# V2.678 修复物流复核台明细全空（丰源/顺丰等）

## 症状
进复核台任一承运商（丰源、顺丰冷运……），上方「账单合计」显示「—」、待处理筛选全 0、下方明细表整张空白。后端 `/api/logistics-review/result` 返回 200，金蝶数据也在库（丰源 9 单 7324.39 元实测在），但页面就是空。

## 根因
V2.676 把计提对账拆成独立异步接口时，`@router.get("/api/logistics-review/result")` 这个路由装饰器被错放到了辅助函数 `_accr_lines()` 头上，而真正的 `review_result()` 反而没了装饰器（成了没人调用的孤儿函数）。

于是 `/result` 实际执行的是 `_accr_lines()`，它 `return lines, total`（一个元组），被序列化成 JSON 数组 `[[{…计提行…}], 合计]`。前端 `setD(数组)` 后，`d.total_bill` / `d.by_box` 全是 undefined → 账单合计「—」、无表格。所有承运商都中招，用户恰好在丰源/顺丰上发现。

## 修复
把 `@router.get("/api/logistics-review/result")` 从 `_accr_lines` 移回 `review_result`。`_accr_lines` 恢复为纯辅助函数（由 `/accrual` 接口调用）。仅后端一行装饰器归位，前端不变。

## 影响 / 上线
- 后端 .py 改动 → 部署会自动重启。无需重建前端。
- 验证：`/api/logistics-review/result?carrier=丰源&period=2026-08&group=ex` 应返回 `{"ok":true,"by_box":true,"total_bill":7324.39,"detail":[…28行…]}`。
