**【物流对账】逐单运费 V1/V2 与 BP 当前有效费用**。**起因**：BP 等不及全部账单复核，物流部需先提交多张不同格式、含合并单元格的装卸/运费表作为 V1，并允许新增、替换、删除；最终仍以账单复核 V2 为准。**改法**：
- 新增独立 `logistics_freight_v1_batch/file/line` 三表，保存账期、批次状态、原始 Excel、SHA256、标准明细、原 sheet/行号/合并区域；新增敏感写权限 `logistics_freight_write`，读沿用物流权限，写操作服务端审计。
- 新增多文件预览、单文件确认、原子替换、软撤回、恢复、取消草稿和原件下载接口。解析覆盖销售成品装货、原辅料卸货、分步调拨、全零/非零退货、金蝶销售出库其他/山姆；合并区域只补元数据，金额不向下复制，完全相同行只提示，原表合计与明细重算勾稽。
- 新增共享 `logistics_doc_freight` 读模型：按 `单号+承运商+费用类型` 有 V2 取 V2、否则取 V1；待复核不进入有效金额，V2 零值只覆盖本费用类型；销售出库和其他单据共用，支持版本/差异/未提交筛选与来源追溯。
- 单据运费新增“物流表 V1”页签，支持多文件上传、勾稽/异常/重叠预览、替换撤回恢复；销售出库显示 V1/V2 金额与差异。新增 `GET /api/internal/bp-doc-freight?period=YYYY-MM`，按费用归属月输出当前有效费用；旧 `bp-logistics-lines` 不变。

**验证**：
- 正式目录 33 个后端测试通过（新增批次/版本/BP 及既有 readiness、导出）；开发夹 57 个解析与既有物流内核测试通过；正式前端 `npm run build` 通过（仅既有 FundDashboard 重复键和大包警告）；Playwright 真实 JSX QA 通过，无 pageerror；`git diff --check` 通过。
- 六份真实附件解析全通过：小料装货 38 行 4,885.11；蜜雪 52 行 13,183.655；原辅料 129 行 18,170.97930375（原表合计漏两行，差异 425.9625，`CGRK183089` 重复只提示）；分步调拨 19 行 263.58282；植物肉 42 行 593.48；销售出库 448 行/285 单 582,606.92552052161。
- 真实 FastAPI+临时 SQLite 闭环通过：上传植物肉表→预览 42 行/593.48→确认 V1→同单 V2 运费 100+V1 装卸 74→待复核 50 不双计→原子替换→撤回→恢复→原件一致。未连接生产库或金蝶写接口。

**影响与遗留**：只新增数据库表，不改旧表结构、不删除旧 API；首次启动由 `create_all` 建表，写功能需给对应用户显式授予 `logistics_freight_write`。未部署、未向生产导入 9 月数据；BP 需切换到新 `bp-doc-freight` 路径后才会使用 V1/V2 当前有效口径。真实非零退货卸货费的冲减符号仍按阻断处理，待业务确认后再开放。

**补：预览交互与物流商标准化（2026-10-26）**：逐单明细改为大弹窗确认，上传后再补归属；批次可勾选并批量指定物流商，读取现有供应商档案，批量仅处理待确认且整批原子生效。新增物流商“精确名称优先、唯一关键字辅助”标准化，原写法保留，唯一映射留提示，未知/多家冲突阻断；通用词不单独作识别依据。补充后累计 59 个内核测试、17 个 API/版本测试通过，浏览器 QA 覆盖弹窗、单批补充与批量指定，正式前端构建和本地预览通过。
