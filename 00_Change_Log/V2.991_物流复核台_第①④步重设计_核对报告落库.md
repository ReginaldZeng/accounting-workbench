# V2.991 物流复核台：第①④步重设计 + 每页核对报告落库提速

日期：2026-10-17

照样机定稿（`output/intake-redesign/`，用户逐轮看过）重设计复核台第①步「数据接入」和第④步「发票审核」顶部面板；顺手把第①步「读取慢」治本。样机截图在 `output/intake-redesign/shots/`。

## 第①步 数据接入（重设计）

- 顶部四张 KPI 卡 → **一张三方对账结论条**：账单原件 →（✓ 一致）→ 读出来的 →（✓ 差 0）→ 请款单（钉钉）。哪一环断了，连线变红 ✕ 并显示差额；主操作「上传/替换/删除账单」收进同一行。
- 「账单从哪来」→ **文件卡**：账单原件一张卡（重新解析留在卡内）、钉钉请款单附件一张卡。
- **解析记录默认折叠**，只写人话（原来每条带"明细 X 行/计提 X 行/跳过 X 表"内部口径）。
- 「每页核对」表结论列更干净；底部保留判定口径说明。

## 第④步 发票审核（从「只看结果」改成「这页能办完事」）

- 同款结论条：请款单 → 发票 → 审核/纸质票进度。
- 每张请款单卡里，发票表格新增两列操作：
  - **纸质票**：拨杆（`/api/inv/paper/mark`），拨到"已收到"才点亮「审核通过」；
  - **审核通过**：走发票管家 `/api/inv/audit/items/approve`（body={folderId,itemIds}），当场变绿标，不跳页；票齐整单通过有提示。
- **发票后补单只读核对**（用户 2026-10-17 定：**后补单由业务在钉钉登记，会计这里只看登记了没有**）：
  - 已登记 → 显示业务登记信息（后补单号/登记人/预计到票），"可以放行"口径；
  - 未登记 → 黄框警告"业务还没登记发票后补单"，注明没登记付款审核不放行。本页无登记表单。
- 原「核对清单」（账单=请款=发票 / 销方 / 购方 / 审核）保留在每张卡底部。

## 性能：每页核对报告落库（治"第一次打开要几秒"）

- 根因：第①步「每页核对」报告是打开页面时按原件**现算**的（openpyxl 全文解析），进程内缓存一遇后端发版重启就全清；"各家接入情况"还要逐家现算。
- 改法（`routers/logistics_intake_check.py` + `kernels/logistics_review_store.py`）：
  - 新表 `logistics_intake_reports`（raw_id × spec_sha → report_json，create_all 自动建）；
  - **导入/重新解析时**（`import_bill` 里延读 import 调 `warm_report`，防循环）顺手把报告算好落库；
  - 打开页面读库（毫秒级）；取数说明变了（sha 对不上）只重算这一家、覆盖回库；内存缓存保留作第二层。
- 效果：重启、换人、总表都不再触发全量解析。
