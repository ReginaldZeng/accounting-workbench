# V2.818 付款做账：金额有差——默认红冲更正，特殊的可部分核销（带凭证说明）

日期：2026-10-05

用户定口径：「金额有差的，按照红冲处理，或者特殊的按照部分核销处理（凭证说明）」。
此前计提和发票含税合计只要不等，系统一律判「金额不符·人工」，没有路可走（连复核台登记的金额更正也过不了）。

## 两种处理

- **红冲更正（默认）**：原计提整笔红冲，按「应为金额」重新计提（税额按税率重算，挂暂估），再核销、支付。发票比计提多、比计提少都适用。
- **部分核销（特殊，要人选）**：不红冲、不更正，只核销「应为金额」那一部分，剩下的留在账上。核销摘要写明：
  `…核销8/393#（部分）计提…（8/393#部分核销：计提29792.38，本次核销29746.39，余45.99未核销；{人写的说明}）`。说明必填。只能比原计提少。

## 「应为金额」从哪来

1. 人在「选择核销哪些计提」里给每张填的「本次按多少」（V2.817 的面板加了金额列、「补差」、处理方式、说明）。
2. 复核台登记的金额更正（`to_amt_tax`）——以前 plan 不认，现在认。
3. 没人填、且这张请款单只对一张计提：系统默认按发票金额红冲更正。
   但先看是不是跨月核销——别的月份有没用过的计提、合起来正好等于发票的（诚煜），不擅自红冲，提示去确认。
4. 几张计提对一张发票、各该多少系统定不了：仍判人工，提示去面板里填。

## 改动

- `kernels/logistics_voucher.py`：`plan(…, amts)` 新增 `amt`（金额更正）、`part`（部分核销）两种处理；按「应为金额」比合计、分税率组、算尾差。`build` 相应出分录。
  顺带：尾差优先挂在本来就要红冲更正的那张上（不再为一两分钱多红冲一张好的计提）；几张都更正进本凭证时，核销摘要里本凭证号只写一次。
- `routers/logistics_voucher.py`：组装 `amts`；做账类型新增「部分核销」；金额更正算「需红冲更正」；更正单带出金额更正；保存选定时收金额、处理方式、说明并校验（部分核销必须有说明）。
- 自动做账：系统默认推的金额更正**不自动做**（留给人点）；人在面板里确认过应为金额的才自动。部分核销不自动。
- `LogisticsVoucher.jsx`：面板加「本次按多少」「补差」、红冲更正 / 部分核销单选、说明；预览和列表显示「金额有差 → 红冲 + 更正 X → Y」「部分核销 Y，余 Z」；做账类型多一栏「部分核销」。

## 验证

- 单测 9 例通过（新增金额有差 1 例，含：不给金额仍判人工、红冲更正分录逐行、部分核销分录与摘要、部分核销不能超过计提、发票比计提多、复核台金额更正）。
- 线上真数据只读试算（不落库）：
  - 迅鸽 29,746.39 只选 8/393#：红冲更正 → 更正后 28,062.63 + 1,683.76 = 29,746.39，借贷平；部分核销 → 只出核销两行，摘要带说明，借贷平。
  - 极鲜达 75,093.68 六张按请款事由填四张的应为金额：4 张红冲更正，另两张直接核销，借贷 6,430.48 平。
  - 诚煜：没选之前不再可能被默认红冲，提示「6/518# + 7/522# 合起来正好等于发票，多半是跨月核销」。
  - 没有人工选定时，27 张请款单结果与线上现版逐张一样。
- **没试的**：金额更正、部分核销都没有真写过金蝶；面板真点保存没试。
