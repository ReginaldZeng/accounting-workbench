**【物流对账】物流复核工作台四步前端重构**。**起因**：已验收的数据接入、逐单核价核量、逐笔计提复核和发票审核样机需要替换旧的表现层；准备做账维度按主体汇总并追溯来源，当前计提不能挤在右侧，小屏与多计提场景也不能错位。**改法**：在隔离 worktree `tmp/logistics-redesign-worktree`、分支 `redesign/logistics-review-20261104` 上，仅调整 React 表现层与组件组合。新增共享页头、真实指标卡、提示、面板与底部导航；第①步展示标准账单金额、文件、逐笔行/单据与接入待办，第②步展示账单与筛选金额、数量异常和待处理单据，第③步展示计提、准备做账、差异及未解释差异，第④步展示准备做账、请款、发票和待办。新增 `PreparedDimensions` 按主体展示账单归属、期间、费用项目、费用类型、产品分类、细目、部门、科目、金额、税率、来源与主体状态；只在后端给出的账单匹配组首行展示金额，多笔计提共用账单不重复计数，比例缺失不显示 NaN。来源仍调用原 `goDocs`，调整/拆分仍调用原 `FixEditor`；更正弹窗移到折叠区外，收起当前计提也能打开。原逐笔计提完整保留在“当前计提”折叠区，发票审核、登记、权限、Excel 导出、金蝶取数和后端逻辑未改。去掉负外边距，宽表在自身容器滚动，底栏使用粘滞定位。**验证**：`npm run build` 成功；`tests/qa_logistics_review_flow.cjs` 原四步加载与错误恢复 7/7 通过；`tests/qa_logistics_doc_panel.cjs` 单据双轴、归类与真实 Chrome 中央弹窗通过；新增 `tests/qa_logistics_redesign.cjs` 覆盖四步真实指标、来源跳转、金额去重、主体筛选、当前计提折叠、折叠后打开更正弹窗、中央弹窗数量标准及物料、390/768/1440px 四步无整页横向溢出；A–J 标准解析与 Excel 导出 12/12 通过。使用生产只读极鲜达数据快照进行本地禁止写入的实际渲染验收，3 个主体、计提 215,163.09、账单 214,484.59、差异 678.50、4 笔未解释差异均一致；深圳星期零 5 笔计提共用 123,329.17 元只展示一次，首单 `XSCKD219348` 的 3 行真实物料合计 4,000kg。逐张检查 `output/logistics-redesign-qa/desktop-lines.png`、`desktop-doc-dialog.png`、`mobile-lines.png` 及局部原尺寸截图，未见页头、期间、指标卡、折叠区、中央弹窗或底栏错位。**遗留**：构建仍有项目原有的 `FundDashboard.jsx` 重复键与大 chunk 警告，本次未改该模块。当前仅为本地隔离分支待验收状态，未提交、未合并、未部署生产，未自动确认异常、登记复核或更正凭证；部署须等待用户另行明确指示。
