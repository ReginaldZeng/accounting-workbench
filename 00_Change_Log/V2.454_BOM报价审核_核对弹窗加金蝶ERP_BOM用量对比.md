# V2.454 · 核对弹窗加 ②「金蝶 ERP BOM 用量 vs 核算表添加量」逐料对比

**日期**：2026-09-06　**业务方提**：「这种（台账里没别的版本可比时），是不是应该将金蝶录入的 BOM 用量和我们这里的作对比」。

## 金蝶实证（只读，241000663 菌菇辣丝丝半成品）

- ERP BOM 在 `ENG_BOM`：编码 `241000663_V1.0`（禁用）/ `241000663_V1.1`（启用），母件单位 **千克**，成品率 100，同一 BOM 按使用组织 101/107 出重复行。
- 子项 12 条：`FMATERIALIDCHILD` 编码/名称、`FCHILDUNITID` 千克、用量 `FNUMERATOR/FDENOMINATOR`（如 0.1719/1）、`FDOSAGETYPE` 2＝变动用量、`FSCRAPRATE` 损耗率。**kg/kg，与核算表添加量同口径，可直接逐料比。**
- 子项里含半成品 200000177「卤味复合调味酱」——正对核算表里「作原料进上层」的行。反向也查得到它被 300400005/6/7 三个成品 BOM 引用。

## 做了什么

- `kingdee_client.fetch_bom(code)`：取母件所有版本 → 挑**启用且已审核**里版本号最大的 → 只取一个使用组织的子项行（避免按组织重复）→ `items[{code,name,unit,qty=num/den,scrap,dosageType}]` + 表头（bomNo/unit/yieldRate/forbidden/versions）。只读。
- `GET /api/bom/kd-bom?entryId=[&code=]`（CAP_AUDIT，10 分钟缓存）：按记录物料编码（或传入的金蝶候选码试比）取 BOM，`_align_kd_bom` 与核算表物料行对齐（真实编码优先、退名字、每条只配一次），并带研发 BOM 清单用量一列；判定 一致 / 用量不符（容差 0.0005 kg/kg）/ 仅核算表 / 仅金蝶 / 单位不同（母件或子项非千克不判）。无编码→提示先采用；金蝶没登 BOM→hasBom=false；连不上→offline。
- 核对弹窗改三段：① 金蝶物料档案候选 ② **金蝶 ERP BOM 用量对比**（自动拉；无编码时用金蝶候选第一个正式码试比并标「未采用」）③ 台账内同码/同 CP 核算表对比（原 ②）。表：段 / 物料 / 编码 / 金蝶子项 / 核算表添加量 / 研发BOM用量 / 金蝶BOM用量 / Δ / 判定，差异排前；表头显示 BOM 号、禁用标、母件单位、成品率、版本数、差异数。

金蝶只读实测：241000663 取到 V1.1、12 子项；TestClient（伪 fetch）：编码对上→一致/不符判定、占位码退名字、仅核算表/仅金蝶各一、单位不同不判、无编码提示、无 BOM 提示。前端 build 过。
