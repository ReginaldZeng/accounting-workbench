# V2.344 · 临时工考勤 · 合同价改成「按行各自带生效期」

> 需求方 2026-08-22：「这里应该是**按行**制定生效日和失效日」，追加「并注明**是谁什么时间录入的**」。
> （本条取代同日的 V2.343「整表一个版本」——那个模型是错的，一并撤除。）

## 一、为什么「整表一个版本」是错的

V2.343 做成了「一版＝整张表 + 一个生效日」。问题是：**各家派遣方的续签时间本来就不同**。
锦绣 8 月调价，那个模型会逼着把华顺、恒祺的价也跟着重述一遍——
既是无谓的重复录入，**又会让人误以为所有家都在 8 月动过价**。

改成：**每一行（派遣方 × 岗位）各自带生效日与失效日**。

实测印证：华顺留在 1/1 的合同不动，锦绣 1/1 → 8/15 调价，锦绣保洁 3/1~6/30 到期不续——
三条互不干扰，2026-07 自动取「华顺 1/1 + 锦绣普工 1/1」，保洁已过期不出现。

## 二、失效日：可留空，也可显式填

- **留空** ＝ 同一行（同派遣方同岗位）下一条的生效日前一天；再没有下一条就是「至今」
- **显式填** 是给「合同到期不再续、这家停止合作」用的——**那种日期推不出来**，必须能填

⚠ 显式填就可能出现两种坏情况，都会让某期取错价或取不到价，所以**逐条检出并标红**：

| | 例 |
|---|---|
| **重叠** | 6/1~12/31 与 8/15 起两条盖在一起 → 「与下一条（2026-08-15 起）区间重叠」 |
| **空档** | 上一条 6/30 失效、下一条 8/15 才生效 → 7 月没有任何行覆盖 |

## 三、谁什么时间录的

每行记 **录入人 / 录入时间**，页面单列一列；保存与删除各留一条审计。
旧字段名（维护人/维护时间）一并识别，历史数据不丢人名。

## 四、连带的一个重要改动

合同价登记表成为**唯一来源**后，页面不再把单价表当 override 发给后端。

> ⚠ 原来 `form()`/`rerun`/`exportForm` 都发 `rates: 页面表`，而 `merge_rates` 里 **override 优先级最高**——
> 它会**盖过合同价**，等于绕开刚建的生效期机制。已改为一律发 `{}`。

随之删掉已无 UI 的死代码：`saveRates` / `addRate` / `delRate` / `rateRows` / `newRate` 状态、
以及 V2.343 的 `ContractVersions` 组件。

取价优先级现在是：**该期适用的合同价行 ＞ 汇总表表头解析 ＞ 内置默认**。

## 五、实测

| 项 | 结果 |
|---|---|
| 各家续签时间不同 | 华顺 1/1 不动、锦绣 8/15 调价，互不干扰 ✓ |
| 失效日自动推 | 锦绣普工 1/1 那条自动变 `~2026-08-14`，标「自动（下一条生效日前一天）」✓ |
| 显式失效日 | 锦绣保洁 3/1~6/30，2026-07 起不再出现 ✓ |
| 期中调价 | 2026-08 标出「锦绣·普工」，其余家不受影响 ✓ |
| 重叠检出 | 「与下一条（2026-08-15 起）区间重叠」✓ |
| 失效日早于生效日 | 拒绝 ✓ |
| 白夜都不填 | 拒绝「至少要填一档单价」✓ |
| 删除 | 需二次确认 ✓ |
| 录入人/时间 | 逐行记录并展示 ✓ |
| 页面 | 两页签、登记表列（生效日/失效日/白班/夜班/备注/录入人·时间）、录入表单 9 个字段 ✓ |

内核回归 **211 项全过**（本次只动路由与前端）。测试数据已清空。

## 六、遗留

`_contract_for()` 仍按「期末」定行——**跨调价日的月份按整月一个价核对**，页面红字交人工。
真要逐出勤日套价，得把 `payable()`／`rate_of()` 改成逐日计价，且人力的结算口径要先跟着变。
