# V2.432 · 纯历史组（0 active）不再当编号「组」，收进「历史留痕」块

**日期**：2026-09-05　**分支**：main

Reginald 作废重立 059207 后成功分成两组（空白袋 CP07118902 + 印刷袋 CP07118902-2，各自用量自洽），但处理页还多出一个空的「组 3」——0/0 已入账、只挂着 9 条作废/被替换留痕。

## 根因

作废/被替换的旧记录（`active=0`）留在它们各自的老 group_id 里。处理页原逻辑只要组内有 superseded 就渲染成一个编号「组」，于是一个 0 active 的纯历史组也占了「组 3」，还把组数/产品数算歪。

## 改动

- 后端 `_approval_view` 每组加 `historyOnly = (无 active) and (无待修批次)`。
- 前端处理页：`liveGroups` = 非 historyOnly 组，**只有它们编号为组 1/2…、计入组数与产品数**；historyOnly 组的 superseded 汇总成单独一块「**历史留痕（已全部作废/被替换的旧版）**」渲染在末尾（`deadHist`），标明「不在台账、不占组号与产品数」。留痕一条不丢，只是不再冒充一个待处理的组。
- 空单判断改用 `liveGroups.length`（全作废但有历史时，显历史块而非「暂无记录」）。

后端 py_compile 过、前端 build 过。
