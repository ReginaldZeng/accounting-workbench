# V2.265 电商对账 · 操作详情抽屉

## 一句话
需求方看完 5123182287333018342 的人工五路解析后定：逐单核销要有「操作详情」抽屉（样机同款）——点任意订单行滑出该单完整档案，把当天的人工侦探路径固化成接口。

## 改了什么
- **routers/ec.py**：`GET order-detail`——四段组装：①核销行（桶/金额/初判）②金蝶应收逐行（蓝红、勾稽字段 T3/T4/T6、源单；查询用 `Text6 like %单号%` 兼容**分号连双单号**）③红字源单 RK → 销售退货单反查（退换单号/退货挂的原始单号）④**同发货 JY 下的伙伴蓝字**（从红字 T3 取 JY 再查 T4=JY 的蓝字并排除已列行——串单侦探自动化，挂他单名下的本单货自动现形）。
- **EcomSettle.jsx**：逐单表行可点（订单号紫色提示）→ 右滑抽屉：核销结论（到账时间/渠道/流水号/差异/机器初判）+ 三张表（应收明细红行红底 / 退货链 / 伙伴蓝字蓝底）+ 各表脚注提示核对动作。

## 验证
018342 实测：抽屉自动给出 红字−53.41(源RK2607160001) + 退货链(TK2607150003/原始单号) + 伙伴蓝字 AR00303360 三行（含辣丝丝53.41 盖…7524）——与当日人工五路排查结论完全一致。浏览器点行滑出正常。
