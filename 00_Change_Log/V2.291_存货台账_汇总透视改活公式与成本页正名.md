## ① 「成本计算单不也是自动导出的吗」→ V2.290 的"退休"是错的，撤销

V2.290 我按业务方一句"是不是可以退休了"，把接口取的「原始·制造费用明细」在有上传原表时撤掉了。
**撤之前没核数据。** 核了才发现：

| | 成本项目 | 金额 |
|---|---|---|
| 业务方上传的那张 | 制造费用 + 直接人工 | 3,900,207.56 |
| 接口取的那张 | 直接材料 9,787,932.32 / 委外加工费 382,377.41 / 直接人工 1,625,191.99 / 制造费用 2,275,015.57 / 间接材料 96,471.23 | 全部 |

**上传的那张是筛过的制造费用部分，不是完整成本计算单。**
而「车间×成本项目」「费用项目构成」覆盖全部成本项目——撤掉接口版，这两块就没有底表可引。

同时确认业务方是被**名字**绕晕的（两张都叫不出来源），改名：

- 「原始·制造费用明细」→ **「原始·成本计算单(接口)」**（灰，接口自动取，完整）
- 「原始·成本计算单」→ **「原始·成本计算单(上传)」**（橙，界面导出件，多 6 列分摊依据）

**教训**：业务方问"是不是可以 X"是**问句**，不是指令。当成指令执行、还不先核数据，就是拿别人的一句猜测当自己的依据。

## ② 「灰色几张表导出是怎么样就是怎么样了吧，你前面的汇总透视用 sumifs 才对啊」

对。灰表是金蝶原样、不动的，那么汇总就该**从它们算出来**，而不是各算各的再摆在一起。
V2.290 我只加了一列 SUMIFS 做"校验"，理由是"封存要存死的数"——这个理由站不住：

- 灰表本身就是**跟着输入一起落库的留痕件**，公式的分母不会跑掉；
- 汇总是公式，反而**动了底表就立刻露馅**，比存死一个数更安全；
- 打开文件点一下就看见口径，不必信"工具算过了"。

故：汇总透视各块**整体改成引用原始底表的 SUMIFS**。

| 块 | 公式 | 底表 |
|---|---|---|
| 收发存汇总·按类别 | 8 列 `SUMIFS(W:W, C:C, 类别)` 等 | 原始·收发存跨维度（C＝存货类别） |
| 收发存汇总·按仓库 | 4 列 `SUMIFS(…, H:H, 仓库)`；组小计＝组内求和；总计＝`SUMIF(B,"小计",…)` | 同上（H＝仓库） |
| 车间×成本项目 | `SUMIFS(I:I, F:F,"成本项目", L:L,"<>是", A:A,车间, G:G,成本项目)` | 原始·成本计算单(接口) |
| 费用项目构成 | `SUMIFS(I:I, F:F,"费用项目", H:H,子项费用项目)` | 同上 |
| 收发存·按事务类型 | **不改** | **没有对应底表页**（流水一期十几万行，不落库也不导出）——如实写明"只能是值" |

两个坑：
- **仓库条件用常量、不用 A 列**：A 列为了缩进带了 4 个空格，拿它当条件匹配不上；
- **车间×成本项目取成本项目层、费用项目构成取费用项目层**，两层不能混（成本项目层的金额＝其下费用项目之和，混了翻倍）；委外用 `L:L,"<>是"` 排除、单列一行。

## 怎么保证公式是对的（这是本版最要紧的部分）

openpyxl 只写不算，本机没有 LibreOffice → **公式写出去就没人知道对不对**。
而 V2.290 刚出过一次同类事故（合并后公式指错块，从 V2.279 起错了十来个版本没人发现）。
所以本版先建验证手段，再改公式：

1. 新增 `kernels/xlsx_formula_eval.py`——**极小的求值器，只认本工具实际写出的三种形态**
   （`SUMIFS` / `SUM` / `SUMIF`），认不出就**抛异常**，不许静默返回 None：
   静默会让"没验到"看起来像"验过了"。支持**嵌套**（总计 → 小计 → SUMIFS 三层）。
2. 新增 `kernels/test_export_formulas.py`——合成数据 → 建 res → 出 xlsx → 真算一遍 → 与内核逐格比。
   四条：全簿公式必须都能求值 / 按类别块 8 列一致 / 按仓库块含总计一致 / **合并后引用不得跨块**。

🧪 真数据（107/2026-3）：全簿 **349 个公式全部求值成功**，与内核逐格比 **293 格 0 不一致**；
按仓库总计（三层嵌套）13,155,666.72 / 22,528,853.51 / 23,769,942.35 / 11,914,577.88 与内核完全相同。
全量 **118 测试通过**（114 → +4）。

⚠自查两处翻车、都是**测试自己的问题**不是产品的：
- 求值器不解嵌套 → 总计算成 0（真 Excel 会算），补递归；
- 断言写成"SUM 只能往上加" → 组小计在**组首**、往下加才对，改成"范围必须落在本块之内且不含自己"。
