# V2.373 · 临时工考勤 · 同名风险改用钉钉手机号硬判

**日期**：2026-08-29　**分支**：main

Reginald 指着「张博G / 张博J / 张博J　同名挂在两家及以上派遣方」问：
**「这种我们不是有方案了吗，怎么还会出来」**——问得对，V2.362 的手机号方案只用在
钉钉取数**内部**定人，没有带进复核。

## 做了什么

**把身份证据带进复核**：钉钉取数生成的打卡表多写一列**手机尾号**，
`parse_punch` 读进来，`cross_agency` 优先拿它判：

| 判据 | 结论 |
|---|---|
| 每行尾号都不同 | **确认是不同的人，直接不报** |
| 尾号相同 | 确认是同一个人，再看日期有没有重叠 |
| 没有这一列（人力手工导的表） | 退回原来的弱判据「看打卡行对不对得齐」 |

张博这一组实测：

```
张博G  广才  尾号 3038  ← 另一个人
张博J  锦绣  尾号 9170  ┐ 同一个人，小料 + 植物肉
张博J  锦绣  尾号 9170  ┘ → 按业务线拆行，正当
结算风险·同名：1 组 → 0 组
```

⚠ **一组里可能同时装着「别人」和「同一个人的两行」**，所以要**先按身份把组拆开再各自判**。
第一版没拆，把三行当一坨，反而升成了高风险——已在代码里写明。

## 顺带修好 + 一处必须讲明的盲区

**① 派遣方识别只认全路径。** `_PK_AGENCY` 要求「临时普工-X人力」，
而钉钉部门树的叶子名是「锦绣人力」，一个都认不出来 → 钉钉取数时「归属不符」全成 0。
改成两种写法都认（`agency_of_dept`），同时保留「…-浮动组」这类调配名目的识别。

**② 但仍有盲区，而且很大：** 离职员工在钉钉查不到部门，
2026-06 有 **215 人**的「归属与打卡不符」这一项**根本没查**。

| | 人力导出打卡表 | 钉钉取数 |
|---|---|---|
| 同名风险 | 1 组 | **0 组** |
| 归属不符 | 70 人 | 39 人 |
| **归属无法核对** | 0 人 | **215 人** |
| 结算风险合计 | 71 项 | 39 项 |

**39 < 71 不是情况变好了，是少查了 215 人。** 新增统计「归属无法核对人数」，
结算风险页顶用红字写明：「**不是没问题，是没查**；要查这一项请改用人力导出的打卡表」。

> 这类「少查了却显示成变好」的错最危险——数字往下走，人会以为是好事。
> 参见 [[feedback-say-what-you-dont-know]]：没查和没事是两回事。
