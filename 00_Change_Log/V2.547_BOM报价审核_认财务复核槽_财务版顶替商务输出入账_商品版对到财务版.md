# V2.547 · BOM报价审核：识别「成本核算表（财务复核）」槽——财务复核发现问题时，台账以财务复核版入账，商务输出降为采购原始参考，商品版对到财务版

**日期**：2026-09-09　**业务方给单**：202609081051000020869（黑豆嫩豆方（香茅青椒风味）CP13118103）「这种就属于是我们财务复核出来有问题，输出了财务版本和商品版本」。业务方澄清：**财务复核版和商品版本其实是同一个财务版，商品版就是它的脱敏形态**。

## 病象（改前）

钉钉「BOM表报价」表单除了`成本核算表（商务输出）`「商品版本」，还有一个`成本核算表（财务复核）`槽——成本会计复核商务输出、发现问题、改了数后传上来的**全量财务版**。工具的 `origin_from_label` 只认「商品版」→costacct、「商务」→procurement，**不认「财务复核」**（既不含"商务"也不含"商品"）→ 落到兜底 `procurement`，被当成**第二份商务底稿**。后果实测 20869：

- 成品 CP13118103 **双份入账**：商务输出 37.8784 + 财务复核 38.1517，同一产品两条台账。
- 商品版（38.15，=脱敏后的财务复核）**diff 对到了错的底稿**——拿去跟商务输出 37.88 比，而不是跟它真正的来源财务复核 38.15 比。

## 口径（业务方定）

- **商务输出** = 采购/商务原始底稿（财务改之前）。
- **财务复核 = 商品版 = 同一个「财务版」**，一个全量、一个脱敏（商品版删了 型号/规格/供应商 三列）。
- 同产品既有商务输出又有财务复核 → **台账以财务复核版为准**（＝传回的财务版），商务输出降为「采购原始」参考差异挂旁边、**不再单独入账**（原件下载里一直都有，可追溯）。
- 老流程（只有商务输出+商品版、没有财务复核）**不动**：商务输出就是那份全量底稿，商品版是它的脱敏。

## 改

- **kernel** `origin_from_label`：新增 `财务` → 来源方 `finance`（财务复核版）；`ORIGIN_LABELS["finance"]="财务复核版"`。判定序：商品版→costacct、财务→finance、商务→procurement。
- **router** `_stage_files`：解析后加**财务复核顶替商务输出**——同产品（先 CP、退身份键）既有 finance 又有 procurement 时，把 procurement 的全成本+五分项存进 finance 记录的 `rawProcurement`（采购原始参考），并把 procurement 从入账池移除；数值有变则 `warnings` 报「财务复核改了商务输出：全成本 X → Y」。商品版随后自然配到 finance 底稿（==商品版，diff 为空、不弹「采纳商品版」）。
- **持久化**：`db` 加 `raw_version` TEXT 列（+迁移+`_BOM_JSON_COLS`）；入账写 `raw_version=it.rawProcurement`；`_entry_view` 回 `rawVersion`。
- **前端** `BomPrice.jsx`：来源方色卡加「财务复核版」（绿，`bom-org-fin`）；详情页「数据来源」下多一行「采购原始 37.88 → 财务复核 38.15（成本会计已改 +0.27）」。

## 测

- **20869**（有财务复核）：成品入账 **1 条**、origin=finance、full=38.1517；warning 报 37.8784→38.1517；rawVersion 全成本 37.8784、原料 20.77；商品版无 diff。✅
- **251965**（也有财务复核）：三产品全 finance，full=39.1767/30.9851/46.0813——正是 V2.515 记录的「财务复核版分毫不差」的数。✅
- **105116**（老流程，无财务复核）：全 procurement、rawVersion=None、无双份入账，读取路径不显采购原始行。✅
- V2.540 手动指认上游回归 ALL PASS。
