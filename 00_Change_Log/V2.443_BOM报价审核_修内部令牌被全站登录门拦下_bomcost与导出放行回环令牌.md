# V2.443 · 修：BP 内部令牌请求被全站登录门 401「未登录」——`_auth_gate` 对 `/api/bomcost/*`、`/api/bom/export/*` 放行回环令牌

**日期**：2026-09-05　**分支**：main　**性质**：热修（用户服务器联调实测暴露）

## 现象

用户按手册在服务器配好 `BOMCOST_INTERNAL_TOKEN` 后：

```
curl -H "X-Internal-Token: …" http://127.0.0.1:8000/api/bomcost/final  →  {"ok":false,"msg":"未登录"}
```

「未登录」不是 `/api/bomcost/final` 自己的文案（它回的是「未授权：需 X-Internal-Token…」）——说明请求**根本没到路由**。

## 根因

`app.py` 的 `_auth_gate` 中间件：除 `_OPEN_API` 白名单和报表取件通道（`_PULL_PATHS` + `X-Pull-Token`）外，所有 `/api/*` 未登录一律 401。V2.439 在路由层做了 `_internal_or_user`，**却没在登录门开口**，令牌请求先被门拦下。
本机验证时用 TestClient 只挂了 router、没挂中间件，所以没暴露。**教训：涉及鉴权通道的接口，必须用整个 app（含中间件）联测，不能只测路由。**

## 修法

- `routers/bom_quote.py`：抽 `internal_token_ok(request)`（令牌一致 **且** 回环来源；空令牌恒 False）；`INTERNAL_PATH_PREFIXES = ("/api/bomcost/", "/api/bom/export/")`；`_internal_or_user` 复用。
- `app.py _auth_gate`：`p.startswith(INTERNAL_PATH_PREFIXES) and internal_token_ok(request)` 才放过登录门（与取件通道同一写法）；到路由后仍各自再验（导出只准已审核版）。**其它路径带令牌照旧 401**——爆炸半径只有这两组接口。

## 验证（整个 app 含中间件，TestClient 指定 client 地址）

| 用例 | 结果 |
|---|---|
| 回环 + 正确令牌 `/api/bomcost/final` / `pending-final` | 200 |
| 非回环 + 正确令牌 | 401 |
| 回环无令牌 / 错令牌 | 401 |
| 回环 + 令牌 `/api/bom/export/pretty`（不存在的 id） | 404（已过门、到路由） |
| 回环 + 令牌打非前缀路径 `/api/bom/ledger` | 401（不放行） |

## 用户侧

部署后重跑手册第 4 步 curl 即可；`.env` 不用改。
