**【银行对账】上行取件机 ini 容错——剔除控制字符，兼容任意编码存法**。
**起因**：真机（取件机）部署时 `bank_pull.ps1` 跑到发请求那步报 `[X] 连不上服务器 …：指定的值含有无效的控制字符。参数名: value`。
根因：用户用记事本存 `bank_pull.ini` 时选了「Unicode」(=UTF-16LE)，脚本按 UTF-8 读，每个 ASCII 字符后夹一个空字节(\0)，
`pull_token` 变成 `z\0e\0n\0g\0…`；Trim() 不去 \0，塞进 HTTP 请求头 X-Pull-Token 时 .NET 抛「无效控制字符」。
**改法**：两个脚本读 ini 时对每个值（.ps1 对每行）**剔除所有控制字符** `[\x00-\x1F\x7F]`（.py 保留 \t\r\n 外的控制字符剔除、
再交 configparser）。这样 UTF-16 被读花的值 `z\0e\0n\0g` → 清成 `zeng`，且对正常 UTF-8/ANSI 无副作用——不再要求用户记得存对编码。
**验证**：本机造 UTF-16(Unicode) 编码的 ini 复现真机故障——改前 `bank_pull.ps1` 报「无效控制字符」，改后同一 ini 报
「无法连接到远程服务器」（因测试端口 9999 不存在），证明 token 已被正确清洗、请求头正常，换真服务器即通。ps1 保持 UTF-8 BOM、语法过；py 语法过。
**遗留**：真机重新拉取本版 `bank_pull.ps1` 后，用现有（哪怕 UTF-16 的）`bank_pull.ini` 直接跑即可；后续填对 server/token/src_root 手工验证一轮 → 注册每小时任务。
