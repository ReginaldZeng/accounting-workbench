# V2.532 · 给 BP 的采购核算表链接带 full=1：主管理员在 BP 侧原地看全量（服务端按「看的人」判，普通 BP 仍脱敏）

**日期**：2026-09-08　**业务方问**：「BP 那边核算表，我也只能看脱敏版本吗？」

## 原因

`_bp_links` 生成的 previewUrl / downloadUrl / sheetUrl **没带 `full=1`**，所以即便主管理员用门户登录态打开（iframe / 下载都同域回核算），`_bp_sheet_entry` 的 `want_full=False` → 一律脱敏。之前以为要 BP 后端接 `X-On-Behalf-Of`，其实 iframe 走的是**门户登录态**（不是内部令牌代拉），核算侧 `_current_user` 直接认出登录人，只差 URL 里的 `full=1`。

## 改（只核算侧本仓库）

`_bp_links` 三个链接都带 `&full=1`。服务端 `_bp_actor` 仍按**实际打开链接的人**判：主管理员或有 `bom:view_full` → 全量（供应商/型号/规格/物料编码都在，文件名「全量版」）；普通 BP 用户 `full_ok=False` → 照旧脱敏（文件名「脱敏版」）。安全闸在服务端，不在 URL。内部令牌代拉路径的 `X-On-Behalf-Of`（V2.452）不变。

## 实测（沙盒 v472）

同一个 downloadUrl：主管理员拿到「全量版」xlsx（含家乐/鸿禧等供应商、型号），普通 BP 拿到「脱敏版」（无供应商/型号）。
