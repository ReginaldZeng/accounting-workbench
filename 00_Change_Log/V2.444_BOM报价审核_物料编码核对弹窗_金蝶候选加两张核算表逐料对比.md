# V2.444 · 物料编码「核对」改弹窗：金蝶候选 + 与同编码/同 CP 的另一张核算表逐料对比（用量·价格）

**日期**：2026-09-05　**分支**：main　**业务方提**：「点核对应该跳弹窗，内容是两个 BOM 用量对比；有核算表的话把价格对比也放出来。」

## 为什么

V2.441 的「核对」只在右栏内联列金蝶候选和一个「已挂 CP07118902-2」标签。真机一看，空白袋（CP07118902）和印刷袋（CP07118902-2）共用物料编码 300600105、金蝶登的却是 CP07118902-1——三个码对不上，光看标签判不出**是同一产品的新旧版（该替代）还是两个并存产品**。要看两张核算表到底差在哪。

## 做了什么

- **后端** `GET /api/bom/erp-lookup` 加 `sameCode[]`＝台账里与本记录同物料编码的其它有效记录（`entryId/cpCode/productName/status/erpCode/calcDate`）；金蝶候选的 `inLedger[]` 同样补齐字段。
- **前端 `CompareEntriesModal`**（右栏「核对」/ 无码面板「已挂 CPxx ›」/ 审核定稿弹窗换码候选「对比 ›」三处入口）：
  - ① 金蝶物料档案候选（同 V2.441，可直接「采用」）；
  - ② 对比对象＝同物料编码（sameCode）∪ 金蝶候选已挂（inLedger）∪ 同 CP 换码候选（obsoleteCandidates），多条切页签；
  - 五分项并排（本单 / 对方 / 差，红涨绿跌）；
  - **逐料表**：段 · 物料 · 编码 · 本单/对方添加量 · Δ量 · （两边都有 BOM 清单时）本单/对方 BOM 用量 · 本单/对方含税价 · Δ价 · 本单/对方成本不含税 · 判定（一致 / 用量不符 / 价格不同 / 用量·价格不同 / 仅本单 / 仅对方），差异排前；
  - 对齐口径同后端 `compare_bom`：真实编码优先（「XX系列」占位不算）、退名字、每条只配一次。
- 弹窗只看不改：换编码点「采用」，判新旧版在「审核定稿」答「原版是否失效」。套在审核定稿弹窗里时点背景/Esc 只关子弹窗。
