# V2.362 · 临时工考勤 · 重名的人靠手机号分辨，定人结果交成本会计复核

**日期**：2026-08-29　**分支**：main　**接** V2.354（钉钉直接取打卡）

## 起因

V2.354 上线后，Reginald 指出两点：重名的人**能不能用手机号或 ID 代替姓名来分辨**，
以及**无论工具怎么自动定人，都要提示出来给成本会计复核**。

后一条是当时的真缺口——页面上只显示「46 个重名的自动定了人」一个数字，
工具替人做了 46 次选择，却没有任何痕迹可查。

## 能不能用别的标识

| 标识 | 汇总表侧 | 钉钉侧 | 结论 |
|---|---|---|---|
| 工号 | 无 | **临时工没有工号**（在职样本 0/25、离职 1/20） | ✗ 走不通 |
| 手机号 | 无 | **智能人事 `sys00-mobile` 能给**，在职离职都有 | ✅ 用它 |
| 钉钉 userid | 无 | 有 | 只能内部用，人核不了 |

`user/get` 不返回 mobile，只有智能人事那个口给。实测覆盖 **101/102 个候选（99%）**，
全公司抽 600 人 **零重号**，可以当唯一键用。

## 改了什么

**① 手机号相同＝同一个人，合并打卡（这是个真缺陷）**

2026-06 的 46 组重名里，**8 组两个候选手机号完全相同**——那不是两个人，
是同一个人在钉钉有两个账号（离职再入职会新建 userid）。
原来的做法是 F1 二选一，**另一个账号那几天的打卡直接丢了**。现在合并。

```
冯必志  4784→155****1163   0033→155****1163   ← 同一个人
```

**② 手机号不同的才是真重名**，仍按「打卡日 vs 汇总表上工日」F1 定人，
但手机尾号一起带出来，让人能核。2026-06：37 组真重名、8 组同一人、1 组缺手机号。

**③ 定人结果摊开复核**（本次的重点）
- 页面：可展开的表格，逐行列出**选中谁（手机尾号）、当月打卡几天、命中几个上工日、吻合度、
  没选的候选各是什么样**；定不了的标红、吻合度 < 0.8 的标黄提示重点看。
- 生成的打卡表加第二页 **「重名定人·待成本会计复核」**，同一份底稿跟着文件走，可打印存档。
  `parse_punch` 只读第一个工作表，加这一页不影响解析。

```
丁菊华  已定人  候选1 尾号9276  打卡6天   命中上工日6/6  吻合度1.00  ✔选中
                候选2 尾号2969  打卡26天  命中上工日6    吻合度0.38
冯必志  已定人  候选1（同一人的2个账号已合并）尾号1163  打卡16天  命中15/15  0.97  ✔选中
```
