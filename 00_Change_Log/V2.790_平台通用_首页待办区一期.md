# V2.790 平台通用：首页待办区一期（确认书 v1.0 + 样机 + 实现）

日期：2026-10-04

**起因**：工具线越来越多，「我做完了、轮到你审」这个交接点每条线各做各的（汇率=钉钉+邮件、物流计提=存草稿、付款做账=提交凭证、计提更正=打印更正单），消息发出去就没了，没有一处能看「我名下还有几件没审」「我交上去的审了没」。用户提出要一个待办区（待办=做完后要指定的人去审/去办），并让盘点哪些活适合进数字员工办公室。

**用户 2026-10-04 定的口径**（确认书 D2–D4、D12、D13）：

1. 汇率写金蝶后进首页待办；邮件和钉钉照发。
2. 在金蝶里审的几类，系统回读金蝶单据状态自动销账，不让人在工作台再点一次；接受销账滞后一个核对周期。
3. 指定人按环节固定配人，在设置里维护。
4. 问候区右侧「已开通页面进度条 + 当前期间 + 是否封存」整块去掉，原位置放待办提示（两个数）。
5. 待办清单默认收着，点了数字才展开。

**改法**：

- 新增 `backend/todo_store.py`：新表 `todo_item`（自带 MetaData，导入时 create_all，只建不改既有表）+ 记一笔 / 撤回 / 办结 + 处理人设置（settings 键 `todo_assignees`）。待办记环节不记人，挂给谁每次读时按设置现算；没配处理人回落主管理员并写明。
- 新增 `backend/todo_scenes.py`：四个环节的 `xxx_touch()`（按源头台账现算：有就挂、空了就撤，全部吞异常只留痕）与核对逻辑。金蝶连不上/报错一律不改状态，只记「这次没核对成」。
- 新增 `backend/routers/todo.py`：`/api/todo/mine|check|close|void|config` + 每 20 分钟核对线程（sqlite 本机库不起）。`app.py` 加 include。
- 四处交接点各加一两行：`routers/fxrate.py`（手工写入、定时写入、撤销）、`routers/logistics_accrual.py`（一键录入、撤销）、`routers/logistics_voucher.py`（写入金蝶后；`_fixes` 带上更正行 id，posted 记录里加 `fix_ids`＝这张凭证合进了哪几笔更正）、`routers/logistics_review.py`（登记/撤掉计提更正）。
- 前端：`views/Home.jsx` + `home.css`（问候区右侧待办提示、点了才展开的清单、手动办结/作废弹框；去掉进度条与期间）、`components/Sidebar.jsx` + `sidebar.css`（首页角标）、`App.jsx`（取待办，首页与侧栏共用一份）、`api.js`、新增 `views/TodoAssigneePanel.jsx` 挂进 `Settings.jsx`。
- `notifier.py` 头注补一句：那里的「不做待办」指通知渠道不走钉钉待办，这条不变。——**订正**：确认书初稿把它读成了「汇率不进待办」并写成要推翻，核代码后发现读岔了，确认书 D2 已改。
- 文档：`01_Current_Deliverables/docs/20261004_首页待办区/` 确认书 v1.0（含第十三节实现与验证记录）+ `prototype/home_todo.html`。
