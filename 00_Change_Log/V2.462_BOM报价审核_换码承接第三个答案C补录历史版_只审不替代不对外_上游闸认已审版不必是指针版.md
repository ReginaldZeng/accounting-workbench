# V2.462 · 换码承接第三个答案「C 补录历史版」：只审不替代、不动定稿指针、不对外；上游闸改认"已审版"而非"指针版"

**日期**：2026-09-06　**场景**（业务方截图）：定稿 240399 的酱（2025-12-03，39.39）时，弹窗列出 522031 的酱（2026-01-22，64.99）已初审。A「原版失效」会让**新版失效、老成本对外**（BP 拿到 39.39）；B「并行」也不对——这是同一个酱的新旧两版。补录历史单时缺一个答案。

## 语义

| 答案 | 含义 | 定稿指针 | 对外 |
|---|---|---|---|
| A 原版失效 | 本版替代原版 | 指本版 | 本版（终审后） |
| B 并行但关联 | 同一产品并行版本 | 各自 | 都对外 |
| **C 补录历史版** | 本版比现有版本更早，只为让同单下游能定稿 | **不动**（留给现在的当前版） | **不对外** |

## 落法

- `bom_quote_entry.historical`（INTEGER）+ 迁移；`classify` / `finalize` 接 `historical=true`：盖初审戳、清失效字段、**不 set_final、不标失效、不并行**；留痕「补录历史版」；返回 `historical`。
- `_obsolete_candidates` 跳过历史版（它不对外、不参与替代）；`_entry_view.historical`。
- **上游闸改口径**：`_upstream_status` 回 `reviewed`（初审/已审核，含历史版）；`_upstream_block` 看 `reviewed` 而不是 `isFinal`——上游那版**审过即可**，不必是对外指针版（价格仍要对得上）。文案「尚未定稿」→「尚未审核」。
- 前端：弹窗第三个按钮「C 补录历史版（只审不替代）」；本版核算日期早于候选时红字提示「多半是补录历史单，建议答 C；答 A 会让新版失效、老成本对外」并高亮 C；候选卡显示核算日期；详情标题挂「历史版·不对外」标；上游表已审历史版显「已审·历史版」。

## 验证

scratch（7 单链路库）：240399 酱答 C → 状态初审、指针仍在 522031 版、`historical=1`、不进候选；240399 半成品上游「已审·历史版」价格对上、可定稿；feed 仍只发指针版；答 A 路径不变。前端 build 过。

## 对使用者

补录历史单：老版复配料/半成品答 **C**；当前版（最新那单）照常答 A 或不问。上游闸只要求"上游那版审过"，不再要求"上游是对外指针版"。
