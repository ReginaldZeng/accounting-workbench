# V2.297 · 存货台账 · 基础资料页仓库表分页

**日期**：2026-08-14　**作者**：Claude / c　**线**：main（存货台账）

业务方看「基础资料」页：**「这个应该和其它工具一样，分页吧」**。

对——143 个仓库一次全铺出来，要滚很久才能翻到底，而工具里别处（收发存明细、电商剔除明细）
早就是分页的。同一个工作台，同类表两套手感，是不该有的不一致。

## 改法

第③块「仓库 → 类型 对照」表加分页：**每页 50 个**，措辞与手感照 EcomSettle 那套
（`筛出 N 个仓库 · 第 x / y 页（每页 50 个）` ＋ ‹上一页 / 下一页›）。

**纯前端分页**，不动接口：仓库对照是一次性全量拉回来的小表（百来行），
不像收发存明细那样需要服务端筛+分页。

两处容易翻车的地方，都处理了：

- **切筛选条件回到第 1 页**（`q` / 类型切片器 / 只看新仓库）——
  否则会停在第 3 页却只剩 1 页数据、看到一片空白（同 CostLedger 明细页那条注释里记的坑）；
- **翻页不丢改动**：编辑中的 `map`/`notes` 是整表共享的 state，
  第 1 页改完翻到第 3 页再存，两页的改动一起提交。
  但**光"不丢"不够**——人看不见就会以为丢了，故分页条上补一句
  「有 N 处未保存的改动（可能在其它页，保存时一并提交）」。

## 影响面

只动 `CostLedgerWh.jsx` 一个文件的第③块；类别↔科目对照、仓库类型切片器、保存逻辑一律未动。
前端已构建。
