# V2.383 · 临时工考勤 · 切不出班次时别硬凑一个「跨度」

**日期**：2026-08-29　**分支**：main

Reginald 指着黄寒寒 6/9 那行问「这是为啥」：

```
9日   上班 00:15   下班 20:03   次数 4   跨度 0   上报 0   重算 0   ◇有打卡·当天未计临时工工时
```

上班到下班隔着 20 小时，跨度却是 0——**自相矛盾**。

## 数据本身没错

```
 8日  19:51                          ← 上夜班
 9日  00:15  00:42  08:32  20:03
10日  20:05                          ← 又上夜班
上报：8日 11、10日 11、11日 11 —— 9 日人力没记工时
```

9 日那四张卡**分属两头**：前三张（00:15/00:42/08:32）是 **8 日夜班的下班卡**，
8 日那行已经把它们算进去了（19:51 → 次日08:32 ＝ 在厂 12h）；
最后的 20:03 是一次**没有下班卡**的刷卡。所以 9 日切不出完整班次，重算＝0，人力也没记工时——
判「有打卡·未计工时」是对的，也不涉及钱。

## 错的是显示

「上班/下班」两列在切不出班次时退回显示**当天首末两张卡的原文**，
于是把前一班的尾巴（00:15）和一次孤立刷卡（20:03）拼成了一行；
而「跨度」用 `if sh else 0.0` 填了个 0。**拿首末算出来的跨度既不是在厂时长、也不对应任何一个班。**

两处改：

- 跨度改成 `None` → 页面显示「—」，不再摆一个假的 0
- 判定后面把原因说出来：

```
◇ 有打卡·当天未计临时工工时（当天 4 次卡分属前后两个班，切不出完整班次）
```

全表 1,632 行里这样的有 21 行（1.3%），都是中性档、不标红、不涉及金额。

> 「没有值」和「值是 0」是两回事。用 0 去填一个算不出来的量，看起来像有结论，
> 实际把「我不知道」伪装成了「答案是零」。

内核测试 114 条全过。
