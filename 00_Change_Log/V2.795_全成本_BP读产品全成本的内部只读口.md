# V2.795 全成本：给 BP 工作台读产品全成本的内部只读口

日期：2026-10-04

## 背景
BP 工作台「STEP6 现金流」每月要人上传成本会计的《产品实际成本表》。用户（2026-10-03）：「我想将 S6 改为自动取数与分析……
所有成本的全成本替换上传的全成本表」。BP 侧「从核算同步全成本」已经上线（BP V2.574 / V2.578），就等这边给一个它读得了的口子——
全成本页面自己的接口要登录、要权限点，BP 后端读不了。用户 2026-10-04：「你来」（同意推核算主干）。

## 改动（只加接口，不改任何既有行为）
- 新文件 `routers/bp_actual_cost_feed.py`：`GET /api/internal/bp-actual-cost?org=107&period=YYYY-MM`
  - 只读、不取金蝶、不重算：把全成本存在 `period_inputs` 里的本期状态（`actual_cost:latest`）、那次取数的结果快照（`ac:r:…`）、
    结账确认（`actual_cost:close`）取出来，整理成 BP 要的样子。
  - 返回：状态（`ready` 正式 / `needs_confirmation` 试算；其余状态只给原因、不给产品行）、是否正式（`ready` 且当前有效的结账确认
    就是这份快照出表时用的那一份，撤销或改依据后不算）、取数时点、规则版本、确认人、待办、控制数、无产出的在产调整、产品行、
    一个指纹（BP 用它判断「同步之后这边又出了新结果」）。
  - 产品行 = 车间 × 物料：完工数量 + 各成本要素**总额**（元，不含税）：material / packaging / labor / indirect / water / power /
    gas / depreciation / rent / other / subcontract / wip / total。委外行（车间「委外」）照给；V2.789 之前的老快照没有
    `subcontract`，按 0 给。
  - **不 import 全成本的代码**（`kernels/actual_cost`、`actual_cost_service`），只认它的存储约定。本期没取过数时返回
    `not_generated`、产品行为空，不报错。
- `app.py`：注册这个路由（两行，跟在 V2.785 `bp_logistics_feed` 那两行后面）。登录门对 `/api/internal/bp-*` 的放行是 V2.728 已有的，不用动。
- 鉴权同 `/api/internal/bp-identity`、`bp-logistics-lines`：仅 BP 后端同机回环 + `X-Internal-Token`（`BOMCOST_INTERNAL_TOKEN`）。不对浏览器开放。

没有动 `routers/actual_cost.py`、`actual_cost_service.py`、`kernels/actual_cost.py`（另一条线当天在密集改它们）。

## 自测
- 桩模块顶替 `core` / `bom_quote`，对纯函数 `build_feed` 和路由逻辑 16 项全过：无令牌 401；账簿 / 期间参数非法 400；试算给产品行、
  非正式；`ready` + 结账确认一致才算正式，确认撤销后不算；依据已改（`needs_inputs`）不给产品行；没取过数的月份 `not_generated`；
  委外行带 `subcontract`；老快照没有该项按 0；带不带委外、试算与正式的指纹都不同。
- 服务器只读验证（上线前）：用线上当前的全成本代码空算 2026-08（金蝶重新取数 → `prepare`，不写库），再过同一个 `build_feed`：
  79 个成本对象、合计 26,401,179.29，与用户当天 14:13 试算存下的快照逐行一致；8 月没有委外行。
- BP 侧用这份结果在服务器库副本上空跑：与用户上传的 8 月《产品实际成本表》比，73 个 车间×物料 里 43 个逐要素一致，其余 30 个只是
  「制造费用-其他」在小料 / 植物肉车间之间差 65.20 元（净差 0）+ 折旧 0.94 元；同步后 BP 现金流毛利 +17.45 元。

## 部署
纯后端，随 main 自动部署后重启生效。服务器 `.env` 已有 `BOMCOST_INTERNAL_TOKEN`，无需新配置。BP 侧已在线上等这个口。

## ⚠ 给以后改全成本的人
BP 那边把这里给的产品行**按列对应**存成它的全成本表（列对应写在 BP `app/hesuan_cost.py` 的 `FIELD_MAP`）。
产品行以后再多一个成本项（像 V2.789 加 `subcontract` 那样）时，本文件的 `_NUM` 和 BP 的 `FIELD_MAP` 要一起跟——
否则新项带不过去：`total` 仍然对，但 BP 那边要素之和会对不上合计并告警。委外行 BP 目前单列、不进它的全成本表
（它的现金流对委外产品按销售成本倒推），委外加工费要不要进现金流待用户定。
