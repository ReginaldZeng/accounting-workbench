# V2.364 · 临时工考勤 · 合同价加「当前状态」「合计」两组列，导入认得出改过的表头

**日期**：2026-08-29　**分支**：main　**接** V2.363（合同价导出导入）

Reginald 用起来提的三条，导出和网页都改：

## ① 当前状态：生效中 / 已失效（灰底）/ 未生效

判据相对**今天**——跟「本期生效」不是一回事，那个相对所选期次。

```
今天 2026-08-29
  新家·普工 2026-12-01 ~ 至今                        → 未生效
  旧家·普工 2026-01-01 ~ 2026-06-30（手填）           → 已失效
  锦绣·普工 2026-01-01 ~ 2026-07-31（被下一条顶掉）   → 已失效
  锦绣·普工 2026-08-01 ~ 至今                        → 生效中
```

**已失效的行不能删**——历史期次要按当时的价核，删了那几个月就没价了。
但摆在一起容易被误当成还在用的价，所以：
- 导出：整行打灰底（`D9D9D9`）；未生效的用斜体灰字
- 网页：整行压灰 + 状态列标 `✖ 已失效`，未生效标 `○ 未生效（X 月 X 日才起算）`

顺带把算出来的「实际失效日」也导出去了——手填的和被下一条顶掉的，现在一眼分得清。

## ② 合计两列（白班·合计 / 夜班·合计）

员工工资 ＋ 管理费 ＝ 结算表上那个含管理费单价。做成 **Excel 公式**（`=IF(COUNT(C3:D3)=0,"",SUM(C3:D3))`），
改了分项自动跟着变。

**导入忽略这两列**。实测过：把合计改成 999、分项不动，导入判「不变」，
不会把 999 当成单价写进去。理由是只改合计不改分项时，两边对不上，
以哪个为准都是猜——不如明确只认分项，并在说明页写死。

## ③ 导出的表头改成使用者那个排法

**指标在上、班次在下**（`员工工资⏎白班`），备注挪到最右，当前状态紧跟失效日。
表头行开自动换行、行高 32，两行字才显示得出来。

原来是「白班·员工工资」这种前缀写法——使用者自己动手改了一版发过来，
说明那个排法更顺眼。既然照着改了，导出就直接出成那样，省得每次导出都要重排一遍。

## ④ 导入认得出改过的表头（这条最要紧）

使用者会照自己习惯改标题。原来按整串名字匹配，一改就找不到单价列，
整表还会被报成「白班、夜班一档单价都没填」——**比直接读不出文件更误导人**。

改成**按词判**：认「白班/夜班」+「员工|工资 / 管理」的组合，
「归属」「供应商」当派遣方，「工种」当岗位，「到期」「终止」当失效日……
「实际失效日」「当前状态」「录入人」「合计」这几列一律不看（都是算出来的）。

实测：把表头改成 `归属 / 工种 / 员工工资⏎白班 / 管理费⏎白班 / 员工工资⏎夜班 / 夜班·管理费 / 合同生效日 / 到期日`，
8 行**全部认出且判「不变」**——改了表头也不会误改一格。

页签也不再认死名字，改成「哪一页同时有派遣方和生效日就用哪一页」。

往返实测：新表头导出 → 原样导回，3 行全判「不变」，一格不误改。

内核测试 113 条全过。
