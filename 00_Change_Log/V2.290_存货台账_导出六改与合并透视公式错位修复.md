# V2.290 · 存货台账 · 导出六项修改 + 修合并透视里公式错位的老 bug

**日期**：2026-08-13　**作者**：Claude / c　**线**：存货台账（cost-ledger-blockers）

业务方看完 V2.289 的包，一口气提了六条。逐条落地，外加过程中逮到一个 V2.279 就存在的错数 bug。

---

## ⓪ 意外收获：汇总透视里的合计**一直是错的**（V2.279 起，已随包发出）

做第④条时读合并逻辑才发现：合并是把源页单元格**原样搬**过去的，公式里的**相对引用没有跟着重算**。

```
汇总透视!B149 = SUM(B2:B40)      ← 「费用项目构成」块在第 108 行往后，
                                   合计却去加第 2–40 行（那是上面「按类别/按仓库」块的存货类别文本列）
```

源页「费用项目构成」单独看是对的（`=SUM(B2:B40)` 在它自己那张页上没问题），
一合并就错——**而源页合并后就被删了，没人能拿它对照**，所以一直没被发现。

修：合并时用 `openpyxl.formula.translate.Translator` 按新坐标重算引用。
🧪 现在是 `B155 = SUM(B116:B154)`，116 正是该块第一行数据。

**教训**：搬运带公式的单元格，等于搬运一组坐标假设。只搬值不搬上下文，就是错数。

## ① 元数据三行改黑字

原先元数据用灰 `5A616D`、留痕用更浅的 `9298A4`，本意"这不是数据"，
实际观感是**像被划掉的废话**——而它恰恰是判断"这份数是谁、哪个期间"的依据。改全黑。

## ② 按日期表列序订正（业务方说"漏了批号/库存状态/单位"）

先核实：那三列**在**（第 6/7/8 列，实测批号 2022 / 库存状态 可用 / 单位 张，2,769 行全有值）。
但顺着去比金蝶原件，比出了**真问题**——列序不对：

```
金蝶原件《成本X月（按时间）》 17 列：物料编码｜物料名称｜物料分组｜规格型号｜存货类别｜期初…
工具原先                          ：物料编码｜物料名称｜规格型号｜存货类别｜物料分组｜批号｜库存状态｜单位｜期初…
```

这页存在的理由就是"跟金蝶导出来的一样"，列序错了就不算原样（同 V2.287 跨维度那次）。
改成**前 17 列与原件逐列对齐**；批号/库存状态/单位金蝶原件没有（导出时那几个开关没打开），
接口能取到且对查批次有用，故**附在 17 列之后**，不打乱原件列序。页脚写明这三列的来历。

## ③ 成本计算单原表加留痕 + 接口版退休

- **留痕加在数据末尾之后**，不加顶上：这页的契约是"与原表逐格相同"，
  放顶上会把整张表推下一行、比对全错位。放末尾则行 1..N 一格不动。
  🧪 加完重比：**仍是 12,139 行、逐格 0 差异（291,336 格全中）**。
- **接口版「原始·制造费用明细」在传了原表时不再出**（业务方「是不是可以退休了」）。
  两张同源同期、金额分毫不差，只差粒度，并排放只会让人问"看哪张"。
  没传原表时照旧出——否则制造费用一张底表都没有。

## ④ 汇总透视注明来源 + SUMIFS 校验

- 五块**各写一行来源**（哪张原始底表、按什么汇总、口径注意），写在块内跟着一起折叠。
  其中「收发存·按事务类型」如实写明**没有对应的原始底表页**（流水一期十几万行，不落库也不导出）。
- 「按类别」块加末列 **`结存金额·公式校验`**：`=SUMIFS('原始·收发存跨维度'!W:W, …!C:C, B<行>)`。
  🧪 先验后写：8 个类别逐项与 SUMIF 一致（只有"合计"行本身没有对应类别）。
  **取"并排校验"而不是把结存金额本身换成公式**——那一列是核对过、要跟着封存存死的数，
  换成公式就意味着"谁动了原始底表页，台账上的数就跟着变"，封存就白做了。
  现在两个数一眼对上：不一致＝有人动过底表。

## ⑤ 三张收发存的区别（业务方问）→ 写进「核对结论」页

| 页 | 维度 | 用途 |
|---|---|---|
| 原始·收发存跨维度 | **含仓库/批号**，一物料一仓一批一行 | 金蝶原件 23 列原样；留痕、逐仓复核；**上面所有按类别/按仓库的汇总都从它来** |
| 原始·收发存按日期 | **无仓库**，同物料跨仓合并成一行 | 与跨维度**互为校验**——两表四项金额合计相等＝第①道勾稽「两表互勾」 |
| 收发存明细 | 同跨维度的数据 | 列序是**业务方指定的工作列序**（D12），供页面查询与人眼逐行看，**不是原件**；要对金蝶请用「原始·」那两张 |

三张长得像、用途完全不同，不写清楚就会被当成重复数据。

## ⑥ 账实勾稽 / 成本勾稽 / 损益归集 → 并成「勾稽与归集」一页

三张都是"总账侧 vs 业务侧、差多少、结论"，看的时候本就要来回对照。
沿用 D18 的合并口径（行分组、可折叠、**默认展开**），每块注明来源。
顺序＝**存货 → 成本 → 损益**：账实勾稽是能不能出台账的闸，成本勾稽是另一套账，损益归集是归集结果。

合并逻辑顺手抽成 `merge_sheets(title, names, subtitle, notes)`，两处共用。
