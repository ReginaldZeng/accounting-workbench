# V2.992 物流复核台：修「切承运商后表格串上一家数据」的响应竞态

日期：2026-10-18

用户截到（2026-10-18 20:35）：页头「物流账单复核台 · 跨越物流 / 2026年9期」，第③步的 KPI 胶囊和表格却是**迅鸽 2026-08** 的数据（RK 单号、全部 5884、账单合计 33,951.13＝迅鸽计提合计）。

## 根因

`LogisticsReview.jsx` 主表 `load`（reviewResult）和第①步 `loadIk`（reviewIntake）**没有防串单守卫**：`.then(setD)` 无条件写入。

事发现场（服务器 access log，同一 IP 连续请求）：

1. 迅鸽 08（5,884 单）请求发出 → 大承运商路径，响应要算几秒；
2. 用户切账期/进跨越，迅鸽 09、跨越 09 请求接连发出；
3. 跨越只有 11 行，**毫秒级先返回**；
4. 迅鸽 08 的大响应**最后到**，`.then(setD)` 把旧数据盖在新页面上。

同文件其它请求（inv3 的 `off`、ov 的 `alive`、allD 的 `alive`）都有守卫，唯独这两个漏了——纯前端 bug，后端各请求的 SQL 过滤（carrier×period）都是对的。

## 改法

- 加 `_reqSeq`（useRef 序号）：`load` / `loadIk` 每次发出请求前 `++`，响应回来时序号不是最新就丢弃（成功和失败两条路径都判）。
- 一处序号供两个函数共用——切承运商时 intake 和 result 都作废，语义正好一致。

## 验证

- `npm run build` 通过（vite，5.2s）。
- 代码走查：文件内其余 `setD`（第 140/249/422 行）均为弹窗组件局部状态，与本 bug 无关。

## 改动文件

- `frontend/src/views/LogisticsReview.jsx`：`load` / `loadIk` 加响应序号守卫（+`_reqSeq`）。
