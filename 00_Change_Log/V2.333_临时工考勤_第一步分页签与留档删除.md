# V2.333 · 临时工考勤 · 第①步分页签 + 留档可删 + 使用说明

> 需求方看过 V2.320 的界面后：「这里应该不能这样做，起码要分页。比如上传通道，历史复核结果，
> 复核结果有的是测试的，支持删除」。另：「参考成本台账的写法，写说明」。

## 一、第①步拆成两个页签

V2.320 把「已核期次」表和上传区堆在同一屏。**期次只会越攒越多，上传按钮会被一路挤下去**——
需求方截图里已经能看出苗头。改成两个页签：

- **上传核对**——两个文件选择 + 开始核对
- **历史复核结果（N）**——期次表 + 分页器

顺带在上传页签加一句提醒：==选的月份若已有留档，跑完会覆盖它==，跑之前就说，不是跑完才发现。

## 二、留档可删（调试期的试跑数据要能清）

不可逆操作，按三道设防：

1. **权限**：走 `CAP_RATES`（维护单价表那一档），不是人人能删。
   接口另回一个 `可删` 标志，**没权限的人页面上根本不显示删除按钮**，而不是点了才被拒。
   ⚠ 本该单开一个 `tempatt_del` 权限点，但 `db.py` 眼下有平台通用线（V2.321–V2.332）的未提交改动，
   **不去动它**；等那条线并回主干后再拆出来。
2. **二次确认**：页面上删除按钮点一下先变成「删掉 2026-07？不可撤销 [确认删除][取消]」；
   接口再挡一道，必须带 `confirm=` 月份原文。
3. **留痕**：审计记「谁、什么时候、删了哪一期、那一期原本是什么结论」——
   实测记录：`原40人/应付51496.0/2026-08-21 23:58:14由管理员跑批`。

删除会同时清掉该期的**结论**与**原表**；删完那一期就查不到、也导不出报告（实测导出回 400 并说明原因）。

### 顺手修的一个 bug
`_period_dir(month)` 只要月份格式合法就返回路径字符串，**不代表目录存在**。
原来的守卫写成 `if not meta and not _period_dir(month)` 永远不成立，
于是「删一个根本不存在的期次」也会回一句「已删」——读起来像真删掉了什么。改用 `os.path.isdir` 判。

## 三、第①步加使用说明（参照成本台账·存货月结核对的写法）

分三块：**这个工具干什么** / **怎么走** / **四件要先知道的**。四件事挑的是最容易误会的：

1. **这不是重算工资**——「重算」是尺子，付款仍以人力汇总表与合同为准
2. **少记不追，多记才查**——超弹性多记是唯一必须逐笔说明的一档
3. **结算风险比工时偏离要紧**——三查排在工时偏离前面；工具只指认，人来认
4. **结果按期留档**——结论长期存，原表只留最近 N 期（数字从接口取，不写死）

## 四、实测

| 项 | 结果 |
|---|---|
| 匿名调删除接口 | HTTP 401 ✓ |
| 不带 confirm | 「删除需要二次确认」✓ |
| confirm 与月份对不上 | 同上 ✓ |
| 正常删除 | 结论与原表目录同时消失；期次列表少一行 ✓ |
| 删完再读该期 | 「没有留档记录，请上传两张表跑一次」✓ |
| 删完再导出该期 | HTTP 400「请上传两张表，或选一个已留档的月份」✓ |
| 重复删除（修复后） | 「没有留档记录，无需删除」✓ |
| 月份格式非法 | 「月份格式应为 YYYY-MM」✓ |
| 审计 | 内容完整 ✓ |
| 浏览器 | 说明卡渲染正常；页签「上传核对／历史复核结果（1）」可切；删除进入确认态文案正确；分页器每页选项已与组件对齐（50/100/…） ✓ |

内核回归 **187 项全过**（本次不动内核）。
