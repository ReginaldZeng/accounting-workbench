# V2.569 电商收入确认页收口台重排

面向核算组的「收入确认（发货与应收核对）」页重排为收口台，口径与字段全部沿用后端现成结果，不改核算规则、业务数据或金蝶。

## 收入确认页（EcomWorkbench.jsx / ecomWorkbench.css）
- 顶部新增**收口卡**：本期应确认收入（=已发货订单的出库应收合计）、金蝶应收对平/差异数与差异金额、应收待同步金蝶数、待人工介入数——先看「还差多少能收口」。
- 表格改为**语义分带**：身份 / 该确认多少·会计口径 / 应收核对 / 平台费用 / 钱到没到 / 结论。
- 新增 **「应确认收入」主列 = 出库应收**（发货即确认）并加粗高亮；金蝶应收列显示「对平 / 差额」；新增「账户净收」列（含结算状态与去向）；**保留**常规/佣金费率列。
- 主列兜底文案区分：未发货「暂不确认」、未付款关闭「未成交」、已发货未匹配出库「待出库应收」，不再把关闭单误显为待出库。
- 发货日期上表（缺则回退发货状态），创建日期降为次要小字。

## 订单全链路抽屉（EcomOrderChain.jsx / ecomOrderChain.css）
- 顶部新增**三结论**：收入确认 / 应收核对 / 收款核对，各自给「可确认·对平·到账 / 待同步·待补 / 差额 / 不适用·未成交」等结论并按语义着色。
- 新增**三方金额对账**一行：出库应收 → 金蝶应收（差额）→ 账户净收（平台费）。
- 未付款关闭单正确显示为「已关闭·未成交 / 不适用 / 无收款」，不计差异、不进待人工；原证据链与「未取得/不适用」诚实措辞保留。

## 导航
- 五阶段导航**换序**：数据准备 → 总览 → 收入确认 → 收款核销 → 账户流水（准备在前）。
- 导航挂**待办角标**：收入确认显示「应收差异＋待同步金蝶」数，数据准备显示缺资料类数——导航即收口流水线。

## U先分类修复（title_kind，kernels/ec_month_fulfillment.py）
- 确定 U先 的前置括号标由「U先紧贴右括号」放宽为「U先开头、括号内后缀不限」：`【U先】`、`【U先试吃】`、`【U先试用】`、`【天猫U先…】` 均判 `ufirst`；「U先/试用」出现在标题中段（非前置括号标）仍留 `review` 交人工。
- 修复前 `【U先试吃】` 落入 `review`（待确认分类）。本地实测：`review` 1,352 → 0，`ufirst` 13,151 → 14,503，`待人工` 7,039 → 5,687；含 ufirst 与 normal 的订单自动归 `mixed`。
- ⚠ 运维：`_business_index` 在 item 文件解析入库时算定，`save_source` 按内容指纹去重跳过重解析。**已解析的历史期需重新导入「商品与子订单(item)」文件**该修复才生效；新导入自动生效。

## 费目科目映射批量设置 + 模糊搜索（EcomBasicData.jsx）
- 「费目科目映射」表新增行勾选框 + 表头全选；选中后浮出批量条「已选 N 项 → 批量设为 常规费用 / 佣金 / 待分类·非费用」。
- 新增费目码 / 费目名模糊搜索框；「全选」只勾当前筛出来的行 → 支持「搜关键词 → 全选 → 批量设类」一次刷一批。
- 纯前端交互，沿用现有整块保存（`fee_categories` 一次落库、一次重算），不改后端、不改口径。

## 先用后付流水分类规则（kernels/ec_flow_ledger.py）
- `DEFAULT_CLASS_RULES` 补一条默认规则 `cat_xyhf_fee`：支付宝备注含「先用后付技术服务费」+「扣款」→ 归入平台费用（bucket=fee，label=先用后付技术服务费）。此前代码已能从摘要拆出订单号，却无分类规则，故 50+ 笔落「流水收支待分类」。
- 本地实测：重算后「待人工」5,687 → 1,655（先用后付是待分类流水最大头）。规则重算即生效，无需重导流水。
- 规则的常规/佣金分类沿用与猫猫币一致的口径——由用户在「流水分类规则」页一键设为常规（先用后付技术服务费属平台常规服务费）；未设时该单转为「费用分类待设置」。
