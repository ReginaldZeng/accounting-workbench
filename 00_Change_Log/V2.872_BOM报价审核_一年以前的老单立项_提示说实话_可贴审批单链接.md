# V2.872 · BOM报价审核：一年以前的老单立项——提示说实话、可贴审批单链接、记住钉钉内部单号

**日期**：2026-10-08　**业务方**：历史补录立项 `202509231841000398887`，页面只闪了一句「当日该模板未找到编号…的实例（模板或日期窗口可能不对）」。

## 查实的原因

这张单是 **2025-09-23** 发起的，距今 380 天。钉钉没有「按审批编号直接取单」的接口，只能按发起日期列出当天的单再逐个比对编号；而「按日期列单」新老两个接口都只给查**近 365 天内发起**的（2026-10-08 实测：往回 365 天可查；366 天起老接口回 400003「时间戳无效」、新接口回 invalidEndTime）。

原代码把钉钉这句报错吞掉了，显示成「当日未找到」——**「接口不让查」和「确实没有」被说成了同一句话**，而且暗示可能是单号或模板不对，方向是错的。历史补录补的多是老单，这类失败会反复出现。

## 改

- **提示说实话**（`kernels/dingtalk_bom.py`）：
  - 超过 365 天：直接说「这张单是 X 发起的，距今 N 天，钉钉只允许按编号查近 365 天内发起的审批单（不是单号填错）」，并给两条路——贴审批单链接，或下载附件走上传。不再白跑一趟钉钉。
  - 钉钉接口报错：照钉钉原话说「是接口报错，不是确认没有这张单」。
  - 确实没有：说「这一天该模板共 N 张单，没有这个编号」，提示核对单号 / 可能不是 BOM 表报价模板发起的。
  - `list_ids` / `get_inst` 可带回钉钉报错原话（原先静默）。
- **贴审批单链接立项**：立项框里除审批编号外，可贴钉钉里这张审批单的链接（或直接贴内部单号）。系统从链接里认出钉钉内部单号（`procInstId` / `procInsId` / `processInstanceId` 等写法都认，转义过的也认），按内部单号取单——这条路不看发起日期。台账上记的仍是钉钉回的**真审批编号**。乱填的东西会直接说「没认出来」。
- **记住内部单号**：每张单第一次找到后，把「审批编号 → 钉钉内部单号」记进通用设置（`bom_dt_iid:<编号>`）。之后取单、重连钉钉替换、从评论区替换、OA 终审同步都直接按内部单号取：
  - 今天立的项，一年以后还能重连钉钉、还能从评论区替换（原先到期就会全部失效）；
  - 不用每次列出当天所有单逐个比对，快一些。
- **立项弹窗**（`BomPrice.jsx`）：失败原因留在输入框下方（原先只在底部闪一下，长一点的原因来不及看）；输入框提示加「一年以前的老单贴审批单链接」；上传立项时如果框里留着链接会提醒改填编号，免得把链接当单号存；顺手修掉说明文字里露出来的 `**` 星号。

## 测

- 真钉钉 + 本地沙盒库：老单按编号 → 0.5 秒回「距今 380 天…贴链接或上传」；乱填 → 「没认出来」；近一年的单（350508）照常立项、内部单号落库；记过之后把「按日期列单」接口堵死，取单 / 评论区清单 / OA 终审节点状态都照样取得到（模拟这张单以后超过一年），清掉进程内记忆只靠落库的也行（模拟服务重启）；用这张单的内部单号拼成链接立项 → 入账 2、台账单号是真审批编号；瞎链接 → 回钉钉原话「审批流不存在」；单号输错一位 → 「这一天共 2 张单，没有这个编号」。ALL PASS。
- **没验到的**：手上没有一年以前老单的真链接，「按内部单号取一年以前的单」这一步钉钉给不给取，要业务方贴一条真链接才知道；取不到时页面会照钉钉原话报出来，并提示改走上传。
- 构建通过；换行干净（`--numstat` 与 `--ignore-space-at-eol` 一致）。
