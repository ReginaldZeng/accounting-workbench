**【平台通用】模型配置页：添加接入（去写死）**

## 起因

Owner：「我加模型的时候，自己选择工作台，或者选择工作台再添加密钥厂商和模型，现在有点写死的意思」。
此前 ① 区只能给四家预置厂商写 key——厂商清单与工作台都不可扩。

## 改动

| 文件 | 内容 |
|---|---|
| `routers/llm_hub.py` | `POST /api/llm-hub/provider`：代理到工作台 `POST /api/llm/provider`（管理员；key 不落核算日志；audit 记「添加模型接入」；成功失效状态缓存）。未接入 llm 模块的工作台 422 提示先拷 BP `app/llm*.py` |
| `ModelConfig.jsx` | ① 区「＋ 添加接入」表单：工作台下拉（已接入可选；未接入灰显提示）→ 厂商下拉（deepseek/kimi/glm/dashscope/**自定义**）→ 自定义需填厂商名+OpenAI 兼容接入地址+默认模型 → 密钥（password，可留空稍后写）。保存后新厂商卡片自动出现（含打码 key/模型切换器/连通性），后续更换密钥/切模型与预置厂商完全同权 |
| `api.js` | addWorkbenchProvider |

BP 侧配套（BP 台账 **V2.242**，包 2.242/徽标 V2.102）：`llm.add_provider` + `POST /api/llm/provider`
（appSettings 闸）——预置厂商补 key/模型/地址；**自定义厂商**注册 `BP_LLM_PROVIDERS` +
`BP_LLM_{NAME}_BASE_URL/API_KEY/MODEL`（V2.187 多供应商机制留的口子，首次有 UI）。校验：厂商名
`[a-z][a-z0-9_]{1,23}`、自定义必填 http(s) 地址与模型名、key 8~300 无空白。写 .env 原子替换 + 热生效。

## 验证（本机 8000↔8010 全链路）

- 自定义厂商（doubao 示意 + 假 key）→ 注册成功、状态接口第 5 张卡出现（打码 dumm***5678、
  模型 doubao-pro-32k、可切模型可换钥）；预置 kimi 只补 key 通；自定义缺地址 → 422 人话顶回。
- UI：① 区「＋ 添加接入」按钮 → 表单（工作台/厂商下拉、自定义分支字段）→ DOUBAO 卡片渲染。
- 测毕清理假数据（.env 三组行删除 + BP 重启复验回 4 家）。py_compile ×3 / vite build PASS。

## 边界

1. 「选择工作台」只能选**已接入 llm 模块**的（现仅 BP）——UI 无法给没有 /api/llm 接口的系统凭空接模型；
   核算/数字员工接入后自动出现在下拉里（接入路径=拷 BP llm 模块，② 区注有说明）。
2. 自定义厂商必须 OpenAI 兼容（工作台按 `地址 + /v1/chat/completions` 调用）；不兼容的厂商属网关选型议题。
3. key 纪律不变：只写不回显、直达工作台 .env、核算不存不记值。
