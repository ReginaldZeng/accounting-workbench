# V2.427 · git 自动部署收口：deploy.sh 补 rsync+重启 + 版本号扫近 30 条提交（修页脚卡 V2.422）

**日期**：2026-09-04　**分支**：main

Reginald：「做」——把 V2.426 起的 git 自动部署补成真·一键全自动，并根治页脚版本号卡壳。

## 两个根因

1. **rsync 缺位**：生产实际跑在独立扁平目录 `/www/wwwroot/finance_workbench/backend`，与 git 克隆目录 `/www/wwwroot/accounting-workbench` 是两处。旧 `deploy.sh` 只 `git pull` 克隆、没把源码同步进运行目录 → 拉了等于没上线。
2. **版本号只看 HEAD 一条提交**：`core.py._compute_version_info` 与 `pack_deploy.py` 取版本 V 号都只读 `git log -1`。合并到 main 后 HEAD 常是**无 V 号的 merge 提交**，候选落空 → 回退台账片段最大号（BOM 那几版没建片段，最大号停在 V2.422），页脚就卡在 2.422。

## 改动

- **deploy.sh**：`git pull` → `rsync -a`（源 backend → 运行目录，**不带 `--delete`**，另逐条 `--exclude` conf.ini/.env/*.db/*_uploads/sample_data 里的 json 与 db/version_stamp.json——护住运行期数据，绝不覆盖真库/凭据）→ 版本戳写进**运行目录** → 执行 `$ACC_RESTART` 重启。新增 `ACC_RUN_DIR` 变量指运行目录；源=目标时自动跳过 rsync（兼容"直接从克隆里跑"）。
- **core.py / pack_deploy.py**：取版本号改**扫最近 30 条提交标题**取最新 V 号（不止 HEAD），merge 提交不再让号丢失；与 deploy.sh 写戳口径一致。
- **部署手册**：改写为源/运行分离 + rsync 衔接的真实架构（原稿误写"直接从克隆里跑、不用 rsync"）；强调 `ACC_RESTART` 必配（rsync 只换文件不重启）。

py_compile 过、`bash -n deploy.sh` 过。运行期数据零风险（不带 --delete + 逐条 exclude 双保险）。
