# V2.936 付款做账：总表改成「四步」的表；发票管家审核通过才算收票；每行「做账步骤」弹窗

- 作者：Claude Opus 5.5

## 起因

用户看付款做账总表：「感觉这个页面不太对。我们是工作台审核账单，工作台收票，付款成功，才执行自动化做账程序」。
V2.934 / V2.935 先把「账单复核」这道闸补上；页面本身出了样机，一轮一轮改到用户说「可以了」，再看了接进工作台的样子：「开发吧」「发票审核才算」。

样机在 `01_Current_Deliverables/docs/20261013_付款做账四步闸/prototype/`（`voucher_gates.html` v0.9、`voucher_gates_inapp.html`）。

## 规则变了一条：② 收票

- 原来：票夹里有票、含税合计等于请款金额，就算收到票。
- 现在：**每张票都要在发票管家审核通过**才算。票收到了还没审核的，状态是「发票没审核」，人点、自动做账都做不了。
- 发票后补（没票、登记了后补单、复核台第③步确认过）照旧算过。

## 页面：总表换成四步的表

一张请款单一行，按承运商分组（全称 · 金蝶供应商编码 · 简称），从左到右：

| 列 | 上面一行 | 下面灰字 |
| --- | --- | --- |
| 请款金额 | 金额 | |
| 计提 | 这张单要核销的金蝶计提含税合计 | 和请款的差异，有差标黄 |
| ① 账单复核 | 已复核 / 还没复核 | 整月登记哪天，或 本主体通过 哪天 谁 |
| ② 收票 | 已收 N 张 / 票后到 / 没票 | 票种＋审核状态（专票已审核、普票待审核…没审核的标黄）/ 发票后补已确认 |
| ③ 付款 | 已付款 / 等付款 | 金蝶付款单号；往来单位选错的在这里给「改成××」 |
| ④ 做账 | 已做账＋已审核 / 等审核 / 可以做账 / 还不能做 | 制单人 · 期间 凭证号 |
| 最后 | 「做账步骤」按钮 | |

- 前一步没过后面不做，卡在哪一步那一格标黄；图标：过了绿勾、卡住黄叹号、票收到没审核是黄圈三点、发票后补是「补」。
- 上面五个数：可以做账 / 卡在①账单复核 / 卡在②收票 / 等③付款 / 已做账，点一下只看那一类。
- 搜索框：承运商全称 / 简称 / 编码、主体、请款金额、计提数、付款单号、凭证号、审批编号、计提凭证号（8/563#）。
- 金蝶还没出付款单的原来不显示，现在也列出来（账单、票可以先办）。
- 「批量保存到金蝶」挪到搜索框右边；四步都过了、做账类型能批量的那一行前面才能勾。
- 「自动做账」那一条和「做完提醒」那一行原样保留；「明细」视图不动（要看每张计提的费用类型、税率还去那里）。
- 账期：和原来一样，几个月的请款单列在一起，右上角下拉可以只看某个账单月。

## 「做账步骤」弹窗

点开一步一步亮出来，**只放一遍**：先过三道闸，再是系统做的那几步——审核金蝶付款单 → 金蝶自动出付款凭证 → 红冲更正（有才出现）→ 核销转待认证 → 提交凭证 → 指定现金流量 → 收尾。
每一步写这张单自己的数；已做账的放当时做的（带凭证号、制单人），没做的放到时候会怎么做，卡住的停在那道闸，系统做不了的写原因。右下角「凭证预览」打开原来的预览。

## 改动

- `backend/routers/logistics_voucher.py`
  - `_inv_state`：② 收票的判断（审核通过才算）；`_status` 多一种 `invwait`「发票还没在发票管家审核通过」。
  - `_review_info`：① 是怎么过的（整月 / 本主体）、哪天、谁。
  - `_bill_nos`、`_voucher_info`：金蝶付款单号；工作台做的凭证现在的制单人、状态、期间（成批读、带缓存；读不到金蝶不让列表挂掉）。
  - 列表接口每行多带：`review`、`invs`、`inv_state`、`later_ok`、`fkd`、`vinfo`。
  - 做账类型接口多带 `acc_sum`（计提原数的合计）、`acc_n`；预览里每张计提多带 `gross0`（原计提含税数）。
- `frontend/src/views/LogisticsVoucherFlow.jsx`（新）：四步表、五个数、做账步骤弹窗。
- `frontend/src/views/LogisticsVoucher.jsx`：总表那一屏换成四步表；状态里加「发票没审核」。
