## 一、报表取件机：每分钟弹一个黑框，误点就冻住

**现场**：那台内网电脑桌面上叠了一摞空白窗口，同步跟着停了。

**原因在设计**。取件任务必须跑在**登录用户的会话**里——共享盘只在这个会话里存在，
SYSTEM 账号根本看不见。但会话里起的进程默认带窗口，V2.241 直接起 `powershell.exe`，
于是每分钟弹一个控制台。而 Windows 控制台**默认开着「快速编辑」**：往窗口里误点一下就选中
文本、**进程当场冻住**，要按 Esc 才继续。冻一个叠一个，一分钟一个，同步就这么悄悄停了。

**改法**

| # | 动作 | 为什么 |
|---|---|---|
| 1 | 加 `pull_hidden.vbs`，用 `Run(cmd, 0, True)` 隐藏窗口起 PowerShell **并等它跑完** | 没有窗口，就没有"误点冻住"这个失效模式。**等待不能省**——不等的话 wscript 立刻退出，任务以为"跑完了"，下面两条护栏全失效 |
| 2 | 注册从 `schtasks` 换成 `Register-ScheduledTask` | schtasks 给不了下面三条，而这次恰恰翻在这三条上 |
| | · 动作＝wscript 起 vbs | 不再有窗口 |
| | · `MultipleInstances=IgnoreNew` | 上一轮没跑完就不起下一轮，不会越叠越多 |
| | · `ExecutionTimeLimit=5 分钟` | 真卡住（共享盘掉线时 SMB 能吊很久）由系统强杀；不设它默认能挂 3 天 |
| 3 | 安装脚本开头先收残局：只杀命令行里带 `pull_reports.ps1` 的进程 | 不碰用户别的 PowerShell 窗口 |
| 4 | 单次请求超时 120 → 45 秒 | 任务每分钟一轮，单次卡过 60 秒就跨轮了 |

**`.vbs` 必须纯 ASCII**——与 `.bat` 同一个坑：按系统 ANSI 码页读，UTF-8 中文注释会整片乱码、解析失败。

**实测**：桩脚本验过隐藏运行、真的会等 PowerShell 跑完、退出码原样透传（退出码 7 → 7，耗时 3.1 秒 > 桩里的 2 秒）。

## 二、导航状态「开发中」：改为仅指定的人可进入

**业务方要求**：在建的模块，自己要能进去看效果，但别让同事撞见半成品——撞见了就会问
"这个怎么用／怎么报错了"，白白多一轮解释。

原来 `NAV_OPEN = (测试验证, 人工并行, 待验收, 引擎正常)`，「开发中」和「敬请期待」一样全员灰显、
点不动，**管理员自己也进不去**。

**改法**：新增 `NAV_OPEN_ADMIN = ("开发中",)`，`_nav_one()` 加 `dev_ok` 参数：

```python
ok = st in NAV_OPEN or (dev_ok and st in NAV_OPEN_ADMIN)
```

`dev_ok` 由 `core.can_enter_dev(u)` 给：

```
conf.ini [nav] dev_users 有名单 → 只认名单（不论 role）
              留空           → 回落"所有主管理员"（不是"谁都能进"，空名单绝不放行）
```

**为什么名单放 conf.ini 而不是数据库/页面**：这份名单的用途是把范围收得**比主管理员还窄**。
一旦它能在页面上改，任何一个主管理员都能顺手把自己加回去——**那这个限制就等于没有**。
放 conf.ini＝只有进得了服务器的人能改，正好和"指定开发者"这个语义对齐。
（同一条边界：密钥/口令在 conf.ini，非机密设置才进 DB。）

**关键点：`可进入` 从此是【因人而异】的**，不能再当成一份全局静态表。
`/api/nav-modules`（侧栏读的就是它）按当前登录人算；**四个变更端点也改成按人算**——
它们虽然都过了 `_nav_can_edit` 闸（必是主管理员），但主管理员未必在开发者名单里。
**该接口无缓存、前端 `cache:'no-store'`，不会串人。**

**名单会下发前端**（就几个账号名，不是机密），设置页显示"当前可进「开发中」：曾禹锡"，
并对不在名单里的人明写"你不在这份名单里"——否则他只会觉得"这功能坏了"，来问一轮。

侧栏配了显眼标记 **「开发中·仅你可见」**（窄行缩写「在建」）。
不给标记不行：进得去的人看到的会是个"跟正常模块一样"的入口，容易忘了同事其实看不见它，
进而在会上拿它当已上线的东西讲。

**边界没变**：这仍是**上线状态、不是权限**——只管左侧导航点不点得动，**不挡接口**。
真要防人访问，仍然靠「账号管理」里的权限点。设置页两处文案都补了这句。

**实测**：

| 场景 | 曾禹锡（管理员，在名单） | 另一个主管理员 | 普通用户 | 未登录 |
|---|---|---|---|---|
| `dev_users` 留空 | ✓ | ✓ | ✗ | ✗ |
| `dev_users = 曾禹锡` | ✓ | **✗** | ✗ | ✗ |
| `dev_users = 小王`（普通账号） | ✗ | ✗ | **✓** | ✗ |

分隔符逗号／分号／中文逗号／中文分号／顿号均可解析；留空解析成空集。
状态维度：`隐藏`、`敬请期待` 对名单内的人**同样进不去**；`always` 模块（基础数据／系统设置）
恒为引擎正常，不受影响。

## 三、顺带

- **报表导出 ①页**：回执改为**跟着触发它的按钮走**——「立即同步」的回执落在同步那一行下面、
  删除回执落在删除按钮下面，不再统一弹到页顶（点的是页面底部的按钮，结果弹在页顶等于看不见）。
- **报表导出 · 旧散件**：`/files` 带 year/period 查询时也列出根目录散件（按文件名前缀认期）。
  原来取件机不带参数来问会拿到散件、跟着同步到共享盘，而页面带参数来问却看不见它们
  → **共享盘上有、平台里删不掉**（实际发生了）。**凡是同步得走的文件，删除面板就必须看得见。**
- **报表导出 · 通知**：改为**等取件机回报"这批已送达共享盘"之后再发**，正文加「共享盘目录」「同步时间」。
  导完就发的话同步时间只能是上一轮的旧值、比这次导出还早，等于让人去拿一个还没到的文件。
  等待上限 150 秒且发生在任务标记完成**之后**（否则进度条会跟着一直转）；超时照发但明说「尚未确认送达」。
