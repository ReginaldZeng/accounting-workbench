# V2.468 · 发起人钉钉账号已不存在的审批单：附件 API 拿不到，立项提示讲清原因并指向手工上传

**日期**：2026-09-06　**业务方问**：「202607011742000186641 这一单什么情况」。

## 排查

- 钉钉能找到实例（COMPLETED · agree，2026-07-01 发起、07-09 结束，标题「罗梓彤/零售/通品/TOC渠道/电商/200kg-500kg BOM表报价」），8 个表单附件都在（4 份研发 BOM + 2 份商务版 + 2 份商品版核算表，控件标注齐全）。
- 但 8 个附件的下载链接一个都拿不到：新版接口回 `userNotExist 用户不存在`，老版接口回 `60121 找不到该用户`。
- 查发起人：`v2/user/get` 同样 60121——**发起人罗梓彤的钉钉账号已不存在**（离职/注销）。钉钉按发起人身份放审批附件，人没了，任何应用、任何权限都拿不到；对照同天正常单（240399）同接口 200。
- 试过用审批人的身份走钉盘 storage 接口，端点不存在（404），此路不通。

## 结论

**不是权限问题，加 scope 也无解。** 这类单只能从 OA 后台人工下载附件，再用立项弹窗的「上传成本核算表」手工立项（单号照填，可溯源）。

## 做了什么

- `dingtalk_bom.download_url` 失败时带回钉钉原因（此前只回 `(None, None)`，页面只能说「拿不到下载链接」）；`fetch_approval` 逐附件 `error` 带原因，并判 `originatorGone`（全部附件都是「用户不存在」）。
- `POST /api/bom/intake`：`originatorGone` → 明确提示「发起人钉钉账号已不存在……请在 OA 后台下载 N 个附件后手工上传」，并回 `attachmentNames` 清单；其它情况把钉钉回的原因拼进提示。

## 验证

本机重跑 186641：提示改为上述人话 + 8 个附件名；正常单不受影响。
