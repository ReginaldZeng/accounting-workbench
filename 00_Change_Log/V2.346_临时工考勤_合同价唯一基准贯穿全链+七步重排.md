# V2.346 · 临时工考勤 · 合同价是唯一基准贯穿全链 + 七步重排 + 恢复误删的认定函数

**日期**：2026-08-22　**分支**：main　**提交**：bd63d6a

## 起因
使用者看着第⑧步复核结论表：「这里还是没改，我估计你56也没改的了」——对。
V2.345 只把第②步的对比换成了纯合同价，`compute()` 里那张 `table`（内置表 ← 表头解析 ← 合同价）
还在**三处**当尺子用：⑧「按合同规则重算」、⑤逐人「应付合计」、逐日/逐人「偏离金额」。
没登记合同价的派遣方照样拿内置表算出一个"正常"。

## 一条原则
**合同价登记了什么就是什么；没登记的格子是「待核」；不拿任何反推出来的价顶上。**

单价从此只有三个来源，各司其职、不混用：

| 来源 | 是什么 | 用在哪 |
|---|---|---|
| 合同价 | 成本会计在第③步登记的行（按行带生效期） | **唯一核对基准**：应付、结算表自查、合同价核对 |
| 表上单价 | 结算表里人力给每个人实际套用的价 | 被核对的一方；同时是偏离计价的依据（公司就是按它付的） |
| 表头解析 | 汇总表表头文字解析出来的规则 | 人力自己写的，只作参考展示，不参与计算 |

## 改动
- 内核：删 `merge_rates / check_rates / rates_diff`；`RATE_TABLE_DEFAULT` 改名 `RATE_TABLE_OBSERVED`，
  注明不参与任何判定；新增 `contract_rate / actual_rate / dev_rate`
- `payable`：只认合同价，缺档 → 应付 None + 合同缺档原因
- `settle`：缺合同价人数；格/小计/合计只要有缺档，按合同价应付留空（不拿部分和冒充合计）
- `settle_verdict`：三态 **正常 / 异常 / 待核**；缺档 + 真问题 = 异常（缺档作原因附在后面）
- 状态条：删「单价与对外总价」（人力表头跟人力表头比），换成「单价 vs 合同价」三态
- 导出：⑤页改写合同价登记表 + 缺档清单 + 表头参考段；②页三态底色；①页写死的"普工19/保洁15"清掉
- 步骤：①数据接入 ②核对总览 ③口径与单价 ④逐人 ⑤逐日 ⑥表外 ⑦报告；
  删「认定台账」一步（需求方拍板），长期认定折进结算风险卡里可展开——否则它能永远压住提示没人看见
- ⚠ **恢复 V2.344 误删的 `reloadCur / doAck / doUndo`**——V2.344、V2.345 两版「确认无误」一点就是 JS 报错
- 删旧的 `/api/tempatt/rates` 读写接口（写入口 = 绕开生效期的后门）

## 实证（2026-07 留档）
```
无登记     → 4 家待核、锦绣异常（超弹性多记 1 处，缺档附作原因）、合计应付留空
只登记锦绣 → 锦绣按合同价 38,961 算得出来；其余 4 家待核
全部登记   → 4 家正常、锦绣异常
```
三种状态下导出 Excel 均成功，②页结论底色 正常绿 / 异常红 / 待核黄。内核测试 89 条全过。

## 留给下一个人的话
`merge_rates` 那种「层层兜底」的取价在这条线上**永久禁用**。凡是拿来当核对基准的价，都必须能回答
「这个数是谁给的」——默认表答不上来，它是工具自己反推的。
