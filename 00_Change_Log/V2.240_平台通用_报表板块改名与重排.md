**【平台通用】报表板块改名与重排**。

> 版本号说明：按 `00_Change_Log/README.md` 的防撞号规则，本号是**暂定**（提出时目录内最大为 V2.239）。
> 若合并前被别的分支占用，改文件名 + 本文 `version` 字段 + 代码注释里的 V2.240 即可。

**起因**：业务方定下报表板块的新信息架构，与现状（V2.52 建的那套）对不上——

| | 现状 | 业务方要的 |
|---|---|---|
| 一级 | 报表模块 | **报表板块** |
| 二级 | 财务会计（纯分组） | **财务报表**（纯分组） |
| 三级 | 科目余额 / 序时账簿 | **报表仪表盘 / 报表导出** |
| 二级 | 源单列表（可直接进入） | **源单列表（改纯分组，不可进入）** |
| 三级 | — | **源单导出** |

「报表导出」「源单导出」页内各两个页签：①一键导出 ②通知设置。业务方定**放页面内**，
不做四级菜单——菜单树内核只支持一/二/三级（sec→parent→leaf），加一层要动 Sidebar + 后端菜单树 +
准入点生成三处，代价与收益不成正比；且这两个页签同属一个动作面（导出与导出通知），本就该在一页里。
做法沿用物流计提「④通知设置页签」（V2.230）。

**改法**：

1. **一级改名**：`NAV_SECTIONS` 里 `report` 的 label 报表模块 → **报表板块**（key 不动，D6 惯例）。
2. **二级改名**：`fiacc` label 财务会计 → **财务报表**（key 不动）。
3. **撤下 `sbal`（科目余额）与 `journal`（序时账簿）**：业务方定「直接删掉」。两个 key 退出 `NAV_MODULES`，
   其自动生成的 `enter:sbal` / `enter:journal` 准入点随之消失（存量账号 perms JSON 里那两个键成为死键，
   `parse_perms` 按 `caps()` 过滤后不再出现，不需迁移）。
4. **新增三个三级占位**（均 `default="敬请期待"`＝不可进入，走既有「尚未开放」占位页）：
   `rptdash` 报表仪表盘、`rptexport` 报表导出（挂 `fiacc`）；`srcexport` 源单导出（挂 `srcbill`）。
5. **`srcbill` 由「二级直接进入」改为纯分组**（`group_only=True`，业务方定）：它的 `enter:srcbill` 因此消失，
   准入闸落到三级 `enter:srcexport` 上，与 `fiacc` 一族一致。
6. **`subject_upload`（上传科目余额表）的 `mod` 由 `sbal` 改指 `rptdash`**——这一条是**必须**改的，不是顺手：
   `mod` 指向一个菜单树里已不存在的 key 时，`_caps_for_ui` 算不出 `gate`，该动作会掉进账号页第③栏的
   「不受菜单门控」堆里**恒显示**，变成一条谁都看得见、却对不上任何菜单的幽灵权限（V2.53 三栏化的设计前提就是
   每个动作都要有归属菜单）。指向 `rptdash` 而非删除，是因为「手工上传金蝶报表做人眼核对」是业务方明确要保的能力，
   报表仪表盘正是它的新家；`rptdash` 现为「敬请期待」、无人持有 `enter:rptdash`，故这条动作眼下对所有人都不渲染。
7. **岗位模板按语义平移**：`cost_acc`／`ap_acc`／`ar_acc` 里的 `sbal`+`journal` → `rptdash`，
   `srcbill` → `srcexport`。`gl_acc`／`tax_acc` 走 `secs=["report"]` 整给，自动跟上、无需改。
   「报表导出」暂不单独进这三个模板（一键导出是新动作，给谁待业务方定）。
8. **前端**：`Sidebar.jsx` 加导出图标 `IC.dl`，`ICON_BY_KEY` 撤 `sbal`/`journal`、加
   `rptdash`(仪表盘=IC.fund)／`rptexport`／`srcexport`(=IC.dl)；`App.jsx` 摘掉 `sbal` 路由与 import、
   出 `CODED_VIEWS`。

**未动（须知悉）**：`views/SubjectBalance.jsx` 与后端 `/api/subject-balance`、`/sync`、`/check`、`/upload`
**原样留着**，只是从菜单摘下后不可达。业务方原话是「反正原来也是占位符」，但科目余额**不是**占位符——
它是在跑的真页面（金蝶取数 + 手工上传逐项核对的双模式）。删页面文件与删既有 API 属治理红线
（`00_治理速查清单.md`「🛡️ 红线」），须先出影响分析，故本次只做菜单级撤下，代码零删除、随时可接回。

**遗留**：

1. **三个新三级都是空占位**，点不进去（状态「敬请期待」）。报表仪表盘要摆哪些报表、报表导出的
   一键导出导什么格式给谁、通知设置发给谁，都待业务方定，按 UI 前置规范先出信息架构与线框再实现。
2. **纯分组父项的状态灯**：`财务报表`／`源单列表` 沿用既有惯例给「已上线→引擎正常」（呼吸绿灯），
   与 `银行对账`／`物流对账` 一致——**不是**说它下面的功能好了，而是纯分组必须落在「可进入」状态里
   才点得动展开/收起（`Row()` 里 `disabled` 会把 onClick 整个摘掉）。觉得绿灯误导，主管理员可在
   「系统设置 › 导航模块上线管理」直接改状态，不需改代码。
3. **`nav_module_overrides` / `nav_section_overrides` 的 label 覆盖优先于代码**。若生产库里主管理员
   曾在设置页手工改过 `report` 或 `fiacc` 的名字，DB 覆盖值会盖住本次改名。开发库无覆盖、改名已生效；
   上线后若发现名字没变，去设置页把覆盖值清掉即可。
