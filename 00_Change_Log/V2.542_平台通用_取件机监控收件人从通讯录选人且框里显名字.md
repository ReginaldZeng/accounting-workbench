**【平台通用】取件机监控 · 收件人从钉钉通讯录选人 + 框里显名字**。
**起因**：门户「取件机监控」配收件人原先要手打手机号、框里也只显号码，认不出是谁。需求方要「直接选人」＋「框里显名字」。先查实——钉钉应用**有通讯录权限**（`notifier.getbymobile`「根据手机号获取成员信息」本就是通讯录接口，V2.162 已实测通），选人不必另开权限。
**改法**（选定最省风险的一条：**底层存的仍是手机号**，另建一张全局「手机号→名字」表只供显示，发送 / DataImport / 银行 / BOM 送达面板 / 发测试全不动）：
① `notifier.py` 三个助手 `dt_depts` / `dt_members` / `dt_mobiles`（复用现有 oapi token：拉部门树 `department/listsub`、成员 `user/listsimple` 翻页取全、选中人手机号 `user/get`；未配置 / 失败只返 `{ok,msg}` 不抛错）。
② `app.py` 三个接口（门户管理·仅管理员）：`GET /api/dingtalk/depts`、`/dept-members`、`POST /api/dingtalk/pick-mobiles`。
③ `app.py` 收件人两接口（alert / result）改吃 `entries=[{m手机号, n名字}]`：手机号照旧只存进各自 mob_key（**存储 / 发送零改动**），名字并进全局 `recipient_names` 表（`_parse_recips` 解析、`_save_recip_names` 合并）；老的 `mobiles` 字符串入参仍兜底（发测试等其它调用不受影响）。`/api/portal/machines` 响应加 `names`（手机号→名字）供前端显示。
④ 前端监控卡每条收件人（停机告警 + 各结果通知）从「输入框」改「标签区」：通讯录勾的人 → 显**名字**、手打的号码 → 显**号码**，各带 × 可删；留一个「加手机号」小输入框加外部人；「通讯录选」弹 `ContactPicker`（部门树钻取 · 勾选 · 面包屑）。保存把当前标签的手机号 + 名字一起提交。
**验证**：Python 语法（`py_compile`）+ 前端 vite build 均过；起一次性测试后端（sqlite）curl 实测——`entries` 带名字入库：mob_key 只落手机号、`recipient_names` 落 {手机号:名字}、`/machines` 回的 `names` 与之一致；纯 `mobiles` 字符串兜底照常入库且不落名字；坏号（非 11 位）被拦截、不入库；清空（`entries=[]`）关闭该条；「发测试」在没配钉钉时**优雅报「需先配钉钉」不崩**。**真通讯录数据 / 真发钉钉要真钉钉环境才出**（测试环境无钉钉：弹窗只显未配提示、发测试只走到「未配」这步），部署后你在真钉钉点一下即验；`listsub` / `listsimple` 若该应用权限档缺项，返回里会提示、再补。
**遗留**：「结果里有错误 → 定向推给制单人」留下一版（用户确认先不做）。⚠ 本仓库并行频繁，本条从 V2.540 连撞至 V2.542（origin/main 的 V2.540 / 541 已被 BOM 报价审核占用）。
