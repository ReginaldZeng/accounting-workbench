# V2.401 · ⑦合同外调整没确认，⑧复核结论也开不了

**日期**：2026-08-29　**分支**：main

Reginald：「那么合同外调整没有确认也开不了8」。

## 签字闸门连成一条链

```
⑦合同外调整「本期奖惩已核对」──签──▶ ⑧复核结论开
⑧复核结论「确认无误」──────────签──▶ ⑨用工成本汇总开
```

⑦没签,⑧锁着(🔒,步骤条点不动,打开是一张「去第⑦步确认」的卡)。
道理:奖 / 罚 / 补贴是全表**唯一没有对照源**的钱,得先由人签一句「核过」,
才谈得上看复核结论、出成本汇总。⑦确认后 ⑧ 自动打开并跳过去。

## 实现

⑦的确认状态从 AdjTable 子组件**上提到主组件**(单一真相),
主组件据此锁 ⑧、`doAdjSignMain` 确认后 `setStep('concl')` 跳到 ⑧;
AdjTable 只渲染确认条、按钮走主组件的回调。指纹(笔数|净额|异常|存疑)一变,
⑦确认自动失效 → ⑧ 跟着重新锁上,提示回去重签。空期照样要签「确认无奖惩」才开 ⑧。

后端沿用 V2.400 的 `/api/tempatt/adjsign`,没动。

## 一句说明

历史期次(读自留档)也一并受这道闸约束:之前没签过 ⑦ 的,现在打开 ⑧ 会先要求确认奖惩。
一次一点,是刻意的审计次序——先认账奖惩,再看结论。
