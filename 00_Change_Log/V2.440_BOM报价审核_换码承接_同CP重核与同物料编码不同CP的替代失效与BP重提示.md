# V2.440 · 换码承接：同 CP 重核 / 不同 CP 同物料编码 → 初审跳「原版是否失效」；对外口只发当前版并带 supersedes

**日期**：2026-09-05　**分支**：main

## 业务规则（业务方 2026-09-05 定）

1. **CP 码正常不重复。** 同一 CP 再来一张核算表 = 同一产品重核，成本会计**初审时必须跳出来问「原来那个是否失效」**，不许静默换版。
2. **不同 CP、同 ERP 物料编码**（研发改配方换 CP，卖的还是同一 SKU）：**后审核的替代先审核的**。1 月审核通过的 CP0001 带物料编码 X，2 月审核的 CP0002 也带 X → CP0001 失效，**凡引用 CP0001 的 BP 定价都要重新提示**。BP 眼里物料编码才是身份，CP 是研发版本。

## 落法

- **db**：`bom_quote_entry` 加 `obsolete_by`(INTEGER) / `obsolete_at` / `obsolete_note`，迁移自动补列。「失效」**不改 active、不改 status**——记录、留痕、历史全在，只是不再是对外版（与「替换」active=0、「作废」voided 三者分开）。
- **检测点**（`_obsolete_candidates`）：本版有效且已初审/已审核、未失效、非本条的记录里，同 CP 或（本版带编码时）同物料编码者。三处触发：
  - `POST /api/bom/classify`（定性即定稿）：四步齐 + 有候选 且未带 `confirmObsolete=true` → **只存定性不定稿**，回 `needConfirm=[候选]`；前端「审核定稿」弹窗列出候选（CP/名称/编码/原因/审核日/全成本）并要求二选一「是，原版失效，本版定稿」/「否，先核对（只存定性）」。
  - `POST /api/bom/finalize`：同闸，`ok:false + needConfirm`。
  - `POST /api/bom/set-erp-code`：给**已审核**行补编码时，若别的 CP 已挂同码且在审核态 → 回 `needConfirm`，按「后审核的替代先审核的」算出谁为当前版（`_audit_at`＝终审时间优先、其次初审），确认后写码并标失效。草稿行留到初审再判。
- **标失效**（`_mark_obsolete`）：旧版 `obsolete_by=新版`，双向留痕（旧版「失效·被新版替代」、新版「替代旧版 #id CP…」）。新版定稿时清自己的 obsolete 字段（重新成为当前版）。
- **恢复**（`db.bom_clear_obsolete_by`）：新版退出审核态——终审退回、撤销定稿、改成本失效（`_invalidate_review`）、作废/被替换（`bom_supersede_entry`）——凡被它替代的旧版**自动恢复**为当前版并留痕「恢复为当前版」；再初审会重新问，不静默再替代。
- **对外口** `GET /api/bomcost/final`（`_live_finals`）：定稿指针 + 已审核 + **没被一条当前对外的新版替代**。旧版在替代者**终审通过那一刻**退出——终审前 BP 仍拿旧版，**不出现「没成本」空档**。链式替代（CP3 替 CP2 替 CP1）正确。每行新增 `supersedes:[{entryId,cpCode,productKey,erpCode,finalizedAt,obsoleteAt}]`，BP 拿去翻引用旧 CP 的定价方案。
  - **兜底去重**：同一物料编码若仍有多条对外版（老数据没走确认）→ 按审核时间只发最新，其余进 `supersedes`，并回 `warnings` 提示成本会计回核算侧确认。BP 永远不会收到同一编码两条。
  - `/api/bom/final`（旧口）同样套用「未被替代」过滤。
- **前端**：台账行标签「已失效 · 被 CPxxxx 替代」（灰、半透明，默认收起，筛选栏「显示已失效 N」切换）/「待替代 · CPxxxx 待终审」（琥珀，仍对外）/「替代 CPxxxx」；核算表详情页两条横幅（本版被谁替代 / 本版替代了谁，可点跳转）；**终审弹窗**提示「本版通过后将替代 N 个旧版——引用旧版的 BP 定价会收到成本更新提示」，财务BP 终审时看得见影响面。

## 验证

py_compile 过；scratch sqlite 冒烟 17 项全过：候选识别（同物料编码/同CP）、初审后旧版「待替代」且 feed 仍发旧版、终审后 feed 切新版、双向留痕、终审退回自动恢复且再初审重新问、老数据同 erp 兜底去重 + `supersedes` + `warnings`、补编码冲突方向（后审核者为当前版）。前端 build 过。
