# V2.548 · BOM报价审核：只有成品主动落盘公盘——半成品/复配料审核完就好、不单独落（已随成品文件的上游页带出）

**日期**：2026-09-09　**业务方问**：「我在想是不是只有成品在主动落库，如果不是成品是不是审核了就好、需要再落库？」→ 定**甲案（严格）**：只有成品主动落盘，半成品/复配料不单独落。

## 现状（改前）

初审通过即落盘（V2.524）是**对每一条**产品触发的（`_drop_outbox_safe` 在两处定稿路径都无条件调用），不分成品/半成品/复配料。而成品导出本就带上游多页（V2.523 `_build_chain_xlsx`：复配料→半成品→成品）。结果**半成品/复配料在公盘上出现两次**——自己单独落一份 + 被打包进成品文件的上游页。冗余。

## 口径（业务方定，甲案）

- **只有成品主动落盘**。半成品/复配料审核完就好，不单独落——它们已随成品文件的上游页带出。
- 甲案不做兜底：不在任何落盘成品下面的半成品/复配料（独立报价/成品未审/成品被删）**不会单独进公盘**，业务方接受（这些本来就都有成品带着）。

## 改

- **`_drop_outbox`**：落盘前加成品闸——`bq.effective_kind(cp_code, product_name, mat_category) != "成品"` → 返回 `{ok:False, skip:True, msg:"非成品（复配料/半成品）不单独落盘——已随成品文件的上游页带出"}`，不写盘。判定用 `effective_kind`（人工定性的物料类别优先，初审必已定性，比编码可靠）。
- **`_drop_outbox_safe`**：`skip` 与 `ok` 一样**不算失败**——不写「落盘公盘失败」留痕、不进失败清单、清掉旧失败项。
- **前端** `BomPrice.jsx`：①详情页落盘状态行——`entry.kind !== '成品'` 时显灰字「○ {kind}不单独落盘公盘——已随成品文件的上游页带出」（不再显「未落盘/重落公盘」误导）；②初审成功提示——`r.outbox.skip` 时显「半成品/复配料不单独落盘（随成品带出）」，不显「⚠ 落盘失败」。

## 测

沙盒实测 20869（2 复配料 SHY913005/913003 + 成品 CP13118103）：定性后逐条 `_drop_outbox_safe`——
- 复配料两条 → `skip=True`、不落、不进失败清单；
- 成品 CP13118103 → 落 2 文件（财务版+脱敏版），且该文件**含 3 页**（香茅复配料 / 青椒复配料 / 黑豆嫩豆方成品）——复配料随成品带出，未丢。
- outbox 最终只 2 个文件、失败清单空。✅

## 未动

- 落盘只是不再对半成品/复配料触发；重排版导出、预览、BP 消费口一律不变（成品导出仍带上游多页）。
