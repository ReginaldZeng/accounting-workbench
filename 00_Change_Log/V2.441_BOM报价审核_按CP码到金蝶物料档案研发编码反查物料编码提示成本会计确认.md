# V2.441 · 补物料编码：按 CP 码到金蝶物料档案「研发编码」字段反查，检测到就提示成本会计确认（不自动写、不设闸）

**日期**：2026-09-05　**分支**：main

## 起因

V2.440 换码承接靠「同 CP / 同物料编码」两把钥匙。业务方追问：CP0001 那时没物料编码怎么办？
我先提议把物料编码做成终审闸，业务方纠正：**没中试的产品本来就没有物料编码**（编码是中试后才建档），闸会拦掉最需要报价的新品 → 收回。
业务方改提：**金蝶有物料列表，检测到这个 CP 码有对应物料编码，就提示成本会计确认。**

## 实证（金蝶本账套只读探测，2026-09-05）

- `BD_MATERIAL` 标准字段 FOldNumber / FMnemonicCode / FDescription 全空，**CP 码不在那里**。
- 拉元数据 382 个字段，找到自定义字段 **`F_ora_Text1` 中文名「研发编码」**：300600092 那条＝`CP05113401-1（SN2）`，与对接文档样例一致。
- 全账套 19,409 行（多使用组织）/ 9,630 个物料，**892 个带研发编码**（产成品 827 / 自制半成品 64 / 委外半成品 1；前缀 CP 845、SZF/SZB/SZY/SHB/SHF/SHY）。
- ⚠ **同一研发编码挂多个物料编码 97 例**：如 SZF004027 → 200000174「复合调味料-沙拉棒阳光番茄」与 200000184「复合调味料-植物肠」（名字都不同）；CP07112504 → 300600096 与 **T00000187**（T 开头临时码并存）。→ **只能出候选让人选，绝不能自动写**。
- 本地台账 12 个 CP 命中 9 个；`CP04108204(SN5)` 金蝶只有无后缀 / (SN2) / (SN3) / -1(SN2) 四个近亲 → 做前缀近似兜底并标「前缀近似，请核对括号后缀」。

## 落法

- **kingdee_client**：`MATERIAL_RD_CODE_FIELD="F_ora_Text1"`（本账套实测，注释写明发现过程）+ `normalize_rd_code()` + `fetch_materials_by_rd_code(cp)`：精确匹配（原样 + 全/半角括号两种写法）优先，没有再按去括号前缀 `like`（前缀 ≥6 位才近似）；多使用组织按物料编码去重；排序＝精确 > 正式码 > T 临时码 > 已禁用。单引号转义，只读。
- **路由** `GET /api/bom/erp-lookup?entryId=|cp=`（CAP_AUDIT）：10 分钟进程内缓存；每个候选附 `inLedger`＝台账里已挂该编码的其它记录（选它会触发 V2.440「后审核的替代先审核的」确认）；金蝶连不上回 `offline`（本机 worktree 常态），不抛垮。
- **前端三处提示，一个都不拦**：
  - 核算表右栏新增「物料编码」行（在单位净重之上）：无码标「未建档」并**自动反查**，列候选「采用 300600092 原味糯米丸子-通品 · 1kg/袋 · 产成品」；有码可「改」/「核对」（按需反查）。未登：「多为未中试/未建档，可先无编码定稿，建档后再补」。
  - 「审核定稿」弹窗：无码时顶部出候选横幅，采用后弹窗内 entry 就地刷新（后端回新视图，含新的换码候选），再走定稿；**不是闸**。
  - 台账「补物料编码」：先反查，候选写进提示、默认值填第一个正式码，成本会计改/确认才写。
  - 三处采用统一走 `adoptErpCode()`：撞码 → 后端 `needConfirm` → 人确认 → 带 `confirmObsolete` 重发 → 旧版失效。至此「CP0001 无码 → 中试建档 → 采用 → 撞码 → 替代 → BP supersedes」链路闭合。
