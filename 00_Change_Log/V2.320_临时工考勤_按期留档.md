# V2.320 · 临时工考勤 · 按期留档

> 需求方 2026-08-19 问：「这个是不进去数据库的吗，每次都要重新上传」。**是，原设计确实不落库。**

## 一、原设计错在哪

V2.318 的铁律 1 写的是「只读不写。对金蝶一个写接口都不调；**两张表算完即走，不留数据**」——
把**两件不相干的事捆成了一条**：

- 「不写金蝶」是安全底线，必须保留；
- 「不存自己的库」跟安全没有关系，纯粹是顺手写严了。

代价不止是每次重传：

- 上期结论查不到——**一个复核工具不留复核记录，本身就说不过去**
- 谁在什么时候核的、结论是什么，没有留痕
- V2.318 曾建议「同名跨派遣方按月常态跑」，**没有历史这条根本做不了**
- 这条线还是本项目里的**异类**：电商有 `ec_uploads/{YYYY-MM}/`、银行有 `bank_uploads/`、
  物流计提有上传登记表，只有临时工考勤算完即走

## 二、定案（2026-08-19）

结论与原表**分开处理**，理由是两者性质不同：

| | 复核结论 | 原始两张表 |
|---|---|---|
| 内容 | 四档统计、请款复核、风险清单、奖罚明细 | ⚠ 打卡表含**全员姓名 + 每天上下班时刻**，人事敏感 |
| 用途 | 查上期结论、留痕、跨月比 | 改参数重跑 |
| 体量 | 实测压缩后一期 13 KB（40 人）／推算全量 331 人约 107 KB／**一年 12 期约 1.3 MB** | 一期约 193 KB |
| 处理 | **长期落库** | **只留最近 6 期**（`tempatt_keep_months` 可改），到期自动清 |

**过了留存期仍能看结论、能导 Excel，只是不能改参数重跑**——页面把那一期的「重跑」置灰并写明原因，
而不是让人点了才发现跑不了。

## 三、实现

- `tempatt_uploads/{YYYY-MM}/{summary,punch}.xlsx` 落盘；`.gitignore` 与部署包提示同步排除
- 结论 gzip + base64 进 `app_settings`：`tempatt_result_<YYYY-MM>`（实测压到原文 **8.0%**）
- 摘要另存 `tempatt_meta_<YYYY-MM>`，给期次列表用，不必解压大对象
- 新增三个接口：`GET /periods`（期次一览）、`GET /period?month=`（读留档）、`POST /rerun`（按留档原表重跑）
- `/export` 改为两种来路都认：现场上传两张表，**或只给 month 从留档出表**
- 页面：第①步顶部「已核期次」表（月份/跑批时间/跑批人/人数/应付/异常数/原表在不在），
  点「查看」直接载入；载入后全程挂一条**留档提示条**，与「刚跑完」在视觉上分开——
  否则改了参数看不到变化会以为工具坏了

## 四、实测（本机 8071，端到端）

| 步骤 | 结果 |
|---|---|
| ① 上传跑一期 | 已留档，重算 2,987 h |
| ② 刷新页面看期次列表（不传文件） | 2026-07｜跑批人｜40 人｜应付 51,496｜异常 0｜原表在库 ✓ |
| ③ 选月份直接看 | 读自留档 ✓，人数 40、请款 51,496、逐日明细 **299 行**全在 |
| ④ 改参数重跑（改四舍五入） | 重算 2,987 → **3,052**，跑批次数 +1 ✓ |
| ⑤ 从留档导出（不传文件） | HTTP 200 / 61,738 bytes ✓ |
| ⑥ 到期清理（保留期临时改 1） | 清掉 2026-06，保留 2026-07 ✓ |
| 浏览器实测 | 一打开页面就有期次表；点「查看」出留档提示条；点「按当前参数重跑」重算变 3,052、提示条消失 ✓ |

内核回归 **187 项全过**（本次不动内核）。
