**【平台通用】「模型配置」权限点化（业务方 2026-08-20：「模型那一页只有主管理员有，其他人没有，可以做到权限配置那里面」）**

## 起因

门户导航「模型配置」此前**人人可见**（nav 数组写死），接口闸是 `can_admin_accounts`（主管理员**或任一工作台子管理员**）。
业务方要求：默认只有主管理员有；其他人要用，去权限配置里开——即一个可授予的权限点，而不是角色硬编码。

## 改法

1. **db.py**：`CAP_META_STATIC` 新增平台级权限点
   `{"key":"model_config", "label":"模型配置（大模型接入/密钥/网关）", "ws":"platform", "group":"门户", "sensitive":True, "tier":"nav"}`。
   **ws="platform" 是机制核心**——它有意不在 `WS_LABEL` 里，于是 `managed_workspaces` 永远不含它：
   子管理员既不「恒有」（`sub_admin_caps` 只并管辖工作台），也**授不出**（`assignable_caps` 同源）；
   `default_perms` / `_legacy_perms` 的 own_ws 判定同样碰不到它。
   「默认只有主管理员有、只有主管理员能授」全部由 ws 归属自然成立，不需要 `enter_settings` 那样的点名特例。
   sensitive 是双保险（日后 platform 若升为正式工作台，仍挡 `_backfill_missing_perms` 自动补发）。
2. **routers/llm_hub.py**：7 处闸 `can_admin_accounts(u)` → `user_can(u, "model_config")`
   （usage / key / provider / model / policy / audit / 网关 `_require_admin`），403 文案统一「需『模型配置』权限」。
   `/api/llm-hub/status` **保持登录即可看**——门户「AI 模型」胶囊的数据源，只有打码 keyHint 与模型名。
3. **Portal.jsx**：`canModel = isAdmin || perms.model_config`；导航「模型配置」按它显隐；
   AI 胶囊无权限时变**纯状态展示**（不可点、无「配置 ›」、待配置文案改「请联系主管理员配置」）；
   `tab==='model'` 渲染加同权限守卫。藏入口只是 UX，真闸在服务端接口。
4. **UserAdmin.jsx**：`WS_ORDER`/`WS_META`/`WS_LABEL_SHORT` 加 `platform` 区块（标题「平台 · 门户」，PLATFORM · PORTAL）。
   ⚠ 不加会重演 V2.240 幽灵权限坑——`wsList` 只渲染 WS_ORDER 里的 ws，新码会静默勾不到。
   子管理员打开账号页时该区块整体隐藏（assignable 过滤），只有主管理员能勾。

## 权限语义（矩阵单测 14 项全 PASS）

| 对象 | model_config |
|---|---|
| 主管理员 | 恒有（role=admin 全权） |
| 核算/BP 子管理员 | **默认无**（不恒有）、**不可授出** |
| 普通账号 / 新建账号 / 老账号(无 perms) | 默认无 |
| 被主管理员在账号页勾选后 | 有（前端入口 + 后端接口同时放行） |
| BP 透传（X-BP-Perms） | 不透传（非 bp 码） |
