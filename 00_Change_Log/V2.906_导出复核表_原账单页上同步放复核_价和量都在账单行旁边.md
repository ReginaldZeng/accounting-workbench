# V2.906 导出复核表：在原账单页上同步放复核——价和量都写在账单行旁边

- 日期：2026-10-11
- 作者：Claude Opus 5.5
- 模块：应付板块 › 物流对账 › 物流账单复核台 › 导出复核表（「原账单-…」各页）

## 起因

用户看导出的原账单页（恒茂冷藏页上有他们自己手工加的黄色两列「财务复核 ＝天数×单价×计费数量」「check」）：
「我觉得最好是在原账单上面同步放这个会不会更好，更直观」。
之前公式都在「复核明细」页，要对着原账单看得来回跳；没有金蝶单号的行（恒茂冷藏费）根本不在复核明细里。

## 改法

每个原账单页，在账单最右一列再空一列的位置，接一组「系统复核」列（浅黄表头），每一行账单对着写：

| 列 | 内容 |
|---|---|
| 标准金额 | 公式，用**这一行自己的格子**算：恒茂入库 `=ROUND(K3*19.4,2)`、冷藏 `=ROUND(E3*L3*M3,2)`、短驳 `=ROUND(D5*1800,2)`、零担 `=ROUND(I2*J2,2)` |
| 价差（账单−标准） | 公式 |
| 价的复算 | 公式：一致 / 核价不符；加班费报价没列价的写明要确认 |
| 核价依据 | 按什么核的；没写单价核不了的也写明 |
| 账单量（本单合计）、金蝶核对量、量差、量的复算 | 写在这张单的第一行，指回「复核明细」页对应的格子，两边永远是同一个数 |
| 核对方式 | 这张单是按什么比的；一张单在账单上有几行的注明「量写在第一行」 |

- **没有金蝶单号的行也核价了**：恒茂冷藏费 313 行（34,326.36 元）原来导出里完全没有核，现在每行都有 天数×计费数量×冷藏单价 的公式。
- 规矩同前：公式写之前先按格子里的数算一遍，和系统记的标准、结论对得上才写。
- 早先那份极鲜达原账单 json 的页，右边原来接着五列写死的复核（计费类别/ERP重量/账单数量/差异/结论），取的是中间表的老数、会和现在的结论打架，不再写。

## 改动

- `backend/routers/logistics_review.py`：新增 `_xl_raw_review`；`review_export` 最后一步调用；老的五列静态复核去掉。只改后端。

## 验证（线上只读；价的公式我按本行格子算过一遍）

| 承运商（8 月） | 原账单页上的价 | 量 |
|---|---|---|
| 恒茂 | 入库 284 行按吨重×19.4、冷藏 313 行按天数×计费数量×冷藏单价，全部一致；出库 1 行没单价核不了 | 41 张单写在各自第一行 |
| 极鲜达 | 零担 50 行、山姆 24 行按账单单价×计费量一致；短驳 36 行按报价（33 行一致，3 行有加班费要确认）；28 行没单价 | 102 张单 |
| 链盟 | 66 行都没有单价，写明核不了 | 66 张单 |

- 「复核明细」页和上线前逐格一样。
- 用时：恒茂 29 秒、极鲜达 19 秒、链盟 17 秒，和之前持平；文件恒茂 15.5 万 → 17.8 万字节，每页格子数正常（没有再凭空多出空格子）。

## 要知道的

- 这组列接在原账单已有内容的最右边。恒茂冷藏页原来就排到 AE 列，所以系统复核从 AG 列起，要往右拉才看得到。
- 恒茂入库的标准金额仍是「账单吨重 × 19.4」，吨重取自账单、没有用金蝶核（每箱毛重的口径还等用户定）。
