# V2.459 · 主管理员密钥删除：标准台账 / 待办 / 处理页三处入口，conf.ini 密钥确认，真删并留全局审计

**日期**：2026-09-06　**业务方定**：「主管理员要配一个删除的入口，密钥确认」「待办也是」。

## 边界

- **作废（既有）**＝标记不删，给成本会计申请、财务BP批准；**删除（本版）**＝真删，**只给主管理员**，且每次输密钥。
- 密钥＝服务器 `conf.ini [bom] delete_key`（凭据不进代码不进文档；**未配置＝通道关闭**，不是默认放行，同取件令牌口径；须纯 ASCII）。
- 删的范围三选一：**单条记录**（详情页）/ **整组**（处理页组动作条，含被替换旧版）/ **整单**（处理页顶部、待办列表行；全部组 + 待修批次）。
- 记录自身的留痕随记录删除，所以**全局审计必记** `bom_delete`：谁、删了哪些（CP#id 列表）、待修/文件数、含几条对外版、理由。密钥错也记 `bom_delete_denied`。

## 做了什么

- `POST /api/bom/delete` {entryId | groupId+approvalNo | approvalNo, key, reason, dryRun}：非主管理员 403；`dryRun` 回影响面（记录清单及状态/对外/定稿标、待修批次、留档文件数、**谁把它当上游**、被它替代将恢复的旧版、并行组其它成员、`keyConfigured`）；真删前 `hmac.compare_digest` 校密钥、理由必填；逐条：恢复被它替代的旧版 → 清定稿指针 → 删 `bom_uploads/{src}/{id}__*` 留档 → 删记录/留痕/指针；并行组只剩一条则清标记；待修批次 `bom_pending_clear`。
- 前端 `DeleteModal`：先 dryRun 摆影响面（对外版红字警告、上游依赖琥珀提示），理由 + 密钥 + 二次确认才删；三处入口按钮红边，只对 `user.role==='admin'` 显示。
- `conf.ini.example` 加 `[bom] delete_key`。

## 验证

TestClient：非管理员 403；dryRun 影响面（含上游依赖、恢复旧版、对外版计数）；未配密钥 403「通道关闭」；密钥错 403 + 审计 denied；正确密钥删单条 → 记录/留痕/指针/文件消失、被替代旧版恢复；整单 → 全部记录 + 待修批次清空；全局审计一条。前端 build 过。

## 服务器上要配

`conf.ini` 加：
```
[bom]
delete_key = <随机串，纯 ASCII>
```
后端每次请求现读，不用重启。
