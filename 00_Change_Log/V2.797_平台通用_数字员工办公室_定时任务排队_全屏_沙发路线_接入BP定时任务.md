# V2.797 平台通用：数字员工办公室大屏——定时任务排队、全屏、去沙发的路线、接入 BP 工作台的定时任务

日期：2026-10-04

**起因**：V2.796 上线后用户看着线上大屏提了三条：①「刚干完的活」下面空着，能不能加一个「定时任务排队」；②要全屏功能；③小人走到沙发的路径有点奇怪。

**改法**：

- **定时任务排队**
  - `backend/worker_store.py`：新表 `worker_next`（工位 → 下一轮预计什么时候跑），`beat(desk, off, next_in=秒)` 报到时顺带写；值班表每个工位多给 `nextTs`（只有在岗的给，没上岗 / 停了的不排队），顶层多给 `nowTs`（服务器时间，大屏拿来校正本机的钟）。单独建表而不是给已上线的 `worker_beat` 加列：新表 `create_all` 自己会建，不用在生产库上改表。
  - 七个后台任务报到时带上「离下一轮还有多久」：`invoice_intake.py`（离下一次整扫钉钉）、`logistics_payreq.py` / `invoice_vouchers.py` / `todo.py`（二十分钟）、`bom_quote.py`（配置的扫描间隔）、`fxrate.py`（下一个 14:00）、`invoice_books.py`（催票：今天没到点＝今天整点，催过了＝明天整点，到点没催成＝十分钟后）。
  - `office-screen.html`：右栏在「刚干完的活」和「值班表」之间加「定时任务排队」——几点、谁、还有多久；三分钟内的标黄，到点的显示「轮到了」。每五秒刷新倒计时。样例模式到点了会自己演一遍派工。
  - **只排按钟点跑的**（工位注册表加 `sched` 标记：汇率录入员、催票员）。第一版把每二十分钟去钉钉 / 金蝶看一眼的六个工位也排了进去，用户看了说「这几个算是定时任务吗」——不算，那是巡检（有新活才干，没有就空转）。改成巡检的不逐个排，在最下面收成一行（几个工位在巡检、最近一次什么时候）。派工单和滚动条上的「定时任务这一轮扫到…」也改成不带「定时任务」的说法。
- **接入 BP 工作台的定时任务**（用户 2026-10-05：「BP 工作台是不是也有些定时任务」→ 有，它自己的 `app/scheduler.py` 内置六条；「那这个属于哪个员工」→「再分两个，我去出图」）
  - 工位注册表加两个：`bp_sentinel` 驾驶舱值守员、`bp_flash` 业绩快报员，组「经营分析组」，都是 `sched`。工位总数 12 → 14。
  - 新文件 `backend/office_bp_bridge.py`：后台线程每分钟读 BP 的 `GET /api/ops/schedule`（它「系统设置 › 定时任务」页用的只读接口），调度在转就替工位报到、把每条任务的下次时点写进排队表；某条任务有了新的运行结果就记一笔（只写任务名和推了几个群）；调度没开 / 全停用报「没上岗」；连不上就不报到（十分钟后「停了」）。第一次连上只记进度，不把以前的运行补记成刚干完。`app.py` 启动它。
  - **不改 BP 代码。** 过 BP 的门：BP 没有登录，认请求头 `X-BP-User` / `X-BP-Perms`（平时由 Nginx 替登录用户注入，权限码由核算签发），且只信本机回环；这里从本机回环去读，带一个服务身份「数字员工办公室」和 `bp:board:appSettings` 这一个权限码。只发 GET，不触发任务、不改时间。
  - `worker_next` 改成一个工位可以有多条（主键 工位 + 任务，带任务名和多久一轮）；`set_queue(desk, [...])` 整组替换；值班表顶层多给 `queue`（一条任务一行）。这张表还没上过线，直接改的定义。
  - `office-screen.html`：两位新员工坐最右一列第一、二排；排队表改成按任务排，最多列四条，多的写「后面还排着 N 条」；各组在岗多一行「经营分析组」。10、11 号人物的图没到时先借 9 号、6 号的形象，开场探一下图在不在，在就用新的。
  - `backend/tools/office_art_pack.py`：人物不再写死 1–9 号，原图文件夹和它下一层子文件夹里成对的 `char-NN-seated.png` / `char-NN-walk.png` 都处理（追加的人物放子文件夹也认）。
- **全屏**：画面右上角「全屏」按钮、按 F、或双击画面；鼠标停三秒后按钮和光标自动藏起来。浏览器不让网页自己全屏时，按钮上提示按 F11。
- **去沙发的路线**：原来是沿左走廊一直走到沙发背后、穿过靠背坐下。量了底图后改成：左走廊下来 → 在第三排桌腿和沙发靠背之间往右 → 从沙发右端绕到前面 → 沿沙发和茶几之间走到座位前坐下。
- **坐在沙发上像站在沙发上**（用户看预览时指出）：原来脚落在坐垫上（y=852）。改成脚落在沙发前的地上（y=884），茶几桌面从底图上再截一块盖在人前面，小腿在茶几后面；从沙发前走过的人同样走在这条线上。
- **顺手修的**：名牌和状态灯画在最上层，会盖在从桌前走过的人脸上——现在有人走到前面时把被挡住的名牌和灯调淡。
- 样例模式多了一个按键 S（让一个人去沙发），调路线用。

**验证**：

- `tests/test_worker_office.py` 加一条（报了下一轮的在岗工位有 `nextTs`、间隔对；不带 `next_in` 不动上次报的；没上岗、停了的不排队；入参怪也不抛），当时共 14 条；接入 BP 后 16 条，连同待办区 35 条全过。
- 本机带口令读测试库（第一版，还排着巡检工位时）：排出的顺序和时间与库里写的一致；右栏没有溢出。改成只排按钟点的之后，用样例数据截图看过：两行（催票员、汇率录入员）+ 一行巡检汇总。
- 接入 BP：自动测试加两条（两个工位各自的排队、第一次不补记、新结果记一笔且不重复记、群名不上大屏只进出错原文、调度没开 / 全停用 / 连不上三种状态），共 16 条全过。本机起了一个**假扮 BP 接口的小服务**（返回形状照 BP `routers/ops.py` 写，没带权限头回 403），核算后台真的走 HTTP 读到了：经营分析组 2/2 在岗、排队表排出 BP 的任务、新结果弹了派工单并走去交接台。
- 去沙发：样例模式按 S 跟了一趟完整轨迹（走廊 236 → 沙发背后 y=748 → 右端 x=366 → 沙发前 y=856 → 坐下 176,852），另把人摆在各拐点和两个座位上截图看过遮挡（坐姿、茶几挡腿、名牌调淡）。

**遗留**：

- **七个任务报「下一轮」的那几行只编译过，没真跑过**（本机测试库不启动这些任务）。上线后汇率启动时就会报、催票十分钟内报，这两行才排得出来，之前显示「在岗的工位里现在没有按钟点跑的定时任务」；巡检那一行要等各工位转完一圈（最慢二三十分钟）。
- **没连过真的 BP。** 本机验的是假扮的接口；真 BP 的返回形状是照它的代码读的。上线后一分钟内看经营分析组两个工位是不是在岗、排队表里有没有 BP 的任务；如果显示「还没上岗：后台任务还没报到过」，多半是 BP 那边拒了（看核算后台 `office_bp_bridge._STATE`）或地址不对（`BP_API_BASE`，默认 `http://127.0.0.1:8010`）。
- 驾驶舱值守只知道「开跑了」，查出几条待办不知道（结果在 BP 的值守页）。
- **新人物 10–12 号**：业务方 2026-10-05 先发来定妆照（每人一张站姿），我用它凑过一版不会动的替身；随后发来完整动作图（`大屏素材/新增人物_10-12_20261004/动作图_20261005/`，坐姿 4×2 + 走动 6×3，1774×887，头身比和前九位一致），已换成真图集。10 号给驾驶舱值守员，11 号给业绩快报员，12 号处理好了、暂时没工位用。`office_art_pack.py` 里「只有定妆照就做替身」那段留着，以后新人物只到了定妆照时还用得上（有动作图的优先用动作图）。
- **图集碎块清理补强**：检查新图时发现个别走动格头顶带一小块上一排的鞋底（11 号 4 格、12 号 3 格），原来的清理要求碎块和主体隔 5 行空白才清，这几块只隔一两行。加了一步：从格子四边找连通块，面积不到整格人物 4% 的抹掉。十二个人的图集整套重跑了一遍并逐格查过：10–12 号的碎块清干净了；前九位重跑出来的文件和已上线的逐字节相同（没有受影响）。
- **全屏没验成**：我这边的预览窗不让网页进全屏，点按钮和按 F 都没反应（没有报错）。要在那台电脑的浏览器里试；不行就按 F11，或者用浏览器的 kiosk 启动参数开机自动全屏。
- 排队表上的时间是任务自己估的「下一轮」，一轮跑得久（比如首扫）会晚于这个时间，这时显示「轮到了」直到它下次报到。
- 人从沙发前走过时，腿会盖住茶几上小盆栽的上半截叶子（约一秒）。
- 改了后端，上线随自动部署重启。
