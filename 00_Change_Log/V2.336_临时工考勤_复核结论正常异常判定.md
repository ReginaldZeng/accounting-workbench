# V2.336 · 临时工考勤 · 复核结论给「正常 / 异常」

> 需求方 2026-08-22（截图圈出结论表右侧空白处）：「这里应该有结论，正常还是异常」。

## 一、原来缺什么

结论表最右只有一列「偏差（结算−重算）」，显示 ¥0。**要人自己看到 0 再推断「那应该就是没问题吧」。**
结论该由工具给，不该让人做二次推断——尤其这个推断还是错的（见下）。

## 二、结论不能只看偏差

一格偏差为 0，同时完全可能存在：

- 单价与合同不符（成本会计底表 17+4=21 那种）
- 奖罚符号反了（8 月李秀英罚记成 +5）
- 某人某天超弹性多记（本期沈武英 7 日 2.5 小时）
- 同名挂在两家派遣方（6 月张博）
- 结算归属与打卡部门不符（程爱莲、周文秀）

**这些都是「这家这条线本期不干净」，但偏差列一个都照不出来。**

新增 `settle_verdict()`：把本期**所有检查按「归属 × 部门 × 岗位」归位**，逐格汇总，
明细 / 派遣方小计 / 业务线小计 / 全表合计各给一句结论 + 原因清单。

实测本期：只有「锦绣 · 植物肉 · 普工」判异常（超弹性多记 1 处），其余五格正常；
派遣方小计里只有锦绣异常；全表合计异常并列出 `异常派遣方 = ['锦绣']`。
**定位精确到格**，不会因为一个人的问题把整家都染红。

## 三、与「认定」的关系

已认定（V2.335）的**不算异常**——人已经看过并说明过了，再报一次就是噪音。
但那一格会留一句「另有 N 项已认定」，不让它彻底消失。

⚠ 顺序要紧：`settle_verdict()` 必须在 `_apply_acks()` **之后**跑，否则认定过的还会被算成异常。
代码里已就近写明。

## 四、落点

- 页面「复核结论」表最右加一列 **结论（正常 / 异常）**，异常的下面直接列原因；
  正常绿、异常红加粗
- 顶部结论句补一句：`⚠ 但 锦绣 本期有需要说明的事项，见下表「结论」列`
- 导出「②复核结论」页同步加 **结论 / 异常原因** 两列，结论格按正常/异常上底色

## 五、实测

| 项 | 结果 |
|---|---|
| 干净数据 | 全部「正常」✓ |
| 只有偏差 | 判异常，原因写「结算与重算差 +5.00 元」✓ |
| **偏差 0 但有其它问题** | 仍判异常 ✓（这条是本次的核心） |
| 五类检查同时命中 | 原因列出 5 条 ✓ |
| 已认定 | 不算异常，另记「已认定 1 项」✓ |
| 小计/合计上卷 | 只有涉事派遣方异常，不误伤别家 ✓ |
| 导出 | 结论列写入并上色，小计合计行同样有 ✓ |
| 浏览器 | 表头两行对齐、行内结论与原因显示正确 ✓ |

新增 7 条单测；全量 **203 项全过**。
