# V2.315 · 修「点击下载台账」变成 422 —— 装饰器挂错了函数

**日期**：2026-08-18　**作者**：Claude / c　**线**：main（存货台账）　**V2.314 的回归，紧急修**

业务方：「点击下载台账，变成这样」——

```json
{"detail":[{"loc":["query","flow_rows"],"msg":"Field required"},
           {"loc":["query","bill_lines"],"msg":"Field required"}]}
```

## 我把辅助函数插到了装饰器和它该修饰的函数中间

V2.314 加 `_merge_bill_only_rows` 时，插入点选在 `def cost_ledger_export` 之前——
但那一行**上面就是它的路由装饰器**：

```python
@router.get("/api/cost-ledger/export")
def _merge_bill_only_rows(flow_rows, bill_lines):     # ← 装饰器修饰到它头上了
    ...
def cost_ledger_export(request, year, period, org):   # ← 反而没有路由了
```

于是 FastAPI 把辅助函数的两个形参 `flow_rows` / `bill_lines` 当成**必填查询参数**，
下载台账直接 422。

**这是整条线里最阴的一类错**：Python 语法完全合法、导入不报错、
V2.314 那 128 项测试**全绿**——因为没有一项测试碰过路由本身。**只有真点一下才会发现。**

## 护栏

`TestRouterWiring` 两条：

- 路由不得挂在私有函数（`_` 开头）上；
- `/api/cost-ledger/export` 必须存在且只挂 `cost_ledger_export`，查询参数**恰好**是
  `{year, period, org}`——多出来的必然是装饰器串位。

**验过它会红**：把 35a5df2（坏版本）的文件换回来跑，两条都失败：

```
AssertionError: '_merge_bill_only_rows' != 'cost_ledger_export'
AssertionError: [('/api/cost-ledger/export', '_merge_bill_only_rows')] != []
```

换回修好的版本，130 项全绿。真起服务打接口：未登录返回 **401**（不再是 422）。

## 教训

新增模块级函数时，插入点要看**上一行是不是装饰器**。
本项目 routers/*.py 里装饰器与函数定义之间从不留空行，看起来就是一整块，
从"函数定义那一行"往前插很自然、也很致命。
