# V2.837 物流复核台：登记制的费用凭证挪进「开始复核」第③步，关联发票后补单，表格重排

日期：2026-10-06

V2.835 把「审核 · 费用凭证」做成总表上的一个弹窗。用户看了真页面：「你不觉得这个有点变形吗」「而且是进去开始复核之后的第三步才做凭证吧，关联发票后补单」。

- 入口：登记制的承运商（路凯、禾享…）总表上不再是「审核 · 费用凭证」「登记（不逐单）」两个按钮，和别家一样是「开始复核」，进去直接到第③步。
- 第③步（登记制）：
  - 每张请款单一张「费用凭证」卡（有正常计提的那种不出这张卡）：发票 / 后补单情况 → 维度核对 → 凭证预览 → 勾确认 → 生成。金蝶里已有的照旧「就认这张（不新建）」；认定或生成之后卡上只留一句结果。
  - 「确认与登记」：各主体 计提（或费用凭证）/ 请款 / 差 一张小表 + 备注 + 登记（原来是弹出的输入框）；有差异备注必填；还没认到费用凭证时不能登记。撤销登记也在这里。
- 关联发票后补单：票夹里还没发票时，卡上亮出发票管家里这张请款单的后补单（单号、状态、预计到票日、登记人）；**没票、也没登记后补单的不让生成**（和 V2.833「没票先做付款凭证」同一口径），生成记录里记下后补单号，操作日志也写。
- 变形：原来两列的表套用了「更正」弹窗三列表的列宽，左列撑得很宽、右列很挤；凭证预览的「贷」表头被染成了黄色。改成三列「项目｜上一次｜这次用」（上一次的值留在旁边对照），凭证预览、登记小表各用自己的列宽。
- `routers/logistics_voucher.py`：`_fee_draft` 多返回 `later_slip`；`_fee_post` 加没票没后补单的拦截、记 `later_id`。
- `LogisticsReview.jsx`：`FeeVoucherModal` → `FeeVoucherCard`；删总表上的 prompt 登记；第③步加登记制分支。

验证：本地渲染四种情形的版式；线上只读叠加——禾享那张现在没票、没登记后补单，新建被拦住，假设登记了后补单则模拟生成正常并带上后补单号。**页面没有在线上真点过，凭证没有真往金蝶写过。**

上线：后端有改动，需重启。
