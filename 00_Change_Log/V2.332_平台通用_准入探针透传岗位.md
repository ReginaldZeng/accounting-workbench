**【平台通用】准入探针透传岗位（配合 BP V2.303）**

## 起因

BP 侧 Owner 提出：工作台左下角要显示**用户名 + 岗位**——多账号切换、或数据域受限的人
（只看某个团队）需要一眼确认自己的身份。

BP 自身无登录，身份全靠本侧 `/api/bp-authz` 随准入透传（既有 `X-BP-User` / `X-BP-Perms`）。
**岗位只存在核算这边**（`users.post`），BP 拿不到，故随同一个探针一并发出。

## 改法（`app.py::api_bp_authz`，3 行）

```python
resp.headers["X-BP-Post"] = urllib.parse.quote(_post_label(str(u.get("post") or "")), safe="")
```

三个要点：

1. **发中文名不发 key**：`_post_label()` 把岗位 key 翻成中文（V2.52 起岗位是 key 化的
   `[{key,label}]`）。BP 不该反查我们的岗位字典——那等于把本侧的内部结构外泄成契约。
2. **percent-encode**：HTTP 头只认 latin-1，中文岗位不编码直接 500（同 `X-BP-User` 的既定处理，
   BP 侧 `_decode_header_user` 会 unquote）。
3. **try/except 包住**：岗位纯展示信息，取不到不能影响 BP 准入判定——探针的主职责是发权限码。

## ⚠ Nginx 必须同步加一行（否则 BP 收不到）

`/bp/` 那段反代里，与既有的 User/Perms 并列补上：

```nginx
auth_request_set $bp_post  $upstream_http_x_bp_post;
proxy_set_header X-BP-Post $bp_post;      # 覆盖注入，客户端伪造的同名头被盖掉
```

改完 `nginx -t && nginx -s reload`。**不加这两行不会报错**，只是 BP 左下角不显示岗位
（BP 侧对空值有兜底：无岗位则退回显示数据范围）——又是一个"静默不可用"，故在此显式记档。

## 验证

BP 侧 `GET /api/me` 带上模拟头，应返回：

```
user = 刘晓琪 | post = 电商运营 | teamScope = {restricted: True, teams: ['电商团队']}
```

（BP V2.303 已实测通过；本侧改动只影响探针响应头，不动任何权限判定逻辑。）

## 遗留

岗位当前只用于**展示**。若日后要按岗位做权限（如"所有成本会计自动获得某板块"），
应在本侧 `bp_perm_codes` 里按岗位派发权限码，**不要**让 BP 去解析岗位字符串做判断——
权限的真相源只有一处：`X-BP-Perms`。
