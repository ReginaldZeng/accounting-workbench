**【平台通用】一键启动重做：单窗口 + 后台服务 + 默认不弹浏览器；配套「停止全部」**。
**起因**：V2.173 的「一键启动全部」实跑翻车——它去调**每个工作树自己的 `启动.bat`**，
但按工作树分端口的新启动器只存在于本分支，其余工作树还是**旧版**：写死 8000、开机先 taskkill
掉 8000 上的进程、6 秒后各自弹一个 `localhost:8000` 的浏览器。结果一键下去 N 个黑框 +
N 个一模一样的 8000 标签页，且几条服务还在互相杀。业务方原话「一次给我打开五个浏览器」。
根因是设计错误：编排脚本不该依赖「每个工作树的启动器都是新版」这一未成立的前提。
**改法**（`start_all.ps1` 重写 + 新增 `stop_all.ps1`/`停止全部.bat`）：
①**不再调用任何工作树的 bat**——编排脚本自己按端口规则直接 `python -m uvicorn app:app --port N --reload`
后台拉起（`-WindowStyle Hidden`），日志落 `%TEMP%\fw_logs\<端口>_out/err.log`；
②**总共只有一个窗口**（打表用），关掉它服务照跑；
③**默认一个浏览器都不弹**，只打印地址表；`-Open 关键字` 才开、且只开匹配的那一条；
④前端过期且装过依赖的顺手重建（约 1 秒），没装依赖的不硬装（npm install 很慢），先跑现有界面并提醒；
⑤`停止全部.bat`：按各工作树固定端口找监听进程，`taskkill /F /T` **连进程树一起杀**——
`--reload` 是父子两个进程，只杀父进程会留下半死的监听（V2.173 实测就出过一个杀不掉的 8017 僵尸，正是这个原因）。
**验证**：①实跑一次：一个窗口内后台拉起 8017/8021/8093，8000（已在跑）自动跳过，全程零弹窗零新增黑框，
表格正确显示 4 条的 名称/分支/端口/前端新旧/在跑；
②`curl` 实证 8021 提供的是 july 分支产物 `index-B-SumEce.js`（内含 V2.176「刷新回执」字样 5 处），
与 8000 上 main 的 `index-kNZMuzWR.js` 是两份——「哪条线在哪个端口」从此可复核；
③僵尸 8017 用进程树方式一次杀净。
**顺带查明的误会**：业务方反映「数据更新还是没显示 XXX 于什么时候更新」——该功能是 july 分支的
V2.176（`23a162b`），当时 8021 **没在跑**，业务方看的 8000 是 main，本来就没有这个功能。不是功能坏了。
**遗留**：①后台跑意味着「关窗口≠停服务」，习惯改变已写进 README 与表头提示；
②july 线在其分支上已用掉 V2.173–V2.177 的版本号（旧式记法），与本线片段号有重叠，
按分片化防撞号规则，**后合并的一方在合并时改号归口**（有 V2.167 撞号先例）。
