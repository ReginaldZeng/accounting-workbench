## E2E 验证（本机全链路，真 DeepSeek）

1. 网关 health：deepseek configured（keyHint 打码）、adminEnabled=true。
2. 管理 API 签发 tok_bp（允许集 deepseek-chat/reasoner，500 次/200 万 token 日额度）。
3. 直调网关：中文对话 200（「收到」）；指定 gpt-4o → 403 越允许集；伪造凭证 → 401。
4. **BP 两行 .env 切换**：`BP_LLM_BASE_URL=http://127.0.0.1:8020/ai` + `BP_LLM_API_KEY=tok_…`，重启 8010——
   BP health 显示 baseUrl=网关、keyHint=tok_***（打码）；真问数「本月客户收入排名前三」全链路走通；
   网关流水：workbench=bp、user=网关验收（body user_id 兜底生效）、2456 token。
5. 吊销凭证 → BP 下一次调用立即 502（detail 含打码 tok_***31e6，不泄漏完整凭证）。
6. **BP .env 已回切直连并复验**（本机 BP 不依赖网关进程常驻）。
7. 门户 UI（8000 实测）：模型配置页 ②-c 渲染凭证表（打码）+ 签发表单；UI 签发成功弹一次性完整凭证横幅
   （含两行 .env 指引），列表新行仍打码。py_compile / vite build PASS。

## 边界与遗留

1. **key 与凭证纪律**：厂商 key 永不出网关进程；完整内部凭证只在签发/轮换响应出现一次；一切列表/报错打码。
2. MVP 不支持 stream；「更换密钥」有意不做 UI 写入（key 永不过浏览器），仍走 .env。
3. 服务器部署顺序建议：传包 → 网关 .env 配 GW_ADMIN_TOKEN + GW_DEEPSEEK_API_KEY →
   `start_gateway.bat`（或宝塔加 8020 Python 项目）→ 模型配置页签发 tok_bp →
   **BP 是否切网关由 Owner 择时**（改两行 .env 重启，回退同样两行；建议网关先稳定跑几天）。
4. X-AI-User 伪造头剥离（P3）与核算侧 X-BP-* 剥离同批做，老账未清，网关 trust 口径与 BP 用量看板一致。
5. 同批 BP 侧 V2.229（AI 分析/chat 落审计账）记在 BP 台账，互为引用。
