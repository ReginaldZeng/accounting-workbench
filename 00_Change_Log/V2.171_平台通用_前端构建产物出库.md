**【平台通用】前端构建产物 `backend/static/` 出库，改为按需重打**。
**起因**：`vite.config.js` 把构建产物直接打进 `backend/static/`，而该目录入了 git。Vite 按内容 hash
给包命名（`assets/index-<hash>.js`），**每条并行分支构建出的文件名都不一样** → 合并时
`static/index.html` 每次必冲突（最近 60 次提交被改 16 次），还会残留一堆旧 hash 的死文件；
而 minified bundle 的内容冲突根本没法手工解，只能重打。这与项目自己的原则也矛盾——`.gitignore`
里已写明「部署包＝构建产物，源码在库随时能重打」，`04_部署包/` 整夹不入库，唯独 `static/` 例外。
**改法**：①`.gitignore` 加 `01_Current_Deliverables/app/backend/static/`，`git rm -r --cached` 取消跟踪
（本地文件保留，历史不动；`02_Revision_History/` 下的版本快照维持原样不受影响）；
②新增 `01_Current_Deliverables/app/build_frontend.bat` 一键构建（自动 npm install → build → 校验产物存在，
支持 `/auto` 静默模式；文件名与内容全 ASCII，遵守既有「.bat 内禁非 ASCII，防 GBK 码页炸」的约定）；
③项目根 `启动.bat` 与 `app/启动.bat` 各加一段守卫：检测到 `static/index.html` 缺失就自动调 build_frontend.bat，
构建失败则明确提示「后端仍会起，但只有 /api/* 能用」而不是让人对着白页猜。
**验证**：①后端本就内建 `static/` 缺失的兜底分支（`app.py` 末尾 `else` 返回提示 JSON），出库不会让服务起不来；
②`git check-ignore -v` 确认忽略生效、`git status` 确认本地文件未被删。
**遗留**：**打后端部署包前必须先构建前端**，否则 zip 里没有前端、服务器上只剩 API——已写进
`README_本地应用_v1.9.md` 的影响对照表。另：新克隆的机器首次启动需要 Node.js LTS，没装会给出安装提示。
