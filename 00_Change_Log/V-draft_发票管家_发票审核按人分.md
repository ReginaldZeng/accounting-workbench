# V-draft 发票管家：发票审核按人分

**起因**：现在「发票审核」是一个公共队列，谁有权限谁都能审。用户 2026-10-13 逐条定下：审票要分人，
接入审批人名单同时就是审票分工表；切换期四位会计还在用票总管，单不能一直往他们名下堆。

## 这一稿做了什么（只有后端，页面没动）

**1. 票夹上记「归谁审」**（`inv_folder` 加 6 栏：`owner_uid / owner_account / owner_name / owner_at / owner_by / owner_via`）
- 和原有的「实际谁审的」（票夹 `reviewed_by`、每张票 `review_by`）是两样东西，分开存。
- 自动接入的记钉钉身份（那位会计可能还没有工作台账号）；认领、转交的记工作台账号。
- 判「是不是我的」时现对：账号认的钉钉身份（钉钉免登记在账号上的＋发票管家设置「财务人员」里绑的）对得上就算。
  所以人后来才开账号也接得上，不用回头改数据。
- 老库缺这几栏：启动时自动补（`invoice_store.ensure_columns`，全是可空栏，老数据不动；回退旧代码时多出来的栏没人读）。

**2. 每位接入审批人带自己的启用日**（设置 `intake.approvers[].since`，留空＝还没启用）
- 只有**提交日**在这个人启用日当天及以后的单，才因为走到他的节点而接进来、记在他名下。没启用的人等于不在名单里。
- 一张单经过几位的，归**最先走到、且对这张单已启用**的那位（按钉钉任务生成的先后）。
- 原来的全局起始日不再参与判断（免得两个日期打架）；老设置里没有启用日这一栏的人，沿用原来的全局起始日，升级前后他接哪些单不变。
- 改了谁的启用日，只从他的启用日起重新列一遍；别人已有的票夹不动。
- 一位都没启用 → 不扫，并写明原因。

**3. 建票夹时就指派清楚**（用户 2026-10-13 晚看样机后改：「不应该进未分派，建了票夹一定是指派清楚的」）
- 有付款单的（钉钉自动接入、收票台扫付款单、后补单、物流对账带进来的）：按审批流找最先走到、且已启用的接入审批人。
- 找不到、或者没有付款单的（收票台新建票夹）：建的人指定一位审核会计；没指定、自己能做发票审核的 → 归自己。
- 实习生（自己审不了）建票夹 / 扫一张系统还没接进来的付款单：不指定审核会计就不让建（接口回 `needAuditor`）；手机上选不了人，提示到电脑收票台扫。
- 后补单带进来的：审批流找不到时归后补单的接收人，再不行归登记的会计自己。
- 实在指派不上的（老数据、接收人做不了审核）留空，只有管理员看得到，由管理员派给某位；「我来审」认领的接口留着给这种情况用（两人同时点只成一个）。

**3a. 没有付款单的票夹：名字系统起、一个票夹只装一家主体**（用户 2026-10-13 晚定）
- 名字＝主体简称-审核会计-开票年月＋进项认证（批量手工 / 单张手工），例：`孝感星期九-陈梓华-202608进项认证（批量手工）`。
  简称读基础数据「主体档案」，不另配；转交以后名字不跟着改。
- 批量（月末一次性）：同一家主体、同一位会计、同一个开票月份只用一个——还在收票就接着用，交上去以后再建排 -2、-3。单张：每次新建，从 -1 排号。
- 建的时候主体必选（接口 `POST /api/inv/folder/manual` 带 `month` 即走新写法，另收 `company`、`way`、`auditor`；不带 `month` 的老页面照旧自己填名字）。
- **按抬头自动分主体**（用户：「主体要分开，要么你自动识别」「做，自动分主体」）：
  - 建的时候主体选「自动识别」（接口 `company: "auto"`）→ 先建一个「主体待定-会计-年月…」的收票口；票放进来，系统读抬头（税号优先、其次名称），
    挪到那家主体自己的票夹（没有就建，归属／开票年月／方式照抄），收票结果里写明「抬头是××，已放到「…」」。
  - 直接选了某一家的票夹里放进别家的票，也自动挪到别家的票夹。
  - 抬头读不出来的（扫码枪扫的二维码里没有抬头、识别失败）留在原处；「主体待定」的收票口里还有票就提交不了，
    由人定是哪家（`POST /api/inv/item/{id}/company`）或移除。抬头不是本公司的不挪，照旧标红。
  - 图片跟着票走：同一个文件里的几张票一起挪；一个文件里有两家主体的票、或还有票在识别 → 这个文件先不动。
    识别是后台做的：识别完、或人手补了抬头以后，再看一次要不要挪。
  - 只动新写法建的、还在收票的票夹里没提交的票；老的手工票夹、钉钉付款单的票夹不动（主体以付款单为准）。
  - 开票月份和票夹的不一样：提交时提醒一句，不拦。
  - 库表：`inv_folder` 再加 3 栏 `bill_month / batch_way / auto_split`（可空，老库自动补）。

**3c. 对纸质票**（用户 2026-10-14 定；新文件 `routers/invoice_check.py`，新表 `inv_check` / `inv_check_hit`）
- 月末准备认证时：选中一堆票夹开一次「点验」，把手上的纸质票连续扫一遍，看和这些票夹里的是不是一样。收票工作台、发票审核都能开。
- 电脑扫码枪和手机都能扫，记到同一次（一个人同时只有一次在对）。扫到选中票夹里的 → 记「扫到」（页面上那一行变绿）；同一张再扫 → 重复、不重复算；
  别的票夹里的 / 系统里没有的 → 只提醒（写明在哪个票夹、归谁审），不登记也不挪。接口回 `say`：确认／重复／不在这里／没有这张，给手机念。
- 「扫到」按这一次点验单独记，不看纸质件已到（审核时就记了已到，月末再对会一上来全是到了）；扫到的票顺手把纸质件记为已到。
- 没有二维码的票（收据、定额票、出租车票）手工勾。可导出没扫到的清单。只有开这次点验的人能看、能往里扫。
- 手机走收票工作台原有的手机配对（`/api/inv/m/check`、`/api/inv/m/check/scan`）——所以手机扫要有收票工作台的收票权限。
- 接口：`POST /api/inv/check/start`、`GET /api/inv/check/current`、`GET /api/inv/check/{id}`、`POST …/scan`、`POST …/mark`、`POST …/close`、`GET …/export`。
- **没验证的**：手机在钉钉里能不能念出声、连续扫的手感，要真机试；念不出来就退成提示音加震动（做页面时定）。

**3b. 审核的闸**（后端拦，不只是藏按钮）：通过、逐张标记、退回、批量通过、审核时改票，都先过同一道闸
- 归别人的：普通会计只读；有「审核分派」权限的人可以直接审——留痕写明「归甲、由乙审」。
- 归的那位还没有工作台账号 / 没开通发票审核：票夹照样记在他名下，页面写明原因，由有权限的人转交或直接审，不掉回公共队列。
- **「不能审自己提交的」对归属人放开**（用户选的）：这张单本来就归他审——会计自己建、自己扫、自己审，或者把纸质票扫进自己名下的付款单——放行，
  留痕标「自审」。不归他的照旧拦（有「审核分派」权限的人审别人名下的单，里面有他自己登记的票也不行）；主管理员照旧放行。

**4. 转交**：本人能转出自己名下的；有「审核分派」权限的能转任何人名下的，也能把未分派的派给某人。
原因必填；接收人要是能做发票审核的账号；留痕记谁转的、从谁到谁、什么时候、为什么。转完原来那位（普通会计）就审不了了。

**5. 新权限点** `inv_assign`「发票管家·审核分派（看全部人名下积压/转交/直接审别人名下的）」：敏感点，默认谁都不给；
主管理员恒有、核算子管理员恒有，其他人靠勾选。

**6. 各人名下积压**：每人名下待审几张、最久等了几天；有「审核分派」权限的看全部人，别人只看自己名下和未分派两个数。

## 页面（第 3 批：对纸质票，2026-10-14 做完）

  同一张再扫＝黄字「这张扫过了」；别的票夹里的 / 系统里没有的＝红字写明在哪，并列在下面「扫到过 N 张不相干的票」里。对上了一声短音，不对的两声低音。

## 新接口

| 接口 | 作用 |
|---|---|
| `GET /api/inv/audit/queue?scope=mine/none/all/<某位>` | 审核队列按人看；每行带 `owner`（归谁、是不是我的、我能不能动、那位审不了的原因） |
| `GET /api/inv/audit/backlog` | 各人名下积压 |
| `GET /api/inv/audit/people` | 转交给谁的下拉（只列能做发票审核的账号） |
| `POST /api/inv/audit/claim` | 我来审（只给没指派上的老数据用） |
| `POST /api/inv/folder/manual`、`POST /api/inv/desk/scan` 加参数 `auditor` | 建票夹时指定审核会计 |
| `POST /api/inv/audit/assign` | 转交（原因必填） |
