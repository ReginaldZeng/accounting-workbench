**【银行对账】上行取件机补 PowerShell 版——取件机没装 Python 也能用**。
**起因**：V2.486 的上行取件机只有 Python 版（bank_pull.py）。真机部署时发现取件机上 `python --version`
零输出——没装可用的 Python。而报表取件机（pull_reports）本就有 .ps1/.py 双版本、默认走 PowerShell 正是
为"这台电脑不需要装 Python"。上行脚本理应同款。
**改法**：新增 `tools/bank_pull.ps1`，与 bank_pull.py 功能完全相同、读同一个 bank_pull.ini：
扫共享盘月目录→稳定期判据（连续 settle_minutes 分钟不变才推）→增量按 size+mtime→推 /api/bank-pull/push→
收齐 commit→回报 report。三条铁律仍由服务器侧强制（只推不删、不覆盖人工上传、保留人工确认闸），
脚本端只管扫和推。PowerShell 特有坑均已处理：①**文件存 UTF-8 with BOM**（PS5.1 无 BOM 按 GBK 读中文全乱，
仓库内已带 BOM）；②响应体 UTF-8 手工解码（PS5.1 无 charset 会乱码）；③请求头 X-Bank-Relname 用
[uri]::EscapeDataString 编码（中文文件名，头传不了非 ASCII）；④状态文件 JSON 反序列化 PSCustomObject→hashtable。
安装说明补双版本选择表（默认 .ps1）与 BOM 警告。
**验证**：①`[Parser]::ParseFile` 语法检查过（转 BOM 后）；②本机起测试后端(8096)+测试 pull_token，
用桌面 6 月真实散件跑完整上行：建基线→推 25 文件→**并入 622 笔·待确认重复**，与 Python 版结果一致；
③"不覆盖人工上传"铁律在 PS 版同样触发（本期已有人工数据时 commit 返回未覆盖）。测试数据/conf.ini/库跑完即清，0 入 git。
**遗留**：真机上 `bank_pull.ini` 待填（server/pull_token=与报表取件同一个/src_root=共享盘资金流水年目录）+
注册每小时计划任务（独立于报表取件机任务，见安装说明）。
