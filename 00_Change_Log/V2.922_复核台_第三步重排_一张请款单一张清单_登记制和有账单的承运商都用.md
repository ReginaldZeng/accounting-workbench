## 起因

用户看禾享 2026-08 的第③步：「这个页面好乱的感觉」。V2.921 先删了没意义的字和空表；用户让出样机（`docs/20261012_登记制第三步重排/prototype/reg_step3.html`），看后：「这个没问题」。
开发途中又问：「别的物流账单也可以这样吗」——可以，一并做了。

## 改成什么样

原来第③步是几张卡各说各的。现在**一张请款单一张清单**，从上到下四件事，每件事右边一个结论：

| 行 | 内容 | 右边的结论 |
| --- | --- | --- |
| ① 费用凭证 / 计提凭证 | 哪张凭证、费用类型·产品线、含税、税率和暂估进项税 | 已认定 / 已生成 / 已计提 / 待做 |
| ② 和请款比 | 费用凭证（计提）合计 ＝ / ≠ 请款金额，不等写差多少 | 一致 / 不一致 |
| ③ 发票 | 到了几张、含税和税额；没到就写后补单是哪张 | 票齐 / 票齐·要更正 / 对不上 / 已确认后补 / 缺后补单；「确认发票后补」按钮在这一行 |
| ④ 做账 | 系统接下来会做什么；做完写凭证号 | 等系统做 / 等发票 / 已做账 / 做完了 |

- 要人动手的那一行有底色；等前面条件的行是灰的。
- 「③ 发票」下面会写发票和计提怎么个对不上法（税率不同要红冲更正、尾差、金额不符），原话取自付款做账的做账类型。
- 「④ 做账」只做支付的会把两行分录写出来（借供应商往来 / 贷银行存款）。

### 登记制（禾享、路凯这类没有账单的）

- 顺序：请款单清单 → 「确认与登记」→ 明细对照表（收起，点开才看）。
- 费用凭证还没做的：第①行展开成原来那张「项目｜上一次｜这次用」的填写表，核对打勾后生成——逻辑没动，只是挪进了这一行。
- 「确认与登记」里那张「主体 / 计提 / 请款 / 差」的小表，只在有几个主体或有差异时才出（单张请款单时第②行已经写了）。
- 有请款单没票、发票后补也没确认的：登记按钮下面提醒一句「可以登记，但确认之前系统不会给它做账」。能登记（用户看样机时认可）。

### 有账单的承运商（恒茂、极鲜达、链盟…）

- 顺序：原来的复核结论和登记（没动）→ 请款单清单 → 「发票与暂估」大对照表（照旧摊着，账单两列对这类承运商有用）。
- 大对照表里不再重复放「确认发票后补」按钮（挪到清单的第③行）。
- 清单不读「上一次的费用凭证」，不多调金蝶接口。
