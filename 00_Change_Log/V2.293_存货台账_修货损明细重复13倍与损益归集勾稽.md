业务方拿导出的 7 月台账，从「损益归集」的货损合计画了根箭头指向「原始·货损与处置明细」页：

## 事故：明细页金额是真值的 13 倍

| 页 | 金额 |
|---|---|
| 损益归集 · 货损合计 | **324,529.82** |
| 原始·货损与处置明细 · 物料级合计 | **4,218,935.14** |

差 3,894,405.32。

### 根因

导出明细页时**按【凭证分录】循环**，每遇到一条分录就把该单据的物料行整套写一遍：

```python
for x in pd["loss"]:                      # 凭证分录，一张单据可能有多条
    ms = by_bill.get(x["billno"])         # 该单据的全部物料行
    for d0 in ms: 写一行                   # ← 第 2..n 条分录会把同一批行再写一遍
```

而**一张单据在总账里常常拆成多条分录**。🧪 2026-7：一张出库单 `QTCK011302`（凭证 记570）
在总账里拆成 **13 条**——报废出库无半成品／无原料／无包材／无零售其他／无植物肉／
无零售山姆／无小料／无豆蛋制品／无海外，各记一条。于是该单的 122 行物料明细被写了 13 遍：

```
122 行 × 13 = 1,586 行          ✓ 与导出件的 1,586 行吻合
324,533.78 × 13 = 4,218,939.14 ✓ 与导出件的合计吻合
```

**2026-3 每张单只对应一条分录，所以碰巧一直是对的**——又一次"单月验不出来"
（同 V2.259「生产退库」：3 月没有那类单据，等式碰巧成立）。

### 修

物料行**按单据写一次**（`seen_bills` 去重），凭证字号取该单第一条分录的。
🧪 7 月明细页 **1,591 行 → 130 行**，物料级合计 324,529.78。

## 顺着业务方的话做实：两页显式勾稽

数字修对了还不够——业务方要的是**看得见的勾稽关系**。损益归集块新增三行：

```
货损合计（凭证侧）          324,529.82     ← 值
　明细页回查合计（流水侧）    =SUMIFS('原始·货损与处置明细'!P:P, …!A:A,"管理费用·货损")
　差异（应为 0）             =B36-B37       → 0.04
处置合计（凭证侧）          0.00
　明细页回查合计（流水侧）    =SUMIFS(…, "营业外支出·处置")
　差异（应为 0）             → 0.00
```

⚠**没有把本页的数换成明细页的 SUMIFS**——这点与 D24 的"能引底表就引"看似矛盾，实则不是：

- 本页 ＝【凭证侧】，科目余额表下钻取的管理费用/营业外支出分录，**进总账的就是它，权威**；
- 明细页 ＝【流水侧】，拿单据号回查收发存流水得到的物料级明细，是**回查**、不是来源。

回查可能对不齐（单据在流水里查不到、或流水报表自身尾差）。硬把本页改成明细页的公式，
等于**让权威数跟着回查结果走**——本末倒置。正确做法是两侧并排 + 差异，差异不为 0 自己现形。

明细页两种版式（物料级 16 列金额在 P／凭证级 7 列金额在 F），公式**按实际版式生成列位**，不写死。

### 🧪 三期实测

| 期间 | 凭证侧 | 明细页回查 | 差异 |
|---|---|---|---|
| 2026-7 货损 | 324,529.82 | 324,529.78 | **0.04**（流水报表四舍五入尾差，同事务类型透视的 1.59 元） |
| 2026-3 货损 | 18,881.52 | 18,881.52 | **0.00** |
| 2026-5 货损／处置 | -4,874.95／8,912.37 | 同左 | **0.00／0.00** |
