# V2.335 · 临时工考勤 · 异常认定（确认无误后不再报）

> 需求方 2026-08-22：「这个异常要怎么消除，我确定他不是异常了就可以消除才对」。

## 一、做成「认定」，不是「删除」

**能把发现无痕抹掉的审计工具，本身就没有价值。** 所以不提供删除，只提供表态：

- 认定后那一条**仍在**，只是从「待认」移进「已认定」区
- 记着**谁、什么时候、因为什么**认的；**理由必填**——
  将来翻这份底稿的人，要知道当时为什么认为它不是问题
- 随时可**撤销**（认错了要能改回来，否则没人敢点第一下）
- 全程留审计

## 二、两档范围

| 范围 | 适用 | 说明 |
|---|---|---|
| **本期** | 全部类型 | 只对这一期生效 |
| **长期** | 仅归属不符 / 同名 / 打卡重名 | 以后每期同一条都不再报，给「浮动组」这类长期安排用 |

**逐日类（多记、待查）不允许长期**——日期是期内的，跨期认定没有意义，接口直接拒绝并说明理由。

长期认定会持续压住提示，所以页面上**永远显示「已认定 N 项」并可展开**，不让它彻底消失；
弹层里也写明「会持续压住提示，情况变了也不会再提醒，慎用」。

## 三、存储与留档的关系

认定**独立存**，不进结论快照：

- `tempatt_ack_<YYYY-MM>`（本期）、`tempatt_ack_standing`（长期）
- 结论快照里**不带**认定标记，返回时才盖上——所以**改参数重跑之后认定照样生效**，不会被覆盖掉

## 四、覆盖范围

可认定：归属不符、同名多行、打卡表重名、⚠超弹性多记、待查、金额核对、奖罚异常。

页面上两处入口：
- **结算风险卡**——每条一个「确认无误 →」；卡片标题随之变化，全部认完变成「本期全部已认定无误」并由红底转灰底
- **第⑤步逐日明细**——多记/待查行末尾直接认定或撤销，判定列打 ✓已认定（悬停看理由）

本期状态条改为**只按未认定条数亮红**，另加一条「已认定无误 N 项」——
否则会出现「一边说已认定、一边还红着」的自相矛盾。

## 五、实测

| 项 | 结果 |
|---|---|
| 不填理由 | 拒绝并说明为什么要填 ✓ |
| 逐日类想选长期 | 拒绝并说明哪些类型才可以 ✓ |
| 类型乱填 | 拒绝 ✓ |
| 认定（长期/本期） | 生效，条目移入已认定区 ✓ |
| 撤销 | 回到待认 ✓ |
| **长期认定跨期生效** | 新核 2026-05：程爱莲已带长期认定，周文秀仍待认 ✓ |
| 审计 | 认定/撤销各留一条，含范围与理由 ✓ |
| 浏览器全流程 | 弹层出现 → 空理由时提交禁用 → 填了可提交 → 卡片转为「全部已认定无误」→ 展开见谁/何时/理由 → 撤销复原 ✓ |

内核回归 **196 项全过**（本次不动内核）。

## 六、过程中发现的两件事

1. **`打卡表重名` 内核出的是纯姓名列表**，加认定要转成对象。第一版只在「有认定时」才转，
   前端就得同时应付两种形态——已改成**不管有没有认定都转**。
2. **调试时被一个旧进程骗了**：8071 上残留着上一轮的服务，新起的那个没抢到端口就退了，
   而 `/api/health` 照样 200，于是页面一直在跑旧代码，看起来像认定不生效。
   以后验证前先确认端口上跑的是不是刚起的那个。
