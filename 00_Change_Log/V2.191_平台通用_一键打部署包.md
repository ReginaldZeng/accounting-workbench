**【平台通用】一键打部署包（pack_deploy.bat + pack_deploy.py）**。
**起因**：双色调(V2.189/190)要让同事用上必须部署服务器，而历次部署包全靠手工打、口径靠记忆
（V2.171 前端产物出库后又多一个"忘构建就发旧界面"的坑）；且 V2.176 有遗留——服务器无 `.git`，
不写戳记文件左下角显示不出版本。
**改法**：①`pack_deploy.py` 把 V2.177 手工包的**白名单口径固化成代码**（top 层 py/conf.ini.example/
requirements + kernels·routers·tools 的 py + static 全量 + sample_data 四个白名单文件；
conf.ini/workbench.db/bank_uploads/真实运行数据永不进包），本次起新增 core.py 与 routers/（V2.172 拆分后
服务器缺了它们起不来）；②打包时自动生成 `backend/version_stamp.json`（ver/branch/commit/packed_at/dirty，
ver 取台账片段最大号与提交标题 V 号较大者）——服务器上 core.VERSION_INFO 读它，左下角从此显示版本；
③打包前校验**前端产物比源码新**，旧了直接拒绝（防发旧界面）；工作区 dirty 时告警并标进戳记（口径=应用目录内已跟踪文件的改动）；⑤**只收 git 已跟踪的源码**——工作区里未提交的在途文件（如其它开发线的半成品）自动跳过并明示，绝不上服务器（static/ 与戳记为有意生成的产物，豁免）；
④`pack_deploy.bat` 一键=先构建前端再打包，产物落 `04_部署包/finance_workbench_backend_V<版本>_<日期>.zip`，
末尾打印宝塔上传三步与验收点。version_stamp.json 加入 .gitignore（本地有 git 用不上它）。
**验证**：实跑产出 `finance_workbench_backend_V2.190_20260805.zip`（49 文件 0.5MB），
zip 内含 core.py + routers/5 模块 + version_stamp.json + 新前端产物；与 V2.177 手工包 diff 顶层结构一致。
**遗留**：打包脚本不做上传——上传/解压/重启仍在宝塔手工做（生产动作留人手，符合一贯原则）。
