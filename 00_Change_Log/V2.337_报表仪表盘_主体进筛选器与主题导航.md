# V2.337 报表仪表盘 · 主体进筛选器与主题导航

日期：2026-08-22　作者：Claude / c　范围：纯前端（`views/ReportDashboard.jsx` + `views/report.css`）

## 起因

业务方看了深粮控股那套数据可视化，觉得对方做得更好。逐屏比对后的判断是：对方赢在第一眼
（主题入口、留白），我们赢在第二眼（每个数写出基准值、口径说明栏、勾稽与过账状态前置）。
样机 v0.1 / v0.2 见 `03_Source_Materials/00_平台通用/报表仪表盘_主题导航_样机_v0.*.html`。

**取数、口径、勾稽一律没碰。** 内核、路由、`reportShared.js` 语义层零改动。

## 改了三处

### ① 主体：横排切片行 → 筛选器内下拉

删掉 `.ents` 那排按钮，主体成为切片器里的第一项。原生 `<select>` 的 option 渲染不了
「名称＋金额＋状态」这种富内容，故按 `components/PeriodPicker.jsx` 的写法自建下拉
（`.entpick` / `.entmenu`）。

下拉里保留了收入与「亏」——挪进去不能把这两个状态丢了。**并且补上了口径**：

    数字＝本年累计营业收入（万元）·「亏」＝本年累计净利润为负

这行是**动态**的，跟着 `st.basis` / `st.unit` 走。原来的切片行只印一个数和一个「亏」字，
没说那个数是收入还是资产还是利润；写死成"本年累计·万元"在切到单月或元时就是错的。

「集团合计（未抵消）」单独成组、与八个主体用分隔线断开——它不是第九家公司，口径也不同。

**期间选择器没动**，仍在页头右上：成本台账、成本看板、物流成本三个页面的页头也是这个位置，
挪走会破全站一致性。样机里把期间画进了筛选栏，这点以真页面为准。

### ② 主题导航条（新增）

页内本就有 `01 发生了什么 / 02 为什么会这样 / 03 下一步看哪里 / 04 三大报表` 四步叙事，
但只能滚过去、点不到。做成可点索引并吸顶，再把埋在 03 里的两个高频入口提出来单列：

| 主题 | 锚点 |
| --- | --- |
| 总览｜这个月怎么样？ | `#rpt-kpi`（新加） |
| 发生了什么｜收入到净利，钱去哪了？ | `#rpt-s1` |
| 为什么会这样｜费用和占用压在哪？ | `#rpt-s2` |
| 八主体横比｜哪几家在亏？ | `#rpt-cmp`（新加） |
| 勾稽自检｜这批数能不能用？ | `#rpt-tie`（新加） |
| 三大报表｜我要看原表 | `#rpt-s4` |

六个主题是从**我们自己已有的内容**长出来的。没照抄对方那套（盈利/偿债/营运/成长/现金流/
杜邦）——那要三大报表加多年数据，我们只有资产负债表与利润表，照搬会做出几个空页。

高亮由 `pickTheme()` 决定：取「最后一个已滑过判定线（视口上沿下方 108px）的锚点」。
触发器用 IntersectionObserver 加 scroll/resize 双保险，**并且点击时立即高亮**，不等滚动事件。

### ③ KPI 基准行两行对调

`基准 <名> / <值>` → `基准 <值> / <名>`。基准值本身比"基准的名字"更常被用到。

## 实测（探针页挂真组件 + 合成数据，验完已删）

* 下拉：点开／点外面关／Esc 关／选项切主体／选后自动关／切后「亏」跟着走 —— 7 项全过
* 下拉浮层 336×326，无祖先裁剪，1100px 窄屏下不顶出右边界
* 主题导航点击高亮 5/5；`pickTheme()` 在 6 个滚动位置的选取结果全部正确
* `scroll-margin-top`：原 `.step` 规则里的 14px 与新加的 64px **同特异性**，后写的赢，
  故直接改在原规则上，别再叠同名规则
* 暗色：吸顶条底色与页面底色两个主题下完全一致（用全局 `--bg`，不是 `--surface-1`——
  暗色下两者 `#16181d` vs `#1a1a19` 不同色，会露出色差带）
* 1440/1600px 切片器与主题条均单行；1100px 切片器折 2 行、KPI 转 3 列；均无横向溢出

**没验到的一项**：滚动时自动换高亮。浏览器面板处于隐藏态、不产生合成帧，
scroll 事件与 IntersectionObserver 回调（含规范保证的首次回调）**一次都不投递**。
选取逻辑与点击高亮已单独验证，触发器本身待真机确认。

## 一处要更正的说法

改版前我说这么改能"两条控制区合成一条、省下一整条横向空间"。**实测是反的**：

| 视口 | 改版前（切片器＋主体切片行） | 改版后（切片器＋主题条） | 差 |
| --- | --- | --- | --- |
| 1600px | 132 + 24 = 156px | 132 + 64 = 196px | **+40px** |
| 1100px | 151 + 47 = 198px | 151 + 64 = 215px | **+17px** |

主体切片行本来就很紧凑（1600px 下只排 1 行、24px）。这次改动是**多占**垂直空间，不是省。
换来的是三样：所有切片集中在一处、金额有了口径说明、多了一个可点且吸顶的索引。
「八家一眼扫完」这件事移交给「八主体横比」那个主题——横排切片行本来就与它重复。
