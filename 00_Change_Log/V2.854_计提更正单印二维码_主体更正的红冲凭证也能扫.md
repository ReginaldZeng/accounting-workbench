# V2.854 计提更正单印上二维码：主体更正的红冲凭证没有纸质付款单，也能扫出来该订在哪

日期：2026-10-06

用户：「常规的肯定没问题，但是那种做错主体，需要更正的，他没有二维码，我们怎么去让小朋友知道呢」。

主体更正会出两张凭证：本主体的付款凭证（有纸质付款单、有钉钉二维码）和原主体的红冲凭证（系统在那边账簿新建，**没有纸质付款单**，只附计提更正单 ①）。实习生手里没有能扫的东西对应那张红冲凭证。

做法：没有二维码就给它印一个。
- 每张计提更正单右上角印系统自己的二维码，内容＝「钉钉审批编号#页别」（0 普通更正单 / 1 主体更正 ① 原主体红冲 / 2 主体更正 ② 本主体补提），下面一行小字「装订时扫这里」。
- 主体更正 ① 那一页另加一行粗字：「本页订在 ××（原主体）的红冲凭证后面（那张凭证没有纸质付款单）；凭证号扫右上角二维码看」。
- 扫码识别（电脑扫码枪 / 手机钉钉扫一扫 / 传照片都认）：
  - 扫更正单 ①：大号显示**原主体 + 红冲凭证号**，另列本主体那张；红冲凭证还没建（付款凭证没保存到金蝶）时提示「建好再扫」。
  - 扫普通更正单 / ②：显示它跟着的那张付款凭证，提示「订在这张凭证后面，凭证号填到更正单上」。
  - 扫主体更正的纸质付款单：结果卡写明「后面订着两张更正单：② 留在这张付款单后面；① 抽出来订到红冲凭证后面」。
  - 扫码枪在中文输入法下把 # 打成全角也认；扫不了可以输更正单上印的审批编号。
  - 扫更正单不算「纸质付款单扫过了」。
- 二维码生成：把 npm 包 qrcode-generator 2.0.4 的单文件（MIT 许可）放进 `frontend/src/vendor/`，没有加 npm 依赖——前端只有 react 两个依赖，别的并行会话不用重装。

验证：本地渲染三种更正单（普通 / ① / ②），用图像识别把二维码读回来，内容分别是 `…#0 / #1 / #2`；线上只读叠加——易风达更正单码返回 记-264，丰源更正单 ① 在红冲没建时给出提示，假设红冲已建时把「深圳星期零 红冲凭证」排在最前。**没有真打出纸来用扫码枪 / 手机扫过。**
