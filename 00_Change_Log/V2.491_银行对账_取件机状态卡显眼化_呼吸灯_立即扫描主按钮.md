**【银行对账】共享盘取件机状态条显眼化 + 呼吸灯 + 修误报"已停"**。
**起因**：需求方在真机跑通上行取件后提两点——①这条状态要**做明显**，因为"有时候发现数据有误、会让出纳更新到共享盘"，
更新后需要一眼找到并点「立即扫描」把更正数据重新接进来；②取件机在工作时要有**明显的呼吸灯**。
另发现：取件机 19:37 刚扫过，状态却显示"○ 可能已停"——误报。
**改法**：①状态条从灰色小条重做成**带色卡片**：在跑时整卡绿底绿框、一颗 **nav-pulse 呼吸绿灯**（复用 V2.173 左侧导航同款
呼吸动画，深浅主题跟令牌）；「↻ 立即扫描共享盘」升为**主按钮**（btn-pri，加大加粗）靠右显眼；新增💡说明
**"发现数据有误、让出纳更新共享盘后，点右上立即扫描即可马上重新接入，不必等每小时"**——正对需求方的纠错场景；
最近扫描时间加"刚刚/N分钟前/N小时前"相对时长。②**停/未部署改红色告警**（需求方追加："如果可能停了，要标记联系开发者才对"）——
取件机停了数据就断流，是需要有人处理的运维问题，不能是安静的灰圈：整卡红底红框、**红灯呼吸**、胶囊「⚠ 可能已停 / ⚠ 未部署」，
红字明写**"此时共享盘新流水不会自动接入，请联系管理员检查取件机（那台常开内网电脑是否关机/任务停了），期间可手工上传兜底"**。
③修 `_bankpull_view` 时间戳解析 bug：回报 `at` 是 `_now()` 的分钟精度（无秒），而解析写死 `%Y-%m-%d %H:%M:%S`（要秒）→
strptime 恒抛 → ago=None → alive 恒 False → 在跑也误报"可能已停"。改为两种格式都试（先带秒后分钟），修好，只有真超 1 小时没回报才红灯。
**验证**：前端构建过、app.py 语法过；独立预览页渲染两种状态（在跑呼吸灯脉动 / 停静态灰圈）确认视觉，已发需求方过目。
**遗留**：取件机每小时计划任务尚未在真机注册（手工验证已跑通：19:37 推 174 文件、8 月并入 442 笔·待确认重复）。
