# V2.458 · 撞名定人：临时工撞名「天天打卡的正式工」时不再被一倍闸门误挡

**日期**：2026-09-02　**分支**：main

Reginald（8 月实测）：丁菊华「报了工时没打卡」，但她明明上了 22 天班。

## 根因（老 bug，非近期改动）

钉钉里**两个丁菊华**（一个临时工、一个正式工，都在耕耘车间）→ `match_names` 判「撞名」不猜 →
`resolve_dups` 按「打卡日 vs 上工日」F1 定人，闸门要 **best ≥ 0.5 且 best ≥ 2×second**。
实测：临时工打卡正好落在 22 个上工日 → **F1=1.00**；正式工整月天天刷、也覆盖了那 22 天 → **F1=0.86**。
`1.00 ≥ 2×0.86=1.73` 不成立 → **定不了人 → 她所有上工日被判「报了工时没打卡」**。
这类「临时工撞名一个天天打卡的正式工」会**批量中招**（正式工 F1 天然不低）。

## 改法

定人闸门加第③条：**最高分近乎完美（≥0.85，即候选打卡日几乎正好＝上工日）且明显领先第二名（≥0.1）也算认**——
临时工「只在上工日刷卡」是它的铁签名（F1≈1、精确率≈1），正式工整月刷必然精确率低、F1 略逊。
势均力敌（两人都高、差不到 0.1）仍交人工，不猜。

```
ok = 只一个候选  或  (best≥0.5 且 best≥2×second)  或  (best≥0.85 且 best−second≥0.1)
```

## 校验

- 真数据（丁菊华 2026-08）：改后 `resolve_dups` **认成临时工 uid（尾号9276、22天、得分1.00、选中）**，正式工（0.86）不选，无「交人工」残留。
- 新增 2 单测：临时工胜过天天打卡的正式工✓；两人都完美→仍交人工✓。全量内核 118/118 全过。

批量取数（V2.419）已排除嫌疑：两个 uid 8 月打卡 批量口 vs 逐日口 逐格 0 不一致。
