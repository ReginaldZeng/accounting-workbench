# V2.919 付款做账：发票后补的单，确认之后也能自动做——先只做支付，票到了再转待认证

- 日期：2026-10-12
- 作者：Claude Opus 5.5
- 模块：应付板块 › 物流对账 › 付款做账（总表、自动做账）

## 起因

用户看总表上禾享国际物流 1,322.00 那一行（「票不齐 · 票夹没有发票」）：

> 这种怎么根据付款单做账呢，如果发票一直不到做不了？其实应该是直接去核销供应商往来吧，然后等发票到了单独做一个待认证？
> 如果提交了后补单的话

这个做法系统早就有（V2.832「发票后补，先做付款凭证」），但藏在凭证预览里，总表上看不出来；而且两笔都要人点，自动做账不碰。

讨论中我先提了「发票管家票夹审核通过」当放行条件，用户反问「如果是发票后补，怎么在发票管家审核通过呢」——查了发票管家的规则，只登记了后补、一张票都没有的票夹根本提交不了
（系统提示「票到了会直接进审核，不用提交」），这个条件是错的，撤掉。

用户最后定：「应该要在第三步确认下已确认登记发票后补之后」——保留一次人工确认（确认已登记发票后补），确认之后系统自动做。

## 现在的流程

| 步骤 | 谁做 | 说明 |
| --- | --- | --- |
| 1. 登记后补单 | 申请人 | 发票管家 |
| 2. 确认发票后补 | 财务 | 付款做账总表上直接点，或凭证预览里点；发票管家里没有后补单的点不了 |
| 3. 第一笔：只做支付 | **系统自动** | 借供应商往来 / 贷银行存款，暂估进项税先挂着 |
| 4. 发票到了，在发票管家审核 | 财务 | 票进票夹后照常审核 |
| 5. 第二笔：暂估转待认证 | **系统自动** | 发票审核通过、税额和挂着的暂估进项税一致（尾差以内）才做 |

第 3、5 步原来都要人点。人仍然可以自己点，系统做过了不会重复做。

## 自动做的条件

**第一笔**（做账类型「发票后补·先付款」）：

- 人确认过发票后补；发票管家里的后补单还开着；金蝶有付款单；
- 找得到计提或费用凭证，含税合计等于请款金额；
- 没有登记多收待扣回；不超过单笔上限；自动范围里勾了「发票后补·先付款」。

**第二笔**（「发票到了·暂估转待认证」）：

- 第一笔已经做过、还没转；票夹里有发票，且**每一张都在发票管家审核通过**；
- 发票含税合计等于计提含税合计，税额和暂估进项税差在尾差以内。

不满足时不做，并在自动做账的清单里写明原因：「发票到了，但发票管家里还没审核通过」「发票税额和暂估进项税差 26.57，超过尾差上限，要人工处理」。

票还没到的单，系统只看本地票夹、不去读金蝶，不增加接口调用。

## 页面

- **总表**：没票、但登记了后补单的行，原来只写「票夹没有发票」，现在写「已登记后补单 #2」，旁边一个「确认发票后补」；确认过的写「已确认发票后补 · 只做支付」。
- **自动做账栏**：范围里多一个勾选项「发票后补·先付款」（管第一笔和第二笔）。
- **做完提醒**：这两类各列一段，不算进「红冲更正」；第一笔的「接下来」写明暂估进项税还挂着、票到了系统会自动转。

## 验证

服务器上只读演练（新版别名加载，写库、留痕、钉钉都只记在内存，全程「演练」档不写金蝶）：

- 禾享那张没确认时：不在自动做账清单里；总表带出后补单 #2（待收，预计 2026-10-15，陈慧娴登记）。
- 内存里假装确认：清单里出现「发票后补·先付款 · 会做」，凭证只有两行——借 2241.02 1,322.00、贷 1002 1,322.00。其它单的结论和没确认时一样。
- 内存里假装第一笔已做、发票到了（假发票）：没审核 → 不做并写明；审核通过、税额 13.09 一致 → 会做；税额对不上 → 不做并写明差多少。

**没验的**：没有真写过金蝶（第一笔、第二笔的写入函数本身是 V2.832 就有的，人点过）；总表上的新按钮没在浏览器里点过。
