# V2.580 金蝶应收取数窗口加次月（T+1）：修跨期发货/入账滞后漏对平

## 现象
- 收入确认「应收待同步金蝶」一直挂着一批（如 38 单）：已按出库应收确认、却匹配不到金蝶应收。

## 根因（routers/ec.py）
- 金蝶应收取数窗口终点 `end` 一直是**当期期末**（08 期 = 2026-08-31）。
- 但月底发货的单，金蝶应收单据日期（FDATE）常落到**次月初**（跨期发货 / 金蝶入账滞后）→ 被期末切在窗外，永远对不上。

## 处置
- 新增 `_kd_ar_to(period)`：取数终点 = 当期期末往后 `forward` 个月的月末，`forward` 可配 `ec_kd_forward_months`，**默认 1 = 含次月**（设 0 则只到当期期末）。跨年、2 月边界均已测。
- 三处 `end` 改用它：`_sync_kd_receivables`（刷新缓存）、`_run_core` 实时拉取分支、逐单钻取（用 `run.period`）——三处口径一致，避免"对平认了、点进单里却显示无金蝶应收"的自相矛盾。
- 增量缓存判据加 `date_to`：窗口终点变了会自动强制一次全量重拉。

## 影响 / 口径
- 只是**把金蝶应收数据网撒宽到次月**去匹配，不改「应确认收入 = 出库应收（发货即确认）」口径；跨期发货单仍按实际发货期间确认、不会被错拉进本期。次月金蝶行只会匹配到本就属本期的出库应收（按 order_key），不重复记账。
- ⚠上线后需在收入确认点一次「刷新数据 / 只读同步」，让缓存按新窗口全量重拉。
