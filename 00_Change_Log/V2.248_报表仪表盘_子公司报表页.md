## 二、取数口径（==照搬已验证的样机脚本，不是重新发明==）

去重三条，缺一条就重复计数：

| 口径 | 为什么 |
|---|---|
| 服务端 `FDetailID=0` | 丢掉核算维度明细行，只留科目合计行 |
| 本地「币别为空」 | GL_BALANCE 同一科目会返回「综合行 + 各币别行」，不滤则金额翻倍 |
| 只取 4 位一级科目 | 避免父子科目重复相加 |

**利润表取单边累计**：损益类已按月结转、净额被抹平，所以收入类取==累计贷方==、成本费用类取==累计借方==。

**为什么自建按期循环查询、不复用 app 的 `_kd_get` 当期缓存**：子公司报表要画跨期趋势（单月营收/净利、同比），必须拿到 2024-01 至今**每一期**；而 app 那个缓存只有当期一期。故内核自建按期查询 + 结果缓存（键含末期，换期自动失效）。

## 三、入库时补的两件事

**① 这批文件此前一直只在工作区、从未入库。** 而 `pack_deploy.py` 第 2.5 步只收 git 已跟踪的文件——**未入库就上不了服务器**。更要命的是 `app.py`（已跟踪、已改）里已经写了

```python
from routers import ..., report_dashboard
app.include_router(report_dashboard.router)
```

==打包脚本会跳过 `routers/report_dashboard.py`，却照原样带走引用它的 `app.py`——装上去后端直接起不来。== 脚本只打印一行「跳过未入库文件」，不会拦。**这是打包前必须先入库的硬理由**，不是流程洁癖。

**② 补本日志。** 治理要求每个版本都有，此前缺 V2.248 这一号。

## 四、一个排查时踩的坑，记下来免得下次再撞

自检路由是否注册时，我按 `app.routes` 里各条的 `.path` 去列，结果**所有 router 的路由一条都看不到**，一度以为注册失败。

实际是 **FastAPI 0.138 / Starlette 1.3 改了 `include_router` 的实现**：不再把子路由逐条拷进 `app.routes`，而是塞一个 `_IncludedRouter` 包装对象（`.path` 为空）。

> ==验路由要用 `app.openapi()['paths']`，别数 `app.routes`。==
> 实测 159 条路径全在，含仪表盘那两条。
